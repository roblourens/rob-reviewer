- Critical path: The click/Enter/Space handler issues one OPEN\_REMOTES\_EDITOR command and awaits the existing editor-open operation. - Scaling input: Boundary count is bounded by remote kinds (up to four discovery operations plus one cold status read), not by disconnected provider labels, automations, or history size; result processing scales with discovered remotes as it did before the PR.
- Effective concurrency: A single activation maps to one command. The existing RemotesWidget cancels/replaces an earlier refresh, while RemotesModel fans out at most one discovery per kind (SSH, WSL on Windows, tunnels, and GitHub environments) via Promise.all. The singleton editor input avoids duplicate editor instances.
- Cache behavior: Cold open constructs the singleton editor/model and starts discovery. Reopening an already active singleton does not create another model; making an existing editor visible uses the editor's existing refresh semantics. A new refresh cancels and replaces the previous request rather than retaining unbounded work.
