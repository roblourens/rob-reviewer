# Performance review: Support Marketplace-native deprecation for extensions

[PR #346881](https://github.com/microsoft/vscode/pull/346881) at `dfd97e44d405bad15923273c5cf5fb2a56492680`

## Findings (1)

### 1. [low] Restrict deprecated-list refreshes to relevant changes

**Finding ID:** `PERF-E2E4E4ED30EE`  
**Location:** <code>src/vs/workbench/contrib/extensions/browser/extensionsViews.ts:349</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** CPU work, PagedModel allocations, and list rendering  
**Scaling:** Every accepted undefined event scans all installed extensions, sorts matching rows, and replaces the list model; queryLocal can emit one event for each local, remote, and web extension server.  
**Outcome:** Increased refresh latency and avoidable list rendering.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Generic undefined workbench invalidations were ignored; only events carrying an installed extension refreshed this model.  
**Changed behavior:** An &#64;deprecated view now accepts every undefined workbench change and unconditionally publishes a newly filtered PagedModel.  
**Confidence:** 0.97 — The event producer, refresh path, collection scan, and model replacement are directly traced. Only the exact duration varies by extension count and server latency.

**Causal diff evidence:** The added \`(isDeprecatedQuery && \!e)\` at line 349 broadens the listener to all untyped invalidations; the added deprecated-query branch later in the same hunk always returns \`newExtensions\`, causing model publication.

Refreshing the Extensions view while &#64;deprecated is open first runs queryLocal, whose per-server queryInstalled calls emit undefined, then runs the explicit search refresh. This can rebuild the list during inventory loading and rebuild it again for the search; unrelated auto-update or install-completion invalidations do the same. Cost grows with installed extensions and configured extension servers.

**Evidence:** queryLocal sequentially calls queryInstalled for each server (extensionsWorkbenchService.ts:1535-1570), and queryInstalled fires undefined (line 748). ExtensionsViewlet.refresh awaits queryLocal before doSearch(true) (extensionsViewlet.ts:762-766). This callback filters/sorts local extensions and fires a new PagedModel (extensionsViews.ts:352-359); updateModel replaces the list's DelayedPagedModel (lines 1098-1101).

**Suggested direction:** Use a deprecation-specific/configuration event or tag the invalidation reason, retain concrete installed-extension events, and avoid publishing when deprecated identifiers and order are unchanged.
