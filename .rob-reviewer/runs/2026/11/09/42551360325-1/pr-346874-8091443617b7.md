# Performance review: sessions: show the Done section by default

[PR #346874](https://github.com/microsoft/vscode/pull/346874) at `8091443617b766c1956d75704e5aea184bcfe1da`

## Findings (1)

### 1. [medium] Lazily build the default-collapsed Done subtree

**Finding ID:** `PERF-BA7B23A640B5`  
**Location:** <code>src/vs/sessions/contrib/sessions/browser/sessions.contribution.ts:152</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** CPU work and allocated/retained tree element objects, including one session node plus nested chat nodes per archived entry on each rebuild.  
**Scaling:** Cost grows linearly with the effective number of locally cached or previously discovered archived sessions and their listed chats, and is paid again on each visible list update; archive history naturally grows over the profile lifetime.  
**Outcome:** Increased Agents-view render/update latency and CPU/GC pressure as archived history grows.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** With the previous false default, \`SessionsList.update()\` removed archived sessions at its early \`\_excludeArchived\` filter and did not construct an archived section or its child tree nodes unless the user explicitly enabled Done.  
**Changed behavior:** Changing the default to true makes \`\_excludeArchived\` false for every fresh profile, so archived sessions now flow through every visible SessionsList rebuild even though the Done section is created collapsed by default.  
**Confidence:** 0.97 — The default-to-filter call path, unconditional child allocation before collapse, and repeated visible-update triggers are explicit in the code. Exact history sizes and milliseconds vary by user, but the linear hidden-work mechanism and fresh-profile reachability are deterministic.

**Causal diff evidence:** The added \`default: true\` line flips fresh profiles from excluding archived sessions to including them, activating the unchanged eager subtree-construction path on initial render and every list update.

Opening the Agents view and ordinary session/status/model updates can become progressively slower and produce UI-thread/GC pressure for users with a long Done history, despite the Done section remaining collapsed and no archived row being visible.

**Evidence:** The constructor derives \`\_excludeArchived\` from this setting (\`sessionsList.ts:4821\`). When false, \`update()\` keeps archived entries, sorts all filtered sessions in \`groupSessionsForList\` (\`sessionsList.ts:5902\`, \`sessionsList.ts:9900\`), and \`renderSection\` unconditionally calls \`renderSessionChildren\`/\`toSessionChildren\` for every archived session and nested chat before assigning \`PreserveOrCollapsed\` (\`sessionsList.ts:6155-6234\`). The resulting full child array is passed to \`tree.setChildren\` (\`sessionsList.ts:6465-6484\`). Session/model/provider changes invoke \`refresh()\` or \`update()\` while the view is visible (\`sessionsList.ts:5639-5673\`). The existing archive-demand guard only postpones remote discovery until expansion (\`sessionsList.ts:6970-6978\`); it does not prevent this synchronous construction for locally cached or already-discovered archives.

**Suggested direction:** Keep the Done header visible by default, but do not build its session/chat children while it is collapsed. Populate the subtree on expansion (and for active search), and clear or cap it again on collapse while preserving the existing remote archive-demand lifecycle.
