<summary>Reviewer scenario analysis</summary>

**Relevant issue families:** serialization-allocation, boundary-fanout, concurrency-burst

### Scenario 1: Routing restricted Copilot engine snapshot telemetry for a model interaction

- Critical path: For each targeted restricted notification, account telemetry context resolution must complete before property multiplexing and routing. On a cold/expiring token this includes account discovery; on a warm token it is an in-memory lookup. Payload gzip for existing large fields is awaited through the libuv threadpool. The final telemetry POST is fire-and-forget and therefore off the notification's awaited critical path.
- Scaling input: One route invocation per existing engine.messages or engine.messages.length notification; effective work scales with model-call snapshot count. The added interaction\_id is already present in event.properties and was already included by the unchanged object spread before this PR.
- Effective concurrency: Concurrent account-context lookups for the same token share one cached promise; different tokens may discover independently. Each eligible event retains the pre-existing independent fire-and-forget telemetry POST behavior, with no new concurrency or fan-out introduced by the diff.
- Cache behavior: Account discovery is cached per GitHub token until its expiry refresh buffer, with concurrent cold requests coalesced. Warm routing performs no discovery network request. Telemetry events themselves are not cached or coalesced; that behavior is unchanged. The diff adds no cache keys or retained runtime state.
- Mechanism confidence: High: all production additions are telemetry schema declarations inside comments; executable routing, property spread, compression, destination selection, and network dispatch are unchanged. Test additions only assert the already-forwarded field.
- Magnitude uncertainty: Actual model-call and snapshot counts vary by interaction, and cold account-discovery latency depends on network conditions, but both multiplicity and boundary placement are unchanged by this PR.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/shared/copilotApiService.ts:995, CopilotApiService.\_getEntryForToken/\_buildClientForToken</code>: Resolve account and restricted-telemetry policy through the existing Copilot account-discovery request when the per-token cache is cold or near expiry.; cardinality: At most one coalesced discovery for concurrent callers sharing a token on a cold/refreshing cache; zero network calls on a warm cache.
    - Introduced by diff: false; previous behavior: Identical context resolution and per-token caching occurred before the diff.; critical-path effect: Cold discovery is awaited before routing the notification; warm cache lookup is immediate.
  - serialization at <code>src/vs/platform/agentHost/node/agentHostRestrictedTelemetry.ts:95, multiplexProperties</code>: Copy event properties and gzip/base64 existing known-large telemetry fields such as messagesJson.; cardinality: Once per targeted notification; interaction\_id is a short pass-through string and does not trigger compression.
    - Introduced by diff: false; previous behavior: The router already spread all event properties, including interaction\_id, and multiplexed them before the diff.; critical-path effect: Multiplexing is awaited before dispatch, but the changed declaration comments do not alter this work.
  - network at <code>src/vs/platform/agentHost/node/agentHostRestrictedTelemetry.ts:257, AgentHostRestrictedTelemetrySender.\_post</code>: Serialize an Application Insights envelope and issue one telemetry HTTP POST for each enabled destination/event.; cardinality: One Enhanced GH POST per eligible engine.messages event; engine.messages.length may additionally go to the existing internal sink. No event or destination was added.
    - Introduced by diff: false; previous behavior: The same property, event, destination, serialization, and POST count existed before the diff because the router already passed event.properties through unchanged.; critical-path effect: Envelope serialization occurs synchronously during routing; fetch completion is fire-and-forget and does not block route completion.
- Verdict: No reportable performance regression. The PR declares and documents an already-forwarded property and extends a test assertion; it adds no runtime work, payload field, boundary call, retention, or concurrency.

**Summary:** Completed the performance pass over all three changed files and all diff pages. Traced restricted engine notification routing through per-token context caching, property multiplexing, envelope serialization, and telemetry dispatch. No executable production behavior changes and no performance findings were identified.
