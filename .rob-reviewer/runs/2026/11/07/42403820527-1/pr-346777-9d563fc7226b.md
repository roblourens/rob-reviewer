# Performance review: Agents window: a chat's Changes tab shows its changes when no window shows the chat

[PR #346777](https://github.com/microsoft/vscode/pull/346777) at `9d563fc7226bf9a537a96e84cd013a8ffa6255af`

## Findings (1)

### 1. [medium] Suspend change observation while the diff pane is hidden

**Finding ID:** `PERF-D229EDDB10FF`  
**Location:** <code>src/vs/workbench/contrib/sessionChanges/browser/sessionChangesEditor.ts:258</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** Agent Host subscription snapshots, up to two text-model references per changed file, and one DiffEditorViewModel/diff computation per file  
**Scaling:** For a hidden editor the retained models and initial/background diff work grow linearly with the chat changeset's file count; each newly appearing file starts original/modified model resolution and a diff even though the pane is offscreen.  
**Outcome:** Background CPU and provider/filesystem I/O increase, and all resolved text models/diff view models remain retained while the hidden pane keeps its input, which can create responsiveness and memory pressure for large changesets.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** When no window showed the session, the chat changeset gate closed; the editor received no live file list (the reported empty-state bug), so the multi-diff did not keep resolving and diffing that hidden chat's files.  
**Changed behavior:** The new observed source is gated only by \`chat\` and \`\_hasInput\`, not \`\_paneVisible\`, so a Changes editor continues the Agent Host session/chat/changeset subscriptions after \`setEditorVisible(false)\`. The resulting resource updates stay connected to the existing multi-diff model while the pane is hidden.  
**Confidence:** 0.97 — The hidden-input lifecycle is asserted by the added test, the changed predicate visibly omits \`\_paneVisible\`, and the complete call path to refcounted protocol subscriptions, per-resource text-model creation, and eager per-document diff creation is explicit. Exact file counts and provider latency vary, affecting severity but not the mechanism.

**Causal diff evidence:** The added return at line 258 keeps the observation alive whenever an input exists, including the explicitly supported \`setVisible(false)\` state; before this diff there was no external changes observation to keep the hidden chat's live file list feeding the multi-diff.

Open a chat's Changes tab, switch the detail panel to Files (the new test explicitly keeps the input observed in this state), and let a background chat accumulate a large changeset. The offscreen editor eagerly resolves both sides and computes diffs for every file and retains those models until the input is cleared or the editor closes.

**Evidence:** \`\_observedChatSource\` at the changed line remains defined solely from \`\_hasInput\`; \`setEditorVisible(false)\` only updates \`\_paneVisible\` at line 601 and does not release it. \`observeChangesEditorChat\` reaches the new Agent Host gate, which subscribes to session/chat/selected-changeset protocol resources. Those changes feed \`ChangesMultiDiffSourceResolver.resources\`; unchanged \`MultiDiffEditorInput.\_createModel\` maps every resource to \`Promise.allSettled(createModelReference(original), createModelReference(modified))\` at lines 225-230, and \`MultiDiffEditorViewModel\` eagerly creates a \`DiffEditorViewModel\` for every document and waits for every initial diff at lines 91-101 and 224-239. Thus visibility suppression only hides the progress bar; it does not suppress model resolution or diff work.

**Suggested direction:** Keep the current diff/view state cached while hidden, but gate the external observation (or propagation of new resources into the multi-diff model) on \`\_paneVisible\`; resubscribe and refresh when shown. The existing hide path already saves collapsed/scroll state, so visible behavior can remain correct without performing new per-file model and diff work offscreen.

### Scenario 2: The Changes pane keeps its chat input while hidden, such as when the detail panel switches to Files, and the chat changes in the background.

- Critical path: The work is off the hidden pane's presentation critical path. Because \`\_observedChatSource\` ignores \`\_paneVisible\`, protocol updates continue into the existing multi-diff model, which eagerly resolves models and computes diffs for new files even though rendering is hidden.
- Scaling input: The retained state and background work scale with F files in the changeset; newly appearing resources start up to 2F cold model resolutions and F diff computations. Multiple hidden panes for different chats multiply this by their respective file counts.
- Effective concurrency: One wire subscription per unique session/chat/changeset URI is coalesced within a connection. Text model resolutions are launched via \`Promise.all\` for all resources, and each file starts both sides concurrently; there is no shared limiter on this hidden path.
- Cache behavior: Warm protocol and model caches reduce cold I/O, but the editor deliberately retains model references and diff view models for the whole hidden-input lifetime. Cached resource pairs avoid recreating unchanged files; new files and cold restored resources still incur eager work.
- Mechanism confidence: Very high: the added test proves observation survives \`setVisible(false)\`, the changed predicate omits visibility, and the transitive model code eagerly resolves and diffs every resource.
- Magnitude uncertainty: The prevalence of large background changesets and provider I/O cost is uncertain, so severity is medium; the linear eager work and hidden reachability are explicit.
- Expensive boundaries:
  - network at <code>src/vs/workbench/contrib/sessionChanges/browser/sessionChangesEditor.ts:\_observedChatSource</code>: Keep receiving Agent Host session/chat/selected-changeset snapshots and updates while the pane is hidden.; cardinality: Three coalesced unique resource subscriptions per observed chat in the normal case, retained until input clear/editor close.
    - Introduced by diff: true; previous behavior: No external observation existed, so once no window showed the session these live subscriptions closed.; critical-path effect: Off critical path while hidden; it competes with foreground work and is only useful for making a later show immediately current.
  - filesystem at <code>src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorInput.ts:\_createModel</code>: Resolve and retain original/modified text models and compute diff models for the hidden editor's files.; cardinality: Up to two model-provider resolutions plus one diff model per effective changed file; all file promises are joined concurrently.

- Verdict: Reportable regression: preserving the hidden observation performs and retains linear per-file work offscreen; gate observation or resource propagation by visibility while retaining/restoring saved view state.

- Mechanism confidence: High: both autorun stores and the protocol manager's zero-ref disposal were inspected, and added tests cover clear/change/close.

- Verdict: No separate lifecycle finding: cleanup and coalescing are correctly bounded.

- Verdict: No finding: the progress bar is visible-only constant UI work, and the session-level editor is unchanged.
