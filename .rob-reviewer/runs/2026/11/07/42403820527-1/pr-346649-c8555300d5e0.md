# Performance review: Repaint only the changed rows of the minimap decorations layer

## Findings (1)

### 1. [medium] Bypass frame recording when scrolling moves the minimap viewport

**Finding ID:** `PERF-962EF2E27491`  
**Location:** <code>src/vs/editor/browser/viewParts/minimap/minimap.ts:1572</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** Main-thread CPU work and short-lived strings, closures, and drawing-record objects, plus a second traversal of all visible drawings.  
**Scaling:** Cost grows with the number of visible decoration-line drawings and their covered pixel rows on every scroll render; aggregate cost grows further with the number of frames in a continuous scroll gesture.  
**Outcome:** Increased synchronous scroll latency, CPU/GC pressure, and potential dropped frames.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before the PR, a scroll render cleared the canvas and issued each visible decoration draw once, with no row-signature array, per-row string concatenation, deferred closure/object allocation, diff scan, or replay traversal.  
**Changed behavior:** Scrolling now synchronously materializes row signatures and deferred drawing closures for the entire visible decoration set before issuing the same canvas drawing calls during replay. On a moving proportional minimap with dense decorations, the dirty band spans most or all of the canvas, so this extra recording pass cannot reduce repaint work.  
**Confidence:** 0.92 — The default minimap size is proportional; onScrollChanged unconditionally schedules a decorations render; a viewport shift changes decoration row signatures; and RecordedFrame.add plus replay visibly add allocation, string construction, scanning, and a second traversal before the canvas calls. Magnitude depends on decoration density and scroll duration, so severity is medium rather than high.

**Causal diff evidence:** RIGHT line 1572 constructs a RecordedFrame for every decorations render; every scroll event sets \_renderDecorations at minimap.ts:1488. When the proportional minimap viewport moves, the changed code first records every visible drawing (including per-row signature strings and one closure/object per drawing) and then replays those same drawings after the diff identifies the broad changed band.

Continuous scrolling through a file with dense minimap decorations can incur thousands of short-lived strings, closures, and drawing records per animation frame before a full-band redraw, adding main-thread CPU/GC pressure and risking dropped scroll frames.

**Evidence:** RecordedFrame.fillRect/add calls RowSignatures.add, which loops over covered pixel rows and concatenates strings, then allocates an IRecordedDrawing object and closure. renderDecorations subsequently scans all canvas rows in RowSignatures.diff and all recorded drawings in replay. During continuous scrolling of the default proportional minimap, layout.startLineNumber changes and dense find/diagnostic/selection decorations move to different pixel rows, making the dirty range effectively the full decorated band; replay therefore performs all prior canvas calls in addition to the newly introduced recording work.

**Suggested direction:** Detect when scrolling changes the proportional minimap viewport and use an immediate full-redraw mode that skips signatures and deferred closures (resetting the cached signatures so the next incremental frame rebuilds them). Keep RecordedFrame only for stable-layout renders where a narrow dirty band can avoid repaint work.

**Performance category:** `rendering`  
**Confidence:** 0.99

**Mechanism:** Every decorations render synchronously cleared and redrew the full visible canvas, causing Chromium to repaint and recomposite the complete minimap decorations layer even for a one-row selection or decoration change.

**Symptom:** Typing and selection changes repaint the entire minimap decorations layer, increasing renderer-task latency on an input-critical path.

**Fixed behavior:** The renderer now clips to the differing row band and clears/replays only drawings intersecting it, avoiding complete decorations-layer invalidation for localized selection or decoration changes.

**Evidence:** In the base revision, cursor, decoration, theme, and scroll events set \_renderDecorations, after which base line 1562 clears the complete decorations canvas and the renderer redraws all visible decorations. The changed code computes RowSignatures.diff and changed line 1596 clears only that differing row band. The supplied measurements corroborate the mechanism by showing repainting fall from the full layer to a four-pixel band for a small edit.
