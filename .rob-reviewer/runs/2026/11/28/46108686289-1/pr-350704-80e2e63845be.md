- Scaling input: Number of requested tool calls and concurrently pending confirmations, not total available tools. Button construction remains bounded to three fallback options and two visible grouped buttons.
- Effective concurrency: Each request awaits its own decision. Existing pending-confirmation reevaluation iterates sequentially with cancellation; client outcome dispatch remains deduplicated. No new parallel scheduling or global limiter change.
- Cache behavior: Existing allow rules still auto-approve matching requests. Choosing the session option still adds a deduplicated tool rule; choosing Allow Once intentionally adds no reusable grant and requires consent again on subsequent calls. No positive/negative cache, invalidation, or coalescing code changed.
- Mechanism confidence: High confidence from the three-option constant, createToolReadyAction fallback, grouped button builder, selected-id dispatch, grant side effect, and provider pending-permission resolution.

### Scenario 3: Smoke automation accepts pending confirmations while waiting for chat responses or Dev Container log links.

- Critical path: When confirmation acceptance is enabled, each response/link polling iteration awaits the shared helper before checking progress. The helper reads button elements, verifies the primary label, locates a visible matching button, and clicks at most one.
- Scaling input: Opt-in polling iterations and currently matching confirmation buttons. The new regular expression remains fixed-size; selector scope, recursive element retrieval, iteration bounds, and timeouts are unchanged.
- Effective concurrency: All helper operations are sequentially awaited, and the helper returns after its first visible-button click. Polling is sequential rather than launching overlapping clicks.
- Cache behavior: No new cache or retained collection. Once clicked, the existing confirmation lifecycle settles the request; subsequent tool calls may intentionally require their own one-time approvals.
- Mechanism confidence: High confidence from all helper callers, the unchanged selector and loops, and the driver's concrete page.evaluate implementation.
- Magnitude uncertainty: Actual polling duration and number of visible/hidden widgets depend on the smoke workflow; no automation was executed.
- Expensive boundaries:

- Verdict: No performance regression or independently established performance-regression fix. The label expansion restores functional acceptance using the existing bounded path; timeout avoidance alone is not treated as a separate performance mechanism.
