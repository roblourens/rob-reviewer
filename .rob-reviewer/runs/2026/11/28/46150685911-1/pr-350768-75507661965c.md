# Performance review: Show structural changes in the Source Control Graph view

[PR #350768](https://github.com/microsoft/vscode/pull/350768) at `75507661965c3673e05a3f885fc924771ecc284d`

## Findings (1)

### 1. [medium] Refresh file nodes without re-querying every expanded commit

**Finding ID:** `PERF-F0E3246E5FDA`  
**Location:** <code>src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts:2515</code> (<code>RIGHT</code>)  
**Performance category:** <code>subprocess</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** Extension-host IPC calls, git diff subprocesses, and repeated full commit-change payloads  
**Scaling:** For N expanded history items, each completed structural-only root update issues N history-change IPC requests and normally N git diff subprocesses, not one call per file. AsyncDataTree runs these sibling requests concurrently; the structural model's three-load limiter does not constrain them. Work also grows with the files and rename detection in each commit.  
**Outcome:** Unnecessary subprocess/I/O bursts and payload allocation delay graph rendering and subsequent operations queued on the tree sequencer.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Changing Show Structural Diff or an unrelated document's language did not re-query the graph's expanded commits. History change queries occurred when expanding commits or explicitly refreshing/updating the graph.  
**Changed behavior:** An undefined structural-model notification now recursively refreshes the graph root, including all expanded history items, even when no file has been expanded for structural changes.  
**Confidence:** 0.97 — The new subscription and undefined-change handler reach a recursive root update. AsyncDataTree refreshes expanded history items concurrently, and the traced Git provider executes an uncached diff for each one. The view-model and element caches do not bypass those calls. Duration and prevalence of large expanded commits are unmeasured.

**Causal diff evidence:** The added onDidChange subscription at line 2298 routes structural model notifications to this newly added \_updateChildren() call at line 2515. Before this diff, structural enablement/provider/language changes had no subscription that refreshed the graph.

With several commits expanded, toggling Show Structural Diff, registering a structural provider, or changing even an unrelated editor's language re-runs each commit's Git diff. Large commits can make the graph update slow and hold up a subsequent Refresh or Load More, despite unchanged history and warm structural results.

**Evidence:** StructuralDiffModel.setEnabled and its provider/language listeners emit undefined (common/scmStructuralDiff.ts:307-329, 335-345). The new handler calls \_updateChildren, which queues recursive tree.updateChildren at scmHistoryViewPane.ts:2480-2490. AsyncDataTree.doRefreshSubTree refreshes siblings via Promises.settled and setChildren includes expanded children (asyncDataTree.ts:1132-1137, 1270-1290). Each expanded history item calls provideHistoryItemChanges at scmHistoryViewPane.ts:1157 before consulting \_getChangeElements. MainThreadSCM crosses IPC at mainThreadSCM.ts:255-262. GitHistoryProvider immediately calls repository.diffBetweenWithStats (extensions/git/src/historyProvider.ts:340-345), reaching an uncached git diff --raw --numstat --find-renames invocation (extensions/git/src/git.ts:1965-1980). getHistoryItems caches only history view models, not these change requests.

**Suggested direction:** Handle structural-only notifications by updating the existing file nodes' expandability and structural children, without refreshing their history-item ancestors. Keep full graph/history queries for actual history refreshes and pagination.
