# Performance review: chat: respect custom agent targets in Configure Tools

[PR #345912](https://github.com/microsoft/vscode/pull/345912) at `b70ea4a5d09ae83d77f988a24f3fa0bee6a8feb3`

## Findings (2)

### 1. [medium] Coalesce bulk checkbox tree refreshes

**Finding ID:** `PERF-5741381876B7`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/promptSyntax/promptToolsCodeLensProvider.ts:265</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** CPU work and QuickTree model/DOM reconciliation for all tool nodes  
**Scaling:** For N unique available tools, QuickTree's global check-all emits O(N) checkbox events, and this handler calls render/setItemTree over the O(N)-node catalogue for every event, producing O(N²) synchronous tree processing.  
**Outcome:** main-thread CPU spikes and picker jank or dropped frames during bulk selection  
**PR causality:** <code>introduced</code>  
**Previous behavior:** GitHub Copilot targets had no Configure Tools tree. Existing VS Code targets continue to use showToolsPicker and do not execute this new full-tree refresh handler.  
**Changed behavior:** Every checkbox event in the new Copilot tree now invokes render(), which replaces the full item tree even when QuickTree has already updated the changed item and descendants in place.  
**Confidence:** 0.98 — The event multiplicity and full-tree reconstruction are explicit in the shared QuickTree implementation, and this diff directly adds the per-event render. Catalogue size controls magnitude, but the quadratic mechanism and UI-thread reachability are deterministic.

**Causal diff evidence:** The added \`render();\` at line 265 is inside \`picker.onDidChangeCheckboxState\`. The shared QuickTree controller's \`checkAll\` loops all nodes and fires onDidChangeCheckboxState for each changed node, so one user bulk-toggle reaches this added line once per node.

Clicking the picker’s global check-all control can synchronously reconstruct a large Copilot tool tree dozens or hundreds of times, visibly freezing or stuttering the Configure Tools UI as installed/client/MCP tool count grows.

**Evidence:** QuickTree.setItemTree drives QuickInputTreeController.setTreeData, which recursively maps the complete hierarchy and calls ObjectTree.setChildren. QuickInputTreeController.checkAll emits a checkbox-state event for each updated root and descendant. The catalogue's effective N is the unique names grouped from every active client's tools plus MCP wildcard entries and built-ins, so larger extension/MCP tool inventories amplify the repeated full-tree reconstruction.

**Suggested direction:** Do not call setItemTree for each checkbox event. Let QuickTree's in-place checkbox propagation handle ordinary changes, update only dependent wildcard/all-tools items, and coalesce any required filtered-tree refresh to one microtask after a bulk operation.

### 2. [medium] Keep the first agent-host snapshot off shared tool lookups

**Finding ID:** `PERF-4830241A3C77`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentCustomizationItemProvider.ts:332</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** agent-host protocol subscription and first-snapshot IPC wait  
**Scaling:** On a cold session, each tool consumer waits for the first snapshot from every matching harness; warm reads are immediate, but an unresponsive session can leave the wait pending indefinitely.  
**Outcome:** blocked completion, hover, picker, and diagnostic latency during cold or stalled agent-host startup  
**PR causality:** <code>introduced</code>  
**Previous behavior:** provideAgentFileTools synchronously read the currently cached inventory. If no first snapshot had arrived, it returned undefined immediately, so resolveAgentFileTools remained fail-open and completion/hover/validation could finish with built-in tools while the existing subscription loaded in the background.  
**Changed behavior:** The added await blocks provideAgentFileTools until the asynchronous session-state subscription receives its first protocol snapshot. Because this provider is shared by resolveAgentFileTools, the wait is added not only to the new picker but also to existing completion, hover, and validation paths.  
**Confidence:** 0.97 — The changed await, the first-snapshot implementation, and all transitive callers are directly traced. The exact snapshot duration varies by host/connection, which limits severity, but the cold critical-path latency change is deterministic.

**Causal diff evidence:** The added line \`await this.\_customAgentsService.whenCustomizationsReady(sessionResource, token);\` at line 332 precedes the formerly immediate \`getAgentFileToolInventory\` read. Existing callers in promptHeaderAutocompletion.ts:243, promptHovers.ts:208, and promptValidator.ts:413 all transitively invoke this method; the validator supplies CancellationToken.None.

Opening or editing a GitHub Copilot agent before its remote/ambient agent-host snapshot arrives delays tool suggestions and hovers; diagnostics and Configure Tools also remain pending. A slow or stalled connection can keep these operations waiting indefinitely instead of returning the built-in/fail-open catalogue.

**Evidence:** WorkbenchAgentHostCustomizationService.whenCustomizationsReady creates/uses a session-state subscription and awaits \`\_awaitFirstSnapshot\`, which resolves only on subscription change/error or cancellation and has no timeout. The prompt completion and hover providers await resolveAgentFileTools on interactive requests, while PromptValidator's visible-editor ModelTracker invokes it after edits with CancellationToken.None. Thus cold or stalled agent-host IPC now directly gates these consumers even though the old cached read returned immediately.

**Suggested direction:** Keep provideAgentFileTools as a nonblocking cached read and put the readiness wait only in the new Configure Tools picker, where the busy UI and cancellation policy explicitly require a complete inventory. Alternatively add an explicit wait mode with cancellation/timeout so completion, hover, and validation retain the previous fail-open path.
