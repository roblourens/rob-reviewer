### Scenario 3: A user selects Refresh in a remote direct chat connected to a host with host-control methods disabled.

- Critical path: The click sends one extension request, validates chat/scope on the host, runs the target certificate refresh, then the existing provider implementation waits for diagnostics refresh across live sessions before replying and clearing the UI spinner.
- Scaling input: Distinct live runtime/credential configurations after cache grouping, not raw chat count; one focused user action triggers the scenario.
- Effective concurrency: The UI's \_certificateBusy flag coalesces repeated clicks in one notification. Host certificate operations are serialized by SequencerByKey; post-operation live-session diagnostic updates use Promise.all, while the certificate cache coalesces sessions sharing the same runtime credential configuration.
- Cache behavior: Refresh intentionally invalidates certificate observations. Subsequent diagnostics are cached by runtime and \[auth.git, auth.gh, credentials\], including failures, and concurrent equivalent reads coalesce. Warm non-refresh diagnostics reuse the cache; each explicit refresh is cold by design.
- Mechanism confidence: High: the full workbench-to-protocol-to-agent-to-SDK call path, cache key, sequencer, Promise.all fan-out, and timeout were inspected.
- Magnitude uncertainty: Hosts may have multiple live credential configurations and SDK checks can approach their timeout, but typical cardinality is unknown. The fan-out is pre-existing implementation used by the newly enabled explicit action.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/protocolServerHandler.ts:3935</code>: Send vscode/refreshSandboxCertificate from the workbench client to the remote agent host and return its result.; cardinality: One request per accepted user click; the notification blocks duplicate clicks while one request is active.
    - Introduced by diff: true; previous behavior: For allowExtensionMethods=false direct hosts, the method gate rejected this request before dispatch and no certificate check ran.; critical-path effect: The refresh UI waits for the response.
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotSandboxCertificate.ts:\_check</code>: Query the Copilot SDK certificate proxy for relevance, installation support, and trust status.; cardinality: After intentional cache invalidation, up to three sequential SDK RPCs for the clicked configuration, then up to three per distinct uncached runtime credential configuration among live sessions; sessions sharing a key reuse/coalesce the same promise.
    - Introduced by diff: true; previous behavior: This boundary was unreachable through direct clients with host-control disabled; it was already the established refresh behavior for clients where refresh was allowed.; critical-path effect: The existing refresh implementation awaits these checks before the protocol response; each SDK read is bounded by a five-second timeout.
- Verdict: No finding. The diff intentionally makes an explicitly requested read-only refresh reachable; duplicate UI clicks are coalesced, SDK checks are bounded and cached by effective configuration, and the changed hunks do not add automatic retries or alter the pre-existing per-refresh fan-out.
