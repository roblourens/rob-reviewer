# Performance review: ci: only run the chat-lib pipeline for changes in extensions/copilot

[PR #345996](https://github.com/microsoft/vscode/pull/345996) at `3147e187ae70770a94d81f0c5621732ceb9ee524`

## Findings

No high-confidence performance findings.

## Performance regression fixes detected (1)

### 1. eager-work

**Fix location:** `extensions/copilot/build/npm-package.yml:7` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/build/npm-package.yml:5`  
**Introducing path:** `extensions/copilot/build/npm-package.yml`  
**Introducing commit:** `3b795b1e58326cf6c70a7d39270981ce2c885128`  
**Mechanism family:** `eager-work`  
**Performance category:** `subprocess`  
**Confidence:** 0.95

**Mechanism:** A repository-wide branch trigger eagerly scheduled dependency installation, extraction, compilation, and a three-platform test matrix for unrelated pushes; batching could merge queued pushes but could not avoid this work when an unrelated push produced a run.

**Symptom:** Unrelated main/release pushes consumed Azure agents and incurred unnecessary package-network, filesystem, build, and test work, increasing CI resource use and potential queue latency.

**Fixed behavior:** The new path include prevents unrelated repository pushes from scheduling the chat-lib build/test pipeline while preserving runs for Copilot changes and manual invocation.

**Evidence:** Before this PR, the top-level trigger included every push to main and release/\* with no path restriction. Each such trigger reaches build-chat-lib.yml, which installs pnpm, runs two frozen dependency installs, extracts chat-lib, and builds it; the pipeline also executes chat-lib tests on Linux, macOS, and Windows. The added paths.include at RIGHT lines 7-9 limits that unchanged expensive path to pushes touching extensions/copilot.
