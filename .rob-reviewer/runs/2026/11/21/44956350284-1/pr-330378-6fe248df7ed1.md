## Findings (2)

### 1. [medium] Release the virtual bundle tree when a scope is disposed

**Finding ID:** `PERF-D51D5C7ACA9C`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostActiveClientService.ts:194</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Uint8Array file contents and File/Directory objects retained by the shared in-memory filesystem root.  
**Scaling:** Retained memory grows with the sum of bundle bytes across distinct root-set authorities ever successfully bundled during the window lifetime, rather than only live scopes; revisiting the same authority does not add another tree.  
**Outcome:** Persistent memory growth that is not reclaimed when sessions/scopes close.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** One bundler per session type reused one virtual directory. Each changed bundle recursively deleted that directory before rewriting it, bounding retained bundle data by the registered provider count.  
**Changed behavior:** Each distinct normalized root set now creates a separate bundler authority. Releasing the last scope holder disposes the bundler object but never deletes its virtual directory.  
**Confidence:** 0.99 — The new bundler namespace is root-set-specific, scope teardown only disposes listeners and removes the scope, and the shared InMemoryFileSystemProvider retains file data until explicit deletion. These ownership paths establish retention without relying on measured bundle sizes.

**Causal diff evidence:** Added line 194 constructs SyncedCustomizationBundler with createScopeAuthority(\_sessionType, \_roots); acquireScope creates one instance per root-set key. Added scope disposal at lines 319-330 and last-reference release at 333-336 do not remove that authority's files.

Opening and closing sessions across different repositories or isolated working-directory sets leaves all their instruction, prompt, skill and MCP bundle bytes resident for the window lifetime, even with few sessions currently open. Long-lived Agents windows accumulate memory unnecessarily.

**Evidence:** SyncedCustomizationBundler.bundle reads source bytes and writes them under /&lt;authority&gt; (syncedCustomizationBundler.ts:136-137, 241-255); its only recursive delete replaces the same authority during another bundle call, and it has no disposal override. AgentHostFileSystemService.ensureSyncedCustomizationProvider owns a single window-lived InMemoryFileSystemProvider (workbench/services/agentHost/common/agentHostFileSystemService.ts:63-68). That provider holds File.data in its root directory map (platform/files/common/inMemoryFilesystemProvider.ts:21, 40, 78, 153). Closing a chat releases the scope through \_disposeActiveClientEntry, not the directory.

**Suggested direction:** Give the scope/bundler ownership of removing its authority tree on final release, or a bounded inactive-tree cache. Coordinate cleanup with in-flight bundling and reacquisition so late writes or stale cleanup cannot recreate or delete a replacement scope's tree.

### 2. [medium] Exclude ambient folder switches from fixed-scope invalidation

**Finding ID:** `PERF-5C4B0AD2E793`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostActiveClientService.ts:247</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Filesystem directory/stat/read calls, content parsing/hashing, and dynamic prompt-provider IPC.  
**Scaling:** For S distinct live scopes with R\_s roots, each coalesced switch schedules S independent updates: 8\*sum(R\_s) explicit-root local listing calls, plus each scope's deduplicated loose-file and agent reads. Each dynamic provider for a prompt type is called twice per scope, not per file. Identical root sets share a scope; the 50 ms debounce does not merge different scopes.  
**Outcome:** Increased filesystem/IPC traffic and CPU contention during repository switching, scaling with distinct live scopes rather than the active repository.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** Each session type had one listener and one resolution pass against the ambient workspace per coalesced folder change.  
**Changed behavior:** The same ambient prompt-change events are now subscribed by every root-set scope, causing all live fixed-root scopes to re-resolve when switching between repositories, even though their roots and files have not changed.  
**Confidence:** 0.98 — WorkspaceFolderManagementContribution swaps folders on active-session changes; PromptFilesLocator and CachedPromise propagate each swap to the exact events subscribed here. Every distinct live scope independently enumerates and rereads its files. The 50 ms debounce and URI/nonce deduplication occur at levels that do not coalesce this cross-scope work.

**Causal diff evidence:** Added lines 247-252 install the global prompt-event listener inside AgentCustomizationScope, rather than once in registerForAgent. Each resulting update executes both resolveCustomizationRefs and resolveLocalCustomAgents with that scope's roots at added lines 201-216.

With multiple open/background sessions in different repositories, every repository switch triggers filesystem scans and content hashing for unrelated repositories, plus repeated extension-provider IPC when such providers are registered. This creates avoidable I/O and renderer CPU contention during session navigation despite suppressing unchanged host publishes.

**Evidence:** WorkspaceFolderManagementContribution updates folders on active-session changes (sessions/contrib/workspace/browser/workspaceFolderManagement.ts:33-38, 62), which fires onDidChangeWorkspaceFolders (sessions/services/workspace/browser/workspaceContextService.ts:166). PromptFilesLocator.createFilesUpdatedEvent fires on that event (promptFilesLocator.ts:246-249); PromptsService CachedPromise forwards it without checking content equality (promptsServiceImpl.ts:1573-1576). listPromptFilesForStorage bypasses cachedFileLocations, so both resolver enumerations perform fresh local discovery. SyncedCustomizationBundler reads every loose file before its nonce check (syncedCustomizationBundler.ts:164-197, 228-229), and resolveLocalCustomAgents rereads agent files. Dynamic extension providers are also re-invoked through $providePromptFiles with no result coalescing (extensionPromptFileService.ts:239-252; mainThreadChatAgents2.ts:733).

**Suggested direction:** Separate ambient-workspace invalidation from actual file/configuration/provider changes and skip ambient-only changes for scopes with fixed roots. Preserve ambient management-UI updates and genuine shared customization invalidations; retain the per-scope debounce.
