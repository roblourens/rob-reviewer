## Performance regression fixes detected (1)

### 1. missing-coalescing

**Fix location:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostActiveClientService.ts:156` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostActiveClientService.ts:157`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostActiveClientService.ts`  
**Introducing commit:** `c14ff798a753dc8afcf8081ffe90a4763a9ee226`  
**Mechanism family:** `missing-coalescing`  
**Performance category:** `latency`  
**Confidence:** 0.98

**Mechanism:** A debounce-only scheduler admitted overlapping full customization scans whenever refresh events were separated by more than 50 ms but scans took longer. Extra scans repeated discovery, extension-provider IPC and agent reads, queued redundant bundled-content traversals, and invalidated completed initial results, delaying the custom-agent picker and session claim until a newer scan completed without being superseded.

**Symptom:** During a startup customization-event burst on slow discovery or remote filesystems, completed initial scans could be discarded, delaying picker population and the session-claim critical path while redundant scan I/O accumulated. This is established by scheduling and call-path evidence, not a measured timing result.

**Fixed behavior:** The added ThrottledDelayer construction serializes scans within each shared session-type/root-set scope and coalesces eligible pending refreshes into one follow-up. Replacing the sequence guard with a disposal guard allows the first completed scan to publish and settle initial resolution instead of waiting for a scan that survives overlapping refreshes. Existing per-authority bundle sequencing and per-bundler I/O limits remain intact; independent scopes remain independent.

**Evidence:** The deleted base line 157 constructs a plain Delayer with a 50 ms debounce. Delayer.trigger (async.ts:443-454) clears completionPromise before invoking the asynchronous task, so another event after the debounce can start another scan before the previous one finishes. Scope listeners include prompt changes, sync-provider changes, plugin and MCP observable changes, and skill-folder file changes. Each scan enumerates prompt locations once, then runs resolveCustomizationRefs and resolveLocalCustomAgents concurrently. Local/user listings perform filesystem discovery and extension listings invoke provider IPC; custom-agent resolution reads each enabled agent file. Bundling is already sequenced per authority and limits source file operations to 10 per bundler, but each extra scan still enqueues another content-read/hash traversal. The deleted sequence guard discards completed results if a later scan has begun, and initial resolution completes only for an accepted scan. ActiveClientEntry.claim awaits scope.whenResolved (agentHostSessionHandler.ts:1304), and ambient draft agents feed the picker (agentHostChatContribution.ts:415-417). The added test at agentHostClientTools.test.ts:288-349 holds a scan open while ten changes arrive 100 ms apart and establishes one scan during the burst, first-result publication, and two total scans. Blame identifies c14ff798a753dc8afcf8081ffe90a4763a9ee226 as introducing the old Delayer construction.

### Scenario 4: Disposing the last scope reference, closing a draft, or removing a provider while a scan and refresh are pending.

- Critical path: Disposal completes the initial-resolution promise, unregisters listeners/watchers and removes the scope immediately; it does not await outstanding I/O. Late scan results do not publish.
- Scaling input: Outstanding work in one active scan per disposed scope and at most one coalesced queued follow-up. Remaining discovery/agent reads scale with the already-started scan, not future events.
- Effective concurrency: ThrottledDelayer.dispose cancels its timer and disposes Throttler; its completion continuation checks cancellation before starting queued work. Already-started I/O settles asynchronously. Before the PR several scans could already be in flight.
- Cache behavior: The scheduler and scope are disposed; queued factories are cleared. Existing in-flight enumeration and agent reads use CancellationToken.None, while bundlers reject further operations after disposal and drain their existing file-operation limiter. No new persistent map or negative-cache state is added.
- Mechanism confidence: High: disposal implementations, reference release, map removal and the added in-flight/queued-disposal test were inspected.
- Magnitude uncertainty: Duration of already-started provider or remote filesystem operations is unknown; their non-cancellation is pre-existing.
- Expensive boundaries:
  - filesystem at <code>src/vs/base/common/async.ts:Throttler.dispose and queue; src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/syncedCustomizationBundler.ts:DrainingFileOperationLimiter.dispose</code>: Allow already-started discovery/agent reads to settle while preventing queued refreshes and new bundle file operations; unregister existing skill-folder watchers.; cardinality: No queued refresh executes after disposal. Residual work is bounded by the active scan and already-started bundler operations; the bundler's existing source-I/O limit is 10 each. Earlier versions could have multiple residual scans.
    - Introduced by diff: false; previous behavior: Delayer disposal canceled only pending debounce work; sequence invalidation suppressed publication but did not cancel already-started parallel scans. Bundler draining and watcher cleanup already existed.; critical-path effect: Cleanup and late I/O do not delay scope-release completion or initial-resolution promise settlement.
- Verdict: No cleanup or retained-resource regression introduced. The change additionally prevents queued refresh execution and preserves suppression of late publication.
