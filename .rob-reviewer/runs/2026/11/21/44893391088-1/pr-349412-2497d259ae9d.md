# Performance review: agentHost: use origin/main as the default branch when origin/HEAD still points at an older origin/master

[PR #349412](https://github.com/microsoft/vscode/pull/349412) at `2497d259ae9de0504521bb8b0dc20ff21f9e8f8c`

## Findings (1)

### 1. [medium] Reuse ancestry results across unchanged Git-state refreshes

**Finding ID:** `PERF-CF1EB5748753`  
**Location:** <code>src/vs/platform/agentHost/node/agentHostGitService.ts:125</code> (<code>RIGHT</code>)  
**Performance category:** <code>subprocess</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Git child processes and commit-ancestry traversal/object reads.  
**Scaling:** For G non-coalesced directory/base refresh groups and R effective refresh rounds, distinct existing main/master tips add 2\*G\*R ref-resolution subprocesses plus G\*R ancestry subprocesses. Within one session, queued refreshes are throttled to five seconds; overlapping reads of the same directory/base/freshness can share one read. Reachability work additionally depends on the history Git must inspect; warm filesystem/commit-graph caches do not eliminate repeated processes.  
**Outcome:** Repeated Git process creation and history traversal increase background CPU/I/O and place avoidable latency before Git-state and downstream Changes updates.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The initial default-branch probe was one symbolic-ref subprocess with no history traversal. With a saved base of main, the existing base divergence/diff stayed anchored to main, so there was no old-master traversal on this default-branch probe to offset the added work.  
**Changed behavior:** Every effective Git-state read now performs two additional rev-parse subprocesses and, for distinct existing main/master tips, one additional ancestry subprocess. The ancestry answer is recalculated even when both immutable commit IDs are unchanged.  
**Confidence:** 0.96 — The helper has no result or in-flight cache; \_computeSessionGitState unconditionally awaits it. File-monitor refreshes reach this path, and the state service coalesces only overlapping reads with the same directory/base/freshness key and throttles each session to five seconds. Subsequent refreshes therefore repeat the command. Exact graph traversal duration depends on history size and Git's commit-graph/disk caches.

**Causal diff evidence:** Added line 125 runs merge-base --is-ancestor whenever origin/HEAD names main/master and both refs resolve to different commits; added line 1470 substitutes this helper for the previous single symbolic-ref probe in \_computeSessionGitState. The configuredBaseBranch override at line 1490 occurs only after awaiting the helper, so saved bases do not avoid the new work.

In a long-lived clone retaining an old origin/master behind origin/main, editing files with Changes observed repeatedly launches and awaits a history reachability check, including for sessions already saved against main. This adds CPU/object-reading work and can delay Changes refreshes in large histories; distinct worktree/directory-base groups repeat it independently.

**Evidence:** AgentHostGitService.ts:112-125 resolves both commit IDs but does not reuse them to memoize reachability. \_computeSessionGitState:1467-1471 awaits the helper before publishing state. ChangesetFileMonitorCoordinator.\_onRootsChanged:366-390 requests forced refreshes for watched, inactive sessions after relevant edits. AgentHostGitStateService:468-476 awaits the Git read before its refresh event; 543-546 imposes a five-second per-session throttle; 565-583 shares only in-flight directory/base reads and removes them on settlement. \_runGit:1590 directly creates a child process without a shared limiter.

**Suggested direction:** Use a bounded cache for successful ancestry answers keyed by repository and the two resolved commit IDs, and coalesce identical in-flight checks. Continue resolving refs on refresh so changed tips naturally select a new key; do not cache transient command failures.


## Performance regression fixes detected (1)

### 1. eager-work

**Fix location:** `src/vs/platform/agentHost/node/agentHostGitService.ts:1470` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/agentHostGitService.ts:1440`  
**Introducing path:** `src/vs/platform/agentHost/node/agentHostGitService.ts`  
**Introducing commit:** `7516b04bc945baf66c23e0af501dd59bb8d67938`  
**Mechanism family:** `eager-work`  
**Performance category:** `latency`  
**Confidence:** 0.93

**Mechanism:** Trusting a stale but existing origin/HEAD target selected an obsolete branch-diff base. Every unrelated changed path since that old commit became a file entry, which the Changes editor eagerly loaded before its complete document set could render.

**Symptom:** Opening Branch Changes in an affected clone loaded potentially hundreds of unrelated files, including binaries, increasing file/model allocation and delaying editor document resolution. This consequence is established by the baseline-to-entry-to-eager-loading call path; no timing measurement is asserted.

**Fixed behavior:** For a session without a saved base, a stale ancestor origin/master is replaced by origin/main before branch-diff baseline selection. Historical main-only file changes no longer enter the diff list, reducing downstream parsing, protocol payloads and eager text-model/file loading to the actual session changes. Saved bases and diverged refs remain unchanged.

**Evidence:** The replaced base-revision symbolic-ref probe at line 1440 supplied origin/HEAD directly to the Git-state fallback base. The new call at line 1470 and helper at 103-126 substitute origin/main when retained origin/master is its ancestor. Added integration test lines 832-856 establishes stale/diverged/dangling outcomes. AgentHostChangesetService.\_getBranchBaseBranch (2671-2685) uses Git-state base when none is saved; \_computeBranchDiffs (1439-1440) passes it into computeSessionFileDiffs, which resolves merge-base HEAD/base and runs git diff (844-868). parseGitDiffRawNumstat (2150-2250) creates an entry for every changed path, including binary paths. \_publishChangesetDiffs (2498-2519) publishes all entries. ChangesMultiDiffSourceResolver (68-75) maps each entry to a MultiDiffEditorItem, and MultiDiffEditorInput (236-246,317) eagerly resolves every side and awaits all document promises. Thus files introduced between the obsolete master tip and main caused real extra model/file loading, not merely an incorrect label.
