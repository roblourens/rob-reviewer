### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/sessions/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:6369` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/sessions/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:10208`  
**Introducing path:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`  
**Introducing commit:** `0695d91131628a77143182333b5bf2a7a57245f4`  
**Mechanism family:** `repeated-work`  
**Performance category:** `cpu`  
**Confidence:** 0.99

**Mechanism:** A config-state observer reasserted its own exact sensitive-location list whenever another window's list differed. For two clients with incompatible lists, every foreign state update produced another config dispatch, creating an idle feedback loop with repeated protocol broadcasts, config allocation/serialization/persistence, and picker DOM reconstruction. Local caching of computed locations did not suppress these differing-value writes.

**Symptom:** Strongly evidenced sustained agent-host/renderer work and repeated picker reconstruction while a shared session is idle, plus unbounded-in-time protocol and persistence operations until one client stops observing or the lists agree; no independent timing or CPU measurement was performed.

**Fixed behavior:** Routine session-state updates and existing peer-chat sends preserve the host's locations and add only missing local locations; equality suppresses writes once the clients reach their union. Exact replacement is reserved for initial config seeding or local setting changes. The turn handler likewise consults live state and avoids redundant writes on subsequent unchanged turns.

**Evidence:** The deleted base line 10208 calls \_syncSensitiveEditLocations after seeding each changed SessionState config; the equal-config branch also calls it. Before the PR, desired was always computed.locations, and any differing host value triggered SessionConfigChanged. With two subscribed clients whose lists are A and B, each foreign config state therefore causes another exact-list write, preventing quiescence even while idle. \_openSessionStateSubscription calls \_applySessionStateUpdate on every state change, which calls \_seedRunningConfigFromState. AgentHostProtocolClient.dispatchAction sends a dispatchAction notification; ProtocolServerHandler.\_broadcastAction sends the resulting envelope to relevant subscribed clients. \_handleConfigChanged and \_seedRunningConfigFromState fire picker events; AgentHostModePicker.\_updateTrigger clears and recreates label DOM. SessionFlagsContribution also queues config serialization and persistence for each config action. Added line 6369 merges the live host locations with local locations in ensure mode, and added lines 10204/10214 select ensure for subsequent state updates, so the union becomes equal and dispatch stops. The new two-client convergence test encodes this trigger. Blame resolves the old reassertion line to 0695d91131628a77143182333b5bf2a7a57245f4.
