## Findings (1)

### 1. [medium] Precompute row accessibility counts before uncapping branches

**Finding ID:** `PERF-A49DFC3DC9DC`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostBranchPicker.ts:14</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Full-list and prefix array scans and allocations performed by per-row accessibility callbacks.  
**Scaling:** For N matching local branches and k newly rendered rows, getSetSize alone performs O(k\*N) work and allocates k arrays of N references; getPosInSet adds prefix copies and scans. Traversing the whole list produces O(N^2) aggregate work. Only roughly ten rows are resident, but N remains the full result count.  
**Outcome:** Increased UI-thread CPU and allocation/GC pressure while opening and scrolling large branch lists, risking dropped frames.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** The workbench picker passed at most 25 matching branches to ActionListWidget, bounding each accessibility scan and allocation to 25 entries. The separate Agents desktop picker already explicitly requested unlimited results and is not newly affected by this cap removal.  
**Changed behavior:** The workbench branch picker supplies an unbounded branch collection to an action list whose accessibility callbacks scan and allocate from the entire collection for every newly rendered row. The new ten-row height cap limits DOM residency, not these callbacks' input size.  
**Confidence:** 0.96 — The uncapped helper calls, inherited accessibility callbacks, and scroll-to-row-insertion path are directly traced. The workbench accessibility override returns an empty object for this noncombined picker, so it does not replace the expensive callbacks. Duration and prevalence of very large local-branch collections are unmeasured.

**Causal diff evidence:** agentHostBranchPicker.ts:14 changes the default limit from 25 to Infinity. AgentHostChatInputPicker.\_showPicker (agentHostChatInputPicker.ts:898-900) and its filter delegate (:948) invoke this helper without an explicit limit, so the workbench action list now receives all N matching local branches instead of at most 25.

In repositories accumulating thousands of local branches, opening or scrolling the workbench branch picker repeatedly scans and allocates large branch arrays on the UI thread, creating CPU/GC pressure and potential scrolling jank despite displaying only ten rows.

**Evidence:** ActionListWidget's default getSetSize filters \_visibleMenuItems for each row, and getPosInSet slices and filters the prefix (src/vs/platform/actionWidget/browser/actionList.ts, accessibilityProvider in the List constructor). ListView.onScroll calls render; render inserts newly visible rows; insertItemInDOM calls updateItemInDOM, which invokes both callbacks at listView.ts:1080-1081. getModePermissionsPickerAccessibilityProvider(false) returns {}. maxVisibleItems only caps height; it does not truncate \_visibleMenuItems.

**Suggested direction:** Preserve the full branch list, but make accessibility counts constant-time per row: compute action count and prefix positions when filtered items change, or supply equivalent O(1) callbacks for the workbench branch-only list. Refresh those counts on each filter/rebuild.
