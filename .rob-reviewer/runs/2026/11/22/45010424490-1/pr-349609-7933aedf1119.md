### Scenario 3: Classify suite/test registrations, nested test structures, and edits inside functions or methods.

- Critical path: Collect entities for both versions, recognize suites and tests, match siblings, classify text coverage, and prune unchanged nodes before returning through the selected TS6/TS7 workflow.
- Scaling input: Suite/test statements and declared members determine collected structural entities; callback AST size additionally affects test-span traversal in non-test files. Compound suite statements expose their syntactic tests, not runtime loop iterations. Offset matching adds a binary search over changes per modified sibling.
- Effective concurrency: Both collectors and matching/classification run synchronously within their existing process. No asynchronous work or boundary request is issued per test; SCM's three-load bound still applies.

Test files skip the separate test-span scan; non-test files retain a traversal for tagging callbacks inside functions. Completed SCM results are cached under the existing lifecycle.

### Scenario 4: Restore many expanded SCM files or edit an already-expanded file repeatedly.

- Critical path: An uncached resource waits for a load slot, model resolution, text diff, and provider completion. Cached structural children return immediately. Content changes invalidate the entry and schedule a view refresh before the next request.
- Scaling input: Distinct expanded SCM resources after per-entry pending-request sharing, not individual structural children. Original/modified versions within one resource share one provider workflow.
- Effective concurrency: A shared Limiter permits three active loads, with a 30-second existing load budget. Provider calls within a load are sequential; synchronous TS6/TS7 classification remains serialized by the process event loop. No new per-child task scheduling or global concurrency burst.
- Cache behavior: entry.pending coalesces concurrent requests for the same SCM resource; children caches success, empty results, and failure/status rows. Content changes, collapse/release, group removal, provider invalidation, and disposal release existing entries and references. Those mechanisms are unchanged.
- Mechanism confidence: High confidence in the three-load limiter, per-resource coalescing, cached negative results, and lifecycle disposal.
- Magnitude uncertainty: Workspace resource counts and analysis durations vary; no profiling was performed. The effective resource concurrency and cache behavior are directly established in unchanged caller code.
- Expensive boundaries:
