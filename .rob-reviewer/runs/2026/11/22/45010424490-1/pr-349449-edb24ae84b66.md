# Performance review: feat(chat-lib): add editor-agnostic NES language context provider (alternative to \#349299)

[PR #349449](https://github.com/microsoft/vscode/pull/349449) at `edb24ae84b66f1c7399f5f7679fdf6e37af8d36a`

## Findings (1)

### 1. [medium] Enforce the deadline while consuming ready snippets

**Finding ID:** `PERF-9843963BCEEB`  
**Location:** <code>extensions/copilot/src/lib/node/chatLibMain.ts:633</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>serialization-allocation</code>  
**Resource:** Iterator processing CPU, URI objects, and LanguageContextEntry objects retained in the per-request items array  
**Scaling:** For each actual uncached/unjoined NES generation, work and temporary entry storage grow with all N immediately yielded snippets, rather than the prefix obtainable before the deadline. NES result-cache hits and joined requests do not invoke a separate collector.  
**Outcome:** Blocked prompt/network issuance and increased event-loop latency and allocation/GC pressure beyond the configured context budget  
**PR causality:** <code>introduced</code>  
**Previous behavior:** chat-lib registered NullWorkspaceService and NullLanguageContextProviderService, so the old XtabProvider language-context path returned undefined without invoking an embedder or collecting snippets. The unchanged VS Code collector is not the subject of this finding.  
**Changed behavior:** The new embedder adapter adds an awaited streaming collector and treats a timer race as its only deadline enforcement, allowing ready snippets to bypass the intended time bound and accumulate before downstream prompt clipping.  
**Confidence:** 0.94 — The new collector checks cancellation but not elapsed time, raceTimeout uses setTimeout, and cancellation occurs only after the race completes. Immediately yielding async iterators drain through microtasks before timers can run. The awaited prompt-gathering call path and per-snippet allocations are explicit; batch sizes and elapsed latency are not measured.

**Causal diff evidence:** Added lines 632-637 consume and allocate entries with only a cancellation check; added line 641 relies on a timer race, while added lines 643-644 cancel the token only after that race finishes. These lines newly create the unbounded-by-deadline collection path in chat-lib.

With language context enabled, an embedder streaming a large cached declaration batch can delay the next-edit request and other work on the same event loop by consuming and allocating the entire batch, including snippets produced after the supplied deadline. This also occurs when prior prompt preparation has already exhausted the debounce budget.

**Evidence:** EmbedderLanguageContextService collects each snippet with URI.parse and items.push (lines 632-637), checking only cts.token.isCancellationRequested. Its timeout is raceTimeout(collect(), request.timeBudgetMs) at line 641; util/vs/base/common/async.ts:159-169 implements that timeout with setTimeout. An async generator yielding cached snippets without an intervening task-level wait therefore keeps scheduling microtasks, preventing the timeout and finally's cancellation from running until the batch finishes. XtabProvider.gatherContextAndClipCurrentFile awaits language context before prompt construction and endpoint.makeChatRequest2. DelaySession.getDebounceTime can return zero, and prompt token clipping happens only after collection.

**Suggested direction:** Store the absolute deadline and check Date.now() against it before starting/advancing collection and before accepting each snippet, alongside cancellation. Race against the remaining time rather than restarting the full budget after provider setup, and retain the existing finally cleanup.

### Scenario 3: Chat-lib uncached NES prediction consumes embedder snippets from cold asynchronous or warm ready-to-yield context

- Critical path: The new EmbedderLanguageContextService is awaited before prompt construction and model issuance. Cold asynchronous collection usually returns on completion, cancellation or timeout. Ready-to-yield async iterators can monopolize microtasks and prevent the timer from enforcing the deadline.
- Scaling input: N snippets emitted by one embedder invocation per actual unjoined generation, including repeated URIs; collection performs no deduplication. The later prompt token budget restricts rendering, not collection.
- Effective concurrency: One sequential collector per actual generation, not one provider call per snippet. Upstream cancellation/joining remains in place; the adapter adds no global limiter. Timer completion cancels the child token in finally, but a microtask-only stream prevents that timer from running until collection finishes.
- Cache behavior: No adapter-level cache exists. Embedder caching is external and unspecified; a warm provider may yield cached results immediately. NES result-cache hits and same-state in-flight joins avoid an additional provider invocation. Document text is passed by reference locally and its transformer is already cached, not newly copied or rescanned here.
- Mechanism confidence: High: the added loop has no wall-clock deadline check, raceTimeout is implemented with setTimeout, and each iteration allocates before any downstream token cap. JavaScript microtask scheduling establishes the timeout bypass.
- Magnitude uncertainty: The embedder implementation and largest context batch are external, so prevalence, CPU time and allocation volume are not measured. Immediate cached async-generator yields are a supported, realistic input.
- Expensive boundaries:
  - other at <code>extensions/copilot/src/lib/node/chatLibMain.ts: EmbedderLanguageContextService.getLanguageContext/provideContext</code>: Invoke the embedder once and pull its AsyncIterable of context snippets; cardinality: One invocation and up to N iterator pulls per actual generation; no local grouping/deduplication. Concrete host IPC or filesystem operations are not provided by this repository and are not assumed.
    - Introduced by diff: true; previous behavior: NullWorkspaceService/NullLanguageContextProviderService caused the old chat-lib context path to return undefined with zero embedder invocations.; critical-path effect: Awaited when prompt language context is enabled.
  - serialization at <code>extensions/copilot/src/lib/node/chatLibMain.ts:632-637</code>: Parse each snippet URI and allocate/store internal snippet and LanguageContextEntry objects; cardinality: One URI conversion and entry allocation for every accepted snippet. With a ready-to-yield stream, all N can be accepted even after the deadline; downstream token clipping does not bound this buffer.
    - Introduced by diff: true; previous behavior: chat-lib collected no language-context entries.; critical-path effect: Runs before language-context collection resolves and before the prompt can be sent.
  - network at <code>extensions/copilot/src/extension/xtab/node/xtabProvider.ts: endpoint.makeChatRequest2</code>: Issue and stream the existing NES prediction request; cardinality: One per actual attempt; the context adapter adds no per-snippet HTTP prediction requests.
    - Introduced by diff: false; previous behavior: Same prediction request but without embedder collection ahead of it.; critical-path effect: Issuance is delayed by the new awaited collector; deadline bypass can extend that delay with total batch size.
- Verdict: Submitted one medium-severity finding for deadline-bypassing collection and allocation. Ordinary asynchronous context work is intentional; the finding concerns work continuing past the intended bound.

### Scenario 4: Chat-lib speculative prediction, recorder-only context collection, cancellation and late provider output

- Critical path: Speculative predictions gather context before their own model call but are normally background work until a matching caller joins them. Recorder-only collection is intentionally not awaited by prompt gathering. Either collector can nevertheless compete on the same event loop. Cancellation/timeout returns from the adapter and cancels its child token; late yielded snippets then hit the cancellation check.
- Scaling input: Actual speculative/ordinary generation attempts and N snippets per started collector. Matching document/post-edit state and cursor window coalesce consumers; not every facade getNextEdit call starts new work.
- Effective concurrency: One pending speculative is replaceable, while claimed requests can coexist for independent states/documents. A new ordinary pending request cancels its predecessor. Cooperative providers stop on the child token; no additional cross-document concurrency burst is proven. Provider-specific cancellation responsiveness is unknown.
- Cache behavior: Pending and claimed speculative requests remain discoverable for same-state joining and are released on completion. Existing positive and no-suggestion caches bypass fresh generation. An embedder unable to describe speculative text can yield nothing; the adapter supplies the exact existing snapshot without constructing a shadow workspace.
- Mechanism confidence: High for traced cancellation, joining and background placement. The same ready-stream deadline bypass is established; no independent lifecycle leak or concurrency regression meets the reporting threshold.
- Magnitude uncertainty: Provider cooperation on cancellation and number of simultaneously claimed independent requests are external/workflow-dependent. Persistent resource leaks from noncooperative providers were not established.
- Expensive boundaries:
  - other at <code>extensions/copilot/src/lib/node/chatLibMain.ts: EmbedderLanguageContextService.provideContext/collect</code>: Invoke/pull the embedder stream with a child cancellation token; cardinality: One per actual started speculative or recorder-enabled generation, with same-state callers joining upstream. No proven per-item host IPC operation.
    - Introduced by diff: true; previous behavior: chat-lib had no embedder context stream for speculative or recording requests.; critical-path effect: Background when speculative/unjoined or recorder-only; can become awaited when a prediction joins, and ready streams still occupy the shared event loop.
  - network at <code>extensions/copilot/src/extension/inlineEdits/node/nextEditProvider.ts: \_createSpeculativeRequest; extensions/copilot/src/extension/xtab/node/xtabProvider.ts: endpoint.makeChatRequest2</code>: Run the existing speculative model prediction and populate the existing suggestion cache; cardinality: One per actual speculative generation attempt, shared by matching callers; existing scheduling/replacement governs multiplicity.
    - Introduced by diff: false; previous behavior: Same speculative prediction and joining mechanisms without chat-lib embedder context.; critical-path effect: Normally background prefetch; joined consumers depend on its result. New collection precedes issuance.
- Verdict: Covered by the single deadline-enforcement finding where ready streams block the event loop; no separate cancellation, retention or speculative-fan-out finding.
