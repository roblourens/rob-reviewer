# Performance review: agentHost: review notebook edits in the editor with Keep and Undo

[PR #349534](https://github.com/microsoft/vscode/pull/349534) at `1ceca457e2822b8970f5bb2066ef24e857c26d45`

## Findings (2)

### 1. [medium] Release the previous comparison's cell resources before rebuilding

**Finding ID:** `PERF-A2E0913D586B`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostEditReview.ts:444</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Obsolete ChatEditingNotebookCellEntry objects and their referenced cell/model state, plus live emptyCell ITextModel instances  
**Scaling:** For V comparison rebuilds and C paired/inserted cells, retained entry objects grow approximately O(V\*C); empty models grow with the sum of inserted/deleted cells across all rebuilds, rather than only the current diff size.  
**Outcome:** Increasing retained memory and GC pressure over the lifetime of an agent-host notebook review  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Agent-host notebook edits were skipped by editor review, so repeated host writes did not create or retain notebook comparison generations.  
**Changed behavior:** Each host notebook version rebuilds all cell diff entries in a long-lived notebook entry, but the inherited ownership retains resources from obsolete generations until the entire file review ends.  
**Confidence:** 0.97 — The new compare call runs after each changed Working Set version. The traced superclass rebuild disposes cell entries without removing them from its lifetime DisposableStore, and creates uniquely named empty text models owned by that same store. DisposableStore retains explicitly disposed children until the parent is cleared. No profiling is required to establish retention; its practical size depends on notebook size and update count.

**Causal diff evidence:** The added AgentHostNotebookReviewEntry.compare invokes initializeModelsFromDiff at line 444 on every \_followNotebook update. Previously \_createEntry returned immediately for supported notebooks and allocated none of these resources.

During a multi-step agent edit of a notebook with hundreds of cells, each published version retains another set of obsolete cell-entry objects; persistent inserted/deleted cells also accumulate live empty text models. Memory grows throughout the undecided review and increases GC pressure even though only the latest comparison is displayed.

**Evidence:** \_followNotebook calls entry.compare after deserializing each new version. ChatEditingModifiedNotebookEntry.initializeModelsFromDiffImpl (219-235) disposes and clears cellEntryMap, but getOrCreateModifiedTextFileEntryForCell (1064) registers every new entry in the parent \_store. Disposing those children does not remove them from DisposableStore.\_toDispose. Each retained ChatEditingNotebookCellEntry still references its cell and original/modified models. createInsertedCellDiffInfo (771-772) and createDeleteCellDiffInfo (814-815) additionally create a unique NewModelCounter-based emptyCell text model and register it for the whole notebook lifetime, with no generation cleanup.

**Suggested direction:** Give rebuilt comparison resources a disposable generation owner and clear it before replacing the diff. Remove disposed cell entries from the lifetime store, release obsolete empty models and cell references, and evict obsolete cache entries while preserving models needed by the current comparison.

### 2. [medium] Move full-notebook hunk validation off the UI thread

**Finding ID:** `PERF-9E9E811B9003`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostNotebookFileChanges.ts:270</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** Renderer-thread CPU work and allocations for full-file JSON parsing, line/character diffing, candidate reconstruction, and content comparison  
**Scaling:** One full-file diff and four full notebook parses per cell/hunk decision that reaches validation; cost grows with total notebook file bytes/lines, including outputs, and repeats with the number of decisions. A cell-wide toolbar coalesces its hunks into one operation, not one operation per source line.  
**Outcome:** Blocked UI critical path and delayed Keep/Undo response, with dropped frames during large notebook validation  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Agent-host notebooks could only be decided as whole files; no renderer-side full-file diff or reconstructed-notebook validation ran for those decisions. Existing text range mapping uses the asynchronous IEditorWorkerService diff path.  
**Changed behavior:** A cell/hunk Keep or Undo now synchronously parses both full ipynb versions, diffs their complete file lines, reconstructs and parses two full candidate notebooks, and compares their contents before issuing the host operation.  
**Confidence:** 0.95 — The action-to-locate-to-computeHunks call chain is synchronous in browser code. The default diff implementation hashes every line and performs line/character diffing, and the helper reparses whole reconstructed notebooks. The 500 ms limit applies to diff computation, not to the surrounding parsing. Exact pause duration varies with notebook size and changes; the UI-blocking mechanism is directly established.

**Causal diff evidence:** The new computeHunks directly calls linesDiffComputers.getDefault().computeDiff on both complete notebook files with a 500 ms budget. The new notebook range operation invokes this synchronously through entry.locate before invokeChangesetOperation.

Keeping or undoing one cell in a large output-bearing ipynb blocks workbench input and rendering while processing the entire notebook, even if that cell has a small source change. Difficult diffs can consume the configured 500 ms computation budget, in addition to unbounded-by-that-budget parsing/copying, and repeat on each decision.

**Evidence:** AgentHostEditReview.\_invokeOperation calls entry.locate(change) at 1397. AgentHostNotebookReviewEntry.locate (366-378) calls readNotebookFile twice and locateNotebookFileChange. That helper calls computeHunks (162), whose new line 270 runs the default line diff inline; lines 171-174 copy/join and parse two full notebooks and compare all expected cells. DefaultLinesDiffComputer maps/hashes all original and modified lines and refines character differences. All of this executes without yielding before the host RPC, and there is no cached validation for the immutable version pair.

**Suggested direction:** Run the version-pair diff and candidate validation in a worker, preserving the exact host hunk-selection rules and timeout handling. Revalidate the Working Set version and cell change after awaiting the result; the existing editor worker service already provides asynchronous advanced diff operations.
