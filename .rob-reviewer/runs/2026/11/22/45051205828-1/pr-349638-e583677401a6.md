### Scenario 2: Search for and select an attachment in the newly reachable context picker

- Critical path: Initial picker display uses fast context/history picks without waiting for workspace enumeration. Typed file queries populate slow results. Selection separately awaits file/model/image resolution before adding the attachment; ordinary chat input is not blocked on background cache enumeration.
- Scaling input: F workspace roots, S resource schemes, effective typed queries after cancellation/coalescing, existing history, and selected-file bytes. Normal file-query results are capped at 512 before combination/deduplication.
- Effective concurrency: SearchService validates roots with Promise.all and groups provider calls by scheme. The local engine concurrently traverses roots. Relative path checks are serial alongside the main search. Existing fast/slow picker scheduling and cancellation are unchanged; there is no diff-added per-result fan-out or new limiter removal.
- Cache behavior: FileQueryCacheState preserves compatible previous cache keys while refreshing, avoids starting another load when an equivalent previous state is updating, and disposes replaced cache state. Loaded queries can use backend cached results, including cached narrowing. Cold typing uses the existing 200 ms throttled delayer; canceled work is checked before issuance and after awaits. Error states are distinct from loaded states.
- Mechanism confidence: High: picker initialization, fast/slow result separation, query cache lifecycle, provider grouping, local process traversal, path checks, and selection-only reads were inspected.
- Magnitude uncertainty: Workspace size, root count, remote provider latency, clipboard state, and selected-file sizes vary. Provider-internal caching and performance differ by implementation.
- Expensive boundaries:
