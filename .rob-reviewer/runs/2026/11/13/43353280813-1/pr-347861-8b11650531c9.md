### Scenario 3: Render and hover the active Sessions title-bar workspace and branch labels

- Critical path: Session state renders the title pill; after the normal hover delay, the content factory reads scrollWidth/clientWidth to decide whether a tooltip is needed. The read is off initial render and only affects tooltip display.
- Scaling input: At most two label elements (workspace and branch) per active pill and one geometry check per hover activation.
- Effective concurrency: Single delayed hover timer on the UI thread; no parallel or queued external work.
- Cache behavior: Managed-hover registrations live in \_dynamicDisposables and are cleared whenever the pill rerenders. No result cache is needed because truncation can change with layout.
- Mechanism confidence: High confidence from ManagedHoverWidget invoking the content factory only when the delayed hover is shown.
- Magnitude uncertainty: Whether layout is already clean at hover time varies, but cardinality is fixed and the new check avoids creating a tooltip for untruncated text.
- Expensive boundaries:

- Verdict: No reportable regression: the bounded delayed geometry check is limited to one label interaction and trades against avoiding unnecessary hover DOM construction.

### Scenario 4: Render, recycle, scroll, and expand rows in the Sessions virtualized tree

- Effective concurrency: Virtualized list rendering is synchronous on the UI thread and serialized; no new async work or boundary calls.
- Cache behavior: The virtualized tree reuses row templates. toggle updates the reused row's disclosure state, preventing stale classes without retaining per-session state.
- Mechanism confidence: High confidence from the three renderer hunks and existing template-based list structure.
- Magnitude uncertainty: Visible row count and rerender frequency vary with viewport and updates, but virtualization bounds the active DOM set and traversal depth is shallow.
- Expensive boundaries: none found
- Verdict: No reportable regression: added work is constant per visible row and does not defeat virtualization, trigger geometry reads, or add collection-wide work.

- Effective concurrency: Browser style and paint pipeline on the UI thread; no application-level concurrency or fan-out.

- Mechanism confidence: High confidence from the CSS-only hunks and scoped selectors.
- Magnitude uncertainty: Browser-specific selector invalidation cost is not measured, but the selectors are scoped and interaction-driven rather than per-frame animation or global polling.
- Expensive boundaries: none found
- Verdict: No reportable regression: there is no concrete evidence of broad style invalidation, forced layout, unbounded DOM growth, or dropped-frame risk from the changed rules.
