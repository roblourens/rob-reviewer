### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:4205` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:1321`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`  
**Introducing commit:** `527b5f320f5ed16b68a43ad0248132f1b102c751`  
**Mechanism family:** `repeated-work`  
**Performance category:** `subprocess`  
**Confidence:** 0.96

**Mechanism:** During Microsoft sign-in from a legacy GitHub account, clearing the GitHub token published an expired GitHub requirement before the account became Microsoft. Connected clients could each re-send their retained GitHub credential, causing the authentication sequencer to revoke Microsoft again, reset its login attempt and request another runtime restart. The reciprocal revoked-Microsoft notification could initiate another account setup. Client recovery coalesces per resource per connection, so this is redundant account-transition work and cross-window fan-out, not evidence of an unlimited loop.

**Symptom:** An account choice could trigger additional runtime teardown/restart, cancellation and deletion of the Microsoft authentication session, and redundant model-catalog refreshes instead of completing one account handoff. Static call-path evidence establishes the extra work; no duration measurement is claimed.

**Fixed behavior:** The new replaced-sign-in marker hides GitHub's requirement before its token is cleared; the selector also hides revoked Microsoft identity requirements when another account replaced them. Clients therefore do not initiate the unnecessary reverse handoff. Runtime-originated service challenges remain eligible, and cancellation can restore the GitHub requirement.

**Evidence:** The deleted base derived fallback at copilotAgent.ts:1321 exposed \_authenticationRequired while the account was legacy. The changed completeAuthentication sets \_replacedSignIn to 'github' at head line 4205 before \_applyGitHubToken(undefined), and selectCopilotAuthenticationRequirement lines 35-39 suppress the replaced requirement. \_applyGitHubToken lines 4120-4130 still records the expired requirement and requests the intended restart. agentSideEffects.ts:748-752 forwards any selected requirement to emitAuthRequired; agentHostStateManager.ts:3495 broadcasts it through the root notification path. agentHostChatContribution.ts:267-272 and agentHostAuth.ts:356-445 show per-connection recovery, invalidation and credential forwarding. A returned GitHub credential reaches copilotAgent.ts:4061-4062, revokes Entra, triggers the onDidRevoke restart at 1670-1671 and CopilotAccountService.reset/release (278-315). \_stopClient (4999-5040) stops the spawned runtime, and \_ensureClient (5320-5334) starts its replacement. The added agent test at 6097-6141 explicitly models one retained-credential response per resource and checks that choosing Microsoft no longer prompts a reverse handoff. Blame identifies the commit introducing the old account-dependent fallback.
