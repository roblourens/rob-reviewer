### Scenario 1: Chat: Plugins from the Command Palette, or /plugins, in a regular window with local chat context; first open and subsequent opens.

- Critical path: The action awaits one OpenEditor command, which opens the singleton customization input and selects Plugins. Editor construction and section layout are synchronous; plugin refresh, sidebar counts, and migration recovery discovery are not awaited by the command. Local installed rows use the existing plugin-service snapshot. Previously the command opened the Extensions container; reaching Customizations required another navigation.
- Scaling input: Installed plugin count P, customization files F across five prompt types, source folders, and distinct configured marketplaces M after canonical-ID deduplication. Migration recovery records R contribute background reads.
- Effective concurrency: One editor-opening command per user invocation. The input is singleton-style. Item-source cached promises coalesce section/count requests. Prompt metadata discovery uses a service-wide limiter of 10. Marketplace repositories run concurrently across distinct references but clone operations serialize per repository key. Recovery manifests are read sequentially.
- Cache behavior: Existing item-source promises are reused per session and harness descriptor until source-change invalidation. Prompt discovery has cached promises and per-type file-location caches when observed. Plugin marketplace snapshots distinguish uninitialized, loading, loaded and failed; they load only when visible and legacy browsing is enabled, and do not repeatedly retry failures. Successful GitHub marketplace results have an eight-hour persisted TTL; clone refresh uses the same age threshold.
- Mechanism confidence: High confidence in command and slash-command reachability, singleton input, asynchronous list/count paths, provider coalescing, marketplace grouping and shared discovery limiter, based on inspected implementations.

### Scenario 2: Chat: Plugins in a regular window whose focused chat selects an agent-host harness, including Copilot CLI.

- Critical path: OpenEditor resolves the existing focused-session target, opens the editor, and selects Plugins. Authoritative session plugin rows require the cached provider result; cold provider resolution waits for grouped runtime inventory and plugin-content expansion. Migration information and contributed Canvases initialization are background work, not awaited by the command.
- Scaling input: Distinct runtime providers K, cold plugin roots Pc, supported metadata files Fc within those roots, migration categories/target types, and visible canvas owner contexts V. Inventory operations group by provider or visible owner, not individual plugins/canvases.
- Effective concurrency: Item-source cached promises coalesce plugin counts and list refreshes. Runtime inventories use Promise.all over distinct providers. Cold plugin expansion runs across roots, with four initial directory resolves per root and parallel metadata reads within supported categories; warm expansions avoid those reads. Migration categories run concurrently, with source-folder requests serialized by distinct target type within each category. Canvas definitions and extension inventory run together per visible owner.
- Cache behavior: PureItemProviderItemSource caches the whole provider promise per session/descriptor and clears failures for retry. Plugin expansion caches children by URI, nonce and plugin label. Warm repeated openings reuse source data unless invalidated. Canvas stores track owner lifetimes and current requests; only visible chat owners contribute. No diff changes any of these keys or invalidation rules.
- Mechanism confidence: High confidence in focused-session resolution, provider-level promise coalescing, runtime-provider grouping, expansion keys, category/type grouping and visible-owner canvas initialization. No evidence establishes a diff-created retry loop or repeated full expansion on warm opens.
- Magnitude uncertainty: Cold remote filesystem and host request durations, eligible plugin files, and visible-owner counts are unmeasured. Upstream service costs can vary; observed grouping and caches prevent interpreting them as per-plugin full-inventory calls.
