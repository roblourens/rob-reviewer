## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `.github/workflows/pr-linux-test.yml:415` (`RIGHT`)  
**Blamed base line:** `.github/workflows/pr-linux-test.yml:418`  
**Introducing path:** `.github/workflows/pr-linux-test.yml`  
**Introducing commit:** `22d53a1ff6572fcdd77a2f919fff96e1f7741e94`  
**Mechanism family:** `repeated-work`  
**Performance category:** `network`  
**Confidence:** 0.96

**Mechanism:** Every fresh merge-queue WebKit job downloaded the missing system packages and transitive dependencies through the uncached `--with-deps` installer before any WebKit tests could run. This repeats a dependency-closure-sized apt transfer for each eligible merge group, despite the package list and runner image being shared.

**Symptom:** Slow apt mirrors delayed the merge-queue test critical path by minutes and could exhaust the install/job timeout before tests ran; the PR reports 9 of 19 installs taking 4.5-10 minutes and one install-step timeout.

**Fixed behavior:** On a matching image/architecture/package-list cache hit, install the missing dependency closure from one restored archive before Playwright runs, leaving Playwright no corresponding .deb files to fetch from apt mirrors. Perform package archive acquisition on the daily/manual producer path instead; retain apt fallback for misses or invalid cached installations.

**Evidence:** The base-revision line runs `pnpm exec playwright install --with-deps webkit` before browser unit tests. The caller in pr.yml:643 enables this job for selected merge groups, and browser-unit-webkit has a 12-minute job timeout. The added pr-linux-test.yml:413-417 invokes the existing package-cache installer with the new 60-package WebKit list; action.yml:84-91 installs all restored .deb files in one dpkg invocation and returns on success without apt downloads. pr-workspace-images.yml:238-242 produces these archives in the daily/manual job after installing the default packages, matching the consumer's earlier default-package installation. Thus repeated package downloads are replaced by one cache restore per warm WebKit job. The PR description reports slow mirror installs of 4.5-10 minutes and a pre-test timeout; these are reported observations, not measurements performed in this review. Blame resolves the original critical-path install to commit 22d53a1ff6572fcdd77a2f919fff96e1f7741e94.
