### Scenario 1: Create a sandbox path-grant confirmation for a read or shell tool targeting current-session, peer-session, or unknown storage

- Critical path: The SDK permission callback builds the pending confirmation; the diff synchronously snapshots materialized chat roots, resolves titles, normalizes paths, and formats the label before emitting pending\_confirmation. This work is on confirmation-display latency, but it does not wait on any new expensive boundary.
- Scaling input: One or two displayed paths per grant (grant path plus optional denied path), each scanning the currently materialized Copilot chat backings. Effective cost is O(P × C), where P is at most 2 and C is loaded chat backings; typical C is small and the operations are map lookups, URI construction, normalization, and short-lived allocations.
- Effective concurrency: Permission requests may be concurrent across live sessions; there is no shared limiter or coalescing for label computation, so aggregate local CPU scales with concurrent confirmations. Each individual computation is synchronous and lightweight, and no new asynchronous fan-out is introduced.
- Cache behavior: Ownership and title data are deliberately read fresh so chat moves, promotion, and renames are reflected. Cold and warm behavior are the same in-memory O(C) scan; there is no filesystem-derived discovery, cache miss, or negative-cache retry.
- Mechanism confidence: High confidence in the O(P × C) synchronous allocation/normalization mechanism and its critical-path placement; low confidence that its magnitude is user-visible at realistic loaded-chat counts.
- Magnitude uncertainty: A process can accumulate more materialized chats, but the reviewed code provides no evidence of a realistic cardinality at which these in-memory scans would materially delay an already user-gated confirmation. Exact duration is unmeasured.
- Expensive boundaries: none found
- Verdict: No reportable regression. The diff adds repeated in-memory work, including a second root snapshot when deniedPath exists, but no expensive boundary and no sufficiently evidenced latency, throughput, memory, or GC impact under a realistic trigger.

- Mechanism confidence: High confidence that all transitive boundary calls are pre-existing and that the diff adds only local computation after them.
