# Performance review: agentHost: hosts enable multipleChatProviders during initialize instead of after a reconnect

[PR #347569](https://github.com/microsoft/vscode/pull/347569) at `35d712b65669a4068ccece3c815731b96cff7bdb`

## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/protocolServerHandler.ts:1085` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/browser/agentHostProtocolClient.ts:1731`  
**Introducing path:** `src/vs/platform/agentHost/browser/agentHostProtocolClient.ts`  
**Introducing commit:** `8c18263e1c0837d1e2df1fb63409ee18da07a970`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.97

**Mechanism:** Enabling the client setting on a remote host forced one redundant full transport reconnect after the initial handshake. That repeated the remote connection and initialize round trip and could fan out restoration work across cached credentials and active subscription snapshots before the client became usable with the capability.

**Symptom:** Remote agent-host connection readiness was delayed by an avoidable reconnect, with interruption and retry of in-flight subscription work; environments that could not recreate the transport could fail to recover at all.

**Fixed behavior:** A client whose multiple-chat-providers setting is already enabled requests the gate in its first initialize; the host enables it before forming the response, eliminating the replacement transport, duplicate initialize, authentication restoration, and subscription snapshot restoration from connection startup.

**Evidence:** Before this PR, when the mirrored host gate became true after the first handshake, `_maybeReinitializeForChatProviders` set `_freshInitializeRequested`, cleared transport listeners, and routed closure through reconnect. The reconnect path constructs and connects a replacement transport, sends a fresh `initialize` with all current subscription URIs, restores authentication, and requests snapshots for active subscriptions omitted from the handshake. The existing regression test also demonstrates an in-flight subscribe being interrupted and retried on the replacement transport. The added initialize metadata at browser/agentHostProtocolClient.ts:1615 plus the server-side pre-response gate update at node/protocolServerHandler.ts:1085 makes the first handshake advertise the capability, so that reconnect branch is not entered on current hosts.
