- Scaling input: One registration per selected remote. The new name lookup scans/normalizes the configured-entry collection once; the name is one ordinary remote display string. Host filesystem roots are deduplicated with the home directory.
- Effective concurrency: The sharing service uses one Sequencer for sharing and synchronization; the host registration and environment configuration each have their existing sequencers. Windows drive discovery retains its parallel batch of 26 probes; root resolution is parallel within one configuration. Different windows/hosts remain independently scheduled as before.

A new host registration computes its name once; subsequent registration calls retain the configured name. Initial compute identity uses persisted state, and signing keys retain their existing five-minute cache. No new cache or retry policy is introduced.
- Mechanism confidence: High confidence from the complete registration call chain that RPC count, filesystem multiplicity, and network scheduling are unchanged.
- Magnitude uncertainty: Configured-entry counts and remote/network latency vary; no runtime timings were collected. The added local lookup and ordinary name string do not establish an actionable degradation.

### Scenario 2: Refresh shared-remote credentials after reconnection, authentication changes, or host restart

- Scaling input: S eligible stored shares among E configured entries; at most one registration per unsynchronized connected address per handshake/generation. The new helper adds an O(E) local lookup for each issued registration, not a boundary call per configured entry.
- Effective concurrency: One renderer-wide synchronization Sequencer awaits addresses serially. RunOnceScheduler coalesces same-turn triggers. Each host serializes configuration, and \_checkIn joins existing work for the same generation. No new cross-address burst is introduced.

- Mechanism confidence: High confidence in unchanged boundary frequency and global serialization from \_synced, \_queue, and the host configuration checks.

### Scenario 4: Select an unshared environment and establish its connection

- Critical path: After selection, the existing service reuses a live/in-progress connection or awaits environment validation, connection credentials, remote relay establishment, and the protocol handshake. The diff only prevents selecting environments already represented by configured shared remotes.
- Scaling input: One selected environment ID, independent of total picker rows. Concurrent requests for the same ID join one pending connection operation.
- Effective concurrency: One connection attempt per selected environment ID; existing deadline, retry delays, cancellation, and account-scoped connection handling are unchanged. No new multi-host connection loop is introduced.
- Cache behavior: Connected/connecting/reconnecting remote entries are reused. The pending-connect map coalesces requests by environment ID and removes completed entries. Unselected hosts do not initiate environment-detail or connect requests.
- Mechanism confidence: High confidence from the selected-ID call chain and the existing pending/reuse guards.
- Magnitude uncertainty: Actual network and handshake duration is not measured; no changed scheduling or call multiplicity exists on this selection path.
- Expensive boundaries:
  - network at <code>src/vs/workbench/contrib/chat/browser/remoteAgentHost/missionControlEnvironmentService.ts:\_connect; cloudSandboxApiService.ts:getEnvironment; cloudSandboxAgentHostService.ts:\_mintWithWaking/\_establish</code>: Fetch selected-environment details, request connection credentials, establish the relay, and perform the remote handshake.; cardinality: Zero new setup for a reusable live connection; otherwise one selected-environment detail operation and one successful credential-admission operation plus relay/handshake setup, subject to existing paced retries and deadlines.

  - IPC at <code>src/vs/workbench/contrib/chat/browser/remoteAgentHost/cloudSandboxAgentHostService.ts:connect</code>: Check the local agent host's own environment ID before connecting a user-local environment.; cardinality: One check for a new user-local connection attempt; none is added per picker row.

- Verdict: No reportable regression. The change removes an opportunity for redundant connections rather than introducing additional setup work.
