## Findings (1)

### 1. [medium] Coalesce credential reads across live-session updates

**Finding ID:** `PERF-BDC89FD1C07C`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:1063</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>missing-coalescing</code>  
**Resource:** Agent-host-to-renderer credential IPC calls, renderer-to-main encryption IPC calls, and synchronous safeStorage decryptions.  
**Scaling:** One snapshot-triggered update causes S × G credential calls and persisted-secret decryptions, where S is the number of live sessions and G is the number of distinct secret-backed vendor/group/credentialVersion tuples after within-session grouping. Promise.all overlaps sessions but secret storage serializes reads of the same key. Repeated resolutions recreate the map even on warm, unchanged snapshots.  
**Outcome:** Redundant cross-process round trips and serialized decryption increase live-session update and model-selection latency as the number of open chats grows.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Live-session sync used the registry's cached model list and an already memoized shared loopback proxy. It performed no group-secret reads or credential IPC before the unchanged-config equality check.  
**Changed behavior:** Every session configuration resolution now fetches all direct groups' credentials again, including resolutions triggered simultaneously for all live sessions by a single model-snapshot change.  
**Confidence:** 0.97 — The global live-session loop, invocation-local map, credential channel, secret-storage read, per-secret sequencer, and main-process decrypt implementation are directly traced. The number of affected live chats and platform-specific decryption duration are unmeasured.

**Causal diff evidence:** The added invocation-local \`credentials\` map at copilotSessionLauncher.ts:1063 deduplicates only one session's resolution. The new resolveCredential call at :1068 is awaited for every direct group at :1076. Previously synthesizeByokSessionConfig only read the cached model snapshot and reused the memoized proxy handle; it made no credential IPC or decryption calls.

With direct routing enabled and S live chats, a model update or bridge reconnect issues S × G credential IPC calls for G secret-backed direct groups, even if those chats use CAPI or their registered credentials have not changed. The repeated main-process decryptions serialize per secret and delay session registration; model selection also waits behind this work.

**Evidence:** CopilotAgent.\_syncByokModelsOnLiveSessions (copilotAgent.ts:5034-5040) starts syncByokModels for every live chat without cross-session coalescing. Each sync awaits resolveByokSessionConfig before checking whether registration changed (copilotAgentSession.ts:8528-8540). resolveDirectByokSessionConfig creates this map anew and calls the renderer once per unique vendor/group/credentialVersion. AgentHostByokLmHandler.resolveCredential calls LanguageModelsService.resolveLanguageModelsProviderGroupApiKey, which calls \_secretStorageService.get. BaseSecretStorageService.get (secrets.ts:139-160) queues by secret key and decrypts on every persisted read; IEncryptionService is a main-process remote service, and EncryptionMainService.decrypt synchronously calls safeStorage.decryptString. Thus concurrent sessions requesting the same group queue repeated decryptions rather than joining one read.

**Suggested direction:** Share in-flight credential resolution across sessions at the launcher/serving-connection scope, keyed by vendor, group, and credentialVersion. Invalidate on serving-connection or authorization/snapshot changes, and remove settled or failed entries so this need not introduce a long-lived secret cache.

### Scenario 3: Update all live chats after a model snapshot, key rotation, renderer connection change, or withdrawal of direct routing.

- Critical path: The catalogue refresh schedules every live session's sync. Each sync resolves the full current BYOK config before equality checking and provider.sync. Model changes queue behind a session's outstanding sync work. Catalogue publication itself does not await all sessions.
- Scaling input: S live chats times G distinct direct credential tuples remaining in the current snapshot. This is group-level fan-out, not per-model credential fan-out. A fully disabled/empty snapshot has G=0.
- Effective concurrency: The live-session loop starts all session syncs without a global limiter or shared credential promise. Per-session Sequencers serialize that session's updates; secret-storage sequencing serializes each group's decryptions across sessions.
- Cache behavior: Channel equality suppresses duplicate snapshots, but registry connection changes can still trigger refresh. Every effective sync recreates the credential map. Provider/model equality prevents redundant provider.sync after resolution. Bridge fallback uses the shared memoized proxy and retains stable provider names.
- Mechanism confidence: High: the global loop, per-session queue, local credential map, and per-secret sequencing are explicit.
- Magnitude uncertainty: The number of live sessions and frequency of effective model/connection changes determine magnitude. No timings are claimed.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_syncByokModelsOnLiveSessions; copilotSessionLauncher.ts:resolveDirectByokSessionConfig</code>: Resolve the same snapshot's group credentials independently for every live chat.; cardinality: S × G credential calls per effective refresh, with matching persisted-secret decryption calls for secret-backed groups.
    - Introduced by diff: true; previous behavior: The pre-existing live-session sync loop used cached metadata and the shared proxy, without reading group secrets.; critical-path effect: Delays registration updates and subsequent session model changes; publication is fire-and-forget relative to this work.
  - IPC/network at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:syncByokModels; copilotSessionLauncher.ts:resolveByokBridgeProvider/mergeByokSessionConfig</code>: Start/reuse the bridge if necessary and replace direct endpoint registrations with bridge-backed registrations.; cardinality: At most one memoized loopback bind per launcher lifecycle, then one provider.sync per session whose registration actually changes.
