## Findings (1)

### 1. [medium] Avoid accumulating notebook focus listeners on visibility restores

**Finding ID:** `PERF-3CC152B8D05F`  
**Location:** <code>src/vs/workbench/contrib/notebook/browser/diff/notebookDiffEditor.ts:545</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Retained focus-listener closures/disposables and repeated CellContextKeyManager listener/observable reconstruction on each cell-focus change.  
**Scaling:** After R restores without replacing the notebook model, the widget retains R extra focus listeners. Each subsequent cell-focus change performs O(R) context-manager updates rather than a constant number; memory also grows linearly with R.  
**Outcome:** Increasing CPU/allocation work during notebook cell navigation and retained listener memory over a long-lived editor session.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** Hiding and restoring the same inline notebook diff did not call NotebookInlineDiffWidget.show again, so visibility cycles did not grow the widget's focus-listener collection.  
**Changed behavior:** Each visibility restoration now calls show, which invokes NotebookEditorWidget.setModel with the already-attached model. setModel bypasses \_detachModel for that model but still registers another onDidChangeFocus listener in \_localStore.  
**Confidence:** 0.97 — Static call-flow evidence establishes one additional retained focus listener per completed restore of the same model: show unconditionally calls setModel, its same-model branch skips detach, and listener registration remains unconditional. onWillHide does not clear the model store. Exact interactive slowdown depends on restore count.

**Causal diff evidence:** The added show call at line 545 runs after every hide/show cycle with an existing inline model. Previously setVisible(true) did not call show or setModel; ordinary visibility restoration therefore did not add these subscriptions.

Repeatedly maximize/restore another group while keeping an inline notebook comparison open. Every completed restore adds a listener that survives the next hide, progressively increasing the cost of navigating between notebook cells.

**Evidence:** NotebookInlineDiffWidget.show (inlineDiff/notebookInlineDiffWidget.ts:41-55) always awaits widget.setModel. NotebookEditorWidget.setModel (notebookEditorWidget.ts:1176-1230) calls \_detachModel only for a different model, but unconditionally adds \_list.onDidChangeFocus to \_localStore at 1226. \_localStore is cleared on detach/dispose, not onWillHide (2039-2050). Each listener calls updateContextKeysOnFocusChange, which invokes CellContextKeyManager.updateForElement (view/cellParts/cellContextKeys.ts:90-125), clearing/recreating cell listeners and an autorun and updating context keys.

**Suggested direction:** Keep comparison/layout restoration, but avoid re-running same-model setModel merely to show the widget, or register the focus listener only when attaching a model so repeated setModel calls remain subscription-idempotent.
