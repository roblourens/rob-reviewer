- Critical path: Picker construction, one visible-label DOM update during show, picker layout, and existing provider result production are on the path to displaying the picker/results. - Scaling input: Typed query frequency, provider-prefix transitions, workspace-folder count for path probes, and up to 512 returned file matches. The diff adds one label element per QuickInputController and one bounded text assignment when a picker is shown, not work scaling with matches or keystrokes.
- Effective concurrency: Provider changes cancel/dispose the previous picker work before creating the replacement. The Anything provider retains its existing cancellation token, 200 ms throttled file-query delayer, cache, and fast/slow result merge behavior; the label adds no task or concurrency.
- Cache behavior: The Anything provider's existing FileQueryCacheState is loaded for normal runs and reused by search-service cache key; quick navigation and nondefault delegates retain their prior behavior. The label has no cache key, miss, retry, or invalidation effect.
- Mechanism confidence: High confidence from tracing QuickAccessController.doShowOrPick through QuickPick.show/update and the input listener's skipUpdate path, plus the provider search implementation.
- Magnitude uncertainty: Browser layout cost varies with font and translated label length, but there is only one label and one show-time layout; no realistic multiplicative regression was found.
- Expensive boundaries:
  - filesystem/search service at <code>src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts:685-704, 847-855, 899-953</code>: Workspace file search, capped at 512 results; path-shaped queries may additionally stat candidate paths and resolve filename casing.; cardinality: One logical cached file-search request per settled query, with an existing second search only when a multi-part query hits the result limit; relative path probing can issue one stat per workspace folder. - Verdict: No reportable regression. The change adds constant DOM/text/layout work at picker creation/show and does not increase search boundary cardinality, concurrency, or steady-state typing work.

### Scenario 2: Show or update an internal IQuickPick with inputLabel set

- Critical path: On first use, QuickInputController lazily creates one label DOM node and associates it with the existing input. When a visible picker is shown or its label property is explicitly changed, update writes text only if changed, updates visibility, and performs the same controller layout pass already used by QuickPick updates.
- Scaling input: One label node per QuickInputController and one text/visibility update per explicit inputLabel mutation. Repository usage sets it before show; no loop, collection-sized mutation, or per-keystroke setter call exists.
- Effective concurrency: All work is synchronous UI work on the renderer thread; there are no queues, subprocesses, IPC calls, or asynchronous bursts introduced by the label.
- Cache behavior: No cache is involved. Equality checking prevents repeated textContent writes when unrelated picker updates occur; visibility remains part of the existing layout update.
- Mechanism confidence: High confidence from the complete inputLabel usage search and QuickPick/QuickInputController update trace.
- Magnitude uncertainty: Exact relayout duration depends on viewport and label wrapping, but cardinality is constant and repository call sites do not mutate the label on a hot path.
- Expensive boundaries: none found
- Verdict: No reportable regression. The added allocation and show-time layout are bounded feature costs, and no realistic hot-path label mutation is introduced.

### Scenario 3: Open an anchored or overlay Quick Access picker

- Critical path: Quick Access resolves inputLabel to undefined for anchored options before show, so the label remains hidden; existing anchor geometry reads and overlay alignment remain on the show/resize critical path.
- Scaling input: One anchor and one QuickInputController. Resize frequency controls existing layout calls, but the hidden label adds neither geometry reads nor changed boundary cardinality.
- Effective concurrency: Existing ResizeObserver scheduling and next-animation-frame coalescing are unchanged. The diff adds no observer, callback, or concurrent operation.
- Cache behavior: Overlay layout correction caching and invalidation are unchanged; label selection does not alter its key or lifecycle.
- Mechanism confidence: High confidence from the options.anchor branch and controller layout trace.
- Magnitude uncertainty: None material: the changed branch explicitly omits the visible label for anchored pickers, and tests cover the hidden state.
- Expensive boundaries: none found
- Verdict: No reportable regression. Anchored layouts preserve prior visible geometry and scheduling.
