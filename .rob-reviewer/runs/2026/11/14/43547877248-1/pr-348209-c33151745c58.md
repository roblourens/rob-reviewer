### 1. [medium] Avoid installing Linux packages twice in the chat-lib job

**Finding ID:** `PERF-7D35C09D340E`  
**Location:** <code>.github/workflows/pr.yml:1013</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** GitHub cache/network transfers, apt metadata downloads, dpkg filesystem operations, and subprocess time  
**Scaling:** The duplicate setup runs serially on every Copilot-affecting pull request and merge-group execution selected for chat-lib Linux tests; a cold apt-package cache adds a second apt update/install sequence, while a warm cache still restores and installs the cached .debs before the existing apt sequence.  
**Outcome:** Increased required-check latency and unnecessary runner I/O  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The chat-lib Linux job invoked test-chat-lib directly, whose Linux path already runs apt-get update and installs libkrb5-dev once before rebuilding dependencies.  
**Changed behavior:** The new workflow step first invokes install-linux-packages, which restores or downloads and installs the packages in packages.txt, and then test-chat-lib still unconditionally runs apt-get update and apt-get install -y libkrb5-dev.  
**Confidence:** 0.99 — The two serial package-install boundaries and their overlap on libkrb5-dev are explicit in repository code, and the job is explicitly required by pr-gate. Exact elapsed time varies with apt/cache state, but the redundant I/O and critical-path placement do not.

**Causal diff evidence:** The RIGHT-side addition at .github/workflows/pr.yml:1013 inserts install-linux-packages immediately before the unchanged Test chat-lib action, whose Linux implementation already performs apt-get update/install.

Every Copilot-related PR can spend additional critical-path time restoring/installing the shared nine-package bundle and then refreshing apt metadata/installing Kerberos again before chat-lib can build or test; mirror/cache latency directly delays the required PR gate.

**Evidence:** The added line invokes .github/actions/install-linux-packages/action.yml; that action always restores an apt package cache and executes dpkg, or falls back to apt-get update/install. Immediately afterward, .github/actions/test-chat-lib/action.yml lines 32-37 unconditionally execute apt-get update and install libkrb5-dev on Linux. libkrb5-dev is also present in install-linux-packages/packages.txt, and pr-gate lists chat-lib-linux-tests as a required dependency.

**Suggested direction:** Keep a single Linux package setup: either remove this workflow-level step and retain test-chat-lib's existing Kerberos install, or move the cached package action into test-chat-lib and remove its unconditional apt update/install so all Linux callers install prerequisites exactly once.
