# Performance review: nes: serve documents of every scheme except a denylist

[PR #348246](https://github.com/microsoft/vscode/pull/348246) at `9e7db1928d7b2fab6b537bcd8819335e4ad44935`

## Findings (1)

### 1. [medium] Dispose trigger state when virtual documents close

**Finding ID:** `PERF-FF8BAE1B780A`  
**Location:** <code>extensions/copilot/src/extension/inlineEdits/vscode-node/parts/documentFilter.ts:46</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Closed virtual-file TextDocument objects and their full line arrays  
**Scaling:** Retained memory grows with the cumulative bytes of every distinct non-file document edited during the extension-host lifetime, even after those documents are closed.  
**Outcome:** Unbounded extension-host memory growth and increasing GC pressure during long virtual-filesystem editing sessions.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** The previous allowlist rejected non-file/non-untitled virtual documents before they entered VSCodeWorkspace, so edits to zowe-ds:, memfs:, and other FileSystemProvider documents could not populate InlineEditTriggerer's per-document state.  
**Changed behavior:** The denylist now admits every unlisted scheme. Each edit to one of those newly tracked documents reaches InlineEditTriggerer, which stores LastChange(e.document) in docToLastChangeMap; that map has no document-close cleanup and lives until the feature is disposed.  
**Confidence:** 0.97 — The changed admission condition, VSCodeWorkspace-to-InlineEditTriggerer call path, absence of close cleanup, and TextDocument-to-MirrorTextModel retention are all directly visible in repository code. Exact session file counts and document sizes vary, affecting severity but not the retention mechanism.

**Causal diff evidence:** RIGHT line 46 replaces the old file/untitled/notebook allowlist with a check that rejects only \`ignoredSchemes\`, newly allowing arbitrary FileSystemProvider schemes to reach the leaking per-document trigger map.

A user who edits and closes many virtual files or dataset members in one VS Code session retains each closed document's complete text in the Copilot extension host. Large/generated virtual files make memory and GC cost grow throughout the session rather than returning after close.

**Evidence:** VSCodeWorkspace creates a DocumentId for every document admitted by this condition and InlineEditTriggerer.\_registerDocumentChangeListener stores \`new LastChange(e.document)\` keyed by that id. InlineEditTriggerer registers only change and selection listeners, not onDidCloseTextDocument, so entries are removed only during rejection cooldown or feature disposal. VS Code's ExtHostDocumentData.document object closes over ExtHostDocumentData, whose MirrorTextModel \`\_lines\` remain readable after dispose, proving the retained TextDocument keeps full text alive.

**Suggested direction:** Register document-close cleanup (or observe removals from VSCodeWorkspace.openDocuments) and call \`docToLastChangeMap.deleteAndDispose\` for the closed DocumentId. Keep the broader scheme support; bound trigger state to currently open documents.
