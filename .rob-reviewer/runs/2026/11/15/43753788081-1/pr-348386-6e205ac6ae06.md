UI work scales with the effective number of references and total reference-name characters among rows actually rendered/recycled by the virtualized tree. - Effective concurrency: The provider request is awaited as one logical page request; its Git log and subsequent provider steps are sequenced. Row rendering and the added string scans/class toggles execute synchronously on the UI thread for virtualized rows, not as a concurrent burst.

### Scenario 2: Displaying and interacting with a history-item hover containing long reference names

- Critical path: Hover content has already been constructed during row rendering. Showing the delayed hover attaches/displays that content and browser style/layout computes flex wrapping, max width, clipping, and ellipsis. The added native title is consulted only when the user points at a badge and performs no repository or extension-host work.
- Scaling input: Layout scales with the references on the single hovered commit. The patch keeps one existing span per reference and adds CSS properties/title text rather than adding DOM nodes; long labels no longer create additional wrapped lines.
- Effective concurrency: Hover display and layout run on the single UI thread. Hover lifecycle grouping allows one SCM history-item hover group rather than creating parallel boundary work.
- Cache behavior: The pre-rendered hover content lives with the virtualized row and is disposed when the row is recycled. There is no cold/warm remote cache or negative cache on hover display, and the diff adds no persistent map or retained-key collection.
- Mechanism confidence: High confidence: the CSS applies only beneath .monaco-hover.history-item-hover, and the TypeScript change marks only the injected reference Markdown section. The path contains DOM/style work but no changed IPC, subprocess, filesystem, database, or network call.
- Magnitude uncertainty: Exact style/layout cost depends on badge count and hover width, but the new selectors are scoped to the one visible history hover and add ordinary overflow/ellipsis properties. No forced geometry read, repeated relayout loop, filter, or animation is introduced.
- Expensive boundaries: none found
- Verdict: No reportable regression. The patch changes the layout result for long labels without increasing node count or triggering a repeated layout mechanism; it likely reduces hover height for long names and has no new expensive boundary.
