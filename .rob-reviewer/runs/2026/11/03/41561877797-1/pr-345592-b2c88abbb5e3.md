- Effective concurrency: Language modes are awaited serially in htmlServer; URI parsing and path resolution are synchronous, with no introduced worker, queue, fan-out, or parallel boundary.
- Cache behavior: The DocumentContext is recreated per request and has no reference-result cache. Warm HTML model state does not change the resolver cost. No cache is defeated; the newly rejected base case avoids downstream resolution rather than retaining negative entries.
- Mechanism confidence: High confidence in the per-reference synchronous call path and short-circuit behavior from the changed resolver and htmlServer call site; exact language-service scan internals are dependency-owned but do not alter the before/after conclusion.

- Expensive boundaries:

- Verdict: No reportable regression. The changed guard is constant-time on common bases and reduces work for rejected bases; the uncommon same-scheme non-hierarchical case adds a small parse without evidence of material latency.

### Scenario 2: HTML or embedded-CSS completion while editing a relative URL

- Critical path: An existing LSP completion request obtains settings, creates a DocumentContext, and synchronously invokes HTML doComplete2 or CSS doComplete2; any reference resolution used to produce completion paths is on the response critical path.
- Scaling input: Completion is scoped to the active cursor and its relevant URL context rather than every document link. Standard file/http/https bases short-circuit after one Set lookup.
- Effective concurrency: One completion mode is selected per cursor position and awaited for the request. Reference resolution is synchronous and introduces no concurrent I/O or burst.
- Cache behavior: HTML parse state is held in the existing language-model cache; the new scheme Set is module-scoped. The DocumentContext is per request, and the change neither invalidates model caches nor adds retained cache keys.
- Mechanism confidence: High confidence from htmlServer mode selection and htmlMode/cssMode call sites that the changed resolver is local, synchronous work on an existing completion path.
- Magnitude uncertainty: Dependency internals determine whether a completion request invokes the resolver once or a small bounded number of times, but there is no changed boundary call or collection-wide work.
- Expensive boundaries:

- Verdict: No reportable regression. The diff adds bounded local checking and no expensive boundary, retained state, or concurrency amplification.
