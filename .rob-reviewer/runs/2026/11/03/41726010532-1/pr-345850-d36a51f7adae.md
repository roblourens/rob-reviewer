## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/byokLmProxyService.ts:319` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/byokLmProxyService.ts:305`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/byokLmProxyService.ts`  
**Introducing commit:** `f7c07eeb5cc1305c877f5f2a09799d99687d05d6`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.98

**Mechanism:** A deterministic provider client error was rewritten as retryable HTTP 502, causing the runtime to repeat the same loopback HTTP request, renderer IPC call, LM API request, and upstream provider request before surfacing the failure.

**Symptom:** Deterministic BYOK provider errors incurred repeated remote attempts and roughly 15 seconds of avoidable failure latency before being surfaced.

**Fixed behavior:** The handler extracts the provider's 4xx status, the bridge result carries it, and the proxy now returns deterministic 4xx statuses directly while retaining 502 for transient or server failures, preventing runtime retries of deterministic failures.

**Evidence:** In the base revision, ByokLmProxyService converted every renderer/provider failure into HTTP 502 at line 305. The proxy documents that the SDK runtime retries 5xx responses, and the changed end-to-end path now transports the provider status from AgentHostByokLmHandler over the existing IPC result and maps deterministic 4xx responses to invalid\_request\_error. Thus one provider-side 400 previously became repeated loopback IPC/LM/provider requests before the turn failed; the PR tests the resulting 400 versus 502 classification.

### Scenario 2: Deterministic BYOK provider client error returned through the renderer bridge and local proxy

- Critical path: A runtime request reaches the loopback proxy, performs one renderer IPC chat call, invokes the extension-host LM provider, and performs an upstream network request. On failure, the renderer now extracts the numeric status from the existing error string and returns it over the same IPC response; the proxy maps deterministic 4xx to a non-retryable response.
- Scaling input: One logical model request that receives a deterministic 4xx. Before the PR, retry count rather than collection size controlled cost: rewriting the error to 502 caused up to an initial attempt plus five retries; after the PR, the runtime receives the deterministic 4xx after one attempt.
- Effective concurrency: Retries are sequential on the same turn. Independent sessions remain independently concurrent; the diff adds no burst or shared-state contention.
- Cache behavior: No cache or coalescing participates in failures. Every retry repeats the bridge and provider boundaries; the change avoids those repeats for recognized deterministic 4xx statuses. Negative caching is unnecessary because the first response now terminates the turn.
- Mechanism confidence: Very high confidence: the base proxy unconditionally wrote 502, the proxy documents 5xx retry behavior, and changed tests establish deterministic 4xx forwarding. This concrete regression fix was recorded separately with its blamed introducing commit.
- Magnitude uncertainty: The exact backoff and provider latency depend on the runtime and endpoint, but repeated remote attempts and their removal are directly established; the PR description reports about 15 seconds for the affected loop.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/byokLmProxyService.ts:\_handleResponses and src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts:chat</code>: Proxy calls the serving renderer, which invokes the renderer LM service and extension-provided BYOK model.; cardinality: After the diff, one IPC chain for a deterministic 4xx; before, the proxy's 502 classification allowed the runtime to repeat the same chain for each retry.
    - Introduced by diff: false; previous behavior: The boundary existed, but its deterministic-failure result was always converted to retryable 502, multiplying calls.; critical-path effect: Each repeated IPC/LM attempt blocked failure completion; forwarding 4xx removes those sequential waits.
  - network at <code>extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts and the configured OpenAIEndpoint</code>: The BYOK extension sends the model request to the configured provider and receives the deterministic 4xx.; cardinality: One provider call after the diff versus the initial call plus runtime retries when the old proxy returned 502.
    - Introduced by diff: false; previous behavior: The same deterministic request could be repeated despite receiving a client error.; critical-path effect: The remote request dominates each retry delay and directly extends time until the user sees the error.
  - serialization at <code>src/vs/platform/agentHost/common/agentHostByokLm.ts:IByokLmChatResult and src/vs/platform/agentHost/node/copilot/byokLmProxyService.ts:\_handleResponses</code>: The optional numeric errorStatus is serialized in the existing renderer-to-agent-host bridge result and used to construct the proxy JSON error.; cardinality: One small optional numeric field per failed bridge response.
    - Introduced by diff: true; previous behavior: Only the error string crossed the bridge and the proxy emitted 502 unconditionally.; critical-path effect: Constant-size serialization is negligible and enables removal of repeated boundary calls.
- Verdict: Performance improvement, not a regression. The change eliminates repeated IPC and network work for deterministic provider failures.

- Effective concurrency: Retries remain sequential per turn; independent turns can overlap exactly as before. No new limiter or concurrency burst is introduced.
- Cache behavior: Failures are not cached or coalesced before or after the diff. The new status parser and classifier perform constant work per failed attempt.
- Mechanism confidence: High confidence from the explicit clientErrorStatus exclusions and fallback to 502.
- Magnitude uncertainty: Runtime retry delays and endpoint latency vary, but there is no changed multiplicity for these statuses.
- Expensive boundaries:

- Verdict: No reportable regression; the existing transient retry behavior is intentionally preserved with only constant-time parsing/classification added.
