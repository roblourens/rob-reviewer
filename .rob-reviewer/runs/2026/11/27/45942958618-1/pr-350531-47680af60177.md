### Scenario 3: Connection rejected because state ownership or volume trust changed

- Critical path: The root script performs trust checks, removes only its own earlier user-folder symlinks when required, and exits before subsequent startup proceeds.
- Scaling input: Fixed known/selected product folders and reconnect frequency, not number of sessions, files, or state bytes.
- Effective concurrency: One serial shell loop. This early-exit path precedes the existing flock, but parent walks and exact-link removals remain fixed-size; no added async fan-out.
- Cache behavior: No trust-result cache. Once links are removed, repeated rejected connections perform bounded checks without repeatedly removing them. Capability and read-only-rootfs exits precede marker creation and this cleanup.
- Mechanism confidence: High: all added unlink loops and early exits were inspected; their effective cardinality is explicit.
- Magnitude uncertainty: Actual syscall latency and frequency of trust rejection are unmeasured.
- Expensive boundaries:
  - subprocess at <code>src/vs/platform/agentHost/node/devContainerAgentHostService.ts:\_linkUserState</code>: Existing mount inspect, user query, and root script execution; cardinality: Same three grouped calls for a mounted workspace container; unlink helpers execute within that one root script.
    - Introduced by diff: false; previous behavior: Same grouped calls, but the root script exited immediately after the failing ownership/trust check.; critical-path effect: Awaited before startup.
  - filesystem at <code>src/vs/platform/agentHost/node/devContainerState.ts:unlink\_folder and unlink\_state, lines 286-319</code>: Walk parent components without following symlinks, read exact link targets, and remove matching links; cardinality: At most 9 unlink\_folder invocations for a known product or 13 for a custom product, including unused products. - Verdict: No reportable regression: bounded, necessary unlink cleanup does not create collection-scaling subprocess fan-out or recursive work. Removing untrusted links is not itself a performance bug.

### Scenario 4: Restore trusted volume state after a skipped or failed link in the same container

- Critical path: On an eligible restore, trust validation and preservation of the local directory finish before local removal and link publication; the entire root script precedes lifecycle/server startup.

- Cache behavior: connected\_before records container lifetime, while successful source symlinks suppress future backup work. A new container remains exempt.
