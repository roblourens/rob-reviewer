## Findings (1)

### 1. [low] Avoid saving directory history on trust-only cwd updates

**Finding ID:** `PERF-BADE282552B9`  
**Location:** <code>src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1:132</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** CPU for full-cache traversal, JSON serialization and downstream string comparison; temporary arrays, per-directory objects and JSON strings.  
**Scaling:** For P prompt displays and H retained distinct directories (bounded by terminal.integrated.shellIntegration.history, default 100), the mixed-protocol case adds 2P full-history rebuilds, O(PH) objects and O(PB) serialization work for B bytes of retained directory data. Storage coalescing does not reduce those two serializations.  
**Outcome:** Repeated synchronous history serialization increases renderer-thread prompt-processing work and GC pressure, particularly with enlarged populated history limits.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** Both VS Code's nonce-less report and the custom prompt's legacy report were untrusted. Once cwd/trust stabilized, redisplaying the prompt in the same directory emitted no cwd-change event and performed no directory-history serialization.  
**Changed behavior:** For a prompt emitting a legacy cwd report after VS Code's report, the new nonce makes trust alternate true/false on every prompt even when the directory is unchanged. Both transitions synchronously invoke the directory-history persistence consumer.  
**Confidence:** 0.95 — Static tracing establishes both report ordering in PowerShell and trust-only event emission, and the history consumer unconditionally serializes its complete cache. Storage equality checks occur only afterward. The prevalence of mixed-protocol prompts and the duration with large histories are unmeasured.

**Causal diff evidence:** shellIntegration.ps1:132 now appends the matching nonce to its Cwd report, before OriginalPrompt.Invoke() at line 152. If that original prompt emits OSC 7/9;9/CurrentDir for the same directory, shellIntegrationAddon.ts marks the first report trusted (589) and the latter untrusted (685/707/732). Unlike the base's two untrusted reports, these now cause two trust transitions per prompt; cwdDetectionCapability.ts:35 includes trust changes in didChange and fires onDidChangeCwd at 42.

In PowerShell terminals with a custom prompt that also emits a legacy cwd sequence, repeatedly showing the prompt now rebuilds and serializes the complete directory history twice even without changing directories. Populated, enlarged shell-integration histories incur avoidable renderer CPU and allocation/GC pressure during prompt processing.

**Evidence:** TerminalHistoryContribution subscribes to onDidChangeCwd and calls getDirectoryHistory().add for every event (terminal.history.contribution.ts:59-60). TerminalPersistedHistory.add always calls \_saveState (history.ts:111-115); \_saveState allocates an entry object for every cached directory and JSON.stringify's the entire collection (171-174). Storage.set's identical-value check is downstream of serialization (base/parts/storage/common/storage.ts:278-281), so deduplicated storage writes do not eliminate this renderer-thread work.

**Suggested direction:** Keep nonce verification and trust transitions, but deduplicate the directory-history listener by actual cwd value, or separate trust-change notification from cwd-history updates. Trust-only updates should not rebuild and persist directory history.
