# Performance review: SCM - switch to using ReferenceCollection in the IdirtyDiffModelService

[PR #235579](https://github.com/microsoft/vscode/pull/235579) at `edde2c1486a30a8c2f5f8155d2ecb767f183ef20`

## Findings (1)

### 1. [low] Release superseded diff-model references on recomputation

**Finding ID:** `PERF-33C707A5E08F`  
**Location:** <code>src/vs/workbench/api/browser/mainThreadEditors.ts:187</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** IReference objects, single-call disposal closures, and disposal-array entries; the same-key DirtyDiffModel itself remains shared.  
**Scaling:** For N same-text-model diff replacements, each surviving API editor retains N additional reference handles. Normally both inner editors survive, giving two handles per replacement per extension-host customer, but still only one shared DirtyDiffModel for that URI/algorithm.  
**Outcome:** History-dependent retained memory and an O(N) synchronous disposal pass when the editor closes.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Repeated derived evaluations reused the service's URI/algorithm-cached DirtyDiffModel without retaining per-evaluation reference objects; this path's model ownership did not grow with hunk-navigation history.  
**Changed behavior:** Each diff-model replacement now acquires a fresh IReference and appends it to the API editor's lifetime disposal array; replacing the derived value never releases the previous reference.  
**Confidence:** 0.98 — DirtyDiffWidget.showChange calls setModel with a newly constructed IDiffEditorModel (dirtydiffDecorator.ts:208-212; dirtyDiffModel.ts:210-216). DiffEditorWidget creates a new view model and emits a model change, while the unchanged inner text-model IDs keep the same API editors alive (MainThreadDocumentsAndEditors' TextEditorSnapshot and key-based diffMaps). ReferenceCollection allocates a new handle on every acquire even for a cached key. The array is disposed only on API editor removal. The retained-handle count is proven statically; typical session size is unmeasured.

**Causal diff evidence:** The added \`toDispose.push(dirtyDiffModelRef)\` at mainThreadEditors.ts:187 runs inside \`editorChangesObs\`'s derived computation. Before the PR this computation only called \`getDiffModel\`, which returned the cached model without allocating or retaining a new reference handle for each computation.

Keeping a dirty-diff peek open while repeatedly navigating hunks or refreshing it accumulates reference objects and closures until the peek/editor closes. This increases retained memory with navigation history and makes closing synchronously dispose the entire accumulated history.

**Evidence:** mainThreadEditors.ts:147-150 observes diffEditor.onDidChangeModel and recomputes editorChangesObs. Lines 182-187 acquire and retain another reference each time. DirtyDiffWidget.showChange resets the embedded diff model on hunk navigation and refresh, even with the same underlying text models. ReferenceCollection.acquire (lifecycle.ts:646-665) shares one DirtyDiffModel per key but creates a new reference object and disposal closure for each acquisition. mainThreadEditors.ts:108-110 releases the accumulated array only when the API editor is removed.

**Suggested direction:** Keep only the current reference in a replaceable/scoped disposable and release the previous one when the derived value changes. Acquire the replacement before releasing the old reference so same-key refreshes do not unnecessarily destroy and rebuild the shared model; release the remaining reference on editor removal.
