# Performance review: Sessions: show active automations on hover

[PR #350671](https://github.com/microsoft/vscode/pull/350671) at `1f93a0a63c442b88f21177063d5fedd135158a00`

## Findings (1)

### 1. [medium] Avoid per-run rescans of an empty cloud session cache

**Finding ID:** `PERF-DE84695C6BED`  
**Location:** <code>src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts:1039</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>cache-lifecycle</code>  
**Resource:** Full agent-session arrays, migration-deduplication work, and complete provider-cache scans on the UI thread  
**Scaling:** For E mouseover/content requests, S total agent-model sessions, and K eligible active-run resources whose lookup reaches the empty Copilot provider, the added work is O(E\*K\*S), including repeated O(S) array allocations. Grouping into U automation rows happens afterward and does not reduce K; initialized host providers coalesce cold remote listing requests separately.  
**Outcome:** Synchronous UI latency and avoidable CPU/GC pressure while interacting with the sidebar  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** The sidebar associated runs with the already-collected automationSessions using a resource map. An empty Copilot cache could be rebuilt during existing session-list refreshes, but not once per active run on entering the Automations row.  
**Changed behavior:** The new hover resolves eligible active runs through the aggregate management service individually. Each lookup that reaches the empty default Copilot provider repeats a full model rebuild, even for a foreign resource. setupDelayedHover resolves this content synchronously on mouseover, before the display delay and hover identity deduplication.  
**Confidence:** 0.94 — The new helper resolves each eligible active run before grouping. SessionsManagementService visits registered providers in order; the default Copilot provider rebuilds its cache whenever its size is zero, and that rebuild copies/deduplicates and scans the complete agent-session model. This is statically traced; the prevalence and duration of large histories are not measured.

**Causal diff evidence:** Added line 1039 supplies SessionsManagementService.getSession as the new hover helper's per-run resolver. Added sessionsListRenderers.ts:553 calls it inside the active-run loop, before grouping. Previously the section's automationStatus used one sessionsByResource map, with no per-run provider lookup or mouseover-triggered cache rebuild.

With a large non-cloud session history, no Copilot Cloud sessions, and active runs on a later-registered remote host, entering or moving between children of the Automations row repeatedly copies and scans the entire history for each eligible run. This blocks the UI thread and adds allocation/GC pressure even when the hover is never displayed.

**Evidence:** sessionsListRenderers.ts:545-553 loops eligible runs and invokes getSession before grouping. sessionsManagementService.ts:445-446 visits provider.getSession until a match. CopilotChatSessionsProvider.getSession at 1410-1413 calls \_ensureSessionCache; 2891-2895 treats size===0 as uninitialized; \_refreshSessionCache at 2922-2937 scans model.sessionsIncludingAutomationRuns for Cloud sessions. AgentSessionsModel.ts:562-563 constructs and deduplicates an array of the full model on each read. A user with non-cloud history and no Copilot Cloud sessions therefore never gets a warm negative cache. Copilot is unconditionally registered, and later-connected remote providers can be visited after it. HoverService.ts:230-233 evaluates the callback on each bubbling mouseover before showDelayedHover.

**Suggested direction:** Ensure an authoritative empty Copilot session cache is considered initialized, refreshing it through the existing model.onDidChangeSessions path rather than on every lookup, before introducing these per-run hover lookups.
