# Performance review: scm: don't re-run git when switching back to an unchanged tab

[PR #350670](https://github.com/microsoft/vscode/pull/350670) at `0800ac61b045e84cdfd24bb45bade354e222b1f9`

## Findings (1)

### 1. [medium] Skip already-queued diffs when a model is suspended

**Finding ID:** `PERF-1A58DF8F6F95`  
**Location:** <code>src/vs/workbench/contrib/scm/browser/quickDiffModel.ts:267</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>missing-coalescing</code>  
**Resource:** One queued provider-discovery pass and full worker diff computations for the hidden model, plus Git check-ignore for a normal tracked Git file.  
**Scaling:** At most one already-queued follow-up per suspended model because Throttler coalesces queued factories; that follow-up computes each eligible provider original sequentially and its CPU cost grows with file/diff size. Independent suspended models can each retain such a follow-up; the cache caps retained models at ten. Warm original references avoid re-resolving git: files but do not cache getOriginalResource across completed diffs.  
**Outcome:** Unnecessary background CPU and provider I/O, with extra latency for visible-editor operations sharing the editor worker.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Releasing the last reference disposed the model and its ThrottledDelayer, clearing the queued follow-up so it did not discover providers or compute a new hidden-file diff. A worker computation already dispatched before disposal was not cancelled; that unchanged limitation is not the reported regression.  
**Changed behavior:** After a pending debounce has elapsed and queued a follow-up behind an active diff, hiding the tab retains the model and lets that queued diff run even though the model is suspended. The suspension guard in triggerDiff() only rejects new submissions; the queued async factory and diff() do not check suspension.  
**Confidence:** 0.99 — Static call-flow proof: ThrottledDelayer delegates isTriggered/cancel exclusively to Delayer; Throttler.queue stores a follow-up factory until its active promise settles; diff() tests disposal but not suspension. The old disposal cleared that factory. Only the frequency and duration of overlapping diffs are unmeasured.

**Causal diff evidence:** The final-reference release now calls object.suspend() at quickDiffModel.ts:105 rather than disposing the object. Added suspend():267 checks only ThrottledDelayer.isTriggered() and :268 calls cancel(), both of which affect only the debounce timer (async.ts:517-523). It leaves an already-queued Throttler factory live. Before the diff, QuickDiffModel.dispose() called super.dispose(), which disposed the ThrottledDelayer's Throttler and cleared its queuedPromiseFactory (async.ts:293-295,526-528).

Edit a file while a slow provider or substantial diff is still running, let the follow-up's 200 ms debounce expire, then switch tabs before the active diff completes. The hidden tab runs one unnecessary follow-up: normally another Git check-ignore and one worker diff per eligible original, despite nobody displaying it. This consumes CPU and worker capacity needed by the newly visible editor.

**Evidence:** async.ts:252-276 queues the latest factory when a diff is active and starts it on completion. ThrottledDelayer.trigger at :514 transfers the task into that queue after its 200 ms debounce; isTriggered at :517-519 only reflects the now-expired timer. quickDiffModel.ts:338-339 executes the queued factory without checking \_suspended, and diff():360-395 re-queries providers and calls computeDiff for each eligible original. getQuickDiffsPromise():476-536 only shares in-flight discovery, not completed provider requests. EditorWorkerService.computeDiff at editorWorkerService.ts:110-112 dispatches to the shared editor worker. The new tests release before a diff starts or after it finishes, so they do not cover this overlap.

**Suggested direction:** Check \_suspended when the delayed/queued factory actually starts, mark \_diffPending and skip diff() while suspended. Preserve the single resume-triggered recomputation; similarly re-check suspension before issuing worker work after awaited provider resolution.
