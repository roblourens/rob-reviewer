### 1. missing-coalescing

**Fix location:** `src/vs/platform/agentHost/node/agentHostChangesetService.ts:2098` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/agentHostChangesetService.ts:2200`  
**Introducing path:** `src/vs/platform/agentHost/node/agentHostChangesetService.ts`  
**Introducing commit:** `532f98a972e3fed1e9f0bf1e44ac96772957e93e`  
**Mechanism family:** `missing-coalescing`  
**Performance category:** `subprocess`  
**Confidence:** 0.94

**Mechanism:** A refresh queued while the active branch computation awaited its persisted base could not join that computation; it ran a second repository-wide fingerprint even though the first read already covered the change. For R unique repositories this repeated R full status scans and their baseline/HEAD probes plus up to 2,000 path stats per repository, with recursive work for changed submodules. This was one extra coalesced pending pass, not a pass per changed file or per chat.

**Symptom:** Redundant serialized Git processes and filesystem scans after a single checkout change consume I/O/CPU and prolong the branch recompute queue. The mechanism is established by call flow and the added controlled-interleaving test; duration and prevalence are not independently measured.

**Fixed behavior:** Snapshot the already-coalesced pending requests after base resolution but before repository discovery/Git reads; after a successfully recorded or reused branch fingerprint, remove covered non-telemetry requests. In the tested duplicate-refresh scenario this reduces two serialized fingerprint passes to one per canonical owner, while preserving requests arriving after the snapshot, telemetry requests, and retries without a successful fingerprint.

**Evidence:** The base scheduler shifted the active request out of scheduled.requests and awaited \_doComputeStaticChangeset (base line 2092). A refresh of the same canonical branch owner during \_resolveBranchBaseBranch therefore queued another pass, and base line 2200 fingerprinted again before checking whether the published changeset was current. File-monitor refreshes fan out by source; agentHostChangesetCoordinator.ts:656-693 resolves session/default-chat refresh events to the same branch owner. agentHostGitService.ts:991-1040 traces each fingerprint to HEAD/baseline Git reads, a full status, and changed-path lstat calls. Repository-root caching does not cache these fingerprints; optional Git-read sharing only shares overlapping commands, not the serialized second pass. Added test lines 2001-2038 explicitly model the second refresh while base loading is suspended and assert one fingerprint and one diff, whereas telemetry-bearing requests retain two fingerprint passes. Blame of the old fingerprint invocation identifies commit 532f98a972e3fed1e9f0bf1e44ac96772957e93e.
