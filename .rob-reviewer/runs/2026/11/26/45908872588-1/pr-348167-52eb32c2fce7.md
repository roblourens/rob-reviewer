# Performance review: agentHost: stop one Git refresh from recomputing every worktree of a session

[PR #348167](https://github.com/microsoft/vscode/pull/348167) at `52eb32c2fce779a165fd4a44f36afd29b8be0a6c`

## Findings (2)

### 1. [medium] Limit the repository fingerprint fan-out

**Finding ID:** `PERF-3AA7FF6FCF3B`  
**Location:** <code>src/vs/platform/agentHost/node/agentHostChangesetService.ts:2087</code> (<code>RIGHT</code>)  
**Performance category:** <code>subprocess</code>  
**Mechanism family:** <code>concurrency-burst</code>  
**Resource:** Concurrent Git subprocesses, repository-wide status scans and associated CPU/disk I/O.  
**Scaling:** For R distinct repositories in one owner's effective folders, the new fingerprint pass can issue about 3R Git subprocesses concurrently, rather than processing at most 5 repository diffs at a time. Multiple folders inside one repository count only once.  
**Outcome:** CPU and disk contention during Branch refreshes, reducing agent-host responsiveness and increasing refresh latency on many-repository workspaces.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** A Branch refresh for one multi-folder owner resolved roots with a limiter of 5, then computed repository diffs with MAX\_DIFF\_REPOSITORY\_CONCURRENCY=5. Each repository's diff issued its Git commands sequentially.  
**Changed behavior:** Before that limited diff pass, the new guard starts a fingerprint for every unique repository simultaneously. Each fingerprint starts merge-base resolution, HEAD resolution and a full Git status probe in parallel.  
**Confidence:** 0.99 — Static call-flow establishes deduplication, the newly unlimited Promise.all, the three parallel command chains per fingerprint, and direct subprocess spawning. Exact overlap duration and affected workspace prevalence are unmeasured.

**Causal diff evidence:** The added Promise.all(directories.map(...getBranchDiffFingerprint...)) at line 2087 has no limiter; \_doComputeStaticChangeset now awaits this pass at line 2162 before reaching \_computeMultiFolderBranchDiffs' existing limiter.

Opening Branch Changes or refreshing a subscribed chat spanning, for example, 16 distinct repositories can start roughly 48 Git probes together before the Branch result can progress. Warm repository-root caching does not prevent this burst; unchanged diffs still require the fingerprint pass.

**Evidence:** resolveSessionRepositories deduplicates roots and limits resolution to 5 (agentHostSessionRepositories.ts:60-94). getBranchDiffFingerprint (agentHostGitService.ts:796-800) starts three independent Git command chains per root. \_runGit (1499-1506) directly calls cp.execFile without a shared limiter. The old and retained diff fan-out is limited to 5 at agentHostChangesetService.ts:1472-1476.

**Suggested direction:** Queue repository fingerprints through MAX\_DIFF\_REPOSITORY\_CONCURRENCY, disposing the limiter after settlement, while preserving repository order and the unchanged-result guard.

### 2. [medium] Preserve inconclusive fingerprints for the diff pass

**Finding ID:** `PERF-CDB8BC9657A3`  
**Location:** <code>src/vs/platform/agentHost/node/agentHostChangesetService.ts:2089</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Repeated Git subprocesses and full working-tree status scans; repeated lstat operations for repositories whose first fingerprint succeeded.  
**Scaling:** One repository above the 2,000-path cap causes two fingerprints per unique repository on every refresh. With a usable merge base, each fingerprint adds four Git invocations. If both roots of a two-repository owner exceed the cap, the new path adds sixteen probe invocations and four full status scans before the same diffs the base performed.  
**Outcome:** Excessive repository I/O and subprocess work delay Branch Changes publication, especially for large dirty working trees.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** A refresh of a single subscribed multi-folder Branch owner computed one diff per unique repository, with no fingerprint probes. With a usable base and only tracked modifications, each repository's diff performed one merge-base resolution, one status scan and one diff.  
**Changed behavior:** The guard fingerprints all repositories, but discards all results when any fingerprint is undefined. The following multi-folder diff pass receives no map and fingerprints every repository again before computing or reusing its diff.  
**Confidence:** 0.99 — The cap, all-or-nothing return, optional-map propagation and second probe are explicit in the traced code. The scenario uses deduplicated repositories, not per-chat fan-out; runtime duration is unmeasured.

**Causal diff evidence:** The added early return at 2088-2089 discards the complete first-pass fingerprint array. The added nullish fallback at 1478 then calls getBranchDiffFingerprint again for every repository because repositoryFingerprints is undefined.

A chat subscribed to Branch Changes across multiple repositories, with a bulk tracked-file rewrite exceeding 2,000 paths in any root, repeats the guard for all roots. The cap deterministically fails again for the large root, so this duplicated work cannot enable reuse there and recurs even with warm caches.

**Evidence:** \_doComputeStaticChangeset:2162-2164 passes fingerprinted?.repositories to \_computeMultiFolderBranchDiffs:2240. getBranchDiffFingerprint:796-807 has already completed its Git probes before returning undefined for more than 2,000 changed paths. \_computeMultiFolderBranchDiffs:1478 repeats that probe. Repository-root caching only caches root lookup; fingerprints and status scans are not cached or coalesced.

**Suggested direction:** Return the per-repository results even when the aggregate fingerprint is unavailable, preserving explicit undefined results. In the diff pass, distinguish an already attempted inconclusive fingerprint from an unprobed repository so each root is fingerprinted at most once per refresh.
