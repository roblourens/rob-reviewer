# Performance review: Show structural changes in the multi-file diff editor's file list

[PR #350138](https://github.com/microsoft/vscode/pull/350138) at `f467c668eef59357eb4406dd2639e1044677fa87`

## Findings (1)

### 1. [medium] Release rendered structural results when hiding the editor

**Finding ID:** `PERF-35E0364CD1CE`  
**Location:** <code>src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorFileList.ts:351</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** Structural-diff node payloads, wrapper elements, and object-tree nodes retained by hidden file lists  
**Scaling:** Retained memory grows with the total changed-symbol and coverage payload across expanded files in the hidden editor groups; the retention lasts until the input is cleared, results are replaced, or structural children are explicitly removed.  
**Outcome:** Unnecessary retained heap and associated GC pressure while the editor area is hidden  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The multi-diff file list contained only files and folders, so hiding the editor retained no structural-diff payloads or structural tree nodes.  
**Changed behavior:** Hiding the editor disposes the model entries and their document references, but keeps the computed symbol elements strongly reachable through the file-list map and tree for the hidden editor's lifetime.  
**Confidence:** 0.97 — The hide path clears StructuralDiffModel.entries without emitting a tree refresh, while both \_structuralChanges and the object tree retain the returned elements. Maximizing the panel propagates visibility without clearing editor input, so this is a reachable retention path, not just a hypothetical direct call. Retained byte counts are not measured.

**Causal diff evidence:** The diff adds \_structuralChanges, stores computed elements in it at line 486, and installs them in the tree at line 487. The new setVisible(false) path at line 351 only calls the model's setVisible(false); it does not clear either newly added owner of the results.

After expanding files in a large multi-file diff, maximizing the Terminal/Panel or hiding the editor area for chat keeps the full structural trees alive even though their model cache was released. This can retain substantial symbol/coverage data throughout an extended terminal or chat workflow.

**Evidence:** MultiDiffEditorFileList.setVisible calls only \_structuralDiff.setVisible before optionally reloading on show. StructuralDiffModel.setVisible(false) calls clear(), which disposes entries but fires no onDidChange event. \_structuralChanges.set and \_tree.setChildren retain the returned SCMStructuralDiffElement objects, whose node and children fields retain the provider payload. Layout.toggleMaximizedPanel calls setEditorHidden(true), which hides the editor grid view; Part.setVisible -&gt; EditorGroupView.onDidVisibilityChange -&gt; EditorPanes.setVisible forwards visibility without clearInput. Thus ordinary input-clearing on tab switches does not eliminate this panel-maximization case.

**Suggested direction:** On hiding, clear \_structuralChanges and remove structural children from the tree while preserving file expansion/scroll state, then reload expanded files on show as the existing code already does.
