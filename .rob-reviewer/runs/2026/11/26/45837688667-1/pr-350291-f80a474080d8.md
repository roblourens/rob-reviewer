## Performance regression fixes detected (1)

### 1. synchronous-ui-work

**Fix location:** `src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts:300` (`RIGHT`)  
**Blamed base line:** `src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts:291`  
**Introducing path:** `src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts`  
**Introducing commit:** `b7d35c8bdddeb7d4bfebf81cb6733b4a5ee06aa9`  
**Mechanism family:** `synchronous-ui-work`  
**Performance category:** `layout`  
**Confidence:** 0.99

**Mechanism:** Repeated synchronous clientHeight reads after per-hunk top/height writes force browser layout on the scroll critical path. Previously each laid-out visible hunk made two height reads per scroll, plus one gutter-height read per render; the first hunk read follows geometry writes and the second can follow toolbar reconstruction.

**Symptom:** Strongly evidenced synchronous layout work on each scroll, scaling with visible hunk layout invocations and scroll-event frequency, consumes renderer main-thread time and risks scroll jank. This is static call-path evidence; no benchmark timings were independently measured.

**Fixed behavior:** Warm scrolling reuses one height per live toolbar and one height per gutter; toolbar measurement occurs on creation, reconstruction, menu change, or retry of a zero result, and gutter measurement occurs at construction and resize. Offscreen views are disposed, so cached state remains bounded by visible hunks.

**Evidence:** The deleted base line 291 reads buttons.clientHeight inside DiffToolBar.layout, and base line 294 repeats that read after \_isSmall may rebuild the toolbar. EditorGutter.render is synchronously subscribed to editor.onDidScrollChange and, for each intersecting visible hunk, writes view.domNode.style.top and style.height immediately before calling that layout method. Thus the base implementation crosses a synchronous browser layout boundary after geometry writes for each laid-out hunk on every scroll. The new line 300 uses a cached nonzero height, invalidated only on toolbar reconstruction (254) and menu-item change (278). The companion gutter change replaces the per-render clientHeight read at base editorGutter.ts:86 with initialization/ResizeObserver measurements. The added test asserts ten scroll-triggered layouts with zero gutter-height reads. Blame identifies b7d35c8bdddeb7d4bfebf81cb6733b4a5ee06aa9 as introducing both base height-read paths.
