# Performance review: chat: show organization-required plugins from the Copilot runtime as managed

## Findings (1)

### 1. [low] Coalesce session inventory reads across anchors

**Finding ID:** `PERF-E0B9FD04EF09`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:759</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** SDK session plugins.list IPC calls  
**Scaling:** One logical refresh adds one identical session inventory RPC per live anchor, plus the existing session inventory read in the concurrent runtime-plugin refresh, so cost and concurrency grow as A+1 for A anchors.  
**Outcome:** excessive IPC and delayed customization publication  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Anchor discovery read only the global inventory; runtime-plugin refresh performed one session-effective inventory read independent of anchor count.  
**Changed behavior:** Every anchor discovery now reads the same session-wide inventory, even when there is no missing managed plugin.  
**Confidence:** 0.93 — Every live anchor runs this added await, refreshDiscovery starts all anchors with Promise.all, and each callback targets the same default chat. Tests establish multiple distinct live anchors; only runtime duration and prevalence are uncertain.

**Causal diff evidence:** RIGHT line 759 adds \`await this.managedPluginsWithoutContent(sessionPlugins, plugins, token)\` to every anchor's plugin discovery. The callback is wired to the default chat's \`listInstalledPlugins()\`.

Managed-plugin completion/failure and plugin installation refreshes issue a concurrent burst of duplicate runtime IPC in sessions with peer chats in different workspaces. Publication waits for all anchor refreshes, delaying the managed-state update when the runtime is slow.

**Evidence:** SessionDiscoveredEntry passes \`\_sessionPlugins\` to discovery, one entry exists per unique CustomizationAnchor, and SessionPluginController.refreshDiscovery concurrently refreshes every live anchor together with \`\_refreshRuntimePlugins()\`. The latter calls listPluginInstallations, which already calls the same session's listInstalledPlugins. Per-chat anchor tests demonstrate main, peer-folder, and multi-folder anchors can coexist.

**Suggested direction:** Fetch the default chat inventory once per controller refresh and share that snapshot with every anchor, or coalesce it in a controller-level promise/cache invalidated by runtime-plugin events.
