## Performance regression fixes detected (1)

### 1. cleanup-lifecycle

**Fix location:** `src/vs/workbench/contrib/extensions/browser/extensionEditor.ts:537` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/extensions/browser/extensionEditor.ts:538`  
**Introducing path:** `src/vs/workbench/contrib/extensions/browser/extensionEditor.ts`  
**Introducing commit:** `a55d9674eaec9f392f1c18eaa3b6f39da80cb1f0`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `cpu`  
**Confidence:** 0.97

**Mechanism:** Rapidly switching extension inputs or clearing an extension editor while manifest/gallery resolution is pending allowed the obsolete continuation to perform README filesystem/network I/O, Markdown rendering, and webview allocation because disposing the CTS did not cancel its token.

**Symptom:** Obsolete extension details could continue loading and rendering after navigation or editor clear, adding avoidable I/O, CPU/GC work, and transient webview resources.

**Fixed behavior:** The added disposal sentinel is set whenever transientDisposables is cleared and is checked after each awaited gallery/manifest stage, so superseded or cleared renders return before loading README content, rendering Markdown, or allocating a stale webview.

**Evidence:** In the base render path, transientDisposables.clear() disposes the registered CancellationTokenSource with its default dispose(false), and CancellationTokenSource.dispose(false) only disposes the token emitter without setting isCancellationRequested. Therefore the base checks at the blamed line and after getManifest do not stop a superseded render. The stale continuation reaches renderNavbar/onNavbarChange, which calls extension.getReadme (filesystem for installed extensions or gallery network for Marketplace extensions), renders Markdown, and can create a webview overlay. The added test explicitly exercises switching/clearing while a manifest is pending and requires that only the current extension's README is requested and no cleared extension README is requested.
