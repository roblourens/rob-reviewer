# Performance review: agentHost: publish SDK hook and MCP customization inventory

## Findings (1)

### 1. [medium] Run the workspace-hook fallback without a serial SDK round trip

**Finding ID:** `PERF-99D46F9A543F`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:815</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** Copilot SDK RPC calls and the hook inventory/filesystem parsing they trigger  
**Scaling:** For every customization-discovery anchor and every watched refresh, a workspace whose \`.github/hooks\` directory exists but whose native result has no repository action performs two hooks-discovery RPCs in sequence; the cost multiplies across live session/chat anchor sets.  
**Outcome:** blocked customization/session setup and refresh latency  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Hook inventory was discovered from the watched filesystem inside the existing parallel discovery pass, so this path did not wait for two sequential SDK hook-discovery calls.  
**Changed behavior:** The new path first awaits \`client.rpc.hooks.discover\`, then awaits \`discoverWorkspaceHooksFallback\`; when the runtime's documented repository-hook gap is hit and \`.github/hooks\` exists, that helper issues and awaits a second \`hooks.discover\` call before discovery can settle.  
**Confidence:** 0.97 — The serial awaits, the second RPC, the critical-path callers, and the runtime gap trigger are all explicit in changed code and tests. Exact milliseconds vary by SDK/runtime and repository contents, which affects severity but not the mechanism.

**Causal diff evidence:** RIGHT line 815 newly awaits \`discoverWorkspaceHooksFallback\` only after the newly added native \`hooks.discover\` has completed; the fallback's added code performs a second \`client.rpc.hooks.discover\` for existing workspace hook directories.

Opening or resuming a Copilot chat in a repository with workspace hooks, and later refreshing its customizations, now pays an additional full SDK round trip on the critical path. Multiple live sessions or chat anchors repeat the delay independently.

**Evidence:** \`SessionDiscoveredEntry.whenSettled()\` is awaited by \`getCustomizationsSettled()\` and \`getAppliedCustomizations()\`, which feed session customization publication and \`ActiveClient.snapshot()\`. At lines 812-815, the native hooks RPC completes before the fallback starts; lines 879-882 show the fallback makes another SDK RPC. The added integration test establishes the realistic trigger: native discovery returns no workspace hooks while the explicit-directory fallback finds them.

**Suggested direction:** Probe the workspace hook directory before starting discovery and launch the native and explicit-directory SDK requests concurrently, then preserve the existing ID-based merge and provenance rules; if the SDK can return equivalent inventory/provenance from one request, coalesce them into a single call instead.
