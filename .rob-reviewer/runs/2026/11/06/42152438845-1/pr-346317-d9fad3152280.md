### Scenario 1: Browser unit-test worker completes a top-level suite and advances to the next suite in the shared page

- Critical path: The existing afterAll isolation check reads scroll state, then the added reset synchronously assigns body/document scroll offsets and calls window.scrollTo before Mocha can advance. No geometry read follows the writes, so style/layout is not synchronously forced; rendering and scroll notification can be coalesced by the browser.
- Scaling input: Number of top-level suites assigned to one worker; realistic full runs contain hundreds of files split across up to four workers. Cost is a fixed five assignments per suite, while meaningful scroll changes are limited to suites that moved the page.
- Effective concurrency: Top-level suites are serialized within each browser page. CI may run up to four independent worker processes, each with its own browser/page, so there is no shared-page concurrency or burst within a worker.
- Cache behavior: No cache or network lookup is involved. The existing per-suite snapshot is retained in a WeakMap and deleted at teardown; the diff does not alter its lifecycle or introduce retained keys.
- Mechanism confidence: High confidence in the synchronous per-suite writes and serialized runner path from the changed reset through installIsolationCheck and the browser runner integration.
- Magnitude uncertainty: Exact browser cost of assigning unchanged scroll values varies by engine, but the code has no forced-layout read, unbounded work, or per-element traversal, and browser rendering can coalesce the writes.
- Expensive boundaries:
  - other expensive boundary at <code>src/vs/base/test/browser/isolationCheck.ts:scrollDetector.reset</code>: Five DOM/window scroll-state assignments across the browser/compositor boundary; cardinality: One reset invocation per top-level suite; five constant property writes, with an actual scroll-state change only when the suite changed one of the captured positions

### Scenario 2: Electron unit-test renderer completes a top-level suite and advances within the shared renderer page

- Critical path: The same added scroll reset executes in the existing Mocha afterAll hook before the next top-level suite. It is synchronous but performs only fixed scroll writes after the detector's reads, without a read-after-write layout flush.
- Scaling input: Top-level suites run by one Electron worker, commonly hundreds distributed across up to four processes. Added work remains O(suites) with a small constant and O(1) memory.
- Effective concurrency: Suites are serialized in each Electron renderer. Worker mode uses separate Electron processes/windows (up to four in CI), so resets do not contend on one document.
- Cache behavior: No cache is consulted. Existing snapshots are removed after each suite, and reset retains no new objects beyond the current hook invocation.
- Mechanism confidence: High confidence from the Electron runner installation, sequential Mocha hook execution, and the changed detector implementation.
- Magnitude uncertainty: Engine-specific scroll setter overhead is not measured, but there is no evidence of synchronous layout, IPC, filesystem access, retained state, or collection-sized work in the added path.
- Expensive boundaries:
  - other expensive boundary at <code>src/vs/base/test/browser/isolationCheck.ts:scrollDetector.reset</code>: Five body/document/window scroll-state assignments in the Electron renderer; cardinality: One fixed-size reset per top-level suite in each worker; only suites that actually scrolled require a compositor-visible change
    - Introduced by diff: true; previous behavior: Suite teardown checked the captured scroll positions but left them unchanged; critical-path effect: The assignments execute before the next suite, but no paint, frame, IPC, or layout result is awaited
  - filesystem at <code>test/unit/electron/renderer.js:writeIsolationFindings</code>: Synchronously append optional isolation findings at the end of the run; cardinality: At most one append per renderer run when reporting is enabled and findings exist
    - Introduced by diff: false; previous behavior: The optional end-of-run append already existed with the same cardinality; critical-path effect: End-of-run reporting only; not moved into per-suite teardown by this diff
- Verdict: No reportable performance regression. The bounded property writes do not meet the evidence threshold for material test-run latency or resource pressure.
