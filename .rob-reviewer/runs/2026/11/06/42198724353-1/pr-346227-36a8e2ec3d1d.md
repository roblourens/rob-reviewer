## Findings (1)

### 1. [medium] Keep session event logs out of eager file attachments

**Finding ID:** `PERF-5A7C52BC78E4`  
**Location:** <code>src/vs/workbench/contrib/chat/common/requestParser/chatParserTypes.ts:241</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** Bytes read from each attached \`events.jsonl\` and associated filesystem I/O/CPU for SDK attachment preprocessing.  
**Scaling:** Cost grows with the total byte size of referenced session logs and repeats for each referenced session on each send or edit/resend; there is no deduplication or size gate on this path.  
**Outcome:** Increased send latency and avoidable filesystem I/O before the model request begins.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this change, the completion produced a private generic marker. \`SessionsManagementService.\_augmentOptionsForTroubleshoot\` removed that marker from outgoing attachments and, only for \`/troubleshoot\`, appended the log path as prompt text; ordinary requests sent no event-log attachment and troubleshoot requests did not pass the log through SDK file-attachment preprocessing.  
**Changed behavior:** The new session-reference branch turns every accepted \`\#session\` token into a \`sessionReference\` entry. The existing Agent Host conversion then emits both a simple attachment and a \`MessageAttachmentKind.Resource\` for that session's \`events.jsonl\`, which Copilot converts to an SDK \`file\` attachment before calling \`session.send\`.  
**Confidence:** 0.94 — The changed entry kind, its unchanged conversion into a Resource attachment, and the Resource-to-SDK-file call path are explicit. Provider captures establish eager pre-request file metadata generation, including line counts. Exact scan duration varies with disk/cache state, but the log's realistic hundreds-of-MB size is documented in this diff.

**Causal diff evidence:** Added line 241 changes the parsed variable from the former generic private marker into \`kind: 'sessionReference'\`; that is the discriminator that activates the existing trajectory Resource-attachment branch. The same PR deletes the old send-time code that stripped the marker and appended only a path string.

Attaching a long-running session can make request dispatch perform a full-file pass just to prepare the SDK file attachment, delaying the first model request and generating substantial disk I/O; editing/resending or attaching multiple sessions repeats that cost.

**Evidence:** The added return at line 241 reaches \`AgentHostSessionHandler.\_convertVariableToAttachment\`, whose \`sessionReference\` branch calls \`\_toSessionReferenceAttachments\`; that creates a Resource attachment for the trajectory. \`CopilotAgentSession.\_toSdkAttachment\` maps Resource attachments to \`{ type: 'file', path }\`, and \`\_send\` awaits \`session.send\` with them. Repository E2E captures for resource attachments show the SDK expands each file into \`&lt;tagged\_files&gt;\` with an exact line count before the provider request and then exposes it to the model's file-reading tool. The newly added troubleshoot content itself documents that \`events.jsonl\` can be hundreds of MB and must never be loaded whole.

**Suggested direction:** Keep the session-reference metadata and host-local path, but do not emit the raw event log as a generic SDK file attachment. Send a lightweight simple attachment/path and let \`/troubleshoot\` or the agent's tools stream and narrow the log on demand; if generic session context requires eager content, enforce a byte/line cap before creating the attachment.
