- Critical path: The constructor reads productService.copilotVersions.sdk once and stores it on the telemetry router. Client startup later registers a fire-and-forget telemetry callback; no changed work must complete before client.start() or user interaction can progress.
- Scaling input: One router instance per CopilotAgent; the added constructor work is a single optional string property read independent of chats, model calls, or history size.
- Effective concurrency: No new asynchronous work, queue, limiter, IPC, or subprocess activity is introduced during construction. Runtime telemetry callbacks remain independently fire-and-forget as before.
- Cache behavior: No cache is read or changed by the new SDK-version constructor argument.
- Mechanism confidence: High confidence from the constructor and client-options call path: the version is read once and only retained as a short string.
- Magnitude uncertainty: None material: the changed startup operation is constant-time and does not add an expensive boundary.
- Expensive boundaries: none found
- Verdict: No reportable regression. The change adds constant-size router state and no startup-critical work.

### Scenario 2: Routing restricted engine.messages and engine.messages.length snapshots for root calls, subagents, and older runtimes

- Critical path: The SDK invokes onGitHubTelemetry via a void, fire-and-forget callback, so routing and upload are off the model-call/user-response critical path. Routing resolves the existing per-token telemetry context, multiplexes existing event properties, serializes an envelope, and starts the existing telemetry send.
- Scaling input: Work scales with the number of runtime-emitted engine snapshots, typically the existing engine.messages and engine.messages.length events per model call across root and subagent calls. The diff creates no events; it adds one bounded SDK-version string per existing snapshot. The five runtime metadata fields were already passed through by the pre-diff event.properties spread, so their client-side cardinality and serialization are unchanged.
- Effective concurrency: Each notification is routed independently as before. Concurrent cold context lookups for the same token share the existing discovery promise; warm lookups use the cached per-token entry. Telemetry POSTs remain fire-and-forget and can overlap, but the diff neither increases event count nor changes concurrency.
- Cache behavior: Cold per-token restricted-context discovery may perform one coalesced /copilot\_internal/user request; warm notifications reuse the cached entry. The diff does not alter cache keys, positive/negative states, coalescing, or invalidation.
- Mechanism confidence: High confidence: the pre-diff router already spread every runtime property, while the sole runtime behavior change stamps one optional short string before the existing multiplex/send path.
- Magnitude uncertainty: Exact snapshot frequency varies with model calls and subagent fan-out, but that affects only a constant payload-byte delta because event count and boundary-call count are unchanged.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_routeGitHubTelemetry and src/vs/platform/agentHost/node/shared/copilotApiService.ts:resolveRestrictedTelemetryContext</code>: Resolve the restricted telemetry context through per-token Copilot account discovery on a cold cache.; cardinality: At most one coalesced cold discovery for concurrent callers sharing a token; warm notifications reuse the cached entry.

  - serialization at <code>src/vs/platform/agentHost/node/agentHostGitHubTelemetryRouter.ts:route and src/vs/platform/agentHost/node/agentHostRestrictedTelemetry.ts:multiplexProperties/\_post</code>: Copy properties, gzip/base64 values that are already oversized or always-compressed, and JSON-serialize the telemetry envelope.; cardinality: Once per existing routed snapshot; compression remains once per qualifying large property. copilotSdkVersion is short and does not qualify for compression.
    - Introduced by diff: false; previous behavior: All event properties were already copied, multiplexed, and serialized.
