The diff changes only GDPR schema documentation plus tests; it adds no executable step to this path, and \`event.properties\` already passed through unchanged before the PR.
- Scaling input: Work scales with the number of runtime engine notifications across root and child model calls. Effective cardinality remains one routing/serialization operation per notification, one enhanced-GitHub upload for each eligible notification, and an additional internal sink emission only for eligible \`engine.messages.length\` notifications from internal accounts. The added bounded \`initiatorType\` value does not change event count or effective grouping.
- Effective concurrency: Account discovery is coalesced per GitHub token through the cached in-flight promise. Warm context reads require no network request. Notification routing awaits multiplexing, while enhanced-GitHub uploads are fire-and-forget; there is no new limiter, queue, fan-out, or concurrency introduced by the diff.
- Cache behavior: Restricted telemetry context is cached per token and concurrent cold requests share one discovery promise; warm reads reuse the entry until its refresh window. This PR changes no cache key, hit/miss behavior, invalidation, negative-cache behavior, or coalescing. Older runtimes omit \`initiatorType\`; newer runtime properties were already spread by the router before this declaration.
- Mechanism confidence: High: the only production TypeScript change is inside a GDPR comment fragment, while executable routing demonstrably spreads \`event.properties\` wholesale both before and after the PR. Tests and documentation do not execute in the product path.
- Magnitude uncertainty: Backend schema retention may determine whether curators can consume the field, but it does not alter client-side event cardinality, serialization placement, payload construction, or boundary calls. Runtime dependency updates are explicitly outside this diff.
