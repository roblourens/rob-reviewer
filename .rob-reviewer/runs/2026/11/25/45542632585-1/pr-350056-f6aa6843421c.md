- Scaling input: Document DOM/text size controls browser reflow cost; command frequency controls how often zoom changes. Zoom is bounded to 50–200%; commands at an unchanged value return early. Only the active pane is addressed, not all open panes.
- Effective concurrency: Renderer JavaScript runs synchronously per command; there is no newly introduced per-document-item async fan-out. A single pending anchor is replaced/reused across successive commands, and scroll persistence remains requestAnimationFrame-throttled.
- Cache behavior: No new content cache or per-command collection is created. Existing model and DOM are reused. The pending anchor is a single Range, cleared on consumption or the next zoom operation; persisted state adds one numeric field.
- Mechanism confidence: High confidence in the command, state-save, and bounded anchor paths from inspected source. Insufficient evidence to classify the necessary user-requested zoom reflow as an actionable regression.
