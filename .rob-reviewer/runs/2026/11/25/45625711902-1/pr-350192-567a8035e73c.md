### 1. repeated-work

**Fix location:** `extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts:752` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts:732`  
**Introducing path:** `extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts`  
**Introducing commit:** `094867341993c3eb5dfd97911a1dd7047a461c15`  
**Mechanism family:** `repeated-work`  
**Performance category:** `cpu`  
**Confidence:** 0.97

**Mechanism:** Repeated synchronous SQL compilation on the initialization/search critical path: N unchanged reconciled files required N identical SELECT preparations; M new/changed files additionally prepared another lookup and an upsert each. Other DB update/delete paths also compiled fixed SQL per call.

**Symptom:** Avoidable synchronous CPU and native statement allocation scale with workspace file count before external-ingest initialization and first search can finish. This consequence follows statically from the serial per-file loop and DatabaseSync.prepare; no timing claim is needed.

**Fixed behavior:** Reuse each SQL statement after its first preparation on the instance's database, bounding preparation to nine literal queries for the index lifetime instead of compiling per file, per file event, and per row update.

**Evidence:** Base line 732 prepared the identical parameterized SELECT on every get(uri). initialize() awaits reconcileDbFiles(), which calls get for each statted candidate; previously new/changed candidates also called get again via tryAddOrUpdateFile. search() awaits doIngest(), which awaits initialization. RIGHT 752 now calls prepare(query); RIGHT 191-198 caches on the single readonly database, so SQL compilation becomes once per literal per index rather than once per file. All nine call sites use fixed SQL literals, methods complete synchronously, and dispose clears the map before closing the database.
