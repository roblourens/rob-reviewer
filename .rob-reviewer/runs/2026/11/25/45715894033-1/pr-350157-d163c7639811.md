## Findings (1)

### 1. [medium] Clear phase timing scopes when a staged stream is cancelled

**Finding ID:** `PERF-CAF67DEF7602`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:12575</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** Accumulated reasoning and markdown strings, response-part objects, and timing scopes in CopilotReasoningTiming.\_scopes.  
**Scaling:** Retained bytes grow with the sum of streamed output prefixes across cancelled child-chat phases with distinct Fusion IDs in the same live session; there is no eviction or per-phase content cap.  
**Outcome:** Session-long retained heap growth and additional GC pressure after repeatedly stopping long repair/revision generations.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before the phase's first complete assistant.message, provisional text/reasoning deltas were handled in the root timing scope. That scope was cleared when the root turn ended or the next turn started, rather than retaining interrupted output under a unique phase ID.  
**Changed behavior:** Repair/revision deltas now accumulate under fusion:&lt;fusionId&gt;:&lt;phaseId&gt;. Cancelling before the complete message prevents completeMessage from releasing scope.parts, but the phase cleanup only removes routing state, leaving the accumulated strings reachable for the session lifetime.  
**Confidence:** 0.96 — The new handler passes the unique phase tool-call ID into \_emitReasoningDelta/\_emitMarkdownDelta. CopilotReasoningTiming explicitly accumulates their content in its session-owned \_scopes map. Traced abort, error, phase-chat closure, and turn-reset paths do not clear these phase keys; only real subagent completion clears a child scope. Static evidence establishes retention; cancellation frequency and output size determine its magnitude.

**Causal diff evidence:** Added lines 12572–12578 route provisional deltas into phase-keyed timing scopes. Previously these deltas used the ordinary root handlers at 11705/13466, whose undefined-key scope is cleared on the next \_startTurn (3936). Consider cancellation before the phase's first complete assistant.message: before this change no partial model output was accumulated under that phase key.

Stopping a repair or revision while it streams, before its first complete assistant.message, leaves an extra retained copy of its partial output even after subsequent turns. Repeated cancellations in a long-lived chat accumulate these copies until the CopilotAgentSession is disposed.

**Evidence:** CopilotReasoningTiming.start/getScope stores each phase in \_scopes (copilotReasoningTiming.ts:63–68,160–165), and append/markdown retain concatenated content (71–94). completeMessage normally empties scope.parts (132–138), but late provisional messages are rejected by \_fusionPhaseToolCallId after cancellation (copilotAgentSession.ts:3257–3258). \_forgetFusionPhaseChats (14636–14640) and \_completeFusionPhaseChats (14642–14675) never clear timing scopes; \_startTurn clears only undefined (3936). \_clearSubagentResponseParts does clear a child key (3903–3906), but its sole caller is the real-subagent completion path (3381–3385), not Fusion phase closure.

**Suggested direction:** Clear each phase-owned timing scope when its chat is definitively cancelled or closed, respecting the existing drain/reopen ordering. Include the abort/forget path, not just normal message completion.

### Scenario 3: Cancel a streaming repair/revision before its first complete message, then continue using the same session

- Critical path: Cancellation sets the late-event gate, aborts the SDK execution, forgets phase routing, and allows later turns. Retained timing scopes are not on the cancellation latency path but remain reachable afterward.
- Scaling input: Sum of partial reasoning/markdown output bytes across interrupted child-chat phases with distinct fusion/phase keys over the live session lifetime.
- Effective concurrency: One retained scope per affected phase key; repeated cancellations accumulate even with completely sequential turns. This is not a concurrency-burst issue.
- Cache behavior: The stream-flag map is cleared, but it does not own the accumulated output. CopilotReasoningTiming.\_scopes retains each phase's partial parts. Turn startup clears only the undefined/root scope; real-subagent completion clears child scopes but Fusion close/forget does not. Disposal eventually clears all scopes.
- Mechanism confidence: High: all timing-scope clear sites, abort/idle/error paths, phase close/forget paths, and subsequent-turn reset were traced. Existing tests explicitly exercise cancellation followed by reuse of the same session.
- Magnitude uncertainty: The number of user cancellations and partial-output lengths are unknown. These affect severity, not the established lifetime/scaling mechanism.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:abort</code>: Request SDK session abort.; cardinality: One existing session.abort call per cancellation, independent of streamed byte count.
    - Introduced by diff: false; previous behavior: The same abort request existed. Partial provisional stream content was accumulated in the root timing scope, which was cleared on reuse rather than stranded under a phase key.; critical-path effect: abort awaits the SDK request; the memory regression persists after this settles and after later turns start.
- Verdict: Reported one medium-severity cleanup-lifecycle regression at copilotAgentSession.ts:12575: newly phase-keyed partial streams retain output until session disposal.
