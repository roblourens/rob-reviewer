**Mechanism:** An extra independent esbuild run traversed and bundled the same Mermaid dependency graph and emitted its own shared/lazy chunks. With the common previewSrcDir watch subscription, every source change triggered that additional fresh whole-graph build and output writes.

**Symptom:** Redundant full Mermaid bundling and duplicate dependency-chunk writes in extension/product builds and on each debounced webview source change; static call-path evidence, not measured timings.

**Fixed behavior:** The editor entry is now part of the same three-entry splitting-enabled build as preview and notebook, so their common dependencies are bundled/emitted once and one subscription rebuilds the graph for a preview-source edit, rather than a third independent whole-graph build.

**Evidence:** The deleted base line 83 started an additional standalone Markdown-editor run with splitting enabled, after standalone preview and notebook runs. All three entries import mermaid and ../shared; shared/index.ts imports the layout/ZenUML packages and iconPackConfig.ts contains the same lazy icon imports. runBuild calls esbuild.build separately for each run. In watch mode all three subscribed to the same previewSrcDir, and watchWithParcel explicitly starts an entire fresh build on every debounced change instead of retaining an esbuild context. The new lines 63-72 build these three entries in one splitting-enabled run, removing the additional duplicate dependency traversal and output emission. build/lib/extensions.ts:748-760 invokes this script in both product builds and watch mode; package.json invokes it for extension compilation and prepublish. Blame of the extra standalone editor run identifies f6d4809eda8172f8c30f13189df4eecec710130d.
