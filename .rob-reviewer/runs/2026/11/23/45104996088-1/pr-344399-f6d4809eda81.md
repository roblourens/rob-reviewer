## Findings (2)

### 1. [medium] Scope refreshes to the provider that changed

**Finding ID:** `PERF-0842110C187A`  
**Location:** <code>extensions/markdown-language-features/src/preview/markdownEditorProvider.ts:706</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** Filesystem reads and associated IPC, full HTML byte decoding, and provider-definition payloads.  
**Scaling:** Each settings event causes M open panels to issue S static-provider reads each: M\*S calls and M times the combined HTML bytes. Panels run concurrently; reads within each panel are sequential and are not coalesced across panels.  
**Outcome:** Excessive filesystem/IPC work and delayed settings application behind unrelated resource reads.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Mermaid setting changes did not trigger the Markdown editor's provider loader. Static HTML was read during editor initialization or contribution/resource invalidation, not unrelated Mermaid configuration changes.  
**Changed behavior:** Provider onDidChange events are forwarded without provider identity to a global event. Every open Markdown panel responds by clearing all resolved descriptors and loading all provider definitions, including unrelated static HTML.  
**Confidence:** 0.98 — The added event handler directly invokes a loader that awaits an uncached filesystem read for every static contribution. Per-panel subscriptions establish M\*S reads without relying on unavailable SDK internals; file sizes and remote latency are unmeasured.

**Causal diff evidence:** Added lines 705-707 invoke refreshCodeBlockEditorProviders(false, true) for every panel. That function clears all resolved caches and awaits \#loadCodeBlockEditorProviders, whose contribution loop at lines 790-803 reads every static provider. Added lines 935-936 discard the identity of the provider that changed.

After resolving a Mermaid editor, changing a Mermaid setting with M Markdown panels open causes M\*S unrelated HTML reads for S installed static providers, even when their blocks are absent. Applying the setting waits behind S sequential reads per panel, potentially over a remote extension filesystem.

**Evidence:** MermaidCodeBlockEditorProvider fires on markdown-mermaid setting changes at mermaidCodeBlockEditorProvider.ts:25-28. Each open panel subscribes to the global event. \#loadCodeBlockEditorProviders awaits vscode.workspace.fs.readFile(provider.source.resource) inside its loop, with no cache or in-flight joining. Static providers are supported by both the contribution schema and legacy markdown.codeBlockEditors. The renderer notification waits for all these reads.

**Suggested direction:** Carry the changed provider ID through the event, invalidate only its descriptors, and refresh it without reloading unchanged static contributions. Retain full reloads for contribution/resource changes.

### 2. [medium] Exclude preview-only settings from the Mermaid runtime key

**Finding ID:** `PERF-DFB6DCE799AB`  
**Location:** <code>extensions/mermaid-markdown-features/src/markdownEditor/mermaidCodeBlockEditorProvider.ts:40</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>cache-lifecycle</code>  
**Resource:** Iframe/guest-runtime creation, Mermaid initialization, diagram parsing, SVG layout, and DOM reconstruction.  
**Scaling:** Work scales with the number of instantiated Mermaid frames refreshed across open panels and each diagram's complexity, not all fenced blocks. Warm script caches can reduce transferred bytes but do not eliminate fresh guest initialization and rendering.  
**Outcome:** Avoidable diagram redraw latency and renderer CPU/allocation pressure on preview-only configuration changes.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The built-in Mermaid provider used the constant runtimeKey vscode.markdown.mermaid, and changing preview controls or mouse-navigation settings did not refresh or reconstruct the Markdown editor's Mermaid frames.  
**Changed behavior:** The provider hashes the entire HTML, including all shared preview settings, into the runtime key. Its configuration listener also fires for preview-only changes, so otherwise compatible editor frames receive an incompatible runtime identity.  
**Confidence:** 0.94 — The configuration serializer includes preview-only keys, the new runtime key hashes that serialization, and the documented iframe contract prohibits reuse across different keys. The guest never consumes these keys. Exact recreated-frame counts depend on virtualization, so the finding is limited to instantiated frames rather than every document block.

**Causal diff evidence:** Added line 40 derives runtimeKey from hashString(html); line 35 builds that HTML with renderMermaidConfigSpan(). The added listener at lines 25–28 fires for any markdown-mermaid configuration change. Previously the deleted mermaidProvider.ts:13 used a constant runtime key.

Changing controls.show or mouseNavigation.enabled for the preview unnecessarily reconstructs instantiated Mermaid frames in open Markdown editors and redraws unchanged diagrams. With several visible, complex diagrams this adds avoidable rendering latency and CPU work to a setting change that has no editor effect.

**Evidence:** src/markdownMermaid/config.ts:33–43 serializes clickDrag (mouseNavigation.enabled) and showControls (controls.show) along with rendering settings. Neither value is read by preview-src/markdownEditor/index.ts or buildMermaidConfig, and neither affects the provider's presentation. Nevertheless either changes the hashed HTML. markdown-language-features/schemas/package.schema.json:107 documents that only equal runtime keys may reuse an iframe. Each replacement guest runs main(), registers addons/connects, and performs a fresh Mermaid parse/render through renderMermaidBlocksInElement.

**Suggested direction:** Filter onDidChange to settings actually consumed by the Markdown editor, and exclude preview-only fields from its serialized runtime configuration/key. Preserve runtime invalidation for genuine rendering-setting changes.
