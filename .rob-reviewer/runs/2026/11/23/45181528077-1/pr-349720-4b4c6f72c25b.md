## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `extensions/merge-conflict/src/documentTracker.ts:128` (`RIGHT`)  
**Blamed base line:** `extensions/merge-conflict/src/documentTracker.ts:119`  
**Introducing path:** `extensions/merge-conflict/src/documentTracker.ts`  
**Introducing commit:** `f4c0e976e26e6e695e8ac558903c16bc7fc0b9e8`  
**Mechanism family:** `repeated-work`  
**Performance category:** `cpu`  
**Confidence:** 0.95

**Mechanism:** Edit-triggered conflict queries repeatedly materialize and search an entire conflict-free document. Pending consumers are coalesced per URI, but completed negative results are not retained. For E edited versions actually scanned and D document characters, the old path performs O(E\*D) whole-document work; the model's string cache only avoids another join within the same unchanged version.

**Symptom:** Strongly evidenced synchronous extension-host CPU and document-sized string allocation after small edits in large conflict-free files, delaying decoration/code-lens completion and other extension-host work. This is static call-path evidence, not an independently reproduced timing measurement.

**Fixed behavior:** Caches the conflict-free result per TextDocument and version, and preserves it across single edits of at most 256 inserted characters with no newline when the bounded marker neighborhood is safe. Warm requests avoid whole-document materialization and searching; unsupported edits or possible markers retain the existing full-check fallback.

**Evidence:** The base getConflictsOrEmpty unconditionally calls MergeConflictParser.containsConflict (base documentTracker.ts:119) before returning an empty result. MergeDecorator.begin subscribes to document changes and applyDecorations awaits tracker.getConflicts for visible editors (mergeDecorator.ts:34-35, 178). The per-URI Delayer coalesces pending requests, but documentTracker.ts:83 removes each completed task, so subsequent edit-triggered tasks repeat the check. containsConflict calls document.getText and searches the document-sized string (mergeConflictParser.ts:150-151). ExtHostDocumentData delegates getText to MirrorTextModel, whose getText joins all lines when its string cache is empty and whose onEvents invalidates that cache on every model change (mirrorTextModel.ts:84-107). The added version check at documentTracker.ts:128 returns before this work; the added listener advances the negative-cache version for eligible marker-free edits.
