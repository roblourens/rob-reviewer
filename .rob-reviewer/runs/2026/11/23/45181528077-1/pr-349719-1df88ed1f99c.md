## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/editor/browser/viewParts/minimap/minimap.ts:2003` (`RIGHT`)  
**Blamed base line:** `src/vs/editor/browser/viewParts/minimap/minimap.ts:2030`  
**Introducing path:** `src/vs/editor/browser/viewParts/minimap/minimap.ts`  
**Introducing commit:** `edb01abaf1c7e5802b0e8b1e5dfff8ea2a2ce1e9`  
**Mechanism family:** `repeated-work`  
**Performance category:** `rendering`  
**Confidence:** 0.96

**Mechanism:** Repeated synchronous canvas text-style setup once per dirty minimap decorations frame, even when there are zero headers and row-signature comparison subsequently determines that no repaint is needed. Work scales with rendered dirty frames and visible editor instances, independent of header count in the empty case.

**Symptom:** Unnecessary main-thread canvas font/style work consumes the scrolling and typing rendering budget in files with no headers or header-free minimap ranges; the PR reports profiling that attributes most section-header rendering time to setStyle, while the call path independently establishes the repeated wasted work.

**Fixed behavior:** Queries the same viewport decorations first and returns when the filtered header array is empty, avoiding style-string/closure creation, canvas state save/restore and native text style/transform setup on header-free decorations frames. Nonempty-header measurement, sorting, recording and dirty-row replay remain unchanged.

**Evidence:** The diff adds an empty-decoration guard at head lines 2002–2005 before the previously unconditional canvasContext.save()/setStyle(canvasContext) (base 2029–2030). setStyle assigns letterSpacing, font, strokeStyle, lineWidth and a transform. Scroll, selection, decoration and theme handlers mark \_renderDecorations; renderDecorations calls \_renderSectionHeaders once per dirty decorations render, before RowSignatures.diff can skip an unchanged repaint. Thus even a warm, unchanged, header-free frame previously entered canvas text styling despite never recording a header drawing. View.\_scheduleRender coalesces pending events, so the removed cost is once per rendered dirty minimap, not per raw input event or file line. Blame resolves base line 2030 to edb01abaf1c7e5802b0e8b1e5dfff8ea2a2ce1e9. The PR's reported profiling is corroborating but not independently reproduced.
