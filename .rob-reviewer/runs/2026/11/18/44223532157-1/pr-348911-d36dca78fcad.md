- Effective concurrency: Panel setup is synchronous within each \#wireSingle invocation. Untitled lookup promises may overlap across opening panels; no per-panel network send is made at session creation.
- Cache behavior: ExtHostDocumentData.document.getText delegates to MirrorTextModel.getText, which caches the joined document string. \#wireSingle already calls getText before the newly added getText().length; there is no intervening await or mutation. The untitled service is already eagerly created at BlockStartup, and getUntitledDocumentId is an existing ResourceMap lookup; misses do not schedule retries.
- Mechanism confidence: High: traced the text cache, call ordering, command RPC, already-eager service ownership, and constant-time lookup.

### Scenario 6: Close or reload the window with custom Markdown editors still open, or dispose extension subscriptions.

- Critical path: The new deactivate hook synchronously ends all live sessions and awaits one reporter-disposal promise. The host starts deactivation for activated extensions in parallel and caps extension-host termination at five seconds. Subscription disposal is invoked immediately after starting a module's deactivate, rather than waiting for its promise; the reporter's memoized disposal and ended guards cover the overlapping cleanup calls.
- Scaling input: P live custom-editor sessions at shutdown, plus already-buffered bounded telemetry events.
- Effective concurrency: Session payloads are submitted in one synchronous loop over live panels, followed by one SDK disposal promise. The host uses Promise.all for extension deactivations, not a serial per-editor or per-extension network wait.
- Cache behavior: end marks sessions ended before submission and clears the Set. ExtensionReporter caches \#disposed so concurrent or later disposal does not re-flush. No history-sized synchronous traversal or document-content serialization occurs.
- Mechanism confidence: High in shutdown reachability, P-session cardinality, idempotence, overlapping subscription cleanup, and host-level concurrency/timeout. No high-confidence pathological network-delay mechanism can be inferred solely from calling dispose.
- Magnitude uncertainty: SDK flush latency, offline behavior, and batching could not be inspected because dependency implementation is unavailable. The changed scheduling is explicit and intentional; no independent repeated-flush or unbounded-serialization mechanism was found.
- Expensive boundaries:
  - network at <code>extensions/markdown-language-features/src/extension.shared.ts:flushOnDeactivate; extensions/markdown-language-features/src/preview/markdownEditorProvider.ts:endTelemetrySessions; extensions/markdown-language-features/src/telemetryReporter.ts:dispose</code>: Submit up to P session summaries, then ask the shared telemetry SDK to dispose/flush.; cardinality: One summary per previously unended live panel and one underlying reporter.dispose invocation. Subsequent provider or subscription cleanup reuses the same promise and emits no duplicate summaries. Exact flush transport requests are SDK-owned.
    - Introduced by diff: true; previous behavior: No custom-editor session summaries or exported asynchronous deactivation hook; reporter disposal was a subscription cleanup call, normally on the no-op reporter.; critical-path effect: The new deactivate promise participates in host shutdown, subject to the existing five-second host limit; regular editing and panel closure do not await this flush.
- Verdict: No reportable regression: awaiting delivery is an explicit lifecycle tradeoff, bounded by existing host termination policy, with correct event/disposal coalescing and no demonstrated amplified cleanup work.
