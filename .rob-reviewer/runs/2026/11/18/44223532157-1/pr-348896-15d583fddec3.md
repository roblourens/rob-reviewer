### 1. cleanup-lifecycle

**Fix location:** `extensions/git/src/model.ts:549` (`RIGHT`)  
**Blamed base line:** `extensions/git/src/model.ts:483`  
**Introducing path:** `extensions/git/src/model.ts`  
**Introducing commit:** `83c722d9a1ed9a2f05331d9e0671459c84bb3410`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `memory`  
**Confidence:** 0.96

**Mechanism:** A removed workspace folder's repository could survive for the remainder of the session after its last editor closed, retaining repository models, filesystem/.git watchers, and optional periodic fetch activity. Cost accumulated with distinct removed repositories.

**Symptom:** Statically evidenced session-long growth in retained repository state/watchers, plus continued status work on filesystem changes and optional network fetches for folders no longer used.

**Fixed behavior:** Repositories temporarily kept for visible editors are tracked and disposed when no visible editor belongs to them; re-added workspace repositories are exempted and disposal removes tracker entries.

**Evidence:** The base workspace-folder handler excludes repositories used by visible editors from disposal at line 483, but its visible-editor handler only detects/opens repositories and never revisits that exclusion. Consequently removing successive folders with an editor open leaves each Repository in Model.openRepositories after its editors disappear. Repository's constructor installs working-tree and .git watchers (repository.ts:932-967), onFileChange schedules status work (3333-3373), and enabled AutoFetcher instances continue periodic git fetch (autofetch.ts:102-136). The added tracker records these repositories (workspaceFolderRepositories.ts:55-56), and model.ts:549-550 disposes them after their last visible editor disappears; the existing disposal path releases repository disposables and removes the model entry. The added test at workspaceFolderRepositories.test.ts:122 exercises this lifecycle.
