## Findings (1)

### 1. [medium] Release inactive chat views while keeping Single-mode history

**Finding ID:** `PERF-0D521F0229F2`  
**Location:** <code>src/vs/workbench/contrib/sessions/browser/agentsView/agentsChatPart.ts:707</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Hidden ChatEditorView/ChatWidget trees, detached DOM, and strongly held IChatModelReference transcript models  
**Scaling:** For N distinct completed chats visited and not explicitly closed in one group, retains N full views/models, with transcript memory proportional to the sum of their sizes, instead of one current completed-chat view/model. Restored inactive entries are initially lightweight; full retention grows as entries are displayed.  
**Outcome:** Growing retained heap and GC pressure during ordinary conversation browsing  
**PR causality:** <code>introduced</code>  
**Previous behavior:** In Single mode, opening another completed chat closed the previous chat's editor, disposing its cached ChatEditorView and releasing its ChatView model reference. At most the current completed chat, plus deliberately preserved composers, remained.  
**Changed behavior:** Every previously visited completed chat now remains an open, pinned editor so that Close can return to it. This also keeps its entire rendered chat view and loaded transcript alive, not just its history entry.  
**Confidence:** 0.98 — The changed filter leaves previous completed chats in the group. ViewEditorPane.hideOrDisposeView explicitly caches every view whose input remains in that group, without eviction; ChatView.setVisible(false) only hides its widget and does not release its registered \_modelRef. The retention chain is explicit; its measured byte cost depends on transcript sizes.

**Causal diff evidence:** The former \_replaceOthers closed every other editor except non-pristine composers. The added condition \`\!\!this.\_chats.get(editor)?.isComposer\` in \_closeUntouchedComposers now excludes all completed-chat inputs from cleanup, and \_open opens every chat pinned.

With the default Single mode, browsing many distinct, long agent conversations accumulates full hidden widgets, transcript models, and detached DOM until those chats are explicitly closed or the window ends, causing growing memory and GC pressure despite displaying only one chat.

**Evidence:** AgentsChatPartService.\_open opens pinned editors and then calls the changed cleanup. src/vs/workbench/browser/parts/editor/viewEditorPane.ts:193-207 keeps a hidden view in hiddenViews whenever group.contains(input), and removes it only when its input closes. ChatEditorView owns ChatEditorContent/ChatGroupView and their ChatView. src/vs/workbench/contrib/sessions/browser/chat/chatView.ts:1160 stores the acquired transcript in \_modelRef; setVisible at 1561-1568 only changes visibility. The editor limit is disabled by default (workbench.contribution.ts:475-478).

**Suggested direction:** Preserve the history entries and saved view state, but dispose inactive Single-mode view/model instances or use a small bounded cache; recreate evicted views when Close returns to their history entry.
