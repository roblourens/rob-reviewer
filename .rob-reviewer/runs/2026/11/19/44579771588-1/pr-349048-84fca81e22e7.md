- Effective concurrency: Within one opening, native always-on-top inheritance precedes window creation and native registration is awaited afterward. Separate invocations remain independent; the diff adds no parallel opening or retry loop.
- Cache behavior: A new window is intentional, not cacheable reuse. Existing session/mode initialization retains its existing caches. Omitting options takes the previous opening path.
- Mechanism confidence: High: traced the changed action through openSession, group selection, auxiliary editor construction, and browser/native window services.

- Mechanism confidence: High: setInput calls setValue and refreshParsedInput; the changed action never calls a request-submission method.

- Expensive boundaries:

- Verdict: No reportable regression. This is one required prefill operation, not repeated or eager hidden submission work.

- Critical path: After window initialization, waitForChatMode performs an immediate in-memory lookup and returns without listeners/timer on a hit; setChatMode then updates the selected mode. This is requested initialization, not an additional service fetch.
- Scaling input: One requested mode name. Built-in lookup is bounded; custom-name lookup materializes, filters, sorts, and scans M existing modes. The selection occurs once per invocation.
- Effective concurrency: Immediate Promise resolution followed by one mode update. Existing background ChatModes refresh remains delayed/coalesced by its 100 ms Delayer.
- Cache behavior: ChatModes already loads workspace-cached custom modes during construction. A name hit uses that state immediately. The helper does not create another ChatModes instance or invalidate discovery caches.
- Mechanism confidence: High: traced ChatModes construction, cached-mode loading, findModeByName, the immediate helper return, and setChatMode with storeSelection=false.
- Magnitude uncertainty: Mode counts and selection-side UI update duration are not measured; a single user-command lookup does not establish a meaningful repeated-work regression.
- Expensive boundaries:

- Verdict: No reportable regression. The added lookup/selection is bounded requested work and does not multiply discovery boundaries.

### Scenario 4: Wait for a late custom agent, time out for an absent agent, or close the widget while waiting.

- Critical path: Only command completion and requested mode selection await the helper, for at most 5 seconds or until widget removal. The window and optional draft already exist and remain usable. Waiting for the requested late agent is intentional behavior.
- Scaling input: One pending waiter per explicit new-window invocation; O(E) lookups over M modes for mode-collection replacements/change events during the bounded wait. There is no polling or per-file listener in the helper.
- Effective concurrency: Each waiter owns one autorun, one replaceable modes listener, one widget-removal listener, and one timeout. settle disposes the store on success/removal/timeout. Discovery reads are queued on the existing service-wide limiter; the helper introduces no new read concurrency.
- Cache behavior: The helper observes existing mode state without refreshing it. A missing name subscribes rather than repeatedly fetching; no persistent negative-name cache or growing retained-name map is added. Underlying discovery retains its existing shared positive/empty cache and invalidation behavior.
- Mechanism confidence: High for bounded waiting, event cardinality, cleanup ownership, and unchanged discovery calls. Provider-internal implementation is outside the available call path.
- Magnitude uncertainty: Actual agent-load times, event counts, and external provider behavior are unmeasured. No in-repository caller passes the new options, so downstream extension sequencing cannot be established from this snapshot.
- Expensive boundaries:

    - Introduced by diff: false; previous behavior: The same discovery ran during widget initialization, but this command did not offer late-agent selection or await its result.; critical-path effect: Discovery completion can now determine when the requested mode is selected and the command resolves, but is not awaited before displaying the window or query. - Verdict: No reportable regression. The new bounded wait implements requested semantics without polling, retained resources beyond completion, or extra boundary calls; no independently avoidable latency mechanism is proven.
