## Findings (1)

### 1. [medium] Reuse the MCP scan before starting Claude

**Finding ID:** `PERF-12E6859D98AE`  
**Location:** <code>src/vs/platform/agentHost/node/claude/claudeAgentSession.ts:927</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** filesystem read operations and JSON parsing  
**Scaling:** Cost is four serial read attempts per materialization/rematerialization and grows with filesystem latency and the number of SDK restarts; three of those reads are discarded by the subsequent workspace/non-.mcp.json filter.  
**Outcome:** increased first-response and rematerialization latency from repeated blocking filesystem I/O  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this change, session creation scanned Claude MCP declarations for the customization snapshot, while \_buildExternalMcpServers proceeded from the cached SessionMcpDiscovery/client-plugin inputs without rescanning Claude settings files.  
**Changed behavior:** Claude startup now calls scanClaudeMcpServers inside \_buildExternalMcpServers before SDK startup, even though AgentService session creation has already requested getSessionCustomizations, which runs the same scan.  
**Confidence:** 0.99 — The duplicate call path, exact four-file serial loop, and placement before sdkService.startup are directly established in repository code. Only the absolute latency varies by filesystem.

**Causal diff evidence:** The added await at line 927 introduces a second scan in \_buildExternalMcpServers; no equivalent filesystem scan existed on this startup path before the PR.

On the first Claude message, and again on every SDK rematerialization, four serial file reads now block SDK startup and therefore delay the first response. The delay is especially visible when the workspace or home directory is on a remote or high-latency filesystem.

**Evidence:** AgentService.createSession awaits provider.getChatCustomizations before publishing the session; ClaudeAgentSession.getSessionCustomizations calls scanClaudeMcpServers. The added line calls it again from \_buildStartupToolWiring's critical path. scanClaudeMcpServers loops serially over workspace .claude/settings.json, .claude/settings.local.json, .mcp.json, and user ~/.claude/settings.json, and readJsonFile performs fileService.readFile even for missing files. \_buildStartupToolWiring is used for both initial materialization and rematerialization.

**Suggested direction:** Cache/coalesce the session's Claude MCP scan and reuse the snapshot produced for initial customizations, invalidating it from the existing customization watchers; at minimum, avoid rescanning the discarded .mcp.json and user settings files and read only the two project settings files together.
