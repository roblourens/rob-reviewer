## Performance regression fixes detected (1)

### 1. boundary-fanout

**Fix location:** `src/vs/platform/agentHost/node/agentHostSessionTitleController.ts:519` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/agentHostSessionTitleController.ts:524`  
**Introducing path:** `src/vs/platform/agentHost/node/agentHostSessionTitleController.ts`  
**Introducing commit:** `274239ff17a15514f74288e0f8fb21eaccce599b`  
**Mechanism family:** `boundary-fanout`  
**Performance category:** `latency`  
**Confidence:** 0.95

**Mechanism:** Every outgoing side-chat turn synchronously joined the title contribution's async persisted-metadata database lookup before the turn could be sent.

**Symptom:** Side-chat send startup incurred an avoidable serialized database open/metadata read on each turn.

**Fixed behavior:** Side-chat turns now return before the persisted-title metadata lookup and therefore do not block send startup on that database read or add the rename reminder to the turn.

**Evidence:** Before this change, SessionTitleContribution.onOutgoingTurn awaited prepareInstructionForAgent for every outgoing Agent Host turn, and the contribution dispatcher awaits each contribution serially before sending. For an independent side chat, prepareInstructionForAgent reached \_readPersistedTitleMetadata, which awaits sessionDataService.tryOpenDatabase and ref.object.getMetadata. The added SideChat-origin guard at line 519 returns before that storage access. blame\_base\_line attributes the old await to 274239ff17a15514f74288e0f8fb21eaccce599b.
