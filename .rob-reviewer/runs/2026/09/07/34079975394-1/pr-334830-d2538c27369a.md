## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `extensions/copilot/src/platform/inlineEdits/common/dataTypes/xtabPromptOptions.ts:577` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/src/platform/inlineEdits/common/dataTypes/xtabPromptOptions.ts:548`  
**Introducing path:** `extensions/copilot/src/platform/inlineEdits/common/dataTypes/xtabPromptOptions.ts`  
**Introducing commit:** `ee9c82e739d0b52261d9804317f83d14f71429aa`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.98

**Mechanism:** PatchBased02Unified eagerness requests were misclassified, redundantly applying a generic debounce or minimum-response delay on every invocation and holding the first visible edit.

**Symptom:** Inline edit suggestions could be artificially delayed to 700 ms at Medium aggressiveness or 1500 ms at Low aggressiveness before the first edit was shown.

**Fixed behavior:** The added strategy classification skips the redundant generic aggressiveness timing policy for PatchBased02Unified eagerness requests, allowing the HTTP request and first streamed edit to follow the strategy's baked latency settings rather than being held to the generic 700/1500 ms targets.

**Evidence:** Base line 548 introduced PatchBased02Unified. Its model configuration accepts eagernessPrompt and its prompt path emits an aggression tag, but before this change isEagernessPrompt omitted the strategy. Therefore xtabProvider.\_configureDebounceTimings invoked \_applyAggressivenessSettings for each non-speculative inline-edit request. Low and Medium set DelaySession.expectedTotalTime to configured defaults of 1500 ms and 700 ms, and stream processing explicitly waits out the remaining artificial delay before yielding the first edit.
