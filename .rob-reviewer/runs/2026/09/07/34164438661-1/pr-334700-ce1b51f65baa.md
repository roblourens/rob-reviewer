<summary>Reviewer scenario analysis</summary>

**Relevant issue families:** boundary-fanout, repeated-work, serialization-allocation

### Scenario 1: A user cancels an active Copilot agent turn while one or more root tool calls are still running, and their SDK tool.execution\_complete events arrive after cancellation.

- Critical path: The cancellation request waits on the existing wrapper.session.abort() call. Late tool-completion handling occurs afterward and is not required for cancellation or the next turn to progress; each completion performs existing cleanup/telemetry checks, then the changed helper emits one trace instead of one error and returns.
- Scaling input: Cost scales linearly with the number of tracked root tool completions that race with an abort; the diff does not increase that count or add work per completion. Existing SQL telemetry parsing additionally scales with query length, unchanged by the diff.
- Effective concurrency: The SDK may deliver completions for multiple in-flight tools, but each event invokes one synchronous JavaScript handler with no new Promise.all, queue, limiter, or concurrency burst. Effective work remains one handler and one drop log per late tracked root completion, as before.
- Cache behavior: No cache or negative cache participates. The boolean cancellation quarantine is checked independently for every completion before and after the diff; there is no cache key, miss behavior, or coalescing change.
- Mechanism confidence: High. The changed call site passes a constant flag only to the late root tool-completion case, while every other call keeps the default. The helper still constructs one identical message and invokes one logger method when quarantining; no new boundary, retained state, batching change, or eager work is added.
- Magnitude uncertainty: The typical number of simultaneously in-flight root tools and logging backend configuration vary, but this does not affect causality: the diff preserves one log call per late completion and generally lowers its enabled severity.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:3259 abort</code>: Invoke and await the provider SDK session abort.; cardinality: One call per user abort.
    - Introduced by diff: false; previous behavior: The same provider abort call was awaited before this diff.; critical-path effect: This existing call is the cancellation critical path; late completion logging runs only after independently arriving SDK events.
  - network at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:5219 reportCopilotTodoStoreOperation</code>: Submit telemetry for a successful eligible SQL tool completion after parsing its query.; cardinality: At most one telemetry submission per successful SQL tool completion; non-SQL tools return without submission.
    - Introduced by diff: false; previous behavior: The same telemetry check and submission occurred before the late-event gate.; critical-path effect: Runs synchronously in the completion callback before the cancellation-drop check, but late completion processing is off the user-visible cancellation critical path.
  - other expensive boundary at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:1249-1254 \_shouldDropLateRootTurnEvent</code>: Send the late-completion diagnostic to the log service.; cardinality: One diagnostic per dropped late tracked root tool completion; effective cardinality is the number of root tools still completing after the abort.
    - Introduced by diff: false; previous behavior: Previously the same event constructed the same message and made one error-level log call; the diff changes that one call to trace level only for tool completions.; critical-path effect: Synchronous in the late SDK event callback but not on cancellation progress; it does not block the next turn.
- Verdict: No reportable performance regression. The only production behavior change replaces an error-level log with a trace-level log at unchanged cardinality, while normal non-cancelled completions return before message allocation. The added test runs only in the test suite.

**Summary:** Completed the performance pass over the full two-file diff. Traced cancellation state, tool-completion event wiring, cleanup, telemetry, logging, and test-only work. The PR neither adds nor amplifies a performance mechanism; it lowers the severity of an existing one-per-late-completion diagnostic.
