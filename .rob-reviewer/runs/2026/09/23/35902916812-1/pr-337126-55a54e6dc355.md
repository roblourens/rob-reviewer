## Findings (1)

### 1. [medium] Batch row measurements before mutating tab classes

**Finding ID:** `PERF-9F51634FDADA`  
**Location:** <code>src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts:2089</code> (<code>RIGHT</code>)  
**Performance category:** <code>layout</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** Browser style recalculation and layout work for tab DOM nodes  
**Scaling:** The extra read-after-class-mutation occurs once per tab in the loop; when row classes change, cost grows linearly with the number of open tabs and can create one additional synchronous style/layout flush per affected tab.  
**Outcome:** Increased synchronous layout latency and potential dropped frames during tab-bar relayout  
**PR causality:** <code>introduced</code>  
**Previous behavior:** This loop performed one offsetTop-based upper-row classification per tab. Although it already interleaved reads and writes across tabs, it did not introduce another geometry read between the upper-row mutation and the next iteration.  
**Changed behavior:** Row classification now reads each tab's offsetTop a second time immediately after toggling connected-tab-upper-row on that same tab.  
**Confidence:** 0.96 — The changed read-after-write ordering, synchronous geometry API, geometry-sensitive selector use, direct UI layout call path, and repository's explicit batching invariant are all established. Exact milliseconds depend on tab count, browser invalidation behavior, and how often users cross row boundaries.

**Causal diff evidence:** The added RIGHT line 2089 evaluates tab.offsetTop after line 2088 has toggled connected-tab-upper-row. The same file's doLayoutTabsWrapping implementation explicitly first records every offsetTop and only then toggles last-in-row because class changes can trigger rendering-engine layouts.

Opening, closing, or resizing a connected editor group near wrapping boundaries can spend extra synchronous renderer time classifying rows, causing resize/tab-operation latency and dropped frames with many open tabs.

**Evidence:** connected-tab-upper-row participates in geometry-affecting CSS, including the new bottom-row border-block-width rule and different action inset/positioning in connectedEditorTabs.css. On initial layout or a wrap/unwrapped transition, line 2088 changes this class; line 2089 then synchronously requests offsetTop before mutations have been batched. The method's existing last-in-row code at lines 2257-2290 documents and implements the required two-pass pattern specifically to avoid layouts caused by class changes.

**Suggested direction:** Measure all tab offsetTop values in one pass (or reuse a stored offset per tab), compute both upper/top classifications, then apply both classes in a separate write pass, matching the existing last-in-row batching pattern.

### 1. synchronous-ui-work

**Fix location:** `src/vs/workbench/contrib/modernUI/browser/media/connectedEditorTabs.css:412` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/modernUI/browser/media/connectedEditorTabs.css:382`  
**Introducing path:** `src/vs/workbench/contrib/modernUI/browser/media/connectedEditorTabs.css`  
**Introducing commit:** `aa2804f8280072b4126ec7bd3688d76818dc0af9`  
**Mechanism family:** `synchronous-ui-work`  
**Performance category:** `layout`  
**Confidence:** 0.94

**Mechanism:** The base selector reserved the terminal shoulder margin only when the terminal tab was active. Changing selection therefore changed the tab row's total width, forcing synchronous geometry updates and potentially changing wrap classification.

**Symptom:** Selecting the last tab shifted tab positions and could trigger a second fit/wrap layout near width boundaries; the added tests explicitly assert positions and margins remain identical across every active-tab choice.

**Fixed behavior:** The new selector reserves shoulder margin on the final non-wrapping tab independently of selection, so activation changes paint rather than row geometry.

**Evidence:** The diff replaces `.tab.active:not(.connected-tab-upper-row):is(:last-child, .last-in-row)` with a non-active-dependent final-tab selector. The new `connected tab positions and spacing stay fixed when changing selection` test iterates active tabs across fit/fixed and wrapped/unwrapped layouts and verifies offset/width/margin stability. Base blame attributes the old selector to aa2804f8280072b4126ec7bd3688d76818dc0af9.
