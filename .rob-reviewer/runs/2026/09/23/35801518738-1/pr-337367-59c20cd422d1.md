### Scenario 1: Copy a chat code block from the toolbar or with the whole-block keyboard command

- Critical path: One clipboard write must complete before the newly delayed telemetry/reporting runs; the clipboard operation itself was already the user-visible copy boundary before the PR. Awaiting it extends the command promise but does not add work to clipboard completion.
- Scaling input: One user gesture and one code-block string; clipboard bytes scale with code length exactly as before, while added telemetry bytes scale with bounded identifier lengths.
- Effective concurrency: One clipboard operation per gesture. The PR serializes reporting after that operation rather than launching additional concurrent work.
- Cache behavior: No cache participates. Repeated gestures intentionally perform separate clipboard writes and telemetry events; there is no miss/retry amplification.
- Mechanism confidence: High confidence from the action handlers, clipboard implementations, MultiCommand dispatch, and synchronous telemetry/event paths.
- Magnitude uncertainty: Clipboard IPC duration varies by platform, but no new call or repeated work is introduced; only command-promise/report ordering changes.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/browser/actions/chatCodeblockActions.ts:167 and :289; NativeClipboardService.writeText</code>: Write the code-block text to the native clipboard; browser builds use navigator.clipboard instead.; cardinality: Exactly one clipboard write per explicit copy gesture, with no collection fan-out.
