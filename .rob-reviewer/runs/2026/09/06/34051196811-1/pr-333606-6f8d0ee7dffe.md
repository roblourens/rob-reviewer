## Performance regression fixes detected (1)

### 1. synchronous-ui-work

**Fix location:** `extensions/copilot/src/platform/inlineEdits/common/dataTypes/xtabPromptOptions.ts:577` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/src/platform/inlineEdits/common/dataTypes/xtabPromptOptions.ts:549`  
**Introducing path:** `extensions/copilot/src/platform/inlineEdits/common/dataTypes/xtabPromptOptions.ts`  
**Introducing commit:** `ee9c82e739d0b52261d9804317f83d14f71429aa`  
**Mechanism family:** `synchronous-ui-work`  
**Performance category:** `latency`  
**Confidence:** 0.97

**Mechanism:** The newly introduced unified strategy was not classified as an eagerness-aware prompt, so every qualifying inline-edit request redundantly installed an artificial post-response latency gate before yielding the first edit.

**Symptom:** Users selecting explicit Medium or Low eagerness with PatchBased02Unified could wait until 700 ms or 1500 ms total request time before the first edit was displayed even when the model response was ready sooner.

**Fixed behavior:** Adding PatchBased02Unified to isEagernessPrompt recognizes that the model already receives eagerness through its prompt and skips the redundant client timing override, removing up to 700 ms (Medium) or 1500 ms (Low) from first-edit presentation without changing prompt construction or network request cardinality.

**Evidence:** Commit ee9c82e739d0b52261d9804317f83d14f71429aa introduced PatchBased02Unified, but the base isEagernessPrompt whitelist omitted it. Model configuration preserves eagernessPrompt in overrideModelConfig, promptCrafting already emits the aggression tag for PatchBased02Unified, and \_configureDebounceTimings calls \_applyAggressivenessSettings whenever isEagernessPrompt is false. For explicit Medium/Low settings that path sets DelaySession.expectedTotalTime to the 700/1500 ms defaults, and stream parsing awaits the remaining artificial delay before yielding the first edit.
