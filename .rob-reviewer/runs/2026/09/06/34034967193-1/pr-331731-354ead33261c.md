# Performance review: Use synchronous hooks for ESM ASAR resolution

[PR #331731](https://github.com/microsoft/vscode/pull/331731) at `354ead33261c210f433c9bad24bbd1456ea55cbe`

## Findings

## Performance regression fixes detected (1)

### 1. boundary-fanout

**Fix location:** `src/bootstrap-esm.ts:97` (`RIGHT`)  
**Blamed base line:** `src/bootstrap-esm.ts:190`  
**Introducing path:** `src/bootstrap-esm.ts`  
**Introducing commit:** `913d5cccc1a0e97311521e7791033ce9d5c2ef2f`  
**Mechanism family:** `boundary-fanout`  
**Performance category:** `startup`  
**Confidence:** 0.96

**Mechanism:** The asynchronous ESM resolver ran on Node's loader worker, forcing the importing thread to issue and synchronously wait for a cross-thread hook request for each module-resolution edge during cold process startup.

**Symptom:** Packaged Electron process startup accumulated loader-worker wait latency across the ESM graph; the supplied profile attributes 149 ms to makeSyncRequest in Agent Host, and the interleaved packaged A/B reports lower end-to-end desktop and child-process startup times after removing the boundary.

**Fixed behavior:** Registers the ASAR resolver in-process with synchronous module hooks, eliminating the loader-worker request/response boundary while keeping package resolution on the same module-linking critical path and preserving resolution cardinality.

**Evidence:** In the base revision, bootstrap-esm.ts imported module.register and registered a data-URL loader whose resolve hook was async and awaited nextResolve. Every Electron entrypoint imports this bootstrap before dynamically importing its main ESM graph (src/main.ts startup, src/bootstrap-fork.ts, src/cli.ts, and server entrypoints), so Node had to synchronously rendezvous with the dedicated loader worker during static linking for each resolution. The PR replaces that registration at RIGHT line 97 with module.registerHooks and a synchronous resolve callback while preserving the same default and ASAR resolution operations. The PR's profiled packaged A/B reports makeSyncRequest time on the old path and lower desktop, Agent Host, shared-process, and extension-registration startup latency with the changed hook.
