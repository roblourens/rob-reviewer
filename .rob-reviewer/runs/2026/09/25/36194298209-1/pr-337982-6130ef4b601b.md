### Scenario 1: Change a mutable picker on an already-running Agent Host session

- Critical path: The picker update normalizes one value, updates the local running-config cache, and synchronously queues one action dispatch; resolveSessionConfig is launched without awaiting it and is off the interaction critical path.
- Scaling input: The helper receives one property from the existing picker path, so filtering/allocation remains O(1) per user mutation; config-cache cloning scales with the bounded session configuration just as before.
- Effective concurrency: Resolution requests can overlap, with last-response application guarded per session by \_runningSessionConfigResolveSeq; the diff does not increase request cardinality or concurrency on this existing path.
- Cache behavior: Requires the existing \_runningSessionConfigs and \_sessionCache entries; there is no new cache key, miss retry, or retention behavior.
- Mechanism confidence: High: the pre- and post-diff helper bodies and resolve call path establish identical one-dispatch/one-resolution behavior for this scenario.
- Magnitude uncertainty: Exact IPC and provider resolution duration varies by Agent Host provider, but this path has unchanged boundary cardinality.
- Expensive boundaries:
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:\_dispatchRunningSessionConfig</code>: Dispatch SessionConfigChanged to the Agent Host.; cardinality: One dispatch per picker mutation after filtering the one supplied property against the session schema.
    - Introduced by diff: false; previous behavior: The prior single-property implementation dispatched the same one action per accepted mutable picker mutation.; critical-path effect: The dispatch call is synchronous queueing on the interaction path, but does not await host processing.
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:\_resolveRunningSessionConfig</code>: Request authoritative configuration resolution from the Agent Host/provider.; cardinality: One asynchronous request per accepted picker mutation; stale responses are suppressed by a per-session sequence number.
    - Introduced by diff: false; previous behavior: The prior single-property implementation launched the same asynchronous resolution after each dispatch.; critical-path effect: Fire-and-forget and therefore off the picker interaction critical path.
- Verdict: No reportable regression; the refactor adds constant-size entry filtering for a one-key input while preserving expensive boundary counts.

### Scenario 2: Change a mutable session setting while the first request is waiting for the new session to commit

- Critical path: The first chat send and session-commit wait are pre-existing critical-path work. Once the committed session is available, the diff compares the draft snapshot with the originally sent snapshot, queues one filtered SessionConfigChanged action, and starts an unawaited configuration re-resolution before returning the committed session.
- Scaling input: Snapshot comparison is O(P) in the number of resolved session configuration properties; expensive boundary cardinality remains one grouped dispatch plus one resolution regardless of how many properties changed.
- Effective concurrency: One replay can be in flight per newly committed session. Separate simultaneously created sessions can resolve concurrently, but this user workflow normally has low concurrency and introduces no per-property burst.
- Cache behavior: The committed running-config cache is seeded from the draft immediately before replay, enabling schema filtering without a cold read. There is no added persistent cache or negative-cache behavior.
- Mechanism confidence: High: the changed line groups all changed values, the helper emits one action, and \_resolveRunningSessionConfig is explicitly invoked without awaiting.
- Magnitude uncertainty: Provider resolution cost is implementation-dependent and concurrent multi-session creation is uncommon, but the one-request mechanism and off-critical-path placement are established.
- Expensive boundaries:
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:\_sendNewSessionRequest</code>: Existing first chat request and wait for the Agent Host to announce the committed session.; cardinality: One first-request send and one commit wait per new session.
    - Introduced by diff: false; previous behavior: The same first-request send and commit wait occurred before the diff.; critical-path effect: These must complete before the draft can graduate to a running session.
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:6112 via \_dispatchRunningSessionConfig</code>: Send the mutable settings that changed after the first request snapshot to the newly committed Agent Host session.; cardinality: At most one grouped dispatch per committed new session, only when at least one changed property is sessionMutable; all changed mutable properties share the action.
    - Introduced by diff: true; previous behavior: No post-commit settings action was sent, so picker edits made during commit were not replayed.; critical-path effect: Synchronous queueing occurs after commit, while host application is asynchronous; there is no per-property fan-out.
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:\_resolveRunningSessionConfig</code>: Re-resolve the grouped changed configuration against the provider/Agent Host.; cardinality: One fire-and-forget request after the grouped dispatch, not one request per property.
    - Introduced by diff: true; previous behavior: No post-commit re-resolution occurred because there was no replay dispatch.; critical-path effect: The promise is not awaited, so provider resolution is off the session-return critical path.
- Verdict: No reportable performance regression. The added remote work is a single bounded, grouped replay needed for the new behavior, with authoritative resolution off the critical path rather than fan-out by property.

- Verdict: No reportable performance regression; the change substitutes current draft selections for captured selections without adding expensive work or boundary calls.
