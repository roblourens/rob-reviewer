# Performance review: sessions: Fix Stop and Mark as Done while a new session is being created

[PR #337985](https://github.com/microsoft/vscode/pull/337985) at `7b2eacf400c23cff5f9c8b7108dad4d9cf5a1f89`

## Findings (1)

### 1. [medium] Move worktree archival off the send commit path

**Finding ID:** `PERF-3559067926FD`  
**Location:** <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:6113</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** Extension/agent-host IPC, detached-worktree database writes, filesystem operations, and Git subprocess work (\`status\`/commit/worktree removal)  
**Scaling:** One archival cleanup is added per new session marked done before commit; its latency grows with remote IPC latency, dirty-file count and commit cost, and worktree/repository size during removal. Different sessions can also perform this cleanup concurrently because sequencing is only per session.  
**Outcome:** Blocked foreground send completion and delayed draft-to-committed-session replacement  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before the diff, archiving the unannounced draft was a no-op, so once \`\_waitForNewSession\` found the backend session, the send path graduated and replaced the draft without awaiting worktree cleanup.  
**Changed behavior:** A draft archived while its first request is still materializing now causes the newly discovered backend session to be archived synchronously inside \`\_sendNewSessionRequest\`, delaying session graduation, replacement notification, and the provider's send promise until detached-worktree cleanup completes.  
**Confidence:** 0.98 — The await is directly added to the foreground commit path; callers await \`provider.sendRequest\` before firing \`onDidStartSession\`/\`onDidSendRequest\`. The remote call path is explicit and performs extension IPC plus filesystem/database and Git subprocess work. The exact duration varies with repository/worktree size and dirtiness, but critical-path placement and the scaling mechanism are certain.

**Causal diff evidence:** The added RIGHT-side line 6113 awaits \`this.archiveSession(committedSession.sessionId)\` before \`newSession.graduate()\`, \`\_onDidReplaceSession.fire(...)\`, and returning from \`\_sendNewSessionRequest\`. For \`RemoteAgentHostSessionsProvider\`, that call awaits \`\_setDetachedWorktreeArchived\`, which crosses an extension/agent-host request and reaches \`setDetachedWorktreeArchived\`; the implementation writes DB metadata, checks/commits worktree changes, and runs Git worktree removal before resolving.

When a user marks a newly created remote Dev Container session done before the host announces it, the session can remain in the in-flight send lifecycle and keep showing the draft instead of the committed session for the full worktree cleanup duration. Dirty or large repositories can add seconds or more of latency even though the draft was already moved to Done immediately.

**Evidence:** \`\_sendNewSessionRequest\` awaits the added archive call before firing \`\_onDidReplaceSession\` and returning. \`RemoteAgentHostSessionsProvider.archiveSession\` queues and awaits \`\_setArchivedWithDetachedWorktree\`, which awaits \`\_setDetachedWorktreeArchived\`; that invokes \`connection.setDetachedWorktreeArchived\`. The worktree implementation persists archive metadata and \`cleanupWorktreeOnArchive\` may run \`hasUncommittedChanges\`, \`commitAll\`, and \`removeWorktree\`. \`SessionsManagementService\` in turn awaits \`provider.sendRequest\` before completing the request activity and publishing send-complete events.

**Suggested direction:** Keep the immediate draft archive state, but do not await detached-worktree cleanup before graduating/replacing the session. Apply the committed session's archived state optimistically, fire the replacement and complete the send, then run the existing per-session sequenced archival in the background with the current logging/rollback behavior so archive/unarchive ordering remains intact.

- Scaling input: One provisional session/turn and its resolved working-directory set; metadata work scales with root/chat count, while the introduced Git refresh is one per changed primary root.
- Effective concurrency: One first-send pipeline runs per affected turn. Git-state refresh is throttled by session key, so overlapping refreshes coalesce/serialize per session rather than fan out unboundedly.
- Cache behavior: No cache controls the cancellation path. Working-directory resolution/worktree creation is the existing first-send operation; \`markSessionPersisted\` is idempotent after the first announcement, and Git refreshes are throttled per session. A repeated cancellation after announcement performs metadata comparison but does not replace the root or launch the new Git refresh unless the resolved primary root changes.

- Magnitude uncertainty: Worktree creation duration is environment-dependent, but it is pre-existing. The newly added background Git refresh has variable cost and a narrow cancellation trigger; it does not block announcement, so it does not independently justify a finding.

### Scenario 2: Mark a newly sent session Done before the host announces it, then commit it across local, remote Dev Container, and cloud-sandbox providers; optionally unarchive during remote cleanup.

- Critical path: The draft moves to Done immediately. Once \`\_waitForNewSession\` discovers the real session, the added awaited \`archiveSession\` is now on the foreground \`provider.sendRequest\` critical path and precedes session graduation, replacement notification, \`onDidStartSession\`, and \`onDidSendRequest\`. For remote Dev Container sessions this await includes worktree cleanup.
- Scaling input: One operation per draft marked done before commit; cost scales with remote round-trip time, dirty-file/commit work, worktree size, and concurrently archived sessions across distinct keys.
- Effective concurrency: Archive/unarchive calls are serialized by session ID through \`SequencerByKey\`, preserving order for one session. Different sessions are not globally limited and can perform worktree operations concurrently, though the realistic trigger is one explicit user action per newly created session.
- Cache behavior: The draft archive state is stored in the existing \`NewSession\` object until discovery. On commit, local and cloud providers update existing cached session adapters; remote Dev Container worktree archival does not use a result cache because it mutates authoritative archive/checkout state. Failed operations are not negatively cached and explicit later actions retry.
- Mechanism confidence: Very high: the added await, the send lifecycle callers, remote IPC, database mutation, Git calls, and per-key sequencing were traced end to end.
- Magnitude uncertainty: Exact latency depends on remote IPC, repository size, dirty files, and Git/filesystem performance. The operation may be fast for clean small worktrees, but the placement on the foreground send path and potentially expensive Git cleanup are certain.
- Expensive boundaries:
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts \`\_sendNewSessionRequest\` -&gt; \`\_setSessionArchived\`</code>: Dispatch \`SessionIsArchivedChanged\` to the Agent Host.; cardinality: One archive action dispatch for a local Agent Host session after commit.
    - Introduced by diff: true; previous behavior: Archiving an unannounced draft did not dispatch an action and session replacement proceeded without this work.; critical-path effect: Awaited by the added commit block, although dispatch itself is synchronous and small for local sessions.
  - IPC at <code>src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostSessionsProvider.ts \`\_setDetachedWorktreeArchived\`</code>: Request archive handling for the detached Dev Container worktree.; cardinality: One extension/agent-host request for a committed remote session with detached-worktree metadata; no call for sessions without that metadata.
    - Introduced by diff: true; previous behavior: This boundary was used for normal archives, but was not on the pending-new-session commit path.; critical-path effect: Awaited before the send resolves and before draft replacement.
  - subprocess at <code>src/vs/platform/agentHost/node/shared/worktreeIsolation.ts \`setDetachedWorktreeArchived\` / \`cleanupWorktreeOnArchive\`</code>: Persist archive metadata, inspect/commit dirty changes, and remove the Git worktree.; cardinality: One metadata update and one cleanup sequence per affected archived draft. Cleanup can issue existence/branch/dirty-state checks, an optional commit, and worktree removal.
    - Introduced by diff: true; previous behavior: No worktree archival was performed while committing a draft whose early archive action had previously been ignored.; critical-path effect: Transitively awaited by the new commit-path archive call.
- Verdict: Reportable medium-severity latency regression for remote Dev Container sessions: expensive cleanup is newly awaited before foreground send completion and draft replacement. Per-session sequencing correctly bounds archive/unarchive ordering and does not leak keys; cloud-sandbox handling is local-only and does not share this expensive boundary.
