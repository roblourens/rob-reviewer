**Relevant issue families:** repeated-work, synchronous-ui-work, serialization-allocation

### Scenario 1: Open the Agent Customizations modal for an active Cloud/virtual session workspace

- Critical path: The delayed workspace service derives activeProjectLabel from activeSession -&gt; activeChat -&gt; workspace, selects workspace.label for a virtual workspace, and the open-editor action copies that string into the singleton editor input before editorService.openEditor. The label read is synchronous and on the modal-open critical path; all existing editor creation and rendering work is unchanged.
- Scaling input: Exactly one active session, one active chat, and one workspace are read. The changed branch accesses scalar fields and does not enumerate workspace folders or customizations, so work remains O(1) regardless of repository size or folder count.
- Effective concurrency: One synchronous derived-observable evaluation per initial demand or invalidation; editor input updates are equality-deduplicated by setTargetLabels. No queue, parallel fan-out, or asynchronous work is introduced.
- Cache behavior: The derived observable retains its normal cached value/dependency behavior. The diff changes only the selected scalar value for virtual workspaces and neither adds a cache nor changes cold/warm execution behavior.
- Mechanism confidence: High confidence from tracing the changed derivation through the modal open action and editor input: no filesystem, IPC, subprocess, database, network, serialization payload, collection copy, or layout read/write is introduced.
- Magnitude uncertainty: No meaningful magnitude uncertainty: the added isVirtualWorkspace check and alternate string property read are constant-time in-memory operations.
- Expensive boundaries: none found
- Verdict: No reportable performance regression. Before the diff, modal opening read folders\[0\].name; after it, virtual workspaces read workspace.label while non-virtual workspaces retain the prior read. Frequency, cardinality, allocation shape, and downstream rendering behavior are unchanged.

### Scenario 2: Change the active session/workspace while the customization editor exists

- Critical path: The activeProjectLabel derived observable is invalidated by the existing active-session/chat/workspace dependencies; the editor's existing autorun calls updateTargetLabelPresentation, which updates the input label only when the string differs. The diff adds no new subscription, autorun, or rendering stage.
- Scaling input: One active workspace transition triggers one constant-time branch and scalar read; effective cardinality is one workspace, not the number of folders, sessions, or customization items.
- Effective concurrency: Synchronous observable propagation on the UI path, with no introduced asynchronous tasks or concurrent operations. Existing string equality in setTargetLabels coalesces unchanged labels.
- Cache behavior: Existing observable invalidation and equality behavior remains intact. There are no positive/negative cache states or remote cache misses on this path.
- Mechanism confidence: High confidence from the service derivation, editor autorun, updateTargetLabelPresentation, and setTargetLabels implementation.
- Magnitude uncertainty: Session-switch frequency varies by user, but each changed evaluation is bounded O(1) and introduces no expensive resource use.
- Expensive boundaries: none found
- Verdict: No reportable performance regression. The PR changes only which already-resident string is returned for virtual workspaces; it does not increase update frequency, force layout, serialize the label, or retain additional workspace state.

**Summary:** Completed the performance pass over the full two-file diff and traced both modal-open and reactive workspace-change paths. The single production change adds a constant-time boolean branch and scalar string read, preserving observable caching, update cardinality, and all expensive-boundary behavior. No actionable performance finding or qualifying regression-fix learning signal was found.
