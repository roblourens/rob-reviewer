## Findings (2)

### 1. [medium] Bound deferred workspace cleanup to each server generation

**Finding ID:** `PERF-E9643E67996A`  
**Location:** <code>src/vs/platform/agentHost/test/node/e2e/suites/agentHostE2ESuites.ts:148</code> (<code>LEFT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** Temporary workspace directories, Git repositories/worktrees, and their filesystem bytes  
**Scaling:** Peak retained disk and final cleanup work now grow with every tempDirs.push across the entire suite; the suite has dozens of allocation sites and hundreds of executions, whereas the existing shared host is already recycled every 40 tests.  
**Outcome:** Increased peak disk usage and a large serial filesystem-deletion tail at suite teardown, with risk of CI disk pressure or teardown timeouts on slower Windows filesystems.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** After each test released its sessions, teardown called removeTempDirs(tempDirs), which spliced and synchronously deleted all workspaces created by that test before the next test ran.  
**Changed behavior:** The diff removes per-test removal and leaves tempDirs populated until suiteTeardown, even though the provider process is stopped and restarted periodically by the lease.  
**Confidence:** 0.98 — The ownership path is explicit: all suite fixtures append to one tempDirs array, the diff removes its after-each drain, and the remaining drain is only suiteTeardown. Exact byte magnitude depends on provider and platform, but suite-lifetime retention and serial final deletion are deterministic.

**Causal diff evidence:** The deleted LEFT-side line \`await removeTempDirs(tempDirs);\` at old line 148 removes the per-test cleanup boundary; the added comment explicitly defers these resources until suite teardown.

A normal full Agent Host E2E run now retains every test repository/worktree until the provider suite ends. As the expanded suite runs, CI workers accumulate all workspace bytes and then must delete the complete backlog on the suite's 120-second teardown critical path.

**Evidence:** The deleted call was the only per-test consumer of tempDirs; suiteTeardown still calls removeTempDirs only after lease.dispose. removeTempDirs performs recursive rmSync for each queued path. The harness caps a shared server generation at MAX\_TESTS\_PER\_SHARED\_SERVER = 40 and \_recycleSharedServer stops that process, but it has no hook to drain tempDirs, so retention continues across safe cleanup boundaries. Repository search shows numerous tempDirs.push sites, including Git workspaces and .worktrees directories, and this PR adds more in the new suites.

**Suggested direction:** Keep the Windows handle-safety intent, but drain pending test directories whenever the lease actually stops/recycles the provider (and at final teardown), or attempt immediate deletion and defer only locked paths. This bounds retention to at most one shared-server generation instead of the full suite.

### 2. [low] Avoid rebuilding the full debug artifact while polling readiness

**Finding ID:** `PERF-6AD58487BC58`  
**Location:** <code>src/vs/platform/agentHost/test/node/e2e/suites/managementExtensionsSuite.ts:79</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Filesystem scans/copies, ZIP compression CPU, and retained debug-artifact bytes  
**Scaling:** Cost is O(current log bytes × readiness attempts): retry can invoke collection 100 times at 50 ms intervals, and the shared server's logs grow over earlier tests.  
**Outcome:** Extra E2E latency, CPU/I/O pressure, and temporary disk growth on CI when process-log creation lags initialization.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Each affected test invoked collectDebugLogs once, producing one copied directory or ZIP artifact.  
**Changed behavior:** collectPopulatedDebugLogs now retries the full collectDebugLogs operation until the manifest contains the asynchronously created process log.  
**Confidence:** 0.96 — The retry multiplicity and collector call path are explicit. The exact number of duplicate artifacts varies with logger startup timing and log size, which lowers severity but not confidence in the mechanism.

**Causal diff evidence:** The added RIGHT-side line \`const artifact = await collectDebugLogs(kind);\` is inside \`retry(..., 50, 100)\`, moving full artifact creation into the readiness-poll loop.

When the asynchronous logger is late, the archive test repeatedly recopies and recompresses all host/provider logs, while the directory test repeatedly copies them. Failed-poll artifacts remain leased for ten minutes, so a slow CI worker can retain many duplicate log sets before the test proceeds.

**Evidence:** collectDebugLogs crosses AHP into AgentHostDebugLogsCollector.collect. Every call creates a staging directory, asks each provider to copy diagnostics, copies Agent Host logs, stats every file, and for \`archive\` calls zip(). Successful artifacts are scheduled for cleanup only after the 10-minute lease. The new retry repeats that complete path up to 100 times solely to observe one file's arrival.

**Suggested direction:** Poll a cheap readiness signal for the process log first, then call collectDebugLogs once. If no direct signal is available, use a slower/backed-off probe and explicitly remove each rejected artifact before retrying, reserving ZIP creation for the final successful collection.
