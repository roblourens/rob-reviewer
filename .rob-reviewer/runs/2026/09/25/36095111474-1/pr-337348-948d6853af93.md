# Performance review: Make deferred title generation the default

[PR #337348](https://github.com/microsoft/vscode/pull/337348) at `948d6853af93a1ee39130cee42411252bd5e5bbe`

## Findings (1)

### 1. [medium] Keep the symbol rename tool on the non-deferred path

**Finding ID:** `PERF-E17816823C72`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/toolSearchDeferral.ts:17</code> (<code>LEFT</code>)  
**Performance category:** <code>network</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** one additional model-provider request plus a client tool-search IPC/tool invocation before the rename tool can run  
**Scaling:** Adds one serialized discovery round trip to each cold symbol-rename turn on supported models with the default-enabled tool-search setting; cost grows with the number of such rename turns.  
**Outcome:** increased end-to-end latency before a requested symbol rename begins  
**PR causality:** <code>introduced</code>  
**Previous behavior:** With \`rename\` in the allowlist, its schema was present in the initial model request and the model could invoke the rename tool directly without first discovering it.  
**Changed behavior:** With tool search enabled by default (threshold 1), \`rename\` is now deferred. To use it, the model invokes \`tool\_search\_tool\`; Agent Host sends candidates across the client action boundary, the renderer invokes VS Code's \`toolSearch\`, and only the returned tool reference loads \`rename\` for a subsequent provider continuation.  
**Confidence:** 0.96 — The changed defer policy, default activation, client boundary, and separate provider continuation are all explicit in code and the repository's E2E capture. Exact milliseconds vary by provider and local search duration, but the additional serialized round trip is unconditional when a cold deferred rename is needed.

**Causal diff evidence:** The diff deletes \`'rename'\` from \`NON\_DEFERRED\_CLIENT\_TOOL\_NAMES\` at the deleted line, changing \`\_createClientSdkTools\` from \`defer: 'never'\` to \`defer: 'auto'\` for this tool whenever tool search is active.

On a normal request such as renaming a symbol, supported Copilot models now wait for a search tool IPC/invocation and an extra provider continuation before they can start the actual rename. This is directly visible as added latency on an interactive refactoring path.

**Evidence:** \`copilotAgentSession.ts:2356-2358\` maps allowlisted tools to \`defer: 'never'\` and all others to \`defer: 'auto'\`. Its tool-search handler waits for \`\_pendingClientToolCalls.registerAndFire\`, while \`agentHostSessionHandler.ts:2974-2991\` invokes the renderer-side search tool. The checked-in tool-search E2E capture shows discovery and the deferred tool execution as separate model-provider requests. \`chat.shared.contribution.ts:1729-1739\` makes this path the default (\`toolSearch.enabled: true\`, threshold 1).

**Suggested direction:** Restore \`rename\` to \`NON\_DEFERRED\_CLIENT\_TOOL\_NAMES\`; this preserves direct invocation for the core refactoring operation while leaving less frequently used tools deferred.

### Scenario 2: A user asks a supported Copilot Agent Host model to rename a code symbol while default tool search is active.

- Critical path: The requested refactoring cannot begin until the model discovers the deferred \`rename\` tool. Tool search, its provider continuation, actual rename execution, and the final continuation are serialized on the interactive turn.
- Scaling input: Number of interactive symbol-rename turns on tool-search-capable models; effective cardinality is one added discovery and provider continuation per cold turn.
- Effective concurrency: Sequential within one turn: discovery must complete before the model receives the tool reference and can invoke rename. Separate turns/sessions may run independently.
- Cache behavior: The returned tool reference loads rename for the current continuation. No application-level cross-turn cache or coalescing is present on this path.
- Mechanism confidence: Very high: the deleted allowlist entry changes \`defer\` from \`never\` to \`auto\`, the setting is default-on, and the checked-in E2E capture demonstrates separate search and deferred-tool provider exchanges.
- Magnitude uncertainty: Provider latency and whether a model chooses rename vary, but every turn that actually needs this newly deferred tool incurs the serialized discovery path.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/copilot/toolSearchDeferral.ts:17 and Copilot SDK deferred-tool flow</code>: Model-provider continuation after \`tool\_search\_tool\` returns the reference that loads \`rename\`.; cardinality: One additional provider request for each cold turn that needs the deferred rename tool.
    - Introduced by diff: true; previous behavior: \`rename\` was non-deferred and available in the initial model request, so the model could invoke it without a discovery continuation.; critical-path effect: Directly delays actual symbol rename execution.
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:2338-2477; src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:2974-3008</code>: Forward tool-search candidates from Agent Host to the renderer, invoke VS Code's \`toolSearch\`, and return matching tool names.; cardinality: One extra search invocation before the actual rename tool call on each cold rename turn.

- Verdict: Reported: the diff adds an avoidable serialized network and IPC round trip to a core interactive refactoring workflow.
