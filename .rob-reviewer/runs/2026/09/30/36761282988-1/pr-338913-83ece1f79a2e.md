### Scenario 1: Open or refresh the tabbed model picker in Copilot Auto mode when HydraFusion is available

- Critical path: The UI thread rebuilds destinations and Auto-mode items, renders virtualized ActionList rows, constructs one Link for the HydraFusion detail in each instantiated active/sizing list, then performs the ActionList's existing width measurement and layout before the picker is usable.
- Scaling input: Total model rows controls the existing list build and width-measurement work; the diff's added link work has effective cardinality one HydraFusion row per instantiated Auto-mode list, independent of the number of ordinary models.
- Effective concurrency: All item construction, DOM rendering, list splicing, width measurement, and layout are serialized on the UI thread; no new queue, burst, or asynchronous work is introduced.
- Cache behavior: There is no cache for rendered rows; refreshes recreate visible row state. Virtualized row reuse clears element disposables first, and the new detail-link registration is removed with that disposal. Cold and warm opens therefore each do bounded constant extra work for HydraFusion.
- Mechanism confidence: High: the changed item builder, renderer, disposal store, registration map, list refresh, and width measurement paths were traced directly.
- Magnitude uncertainty: Exact list instantiation and browser layout duration depends on picker state and platform, but the changed work remains a single anchor/listener registration per HydraFusion row and replaces the prior expandable-hover metadata; it does not scale with the full model collection.
- Expensive boundaries: none found
- Verdict: No reportable regression. The diff adds bounded DOM allocation and CSS layout for one row, removes the expandable hover construction path, and correctly disposes the Link and map entry when the virtualized row is rerendered or removed.

### Scenario 2: Activate HydraFusion's Learn more link by pointer or keyboard

- Critical path: A user activation dispatches through Link to the picker linkHandler, then calls openerService.open for the external documentation URI; opening the URI is the only expensive boundary and is required before the scenario completes.
- Scaling input: One opener call per explicit user activation; there is no per-model or per-event fan-out after grouping.
- Effective concurrency: Each activation is handled independently on the UI event loop. The code does not add background concurrency, retries, batching, or speculative opens.
- Cache behavior: No cache participates. Cold and warm activations have the same one-call behavior, with no retained response or negative-cache state.
- Mechanism confidence: High: Link activation, the supplied linkHandler, and its openerService call were traced end to end.
- Magnitude uncertainty: External browser launch latency varies by platform, but the diff neither adds the boundary nor increases calls per activation.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts:onLinkClick</code>: Open the external HydraFusion documentation URI through openerService, potentially delegating to the OS/default browser.; cardinality: Exactly one call for each pointer, Enter, Space, or touch activation accepted by the Link control.
    - Introduced by diff: false; previous behavior: The expandable HydraFusion hover contained a Learn more link that ultimately invoked openerService for the same URI; the diff changes discoverability and placement, not boundary cardinality.; critical-path effect: The boundary is the requested outcome of the click; it runs only after explicit activation and does not block picker rendering.
- Verdict: No reportable regression. The same user-triggered opener boundary remains one-for-one; it is not moved onto render, focus, hover, startup, or another hotter path.

### Scenario 3: Generate Chat accessibility help containing the updated HydraFusion keyboard instruction

- Mechanism confidence: High: the complete changed hunk is a one-for-one string replacement.
- Magnitude uncertainty: None material; only static localized text content changed.
- Expensive boundaries: none found
- Verdict: No reportable performance regression.
