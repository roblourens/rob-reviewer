### Scenario 1: Expand a single-child directory chain in Explorer with compact folders enabled

- Critical path: Expansion awaits ExplorerDataSource.getChildren; on a cold unresolved directory this awaits ExplorerItem.fetchChildren and fileService.resolve, then AsyncDataTree recursively materializes the already-resolved single-child descendants so the compressed row can reveal its children.
- Scaling input: Depth of the compressible single-child directory chain; one boundary request serves the chain, while in-memory node creation/rendering scales linearly with chain depth.
- Effective concurrency: The first unresolved directory performs one awaited resolve with resolveSingleChildDescendants; descendant traversal is recursive along the one-child chain, while any independently refreshable branches use Promises.settled. There is no new aggregate burst from the diff.
- Cache behavior: Cold unresolved directories use one resolve that includes single-child descendants; \_isDirectoryResolved makes subsequent descendant reads synchronous. Failures are not newly cached or retried by this diff.
- Mechanism confidence: High: the changed predicate returns true for exactly the compressible-directory case, and the data source's resolveSingleChildDescendants option establishes batching.
- Magnitude uncertainty: Filesystem provider latency and practical chain depth vary, but boundary cardinality and recursion are unchanged from the prior compact-folder behavior.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/files/common/explorerModel.ts:327 ExplorerItem.fetchChildren</code>: fileService.resolve(resource, { resolveSingleChildDescendants: true, resolveMetadata }); cardinality: One cold resolve for the expanded directory; the service request includes the effective single-child descendant chain, and warm resolved nodes return cached children without another resolve.
    - Introduced by diff: false; previous behavior: With autoExpandSingleChildren enabled, the same compact directory chain was recursively expanded after the same cold resolve.; critical-path effect: The cold resolve must complete before the compact chain is materialized and rendered.
- Verdict: No regression: the new option preserves the prior work required for compressed folder rows and adds only constant-time compression/delegate checks per single-child node.

### Scenario 2: Expand or refresh a single-child folder with compact folders disabled

- Critical path: The selected folder's children are loaded, then the new predicate observes compression is disabled and stops automatic descendant materialization; rendering proceeds without recursively expanding the child.
- Scaling input: Depth of a single-child folder chain; the diff removes linear descendant node refresh/render work when compression is disabled.
- Effective concurrency: At most the selected folder's cold resolve is awaited. No descendant refresh promises are added by auto-expansion after the diff.
- Cache behavior: Cold and warm filesystem behavior is unchanged; the Explorer model still batches and retains resolved child data. The tree now avoids consuming that prefetched chain solely for auto-expansion.
- Mechanism confidence: High: tree.isCompressionEnabled() directly gates the new automatic expansion behavior.
- Magnitude uncertainty: The saved CPU/rendering work depends on chain depth, but the direction is strictly reducing work.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/files/common/explorerModel.ts:327 ExplorerItem.fetchChildren</code>: Resolve the selected directory and request single-child descendants from the file service.; cardinality: One cold resolve for the selected folder, usually with descendant data batched by resolveSingleChildDescendants; zero additional resolves on warm model state.
    - Introduced by diff: false; previous behavior: The same initial resolve occurred, after which autoExpandSingleChildren recursively expanded and materialized every cached single child in the chain.; critical-path effect: The selected directory resolution remains on the expansion critical path, but automatic descendant tree processing is removed.
- Verdict: Performance improves or remains neutral; no reportable regression.

### Scenario 3: Expand a folder whose only child is an incompressible file nest

- Critical path: The folder children are loaded; ExplorerCompressionDelegate marks the file/nest node incompressible, so automatic expansion stops and the nest's synchronous nested children are not materialized unless separately expanded.
- Scaling input: Number of nested file children and frequency of folder refreshes; the diff avoids automatic nest-child processing.
- Effective concurrency: No new asynchronous work or parallel boundary operation is introduced; nested children use ExplorerDataSource's synchronous fast path when requested.
- Cache behavior: Containing-folder resolution and nested-child model caching are unchanged; nested children are returned synchronously when explicitly requested.
- Mechanism confidence: High: ExplorerCompressionDelegate.isIncompressible is a constant-time property/type check and directly prevents the old automatic refresh.
- Magnitude uncertainty: File-nest sizes vary, but no added work exists.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/files/common/explorerModel.ts:327 ExplorerItem.fetchChildren</code>: Resolve the containing folder if it is cold.; cardinality: One cold containing-folder resolve; nested file children are model-backed and synchronous.
    - Introduced by diff: false; previous behavior: autoExpandSingleChildren automatically refreshed and rendered the sole nest child after loading the containing folder.; critical-path effect: Only the containing-folder resolve blocks expansion; the diff removes automatic processing of the nest children.
- Verdict: No regression; the changed behavior removes eager tree work.

- Expensive boundaries: none found
- Verdict: No actionable performance regression; the abstraction overhead is negligible and existing auto-expansion semantics remain unchanged.
