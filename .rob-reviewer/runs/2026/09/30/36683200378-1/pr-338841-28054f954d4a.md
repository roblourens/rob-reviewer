# Performance review: Chat: disable HydraFusion for free users

[PR #338841](https://github.com/microsoft/vscode/pull/338841) at `28054f954d4ae7779d6a078f20d715153f12cfe9`

## Findings (1)

### 1. [low] Coalesce entitlement events before rebuilding the picker

**Finding ID:** `PERF-47EC2AF77164`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts:143</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>missing-coalescing</code>  
**Resource:** model-catalogue CPU work, action-list DOM updates, and synchronous layout reads  
**Scaling:** For each watched context key changed by one account snapshot, the listener rebuilds work proportional to the model/provider catalogue; a normal Unknown-to-Free update changes at least signedOut and planFree, and SKU/organization changes can add more serial rebuilds.  
**Outcome:** redundant synchronous list reconstruction and layout on the UI thread, increasing picker latency and risking a visible frame hitch for larger model/provider catalogues  
**PR causality:** <code>introduced</code>  
**Previous behavior:** An already-open tabbed picker did not rebuild in response to entitlement context-key updates.  
**Changed behavior:** Every broad entitlement event now synchronously refreshes the visible picker and passes \`models\`, which additionally recomputes destinations and sections for all destinations before refreshing the active action list.  
**Confidence:** 0.96 — The new listener, synchronous per-key event source, unbuffered multi-key update, visible-only refresh guard, and DOM/layout work are all directly traced. Exact milliseconds depend on catalogue size and how often account state changes, which limits severity rather than mechanism confidence.

**Causal diff evidence:** The added RIGHT-side listener at line 143 invokes \`refresh(this.\_models)\` for every \`onDidChangeEntitlement\` emission; before this line, entitlement context-key emissions did not refresh \`TabbedModelPicker\`.

If entitlement resolves or account metadata updates while the model picker is open, one logical update can rebuild and relayout the full picker multiple times; larger BYOK/provider catalogues amplify the UI-thread work and can make the open picker hitch.

**Evidence:** \`ChatEntitlementService.onDidChangeEntitlement\` is derived from changes to all plan keys plus signedOut, canSignUp, organizations, internal, and SKU. \`ChatEntitlementContext.updateContextSync\` sets those keys separately without \`bufferChangeEvents\`, and \`ContextKeyService.setContext\` fires synchronously for each changed key. Thus one snapshot such as Unknown-to-Free emits at least once for signedOut and once for planFree. Each call reaches \`TabbedModelPicker.refresh\`, rebuilds every destination's sections because \`models\` is supplied, then \`TabbedActionListWidget.refreshActiveList\` rebuilds sizing and active lists, updates DOM items, and reads \`body.offsetHeight\` for layout.

**Suggested direction:** Track the last effective gating state (\`entitlement === Free\`) and schedule/coalesce one refresh after the context-key update settles; skip refreshes when that boolean did not change.

### Scenario 3: Resolve or update entitlement while the tabbed picker remains open

- Cache behavior: No refresh coalescing or effective-state cache exists. Passing \`\_models\` forces catalogue-dependent recomputation on every emission, including organization/SKU changes that do not alter Free gating.
- Mechanism confidence: Very high: the broad event definition, unbuffered per-key setters, synchronous event firing, refresh call path, DOM update, and layout read were all inspected.
- Magnitude uncertainty: Account updates while the picker is open are less frequent than ordinary picker use, and exact frame cost depends on catalogue size; the duplicate event and layout mechanism is deterministic.
- Expensive boundaries: none found
- Verdict: Reportable low-severity regression: one logical entitlement update can cause redundant full picker rebuilds and synchronous layouts.
