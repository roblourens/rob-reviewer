# Performance review: show migrate customization hint in chat view

[PR #333216](https://github.com/microsoft/vscode/pull/333216) at `a59d1a9c3382409425496df15811036170c3b9d6`

## Findings (1)

### 1. [medium] Move migration discovery off the send critical path

**Finding ID:** `PERF-D93272D7AA2F`  
**Location:** <code>src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts:1580</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** filesystem enumeration and customization-list CPU work  
**Scaling:** Cold work fans out across three customization types and their configured user/workspace locations; Always runs the computation each request and Once retries until a hint is found.  
**Outcome:** increased request latency on the chat critical path  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Sending a chat request did not compute migration candidates or await customization discovery.  
**Changed behavior:** Chat sends now perform migration discovery and await its result before invoking the selected agent.  
**Confidence:** 0.97 — Direct call-flow evidence proves the new request-path scan and the later invokeAgent ordering; only the filesystem-dependent duration is uncertain.

**Causal diff evidence:** RIGHT line 1580 newly calls computeMigrationHint from every eligible request; this work was absent from the base send path.

With the experiment set to Once or Always, the first agent-host request after startup or prompt-cache invalidation waits for customization filesystem discovery, delaying agent startup and first response in slow or multi-root workspaces.

**Evidence:** computeMigrationHint calls computeMigrations, which lists agent, instruction, and prompt files. On a cold or invalidated cache, listPromptFiles traverses configured user/workspace locations through PromptFilesLocator. The enclosing Promise.all is awaited at line 1655-1658, while invokeAgent is not reached until line 1840.

**Suggested direction:** Populate an event-invalidated hint cache outside request dispatch, or emit the hint asynchronously without awaiting it before invokeAgent, and use the request cancellation token.

### Scenario 1: Send an agent-host chat request with migration hints set to Once or Always

- Critical path: The request creates its UI model, then awaits hooks, instructions, and the new migration hint together. Migration discovery must finish before participant activation, MCP autostart, and chatAgentService.invokeAgent, so it directly delays agent dispatch.

- Effective concurrency: computeMigrations runs UserData and PromptFiles in parallel; UserData lists agent and instructions in parallel, yielding three concurrent list operations. Each list also fans out user/local/extension discovery. Source-folder queries are sequential per migration branch, with the two branches concurrent.
- Cache behavior: PromptsService caches successful per-type file lists and invalidates them on file/provider/configuration events, coalescing concurrent cold calls. There is no cache for the derived migration hint or negative result, so warm requests still filter complete lists and query candidate target folders; no-candidate Once requests repeat indefinitely.
- Mechanism confidence: High: the added awaited call, transitive filesystem/provider implementations, cache behavior, and later invokeAgent ordering are explicit in code.
