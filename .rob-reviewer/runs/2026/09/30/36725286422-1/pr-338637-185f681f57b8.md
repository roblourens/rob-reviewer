### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts:1781` (`LEFT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts:1781`  
**Introducing path:** `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`  
**Introducing commit:** `114237ee174e46546ae9b2ca6d3c1b5f979930a6`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.97

**Mechanism:** The migration hint assessment was placed in every eligible chat request's pre-invocation Promise.all. In Always mode it repeated collection-wide prompt discovery and harness/MCP migration assessment per request; even when prompt-location caches were warm, the request still awaited source-folder/session readiness and optional MCP assessment before sending the message to the agent.

**Symptom:** Eligible agent-host messages could not reach invokeAgent until migration assessment completed, adding cold filesystem discovery and potentially a bounded protocol-readiness wait or MCP file reads to time-to-response on every request in Always mode (or the first request of each session in Once mode).

**Fixed behavior:** Agent-host requests now await only hook and automatic-instruction collection in Step 2; migration-hint discovery, source-folder waits, and optional MCP planning are no longer performed before agent invocation for each eligible response.

**Evidence:** The deleted LEFT line 1781 called collectCustomizationMigrationHint() inside the Promise.all awaited in Step 2 of sendRequest, before invokeAgent. That helper awaited CustomizationMigrationService.computeMigrationHint. computeMigrationHint fans out across user-data, prompt-file, configured-location, and optional MCP migrations; the first three issue six listPromptFiles calls over three prompt types, whose cold implementation searches user/workspace filesystem locations, then asks the harness for source folders. The agent-host provider waits for asynchronous session customization state; its own comment states that 'the chat request path blocks on this before sending the user's message.' The MCP branch can additionally wait for support discovery and read files while creating a migration plan. Deleted tests prove frequency: Always mode produced three computations for three eligible requests, while Once produced one per session. This PR removes the helper and its awaited Promise.all entry entirely.
