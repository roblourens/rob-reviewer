# Performance review: chat: Clean up stale marketplace plugin records

[PR #338781](https://github.com/microsoft/vscode/pull/338781) at `7a5d7ab63a5c2120ce802788969add9e86263045`

## Findings (1)

### 1. [medium] Keep cache deletion off the uninstall critical path

**Finding ID:** `PERF-B9B94C3F2278`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/pluginInstallService.ts:77</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** filesystem stats and recursive deletion of cloned repositories or npm/pip cache trees  
**Scaling:** The added wait grows with the number and size of files in the plugin source cache (especially git repositories and package-manager trees) plus the number of parent directories pruned.  
**Outcome:** User-visible uninstall latency now includes the full cache cleanup, leaving uninstall actions and marketplace state pending for the duration of recursive filesystem work.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** MarketplaceAgentPluginDiscovery removed the durable installed entry, launched cleanupPluginSource(...).catch(...) without awaiting it, and returned true immediately, so repository cleanup ran off the uninstall interaction's critical path.  
**Changed behavior:** The new centralized uninstallPlugin removes the entry and then awaits cleanupPluginSource before resolving; both the plugin action and customization marketplace await that promise.  
**Confidence:** 0.99 — The diff explicitly changes the removable marketplace plugin callback from launching cleanup without awaiting it to returning uninstallPlugin(), and uninstallPlugin awaits cleanupPluginSource. The traced UI callers await plugin.remove(), while cleanupPluginSource performs concrete filesystem existence checks, recursive deletion, and parent pruning. Only the exact duration and affected cache size vary by installation.

**Causal diff evidence:** The added \`await this.\_pluginRepositoryService.cleanupPluginSource(...)\` at RIGHT line 77 replaces the deleted MarketplaceAgentPluginDiscovery code that invoked \`cleanupPluginSource(...).catch(...)\` without awaiting before \`return true\`.

Uninstalling a GitHub/Git URL/npm/pip plugin with a large cached repository or dependency tree can now keep the UI in its "Uninstalling" state for seconds while recursive deletion completes, whereas the same action previously completed after updating the installed record.

**Evidence:** RIGHT line 77 awaits AgentPluginRepositoryService.cleanupPluginSource. That method calls fileService.exists(cleanupDir), fileService.del(cleanupDir, { recursive: true }), then serially resolves/deletes empty parents. MarketplaceAgentPluginDiscovery now returns uninstallPlugin from its remove callback, UninstallPluginAction returns plugin.remove(), and CustomizationMarketplaceInstallService awaits plugin.remove(); therefore this filesystem cleanup is directly on both user-visible uninstall paths.

**Suggested direction:** Resolve uninstall after the durable entry is removed, and launch best-effort source cleanup in the background with the existing logged error handling; if cleanup completion must be observable, expose it separately rather than blocking the uninstall action.
