## Findings (2)

### 1. [medium] Coalesce plugin-list RPCs while typing completions

**Finding ID:** `PERF-67F4D76DEBC0`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotSlashCommandCompletionProvider.ts:181</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Workbench-to-agent-host completion requests plus Copilot SDK \`plugins.list\` RPC calls and their returned plugin arrays  
**Scaling:** After \`/plugin enable\|disable\|uninstall\|remove\|update \`, cost grows by one uncached SDK list RPC for every typed character; when typing outruns RPC latency, canceled completion requests remain in flight and overlap.  
**Outcome:** Excessive IPC/subprocess work and delayed completion updates while users type plugin names  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this diff, plugin argument completion had no branch that called the SDK plugin inventory, so typing these command arguments caused no \`plugins.list\` RPCs.  
**Changed behavior:** The added plugin completion branch awaits \`getInstalledPlugins(sessionId)\` on every completion evaluation before locally filtering the returned inventory.  
**Confidence:** 0.99 — The changed call path, incomplete-list re-evaluation, missing cross-IPC cancellation, and test-observed repeated lookup cardinality are all explicit in the repository. Only the exact SDK RPC duration and user typing rate are uncertain.

**Causal diff evidence:** RIGHT line 181 adds \`await this.\_sessionInfo.getInstalledPlugins?.(sessionId)\` directly to the completion path; the diff also newly wires that hook through \`CopilotAgent.\_listInstalledPlugins\` to the SDK RPC.

Typing a normal plugin spec such as \`/plugin uninstall elasticsearch&#64;awesome-copilot\` can issue dozens of full inventory RPCs. The Monaco bridge returns these host lists as \`incomplete\`, so it re-evaluates on each character, while \`AgentHostSessionHandler.provideChatInputCompletions\` explicitly cannot forward cancellation across IPC; stale calls therefore still consume the agent-host/SDK path and can overlap, making suggestions lag and increasing subprocess load.

**Evidence:** \`AgentHostInputCompletionsBase.\_provide\` returns \`{ incomplete: true }\`, establishing per-character re-evaluation. \`AgentHostSessionHandler.provideChatInputCompletions\` documents that cancellation is not forwarded across IPC. This changed line awaits an uncached inventory lookup, which reaches \`CopilotAgentSession.listInstalledPlugins()\` and \`session.rpc.plugins.list()\`. The added test also expects four separate session lookups for four completion calls, confirming there is no coalescing.

**Suggested direction:** Keep a per-session in-flight/short-lived inventory promise (or reuse a session-owned inventory snapshot) and invalidate it after plugin mutations; at minimum coalesce concurrent completion requests so canceled keystrokes do not each start another SDK RPC.

### 2. [low] Evict expired per-session marketplace catalogs

**Finding ID:** `PERF-DB2C8B5C77D1`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotSlashCommandCompletionProvider.ts:252</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>cache-lifecycle</code>  
**Resource:** Resolved marketplace catalog arrays and promises retained by the completion provider's session-keyed Map  
**Scaling:** Retained memory grows with the number of distinct sessions in which install completion is opened, multiplied by each session's flattened marketplace plugin catalog; elapsed TTL does not reduce the Map or release values.  
**Outcome:** Unbounded retained memory and increasing GC footprint in long-lived agent-host processes  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this diff there was no marketplace catalog completion cache and therefore no session-keyed catalog state retained by this long-lived provider.  
**Changed behavior:** Each cold \`/plugin install\` completion inserts a promise for the full flattened catalog into a Map keyed by session ID, but entries are deleted only on rejection; expiration merely causes replacement if that same session is queried again.  
**Confidence:** 0.98 — Retention and lifecycle ownership are explicit: successful entries have no removal path and the provider outlives individual sessions. The uncertain factor is only how many sessions/catalog entries a given user accumulates, reflected in low severity.

**Causal diff evidence:** RIGHT line 252 adds a persistent Map entry for every session that requests marketplace plugin completion; no added code removes successfully resolved entries after the 30-second expiry.

A user opening install completion across many chats leaves every resolved catalog reachable for the lifetime of the Copilot agent, even after \`\_destroyLiveSession\` disposes the corresponding session. The advertised 30-second TTL therefore bounds freshness but not memory, and large catalogs compound retention across historical session IDs.

**Evidence:** The provider is instantiated once and registered from \`CopilotAgent\`, while live sessions are independently removed by \`\_destroyLiveSession\`. The cache declaration is an unrestricted \`Map&lt;string, ...&gt;\`; the hit path checks \`expiresAt\`, this changed line inserts by session ID, and the only \`delete\` is the rejection cleanup. There is no session-disposal or provider-disposal eviction path.

**Suggested direction:** Delete entries when their TTL elapses and clear them when sessions end/provider disposal occurs, or use a bounded TTL/LRU cache that prunes expired entries on every insertion.


## Performance regression fixes detected (1)

### 1. boundary-fanout

**Fix location:** `src/vs/sessions/contrib/chat/browser/variableCompletions.ts:159` (`RIGHT`)  
**Blamed base line:** `src/vs/sessions/contrib/chat/browser/variableCompletions.ts:159`  
**Introducing path:** `src/vs/sessions/contrib/chat/browser/variableCompletions.ts`  
**Introducing commit:** `910529e09d027eb0060acd84edc36888e90af673`  
**Mechanism family:** `boundary-fanout`  
**Performance category:** `io`  
**Confidence:** 0.94

**Mechanism:** The generic implicit file completion provider treated slash-command argument text with no `#` variable as a file query, walking editor history and invoking workspace search (or recursively resolving virtual filesystem directories) whenever slash-command suggestions were retriggered.

**Symptom:** Slash-command argument completion could launch unrelated workspace file searches and delay/compete with the intended command suggestions on each incomplete completion refresh.

**Fixed behavior:** The added slash-prefix guard returns before `_addFileAndFolderEntries`, preventing history traversal and the search/filesystem boundary unless the token is an explicit variable word.

**Evidence:** The fixed line now rejects implicit completion when text before the cursor begins with `/` and `range.varWord` is absent. The transitive old path immediately called `_addFileAndFolderEntries`, which always invokes `searchFilesAndFolders` for file/remote workspaces or recursively calls `fileService.resolve` for virtual workspaces. Agent-host command completion lists are marked incomplete and plugin choices explicitly retrigger suggestions, making this provider reachable repeatedly while typing slash arguments; the added regression test confirms this exact provider previously needed suppression for `/plugin `.
