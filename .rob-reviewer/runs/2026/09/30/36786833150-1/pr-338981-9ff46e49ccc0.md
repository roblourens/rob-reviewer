# Performance review: Notify when sandboxing dependencies are not present on Windows

[PR #338981](https://github.com/microsoft/vscode/pull/338981) at `9ff46e49ccc0f6a092076371c5fca900c4a9182b`

## Findings (1)

### 1. [high] Avoid re-querying host support before every prompt

**Finding ID:** `PERF-B97F92D4275C`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:5171</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** SDK control-plane RPC calls to sandbox.getHostSupport  
**Scaling:** On Windows and macOS with SDK sandboxing enabled, one additional host-support RPC is issued for initialization, for every subsequent prompt, and for each sandbox configuration refresh; cost therefore grows linearly with turns per session and independently across live sessions.  
**Outcome:** Blocked prompt dispatch and session initialization, with up to 5 seconds of added latency for each slow or hung query.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The deleted platform guard passed \`{ enabled: false }\` to \`CopilotSandboxDiagnostics.update\` on Windows and macOS, so those paths cleared diagnostics without invoking \`sandbox.getHostSupport\`; the updated test's prior expectation was zero queries.  
**Changed behavior:** The changed line now passes the enabled sandbox configuration on Windows and macOS. \`CopilotSandboxDiagnostics.update\` consequently awaits \`client.rpc.sandbox.getHostSupport()\`, and this method is reached from \`\_prepareSdkTurn\` before \`session.send\` on every normal prompt.  
**Confidence:** 0.99 — The added query count, 5-second timeout, and prompt-critical call chain are all directly established by repository code and the changed test. Actual RPC duration varies by host, but the repeated boundary call and its placement before dispatch are not assumptions.

**Causal diff evidence:** At RIGHT line 5171 the PR removes \`\_platform \!== 'linux' \|\|\` from the condition, changing Windows/macOS from \`{ enabled: false }\` (no probe) to the enabled \`sandboxConfig\` (probe). The accompanying changed test updates \`queries: 0\` to \`queries: 3\` for exactly those platforms.

A Windows or macOS user with sandboxing enabled can wait for a redundant SDK support probe before every message reaches the agent. If the RPC stalls, the existing 5-second timeout is paid on every turn as well as during session startup.

**Evidence:** \`\_send\` awaits \`\_prepareSdkTurn\` before calling \`this.\_wrapper.session.send\`; \`\_prepareSdkTurn\` awaits \`\_applyEffectiveSandboxConfig\`, which reaches this changed call. \`CopilotSandboxDiagnostics.update\` awaits \`raceTimeout(this.\_getHostSupport(), 5\_000)\` whenever \`config.enabled\` is true and has no memoization. The changed platform test explicitly observes three queries from initialization, one send, and one root-config refresh, while its pre-diff expectation was zero.

**Suggested direction:** Cache/coalesce successful host-support results per live SDK session and recompute config-specific reasons from that result, or skip the diagnostic update when the effective sandbox config is unchanged. Preserve explicit refresh on real sandbox configuration changes and allow failed/timed-out probes to retry without putting an identical probe on every prompt.
