- Scaling input: Cost scales with editor layout/resize/zoom event frequency and the number of browser editors being laid out, not page content size. The changed arithmetic is O(1).

- Cache behavior: No cache participates in bounds computation. Cold and warm behavior are equivalent; the diff neither adds cache misses nor defeats coalescing.
- Mechanism confidence: High: the synchronous DOM reads and single model.layout call are explicit in the traced call path, and the before/after diff shows no additional invocation on ordinary layout.
- Magnitude uncertainty: Exact resize-event frequency and IPC duration are not measured, but the diff removes DOM ancestor checks and does not increase boundary cardinality.

### Scenario 3: Enabling, resizing, or scaling device emulation in the integrated browser

- Critical path: Emulation events call layoutBrowserContainer, the emulation contribution computes viewport dimensions, and the renderer contribution snaps the result before one model.layout call applies screen emulation and WebContentsView bounds in Electron main.

- Cache behavior: No cache is used. Device layout is recomputed on every relevant event both before and after the diff.
- Mechanism confidence: High: emulation event call sites and the renderer-to-main path are directly traced, and the diff preserves the same boundary cardinality.

- Verdict: No reportable regression. The restored computation changes rounding semantics only and does not add work, calls, retention, or concurrency.
