### Scenario 1: Open the new-session composer with a configured chat background, then hover its bottom-row session/repository/status controls.

- Critical path: Construction creates one bottom control row; browser style resolution and paint must complete before the composer is visually ready. Hover restyles and repaints the hovered control. No asynchronous application work is added to this critical path.
- Scaling input: Cost scales with the finite number of action labels in the single new-chat bottom row (session controls, repository configuration, and status actions), not chat-history length or list-row count. Hover affects one label at a time.
- Effective concurrency: No subprocess, IPC, filesystem, database, or network work is reached by the CSS change. Style matching and painting run in the browser rendering pipeline; controls are created synchronously as one bounded toolbar row, not scheduled concurrently.
- Cache behavior: The stylesheet is loaded through the existing path; the change introduces no application cache, cache key, cache miss, or coalescing behavior. Cold and warm behavior differ only by normal browser stylesheet/rendering caches already present before the diff.
- Mechanism confidence: High confidence that the diff broadens existing background/border/color styling to production \`.chat-view-new\` descendants and adds a hover paint. High confidence it does not add layout reads, animation, collection-wide work, retained state, or an expensive external boundary.
- Magnitude uncertainty: Exact paint cost of the opaque color plus constant linear-gradient layer is browser/theme dependent and was not benchmarked, but the affected node count is small and bounded and the same treatment already applies to equivalent controls under the existing \`.chat-view\` ancestry.
- Expensive boundaries: none found
- Verdict: No reportable performance regression. Before the diff, production \`.chat-view-new\` bottom controls received only the base surface plus a border; after it they receive the same static layered surface already used by \`.chat-view\` controls. The bounded extra paint on a handful of controls, and one hovered control, does not establish user-visible latency or dropped frames.
