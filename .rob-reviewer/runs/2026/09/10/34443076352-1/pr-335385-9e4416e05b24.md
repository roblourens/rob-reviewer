### Scenario 1: Panel or inline Auto conversation negotiating and consuming a Hydra-RL skip schedule

- Critical path: Endpoint resolution must complete before prompt rendering/model invocation can use the selected endpoint. On a cold conversation or after the skip budget reaches zero, POST /auto is on this critical path; authorized warm skips return the cached endpoint without that network round trip.
- Scaling input: Distinct chat request IDs in one conversation and the server-provided skip\_turns value, bounded to 0..7. Same-ID duplicate endpoint resolutions are coalesced, and different conversations use independent queues.
- Effective concurrency: Distinct identified turns are serialized per conversation by SequencerByKey; same conversation/tier/image/request-ID resolutions share TaskSingler promises. Different conversations remain concurrent, and settled queue keys are removed.
- Cache behavior: Cold routing populates a cache capped at 50 conversations. Warm authorized skips mutate a bounded counter and avoid POST /auto. Tier/vision incompatibility, compaction, authentication changes, model rejection, disposal, and eviction clear or invalidate applicable state; transient failures preserve a compatible warm endpoint.
- Mechanism confidence: High: the changed scheduling, deduplication key, queue cleanup, skip decrement, cache cap, and POST /auto call path are directly visible and covered by focused tests.
- Magnitude uncertainty: Server assignment prevalence and the distribution of skip\_turns are unknown, so exact latency savings or added checkpoint frequency cannot be quantified. The per-conversation call bounds and five-second timeout are explicit.
- Expensive boundaries:
  - network at <code>extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts:107, AutoV2Fetcher.getAutoDecision</code>: POST /auto with prompt, tier/image metadata, and optional opaque controller state; cardinality: One cold call, then at most one call per distinct identified user turn when skipRemaining is zero; duplicate resolutions of the same request ID coalesce, while a server-authorized skip window removes up to seven subsequent calls.
    - Introduced by diff: false; previous behavior: POST /auto was already required for a cold, expired, incompatible, or explicitly invalidated session, but the endpoint then remained sticky; the diff intentionally allows additional server-directed checkpoints after bounded skip windows.; critical-path effect: Blocks endpoint selection and therefore the start of the model request, with a five-second timeout.
  - network at <code>extensions/copilot/src/platform/endpoint/node/autoChatEndpoint.ts:70, AutoChatEndpoint.makeChatRequest2</code>: Selected model chat request through the existing Copilot endpoint; cardinality: One model request per normal chat invocation; the new wrapper inspects the returned response once and does not retry it.
    - Introduced by diff: false; previous behavior: The same model request occurred before the diff; rejected responses did not invalidate an active Hydra selection because that state did not exist.; critical-path effect: This remains the main response-generation critical path; the diff adds only constant-time rejection classification after completion.
- Verdict: No reportable regression. Added checkpoint calls are the required server-owned routing behavior, are serialized only where controller ordering requires it, and are bounded/deduplicated; skip turns reduce rather than multiply network work.

### Scenario 2: vscode.lm Auto requests and other ancillary endpoint resolutions without a chat request ID

- Critical path: A cold or expired extension-scoped Auto selection must complete POST /auto before the language-model response starts. Warm compatible resolutions use the cached endpoint; these calls send advance:false and do not consume user-turn skips.
- Scaling input: Concurrent requests from an extension, grouped by requestInitiator-derived session, tier, and image compatibility; request IDs are absent, so ancillary calls never advance controller state.
- Effective concurrency: Equivalent cold calls coalesce. If a conversation already has controller state or queued work, ancillary resolution joins the per-conversation sequence to observe ordered state; unrelated extension sessions remain parallel.
- Cache behavior: One cache entry per request initiator, within the global 50-entry bound. Warm compatible endpoints are reused; expiry renews through /auto with advance:false and retained controller token without refilling a consumed skip budget.
- Mechanism confidence: High: buildAutoRoutingContext omits request IDs and keys by requestInitiator, while the changed resolver's TaskSingler and cache branches establish coalescing and warm behavior.
- Magnitude uncertainty: The number and concurrency of third-party extension requests varies, but grouping and cache behavior make the effective routing cardinality bounded by extension-scoped sessions rather than messages.
- Expensive boundaries:
  - network at <code>extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts:552 -&gt; extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts:107</code>: Resolve Auto through POST /auto for the extension-scoped vscode.lm session; cardinality: One cold call per effective requestInitiator/tier/image key; concurrent no-ID cold resolutions with the same key coalesce through TaskSingler, and warm compatible calls make no routing request.
    - Introduced by diff: false; previous behavior: The same cold POST /auto and extension-scoped cache existed before; the diff adds a small capability object and advance:false but does not increase effective cold-call cardinality.; critical-path effect: Cold selection blocks the extension's model response; warm calls are local cache reads.
  - network at <code>extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts:581, provideLanguageModelResponse</code>: Invoke the selected language model; cardinality: One per vscode.lm response request, unchanged by this diff.
    - Introduced by diff: false; previous behavior: Unchanged model invocation count and placement.; critical-path effect: Main generation boundary after endpoint resolution.
- Verdict: No reportable regression. The diff preserves cold-call coalescing for no-ID callers and does not add per-message routing fan-out.

### Scenario 3: Hydra controller-state rejection, compaction, account change, explicit model switch, or selected-model rejection

- Critical path: Invalidation itself is local. The next Auto resolution places POST /auto on the endpoint-selection critical path. A state-bearing HTTP 400 performs one additional sequential recovery request without the token; selected-model rejection does not retry the failed model call.
- Scaling input: Lifecycle events and typed model failures per conversation. Recovery is bounded to one extra /auto call per state-bearing 400, not proportional to history or model count.
- Effective concurrency: Queued turns remain ordered per conversation. Authentication generation and routing epoch checks prevent stale in-flight responses from repopulating invalidated state; different conversations remain concurrent.
- Cache behavior: Compaction clears active controller state and marks reevaluation; model switches/rejections do so only for active Hydra entries. Authentication and disposal clear the bounded cache, and transient routing errors retain only compatible cached endpoints.
- Mechanism confidence: High: the catch predicate, token-free recursive call, epoch guards, endpoint-identity callback guard, and tests directly establish the behavior.
- Magnitude uncertainty: Actual frequency of server state rejection and model rejection is unknown. The maximum additional boundary count and retry sequencing are explicit.
- Expensive boundaries:
  - network at <code>extensions/copilot/src/platform/endpoint/node/automodeService.ts:341-353, AutomodeService.\_route</code>: POST /auto and, only for a state-bearing HTTP 400, one retry without controller state; cardinality: Normally one request after invalidation; at most two for one state-rejection attempt. The recursion is bounded because the retry omits state\_token.
    - Introduced by diff: true; previous behavior: There was no controller token to reject and therefore no state-stripping retry; ordinary invalidation already caused one reroute.; critical-path effect: Both calls are sequential and block endpoint selection in the 400 recovery case.
  - network at <code>extensions/copilot/src/platform/endpoint/node/autoChatEndpoint.ts:70-76</code>: Existing model chat call whose typed rejection marks the active Hydra selection invalid for the next resolution; cardinality: One existing model call; no automatic retry. Multiple late rejection callbacks cannot repeatedly invalidate after Hydra state is cleared, and callbacks from replaced endpoints are ignored.
    - Introduced by diff: false; previous behavior: The model call already occurred; only next-resolution cache invalidation is new.; critical-path effect: The rejected model call completes with its original response; rerouting is deferred to the next endpoint resolution.
- Verdict: No reportable regression. The sole newly introduced extra network call is a bounded one-time compatibility recovery; invalidation avoids repeated use of rejected selections and does not retry model generation.
