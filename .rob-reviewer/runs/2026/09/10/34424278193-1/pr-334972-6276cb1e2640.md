### Scenario 5: Use shared ActionList filtering, section expansion, focus-group navigation, and popup cleanup

- Critical path: Filtering and section changes rebuild the visible item array and splice the virtualized list; focus or hover updates at most the previous and current highlighted rows. Hiding clears submenu/widget disposables.
- Scaling input: Generic filtering gains one scan of all menu items; focus-group cleanup can additionally scale with retained groups, but current production use introduced by this PR has two groups and a small list.
- Effective concurrency: Filtering cancellation prevents stale async filter results; UI updates are synchronous. Submenu timers are cancelled and disposables cleared on hide/replacement.
- Cache behavior: Highlight state is retained only for groups in the current item set and stale entries are removed during list updates; no external cache is involved.
- Mechanism confidence: High for the added scans and lifecycle behavior; low prevalence/magnitude for any user-visible cost because effective production cardinality is bounded.
- Magnitude uncertainty: Other future callers could supply larger group sets, but repository search found focusGroup production use only in this new small combined picker; theoretical quadratic behavior is not a realistic current trigger.
- Expensive boundaries: none found
- Verdict: No reportable regression. The shared extra scan is dominated by existing filter/list reconstruction at current cardinalities, and cleanup ownership remains bounded.
