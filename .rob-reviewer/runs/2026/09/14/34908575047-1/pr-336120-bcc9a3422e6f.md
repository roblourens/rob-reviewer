## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `build/gulpfile.vscode.web.ts:218` (`RIGHT`)  
**Blamed base line:** `build/gulpfile.vscode.web.ts:174`  
**Introducing path:** `build/gulpfile.vscode.web.ts`  
**Introducing commit:** `02e60e2be0bf2797746e5e24bc61bf91439ce928`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.99

**Mechanism:** Adding the esbuild standalone-web bundle behind a task that still required `compileBuildWithManglingTask` caused two independent whole-source build pipelines to run serially for each local web package; the first pipeline's emitted JavaScript was not consumed by the source-based esbuild bundle.

**Symptom:** Local `gulp vscode-web` and `gulp vscode-web-min` packaging paid an unnecessary full-source compile, NLS generation, mangling, and filesystem emission before the actual esbuild bundle, increasing end-to-end build latency and CPU/I/O.

**Fixed behavior:** The local standalone-web packaging tasks now generate API proposal names and the shared build date, then proceed directly to the existing web-extension preparation and esbuild bundle. This removes one full repository-wide TypeScript/NLS/mangling pass and its `out-build` writes from every local web package while preserving bundle ordering and metadata.

**Evidence:** Before the PR, the local `vscode-web`/`vscode-web-min` task series ran `compileBuildWithManglingTask` and then `vscodeWebTaskCI`, whose bundle step launched the standalone-web esbuild task. `compileBuildWithManglingTask` recursively reads `src/**`, runs the full build/NLS TypeScript pipeline and mangler, and writes `out-build`; `build/next/index.ts:523-570` shows the subsequent esbuild bundle independently bundles entry points directly from TypeScript source and cleans/writes its own output. The esbuild task's introduction at base line 174 therefore made the retained legacy compile redundant except for API-proposal generation and the date file. The changed task series removes that full compile while preserving those two setup operations explicitly.
