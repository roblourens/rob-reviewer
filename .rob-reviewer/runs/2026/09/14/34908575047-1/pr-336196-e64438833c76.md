### Scenario 1: Start or continue an agent chat using a GPT-6 family endpoint, including prompt selection, tool filtering, request-body construction, and optional tool search.

- Critical path: PromptRegistry scans its bounded resolver list, performs an O(family-length) prefix check, renders the selected static prompt bundle, filters available tools, and constructs the model request before the network completion can begin. If the model requests a deferred tool, embedding search and the follow-up model turn are then on the critical path; otherwise that work is absent.
- Scaling input: Resolver count and enabled-tool count per request; deferred-tool search scales with the number of deferred tools after non-deferred filtering, and returns five matches by default. There is no new per-file, per-message, or unbounded concurrent loop in the diff.
- Effective concurrency: Resolver matching is sequential over a small registry as before. Tool definitions are processed synchronously once per request. A requested tool search performs one query-embedding operation, batches embeddings for cache-missing tool definitions, ranks locally, then continues the existing serialized agent turn; the diff adds no parallel burst or limiter bypass.
- Cache behavior: The removed hidden-family predicate used a cached SHA-256 lookup; the replacement prefix comparison requires no cache and is cheaper on cold and warm paths. Tool definition embeddings use precomputed and local caches plus an in-memory promise map; a cold search may batch missing tool embeddings, while warm searches reuse tool embeddings but still compute one query embedding. GPT-6 prompt cache-breakpoint metadata uses the existing conversation cache behavior and does not add a local retained collection.
- Mechanism confidence: High confidence in the call path and cardinality: changed GPT-6 capability checks feed endpoint.supportsToolSearch, agent tool selection, prompt rendering, and Responses API deferral. High confidence that no accidental fan-out or new concurrency is introduced.
- Magnitude uncertainty: Actual deferred-tool counts, embedding backend latency, model tool-search frequency, and provider metadata overrides vary by installation. The mechanism is bounded and intentionally trades an occasional search round trip for smaller ordinary prompts; there is no evidence that the changed family routing produces a net regression.
- Expensive boundaries:
  - network at <code>extensions/copilot/src/platform/endpoint/node/responsesApi.ts:createResponsesRequestBody</code>: Sends the normal streamed Responses API model request, with GPT-6 prompt-cache, verbosity, and deferred-tool metadata selected by the changed capability predicate.; cardinality: One model request per agent turn, unchanged; prompt-cache metadata adds only bounded fields. The initial tool schema set can shrink because deferred tools are omitted.
    - Introduced by diff: false; previous behavior: The same request boundary already existed. The hidden-model family used equivalent capability gates; externally named GPT-6 families previously fell through to generic routing.; critical-path effect: The request is the main agent-turn critical path. The diff changes bounded request metadata and prompt/tool selection, not the number of ordinary completion requests.
  - other at <code>extensions/copilot/src/extension/tools/node/toolSearchTool.ts:ToolSearchTool.invoke -&gt; ToolEmbeddingsComputer.searchToolsByQuery</code>: Computes one query embedding and, on a cold tool cache, one batched set of embeddings for missing deferred tools before local ranking.; cardinality: Zero unless the model emits a tool-search call; then one query embedding per call and at most one batched missing-tool computation for the effective deferred-tool set. Existing prompt instructions explicitly discourage repeated searches.
    - Introduced by diff: true; previous behavior: Named GPT-6 families were not selected by the old hidden hash predicate, so fallback capability inference did not enable this protocol unless metadata explicitly did. The prior hidden-model aliases already used this same tool-search path.; critical-path effect: When invoked, embedding search blocks returning selected tool definitions and therefore the next model turn. When no deferred tool is needed, it is off the critical path and deferred tool schemas are omitted from the initial request.
  - network at <code>extensions/copilot/src/platform/endpoint/node/responsesApi.ts tool\_search handling</code>: Continues the agent with selected deferred tool definitions after a model-requested tool search.; cardinality: At most one additional model round trip per emitted tool-search call; not per available tool, because selected definitions are returned together.
    - Introduced by diff: true; previous behavior: The existing protocol applied to hidden-model aliases and other supported families; named GPT-6 fallback routing did not infer support before this change.; critical-path effect: Adds a round trip only when GPT-6 asks to load a deferred tool, while reducing ordinary request serialization and token payload by omitting all deferred schemas.
- Verdict: No reportable regression. The route change enables the existing GPT-6-specific protocol and static prompt bundle; ordinary turns avoid deferred schemas, while optional search work is model-triggered, grouped, cached, and serialized.

### Scenario 2: Attach one or more PDF documents to a GPT-6 chat request.

- Critical path: For each explicitly attached PDF, FileVariable checks vision/PDF support, reads the file, validates four magic bytes, base64-encodes the complete buffer, and embeds it in the user message before the model network request can start.
- Scaling input: Number and byte size of explicitly attached PDFs. Effective cardinality is one filesystem read and one base64 allocation per attachment; no deduplication or cache exists in this component.
- Effective concurrency: Each FileVariable render awaits its file read. Overall prompt-render scheduling is outside the changed code; this diff adds no Promise.all, queue, or concurrency burst.
- Cache behavior: There is no PDF-content cache here, so repeated prompt renders can reread and re-encode attachments. That behavior already applied to model families classified as PDF-capable, including the prior hidden-model aliases; the diff only recognizes the public GPT-6 family name.
- Mechanism confidence: High confidence that the family predicate enables the existing filesystem read and full-buffer serialization for named GPT-6 endpoints.
- Magnitude uncertainty: PDF size and attachment count vary, but the resource mechanism is explicit and proportional to user-selected content.
- Expensive boundaries:
  - filesystem at <code>extensions/copilot/src/extension/prompts/node/panel/fileVariable.tsx:FileVariable PDF branch</code>: Reads the complete attached PDF from the workspace file service.; cardinality: One read per explicitly attached PDF per render; scales with attachment count and file size.
    - Introduced by diff: true; previous behavior: A named GPT-6 family not otherwise identified as GPT-5-plus was treated as not PDF-capable and omitted the attachment; hidden-model aliases already reached the same read path.; critical-path effect: The read must complete before prompt construction and the network request.
  - serialization at <code>extensions/copilot/src/extension/prompts/node/panel/fileVariable.tsx:FileVariable PDF branch</code>: Copies the PDF buffer into a base64 string and includes it in the request payload.; cardinality: One full-file encoding per accepted attachment, with output proportional to total PDF bytes.
    - Introduced by diff: true; previous behavior: Named GPT-6 fallback routing omitted unsupported PDF content, whereas the prior hidden GPT-6 aliases performed the same native-PDF serialization.; critical-path effect: Encoding and request-byte growth occur before and during the model request.
  - network at <code>agent chat endpoint request with Document content</code>: Uploads base64 PDF document parts in the model request.; cardinality: One chat request containing all accepted attachments; bytes scale with aggregate PDF size rather than producing one network call per PDF.
    - Introduced by diff: true; previous behavior: The public GPT-6 family was not inferred as PDF-capable before the change; hidden aliases already supported the same upload.; critical-path effect: Upload size can increase request latency, but it is the requested native-PDF feature.
- Verdict: No finding. The added work is the direct, necessary implementation of intentionally enabling native PDF attachments for GPT-6, is triggered only by explicit attachments, and does not introduce accidental repetition or fan-out.

### Scenario 3: Prepare edit and notebook tools plus model-specific todo/apply-patch descriptions for a GPT-6 agent request.

- Critical path: Capability checks select apply\_patch exclusively, optionally substitute its shorter schema/instructions, choose notebook representation, and shallow-copy the todo definition during the existing enabled-tool scan before request serialization.
- Scaling input: Enabled-tool count and notebook cell/content size. The todo override is one bounded shallow copy; tool filtering remains one pass over enabled tools. Notebook conversion scales with notebook content, but GPT-prefixed families already selected JSON before this diff.
- Effective concurrency: All changed checks and definition substitutions are synchronous. No subprocess, IPC, filesystem, database, or extra network operation is launched by these predicates.
- Cache behavior: Configuration/experiment lookups use existing services. No new cache, retained key, or invalidation path is added. Prompt and tool definitions are reconstructed on the existing per-request path as before.
- Mechanism confidence: High confidence from the changed predicates and their direct consumers that all work is bounded per request and no expensive boundary is added.
- Magnitude uncertainty: Exact token savings depend on enabled tools and experiment state, but there is no scaling-cost increase attributable to the diff.
- Expensive boundaries:
  - serialization at <code>extensions/copilot/src/platform/notebook/common/alternativeContent.ts:AlternativeNotebookContentService.getFormat</code>: Selects the notebook representation later serialized into agent context.; cardinality: One representation choice per notebook conversion; serialization scales with cells and content.
    - Introduced by diff: false; previous behavior: Named GPT-6 families already matched the generic GPT branch and used JSON notebook representation.; critical-path effect: Notebook serialization can be on prompt construction's critical path, but the changed GPT-6 predicate does not alter it because the pre-existing generic \`family.startsWith('gpt')\` branch already selected JSON.
  - network at <code>agent request carrying filtered edit tools and todo definition</code>: Serializes the selected tool schemas and prompt instructions into the existing model request.; cardinality: One request payload per turn; the GPT-6 path removes the generic edit\_file tool when apply\_patch is available and can use shorter apply-patch instructions, while replacing one short todo description with another bounded description.
    - Introduced by diff: false; previous behavior: The model request already serialized enabled tools. Hidden aliases had equivalent overrides; named GPT-6 used generic GPT apply-patch support but retained additional edit tooling and instructions.; critical-path effect: No additional boundary call is introduced; payload size is bounded and is likely reduced by exclusive/simplified apply\_patch selection.
- Verdict: No reportable regression. The changes are constant-time classification and bounded metadata substitutions; existing notebook serialization behavior is unchanged and edit-tool payloads generally become smaller.

### Scenario 4: Load the extension module and register agent prompt resolvers.

- Critical path: At extension startup, allAgentPrompts imports one renamed module and PromptRegistry appends one resolver, exactly as before.
- Scaling input: Fixed module and resolver count; independent of workspace size, history, files, or requests.
- Effective concurrency: Synchronous module loading and registration as before; no queue, subprocess, IPC, filesystem scan, database call, or network request is introduced.
- Cache behavior: No cache lifecycle changes. The old hidden-model hash list is removed; runtime classification no longer depends on the SHA cache for this family.
- Mechanism confidence: High confidence from the one-for-one import rename and one-for-one registry registration.
- Magnitude uncertainty: None material; import and registration shape is unchanged.
- Expensive boundaries: none found
- Verdict: No startup regression: module count, prompt class size, and registration cardinality are unchanged.

**Summary:** Completed the performance pass over all 9 changed files and every diff page. Traced prompt routing, endpoint capability setup, tool filtering/deferral, embedding search, PDF attachment I/O and encoding, notebook formatting, request serialization, and startup registration. The PR replaces cached hash classification with a cheaper prefix check and extends existing bounded GPT-6 behavior; no high-confidence actionable performance regression was found.
