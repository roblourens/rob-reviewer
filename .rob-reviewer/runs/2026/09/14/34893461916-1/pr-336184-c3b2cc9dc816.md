## Findings (1)

### 1. [medium] Avoid rebuilding the sessions tree on breakpoint changes

**Finding ID:** `PERF-7F0AC617BBDC`  
**Location:** <code>src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts:3041</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** CPU work, temporary tree/chat objects, observable subscriptions, and visible-row DOM  
**Scaling:** Each desktop/phone breakpoint crossing now filters and groups all known sessions, sorts group/section members, creates a SessionChatItem and tree description for every included chat, and replaces the tree model; cost grows with total included session/chat history rather than only the rows whose presentation is onscreen.  
**Outcome:** increased synchronous resize/orientation latency, CPU/GC pressure, and potential dropped frames  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** The handler walked the existing tree and called updateElementHeight for session/chat nodes, avoiding session regrouping/sorting, new chat/tree object allocation, and row-template rebinding.  
**Changed behavior:** The handler calls setCompact(), which toggles the class and synchronously calls update(); update rebuilds the entire hierarchy and passes it to tree.setChildren before the context-key notification returns.  
**Confidence:** 0.94 — The added line, synchronous call path, all-history loops, allocations, replacing tree splice, and viewport breakpoint trigger are directly established in repository code. Exact list sizes and milliseconds vary by user, so severity is medium, but the broadened mechanism is certain.

**Causal diff evidence:** RIGHT line 3041 replaces the prior existing-tree height reconciliation with this.setCompact(); setCompact synchronously invokes the full update() path.

Dragging a Sessions window across the phone breakpoint, or rotating a device with a large session/chat history, can synchronously rebuild the whole list on each threshold crossing and make the layout transition stutter; repeatedly oscillating around the breakpoint repeats the work.

**Evidence:** The added call reaches SessionsList.setCompact (lines 3712-3714), which calls update(). update() filters all sessions, sorts grouped/section sessions, maps every included session and chat into new tree elements (including new SessionChatItem objects), then invokes tree.setChildren(null, children) and recreates chat-height tracking. The ObjectTree identity provider is not passed as a diffIdentityProvider to this setChildren call, so ObjectTreeModel uses a replacing splice; visible renderer templates clear and recreate reactive subscriptions and details DOM. The phone context is synchronously driven by viewportClass, placing this work directly on the resize/orientation transition path.

**Suggested direction:** Use a dedicated presentation refresh for breakpoint changes: toggle the compact class, rerender affected visible rows, and reconcile row heights in a batched tree/list operation without regrouping, sorting, or replacing the sessions model.
