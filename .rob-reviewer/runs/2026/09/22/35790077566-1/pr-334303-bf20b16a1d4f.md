### Scenario 1: Send an Agent Host chat request while customization migration hints are enabled (once or always).

- Critical path: The request model is shown first, then hint collection runs in Promise.all with hooks and automatic instructions; all three must settle before context is merged and the agent invocation proceeds. The diff changes hint metadata/count formatting and propagates the request cancellation token, but does not add a new awaited operation.
- Scaling input: The number of discovered customization files and configured MCP servers. New work is two linear filters plus one combined candidates array over the already-produced migration candidates; boundary cardinality and concurrency are unchanged.
- Effective concurrency: Four migration computations run concurrently. Prompt discovery duplicates coalesce by prompt type through cachedFileLocations; MCP support is shared by scope key when another holder exists. There is no new unbounded concurrency.
- Cache behavior: Prompt lists are cached as promises per type and invalidated by locator/provider change events, covering both cold coalescing and warm reads. MCP support is ref-counted rather than permanently cached. The diff does not change cache keys or invalidation; cancellation can stop cold discovery sooner.
- Mechanism confidence: High confidence that the critical path and boundaries are real, and high confidence that their call count is unchanged by this diff.
- Magnitude uncertainty: Candidate counts are normally small, and no repository evidence establishes a user-visible cost from the added linear count formatting. Exact cold discovery and MCP assessment duration varies by workspace and server inventory.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts:39-83</code>: Discover workspace and user agent, instruction, prompt, and skill files through IPromptsService.listPromptFiles.; cardinality: Six logical list invocations per hint computation across four unique prompt types; the prompts-service promise cache coalesces duplicate agent and instruction reads by type, so a cold run performs at most one discovery per unique type and warm runs reuse those promises until invalidation.

- Verdict: No reportable regression: the only added per-request work is bounded in-memory aggregation over existing results, while cancellation propagation can reduce abandoned work.

### Scenario 2: Click “Review customizations” for a file-migration hint and open the first actionable migration category.

- Critical path: The command awaits opening the singleton management editor, then awaits showCustomizationMigrationPage, which refreshes migration candidates before selecting and rendering the first non-empty enabled category.
- Scaling input: Enabled migration categories (default one, maximum three), unique prompt types, and candidate count. The added refresh repeats bounded provider enumeration, while filesystem discovery is coalesced by the per-type promise cache.
- Effective concurrency: Enabled category computations use Promise.all; duplicate prompt-type discovery is coalesced. Refresh sequencing discards stale results but does not cancel older in-memory provider enumeration.
- Cache behavior: Cold editor creation populates per-type prompt-list promises; the newly awaited refresh shares or reuses those promises. Warm editor navigation reuses cached lists. Change events invalidate the relevant prompt-type cache before a later refresh.
- Mechanism confidence: High confidence that one refresh call is newly added and that prompt discovery is cached/coalesced; high confidence that remaining repeated provider work is bounded enumeration.
- Magnitude uncertainty: There may be uncommon providers with slower source-folder enumeration, but the concrete Agent Host providers inspected enumerate existing in-memory customization/source-folder state. No added uncoalesced filesystem or network fan-out was established.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts:1299-1345</code>: Discover prompt files for enabled migration categories during refreshCustomizationMigrationInfo.; cardinality: One refresh is explicitly added after open. A newly created editor already starts migration refreshes; overlapping listPromptFiles calls coalesce by prompt type, and an already-open editor uses warm cached lists unless an invalidation occurred.
    - Introduced by diff: true; previous behavior: The review link opened the same management editor without selecting a migration page; editor creation already initiated migration discovery in the background.; critical-path effect: The explicit refresh is awaited before the migration page is selected, ensuring the first actionable category is current.
  - network at <code>src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts:1230-1280</code>: Initialize the MCP management widget and request the MCP gallery manifest/refresh.; cardinality: One widget initialization per newly created management editor pane; asynchronous manifest and refresh requests are initiated once by the constructor.
    - Introduced by diff: false; previous behavior: The same command already opened the editor, whose content eagerly constructs McpListWidget regardless of selected section.; critical-path effect: The requests are fire-and-forget from widget construction and are not awaited by showCustomizationMigrationPage.
- Verdict: No finding: the refresh is required to choose a current actionable category, its expensive file discovery is coalesced, and the remaining repeated work lacks a concrete user-visible performance mechanism.

### Scenario 3: Click “Review customizations” when the hint targets unsupported MCP servers.

- Critical path: The command opens the same singleton management editor and synchronously selects the MCP Servers section after openEditor resolves; no new migration refresh is awaited for this target.

- Effective concurrency: Widget refresh and manifest loading remain asynchronous and internally owned by the existing widget; the changed section selection adds no burst.
- Cache behavior: The editor input is singleton-style, so reopening an existing pane reuses it. Gallery/service caching remains unchanged by the diff.
- Mechanism confidence: High confidence that section targeting does not add the MCP widget boundary because the widget is already eagerly constructed on generic editor open.
- Magnitude uncertainty: Network latency and gallery size vary, but the relevant calls are pre-existing on the same editor-open path.
- Expensive boundaries:

- Verdict: No reportable regression: the changed navigation does not introduce or amplify the expensive boundary.
