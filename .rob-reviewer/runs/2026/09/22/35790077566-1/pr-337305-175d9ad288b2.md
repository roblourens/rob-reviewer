### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts:105` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts:73`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts`  
**Introducing commit:** `1c84e6239e8e2be3a8327a1121cfcd6fbfbccf97`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.97

**Mechanism:** Each eligible chat request recomputed disabled MCP migration support by creating a short-lived scope, waiting for its debounced all-server assessment, and disposing it, preventing reuse and delaying agent invocation even though the feature was disabled.

**Symptom:** At least the scope's 50 ms debounce plus MCP support assessment time was added to eligible chat-request preparation whenever migration hints were enabled while the default-disabled MCP migration remained off.

**Fixed behavior:** computeMigrationHint now checks the MCP migration enablement before scheduling its four-way Promise.all and substitutes an already-resolved empty migration when disabled, removing fresh support-scope creation and the 50 ms debounced MCP assessment from the chat request critical path.

**Evidence:** Base line 73 unconditionally included computeMigration(...McpServers) in computeMigrationHint's Promise.all. ChatService calls computeMigrationHint while collecting every eligible request's context and awaits that Promise.all before preparing variables and invoking the agent (chatServiceImpl.ts:1681-1695,1773-1778). The MCP provider acquires a support scope and awaits waitForMcpServerSupport (agentHostMcpServerMigrationProvider.ts:52-60); a newly acquired scope schedules support assessment behind MCP\_SUPPORT\_UPDATE\_DEBOUNCE\_DELAY = 50 and is disposed when the call returns (agentHostMcpServerSupportScope.ts:22,155-215,269-273). MCP migration defaults to false (chat.shared.contribution.ts:2528-2534), and provider-side disabling only skipped createPlan after support resolution, so the old hint path still paid scope creation, debounce, and all-server support assessment despite producing no MCP candidates. The added conditional at line 105 bypasses the provider entirely in that default-disabled case.
