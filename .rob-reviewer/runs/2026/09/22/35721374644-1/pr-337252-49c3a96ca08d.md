### Scenario 1: Create or resume a Copilot Agent Host session and publish workspace/user customizations

- Critical path: SessionPluginController.getCustomizationsSettled/getAppliedPlugins awaits SessionDiscoveredEntry.whenSettled, so initial discovery completes before the initial customization snapshot or applied plugin set can progress.
- Scaling input: Number of workspace roots, SDK-reported discovery paths/customizations, plugin files, and directories beneath the bounded hook roots.
- Effective concurrency: The three path RPCs run in one Promise.all. The three content-discovery RPCs, hook discovery, and watcher update then run in a second Promise.all; discovered plugin parsing is subsequently sequential by plugin root. There is no new aggregate concurrency in the diff.
- Cache behavior: \_discoveredDirectories is populated once per discovery entry and reused on warm refreshes; reanchor/additional-root changes dispose the entry and create a cold cache. The diff preserves this cache for the normal path and removes the alternate scan state.
- Mechanism confidence: High confidence in the call path, six SDK RPC cardinality on cold discovery, cache behavior, and initial-session critical-path placement from the traced implementations.
- Magnitude uncertainty: Users who explicitly selected the removed scan mode now use SDK discovery, but the old path also performed collection-wide filesystem scans and parsing. There is no evidence that the replacement has a concrete worse latency or resource profile, and default users have no boundary-count change.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:getDiscoveredDirectories</code>: Copilot SDK agents/instructions/skills getDiscoveryPaths calls; cardinality: Three concurrent SDK RPCs once per SessionCustomizationDiscovery instance on the cold path; cached \_discoveredDirectories avoids these calls on warm refreshes.
    - Introduced by diff: false; previous behavior: The default 'discover' mode used the same three calls. A caller explicitly selecting the removed 'scan' mode previously used local filesystem scanning instead.; critical-path effect: All three complete before initial discovery can continue.
  - IPC at <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:discover</code>: Copilot SDK agents/instructions/skills discover calls; cardinality: Three concurrent SDK RPCs per initial discovery or coalesced refresh.
    - Introduced by diff: false; previous behavior: The default mode already issued these calls with the same concurrency and cardinality; only the removed opt-in scan branch avoided them.; critical-path effect: All three complete before the customization snapshot is produced.
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:discover/\_updateWatchers/discoverHooks</code>: Resolve discovery paths, parse discovered skills/plugins, recursively inspect hook directories, and establish filesystem watchers; cardinality: One batched resolveAll over distinct discovery paths and ancestors, plus reads proportional to discovered skills/plugins and hook directories; hook roots are limited to the primary workspace and user home.
    - Introduced by diff: false; previous behavior: The SDK-discover branch performed the same work. The removed scan branch instead resolved and parsed all locally scanned customization roots/files.; critical-path effect: Runs concurrently with SDK discovery where possible and must finish before initial discovery settles.
- Verdict: No reportable regression. Default behavior and its expensive boundaries are unchanged; removed scan-mode work cannot establish a concrete degradation without evidence that its local scan was cheaper than the SDK path.

### Scenario 2: React to customization file changes during a live session

- Critical path: Filesystem events fire SessionCustomizationDiscovery.onDidChange; SessionDiscoveredEntry coalesces them for 100 ms, cancels superseded refreshes, and publishes only after changed discovery state is available. This is off the active chat turn's direct critical path but can consume SDK/filesystem resources alongside it.
- Scaling input: Number/frequency of relevant filesystem events after 100 ms coalescing, SDK-reported customizations, and bounded hook-tree size.
- Effective concurrency: Burst events are coalesced by Delayer and the previous cancelable refresh is cancelled. Within one refresh, SDK RPCs, hook traversal, and watcher resolution run concurrently; no diff-added fan-out occurs.
- Cache behavior: Warm refreshes reuse cached discovery directories. Watch registrations are reconciled and reused; disposal cancels refreshes and disposes watchers.
- Mechanism confidence: High confidence from the debounce, cancellation, cache, and watcher code.
- Magnitude uncertainty: SDK cancellation may not stop already-issued subprocess work, but that behavior predates the PR on the default path. Former scan-mode users change mechanisms, with no evidence of a net regression.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:discover</code>: Refresh agents/instructions/skills through Copilot SDK discovery; cardinality: Three concurrent SDK RPCs per refresh that survives the 100 ms debounce; path-discovery RPCs are skipped on warm refreshes.
    - Introduced by diff: false; previous behavior: Default discover mode had identical refresh calls. Explicit scan mode previously refreshed through filesystem scanning/parsing instead.; critical-path effect: Blocks the customization update notification, not ordinary turn progress.
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:discoverHooks/\_updateWatchers/\_reconcileWatchers</code>: Rescan bounded hook roots and update/reconcile watchers; cardinality: Filesystem work scales with directories under the primary workspace/user hook roots and distinct SDK discovery paths; existing watchers are reused when specifications are unchanged.
    - Introduced by diff: false; previous behavior: The discover branch performed the same work; the PR narrows scan-only constants and removes the configuration-change listener, which eliminates rather than adds refresh triggers.; critical-path effect: Must finish before a changed customization set is published.
- Verdict: No reportable regression. The diff does not increase refresh frequency or cost on the default path and removes root-config-triggered refreshes.

### Scenario 3: Choose the primary folder for hooks in a multi-root workspace

- Critical path: computeFolderPickerDecision awaits hook-presence checks for every workspace root before returning the folder-picker decision.
- Scaling input: Number of workspace roots and directories beneath each .github/hooks tree, bounded to eight recursive levels.
- Effective concurrency: All workspace roots are checked in parallel; each directory level also fans out with Promise.all. A found hook cancels sibling branches within that root, but there is no shared cross-root limiter. This concurrency is pre-existing and unchanged.
- Cache behavior: No cache is used for picker decisions; this is unchanged by the diff.
- Mechanism confidence: High confidence from the unchanged traversal and shared folder-picker helper.
- Magnitude uncertainty: Large multi-root hook trees can produce a burst of filesystem operations, but the PR does not introduce or amplify it.
- Expensive boundaries:
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:workspaceDirectoryHasHooks</code>: Recursively resolve .github/hooks directories up to depth 8; cardinality: One traversal per workspace root, with resolve calls proportional to directories visited until a JSON hook is found or all bounded directories are exhausted.
    - Introduced by diff: false; previous behavior: The diff only renames the local cancellation source from scanCts to discoveryCts; traversal, cancellation, depth bound, and call cardinality are unchanged.; critical-path effect: All root checks finish before the picker decision is returned.
- Verdict: No reportable regression because the changed lines are naming-only and preserve the existing performance mechanism.

### Scenario 4: Former scan-mode customization discovery and synthetic bundle support

- Critical path: Before the PR, an explicit root configuration could select local scan discovery; tests could also scan and bundle discovered files. The PR removes that branch, schema option, helper, and bundler implementation.
- Scaling input: Previously the number of configured roots and discovered customization files; after the PR this scan/bundle work is absent.
- Effective concurrency: The deleted scan used Promise.all across roots and conversions while bundle writes were sequential per file. No replacement synthetic-bundle write burst is added.
- Cache behavior: The deleted bundler reused identical content via a lastNonce check but did not own cleanup of persisted bundle directories. Deleting the writer prevents new bundle accumulation; it does not introduce unbounded retention.
- Mechanism confidence: High confidence that the scan and bundling filesystem work is removed from the diff.
- Magnitude uncertainty: The runtime prevalence of explicitly selected scan mode is unknown, but deletion itself is not a regression and there is no direct evidence of a shipped performance symptom to record as a regression fix.
- Expensive boundaries:
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:deleted scan branch; src/vs/platform/agentHost/node/shared/sessionPluginBundler.ts:deleted file</code>: Recursively scan customization roots, read and parse discovered files, and optionally write synthetic plugin bundle files; cardinality: Previously scaled with discovered directories/files, with per-file reads and bundle directory/file writes. The PR removes these operations.
    - Introduced by diff: false; previous behavior: These filesystem operations existed only on scan/helper paths and are deleted, so the diff reduces rather than adds their I/O and allocations.; critical-path effect: Removed scan work no longer blocks scan-mode initialization; former scan selection now follows the SDK-discovery critical path described above.
- Verdict: No finding and no regression-fix record: removal reduces local work, but the evidence does not establish that this PR fixes a concrete shipped performance regression with an attributable symptom.
