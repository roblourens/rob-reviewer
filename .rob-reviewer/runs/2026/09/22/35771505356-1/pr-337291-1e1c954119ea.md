## Findings (1)

### 1. [medium] Keep the center fade out of per-glyph resize updates

**Finding ID:** `PERF-2C69C4389368`  
**Location:** <code>src/vs/sessions/services/chatBackground/browser/chatBackgroundRenderer.ts:271</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** Inline style mutations and repaint/raster work for the Codicon DOM, including the newly filtered far-depth surface  
**Scaling:** On every size change, work grows with the effective grid cardinality, about ceil(width/80) × ceil(height/80) cells, and is repeated by the source renderer plus each visible chat's sticky-background replica.  
**Outcome:** Continuous Agents-window or session-grid resizing can repeatedly invalidate most of the wallpaper and drop frames, with the cost amplified for large windows and multiple visible sessions.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** A resize within the same 80px grid dimensions scanned the existing cells but did not mutate their opacity; existing glyphs were repainted only when cells were added or removed at a grid boundary.  
**Changed behavior:** The viewport-relative center fade changes \`layout.opacity\` whenever width or height changes, and this added branch writes a new inline opacity to every affected existing icon. The far half of the grid now also sits under a full-layer blur, so those writes invalidate its filtered raster.  
**Confidence:** 0.94 — The resize-observer call path, same-grid style mutation, realistic icon count, and replica multiplication are directly established by production code and the added tests. Exact frame loss varies by viewport, GPU, and number of visible sessions, which is reflected in medium severity rather than uncertainty about the mechanism.

**Causal diff evidence:** RIGHT lines 261-272 add viewport-normalized opacity and the inline \`existingCell.icon.style.opacity\` mutation; before this diff opacity was assigned only when a cell was created.

Dragging the Agents window or its session-grid sizing UI now performs repeated per-glyph style updates and wallpaper repaints on the resize critical path. At the test's 960×800 size there are already 109 icons, and the count grows by viewport area; every visible chat can also own a full-size replica renderer.

**Evidence:** \`SessionsChatBackgroundRenderer\` observes its host with \`DisposableResizeObserver\` and immediately schedules \`renderCodicons\`; lines 261-272 derive opacity from exact viewport dimensions and write it when changed. The added test explicitly requires \`resizeWrites &gt; 0\` for a one-pixel same-grid resize, while the adjacent stability test establishes 109 icons at 960×800. \`SessionsChatBackgroundReplica\` creates another renderer sized to the full source, and \`SessionsPart.updateVisibleSessions\` creates one chat view per visible session, so the same resize work is duplicated across replicas.

**Suggested direction:** Preserve each icon's stable random opacity and express the viewport-relative center attenuation once on the shared Codicon container (for example with a radial mask/gradient), or otherwise update one shared visual property per resize instead of every icon; keep replica alignment and the current fade semantics.

- Effective concurrency: Each renderer has a zero-delay \`RunOnceScheduler\`, which coalesces bursts per renderer but not across renderers; during continuous resize each source/replica scheduler can run once per delivered resize cycle on the same UI thread.
- Cache behavior: Cell objects are warm and reused, but exact numeric opacity changes defeat the style-write cache for central cells on every distinct width or height. Unchanged refreshes correctly avoid writes.
- Mechanism confidence: High: production observers and replica flow plus added tests directly prove same-grid opacity writes and realistic cell count.
- Magnitude uncertainty: Exact repaint duration and dropped-frame prevalence depend on GPU, viewport size, and visible-session count; the style mutation, filtered-layer invalidation, and multiplicative cardinality are certain.
- Expensive boundaries: none found
- Verdict: Reportable medium rendering regression: repeated per-glyph style and paint work was added to an interactive resize path.
