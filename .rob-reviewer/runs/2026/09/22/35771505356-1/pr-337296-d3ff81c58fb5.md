### Scenario 1: Archive or mark one or more sessions from the sessions-list toolbar/context action

- Critical path: Click handling registers one temporary action-runner listener, runs the archive command, archives selected sessions sequentially, then creates one confetti overlay after successful completion when enabled. The provider archive calls must complete before the action promise and animation setup complete.
- Scaling input: Number of selected sessions. Provider archive work scales once per selected session and is serialized; animation cardinality remains one burst per click, not per session.
- Effective concurrency: BaseArchiveSessionAction awaits each selected session serially. The temporary onDidRun listener is one per in-flight click and is disposed in finally.
- Cache behavior: Provider session lookup uses existing in-memory session/provider caches; the diff changes no cache key, miss behavior, coalescing, or invalidation. Animation creation is intentionally uncached and bounded to one click.
- Mechanism confidence: High: action-runner, command loop, provider calls, listener disposal, and animation implementation were directly traced.
- Magnitude uncertainty: Exact provider latency and typical multi-selection size vary, but neither boundary cardinality nor concurrency changes. The new default adds 24 short-lived particles and 25 bounded Web Animations once per click, which is low-frequency and intentional.
- Expensive boundaries:
  - IPC at <code>src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:\_setSessionArchived</code>: Persist archived state through the owning agent-host connection dispatch; cardinality: At most one dispatch per selected agent-host session; selected sessions are processed serially.
    - Introduced by diff: false; previous behavior: The same archive command and one provider persistence operation per selected session ran before the diff.; critical-path effect: The archive action awaits each provider call before completing; dispatch itself existed before this diff.
  - IPC at <code>src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostSessionsProvider.ts:\_setDetachedWorktreeArchived</code>: Mark a detached remote worktree archived through the resolved agent-host connection; cardinality: At most one call per selected remote session with a detached-worktree handle, serialized by the archive command.
    - Introduced by diff: false; previous behavior: The same remote worktree call occurred on archive before the diff; the diff only changes animation timing/default.; critical-path effect: Each applicable call is awaited before the next session and before successful action completion.
- Verdict: No reportable regression. The default enables a bounded visual effect, and moving it after success does not increase archive boundary count or fan-out. The per-click listener allocation is constant and promptly disposed.

### Scenario 2: Archive a merged-pull-request session from the chat archive nudge

- Critical path: The button awaits optional onboarding and one session archive, then performs one configuration/reduced-motion check and creates one confetti burst on success. Provider persistence remains the only transitive IPC path and predates the diff.
- Scaling input: One current session and its existing archive provider operation per click; the animation always has 24 particles regardless of session or pull-request count.
- Effective concurrency: The nudge disables archive controls while awaiting completion, preventing concurrent clicks from the same widget. Provider work is a single awaited operation.
- Cache behavior: The nudge uses existing observable session/provider state. No cache behavior is introduced or changed; the confetti overlay is removed by a bounded timer after roughly 2.7 seconds.
- Mechanism confidence: High for one archive operation and one bounded animation; provider/state timing varies by provider but does not affect operation count.
- Magnitude uncertainty: The widget can be removed reactively when archived state changes, so the post-success animation may target a detached button for some providers; however, the resulting work is still a single bounded overlay and does not establish a material performance regression independent of the functional concern.
- Expensive boundaries:
  - IPC at <code>src/vs/sessions/contrib/chat/browser/sessionArchiveNudge.ts:onArchive -&gt; ISessionsManagementService.archiveSession</code>: Persist one session's archived state, and for eligible remote sessions update detached-worktree archive state; cardinality: One provider archive per nudge click; at most one detached-worktree IPC operation for that session.
    - Introduced by diff: false; previous behavior: The same archive and optional detached-worktree operations occurred after the animation was started; the diff moves the existing animation after successful completion.; critical-path effect: Archive persistence must succeed before the newly positioned animation is created.
- Verdict: No performance finding. The changed timing avoids animation on failed archives and keeps CPU/DOM work bounded to one low-frequency user action; any detached-target visibility issue is correctness-only at this scale.

### Scenario 3: Click any generic MenuEntryActionViewItem without an archive animation

- Critical path: Each click now subscribes to onDidRun, awaits the existing action runner, and disposes the listener in finally. The action's own subprocess, IPC, filesystem, database, or network work is action-specific and unchanged by this diff.
- Scaling input: One listener allocation and one event callback per click; callback fan-out grows only with concurrently in-flight clicks sharing the same runner, which is normally very small and bounded by direct user input.
- Effective concurrency: No new scheduler or parallelism. Concurrent actions retain one listener each only until their own run returns, then dispose it.
- Cache behavior: No cache is read or modified by the changed listener/error tracking.
- Mechanism confidence: High: the changed generic click path and finally disposal are explicit.
- Magnitude uncertainty: Individual menu actions can have arbitrary existing latency, but the new listener does not add or duplicate those boundaries. Only a small allocation/event dispatch overhead is certain.
- Expensive boundaries: none found
- Verdict: No reportable regression. The temporary listener is constant work, has a bounded lifecycle, and does not amplify the action's expensive boundaries under realistic click concurrency.
