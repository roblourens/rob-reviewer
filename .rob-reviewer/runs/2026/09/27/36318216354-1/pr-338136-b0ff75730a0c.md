## Findings (1)

### 1. [medium] Avoid full ignored-file scans when selecting symlink folders

**Finding ID:** `PERF-54171E11A6B3`  
**Location:** <code>src/vs/platform/agentHost/node/agentHostGitService.ts:756</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** Repository-wide Git subprocesses, filesystem traversal, and buffered stdout/JS path strings  
**Scaling:** For each worktree, the first two new \`ls-files\` commands emit and buffer one record per ignored or pattern-matched file, so cost grows with the total ignored-file population (not the usually small number of folders eventually symlinked). Concurrent sessions multiply this into three repository scans per session because setup runs after the repository-keyed creation sequencer.  
**Outcome:** Increased first-turn/worktree materialization latency, filesystem I/O, and memory/GC pressure on repositories with large ignored dependency trees  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this PR, worktree creation performed no symlink-discovery scans. Existing include-file setup, when configured, performed its own scans once; there was no additional symlink phase repeating the standard ignored-file and directory traversals.  
**Changed behavior:** With \`git.worktreeSymlinkFolders\` enabled, Agent Host now awaits a discovery phase that launches three repository-wide \`git ls-files\` scans, two without \`--directory\`, then buffers and splits their complete per-file outputs before it can materialize the worktree. If include files are also configured, its existing standard ignored-file and directory scans run immediately afterward as a separate pass.  
**Confidence:** 0.98 — The changed commands, complete buffering, awaited call path, absence of caching/coalescing, and test configuration targeting \`node\_modules/\*\*\` are explicit. Only the exact wall-clock impact varies with repository size and storage speed.

**Causal diff evidence:** The added RIGHT-side \`Promise.all\` at lines 755-759 invokes \`git ls-files --others --ignored -z\` twice without directory collapsing and once with it; these subprocesses and their full outputs did not exist on worktree creation before this diff.

A realistic \`node\_modules/\*\*\` setting (used by the added tests) makes session creation enumerate potentially hundreds of thousands of ignored dependency files even though the result is commonly one symlink. The awaited phase delays the agent's first turn; multiple sessions against the same repository can run these scans concurrently.

**Evidence:** \`WorktreeIsolation.resolveWorkingDirectory\` awaits \`symlinkWorktreeFolders\` at \`src/vs/platform/agentHost/node/shared/worktreeIsolation.ts:984\` before recording the materialized worktree. The added code at lines 754-759 launches three \`ls-files\` subprocesses; the first two omit \`--directory\`, while the existing include implementation documents that directory mode collapses a wholly ignored tree into one entry. \`\_runGit\` buffers up to 32 MiB of stdout, and \`getWorktreeSymlinkFolderCandidates\` then splits both full outputs into arrays/sets. The repository creation sequencer ends before this call, so the added concurrent-session test's same-repository sessions can overlap setup scans. The Git extension mirrors the same full-file discovery at \`extensions/git/src/repository.ts:2087\`.

**Suggested direction:** Discover candidates with directory-collapsing Git queries (preserving nested/partial-ignore semantics), and share the standard ignored-directory result with include-file setup when both settings are present. Coalesce in-flight discovery by repository plus pattern set so concurrent sessions do not repeat the same scans.
