## Findings (1)

### 1. [low] Skip the unused clone added to every metadata check

**Finding ID:** `PERF-9148C35D68EE`  
**Location:** <code>.github/workflows/telemetry.yml:31</code> (<code>RIGHT</code>)  
**Performance category:** <code>network</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** one external Git clone plus its downloaded bytes and checkout writes per run  
**Scaling:** One unused clone is paid on every PR run and rerun; all six clones execute serially before validation starts.  
**Outcome:** increased CI latency and unnecessary network/filesystem I/O  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** The workflow directly ran the extractor on the checked-out repository and performed no Git clones.  
**Changed behavior:** Each PR metadata job now enters a synchronous loop that shallow-clones six external repositories before extraction.  
**Confidence:** 0.99 — The pull\_request trigger, synchronous clone path, and fixed six-clone cardinality are explicit. The extraction config and repository search also prove that vscode-node-debug2 is not consumed; only network-dependent duration is uncertain.

**Causal diff evidence:** RIGHT line 31 replaces the direct extractor command with \`node build/azure-pipelines/common/extract-telemetry.ts\`, newly executing that script's clone loop in every PR metadata job.

Every PR to main or a release branch waits for an unnecessary cold repository download and checkout before telemetry validation, increasing required-check latency and network usage.

**Evidence:** The invoked script synchronously runs \`git clone --depth 1\` for six repositories. One is vscode-node-debug2, while telemetry-config.json references vscode-chrome-debug-core and vscode-node-debug but never vscode-node-debug2, so that checkout cannot contribute to either extractor output.

**Suggested direction:** Remove vscode-node-debug2 from the shared clone list, or derive clones from configured source directories, preserving extraction output while eliminating the unused boundary call.
