# Performance review: Adding reasoning summary as exp setting.

[PR #330565](https://github.com/microsoft/vscode/pull/330565) at `2523be94020d8861c174afa8c484a5abd0dc3238`

## Findings (1)

### 1. [medium] Coalesce the reasoning summary into the existing options update

**Finding ID:** `PERF-EAA2CE491194`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:616</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>missing-coalescing</code>  
**Resource:** A synchronous request/response RPC over the Copilot CLI subprocess stdio connection  
**Scaling:** Adds one subprocess RPC round trip for every GPT-5.6 session create or resume in the startup-experiment cohort; concurrent session launches each add their own call, with no cache or coalescing.  
**Outcome:** Increased session creation/resume latency on the user-visible initialization critical path  
**PR causality:** <code>introduced</code>  
**Previous behavior:** GPT-5.6 creation performed one post-launch \`options.update\` for verbosity, and no reasoning-summary RPC existed. Resumption did not issue a reasoning-summary update.  
**Changed behavior:** When the experiment is enabled, \`\_applyGpt56Customizations\` first awaits the verbosity RPC and then separately awaits \`\_applyReasoningSummary\`, which issues another \`session.rpc.options.update\`.  
**Confidence:** 0.97 — The changed await, its second RPC implementation, the stdio transport, and the caller's initialization/registration ordering are directly traced. Exact round-trip duration and experiment cohort size are unknown, which limits severity but not the mechanism.

**Causal diff evidence:** The added line 616 awaits \`\_applyReasoningSummary\` after line 613 has already awaited \`\_applyVerbosity\`; \`\_applyReasoningSummary\` performs the newly added \`session.rpc.options.update({ reasoningSummary })\` at line 633.

For users assigned the startup experiment (or enabling the setting), every GPT-5.6 new or resumed chat waits for an avoidable extra subprocess round trip before becoming usable. The cost repeats per materialized session and is especially visible when restoring/resuming chats.

**Evidence:** \`CopilotAgent\` constructs the SDK with \`RuntimeConnection.forStdio\`, so \`session.rpc.options.update\` crosses the CLI subprocess boundary. \`CopilotSessionLauncher.\_finalizeSession\` awaits \`\_applyGpt56Customizations\` before constructing the wrapper, and \`CopilotAgentSession.initializeSession\` awaits launcher completion before subscribing and registering the live session. Thus the two updates are serialized on session initialization rather than off-path. Both values target the same \`options.update\` request object and are fixed for this branch (\`verbosity: 'medium'\`, \`reasoningSummary: 'concise'\`).

**Suggested direction:** When reasoning summaries are enabled, issue one \`options.update({ verbosity: 'medium', reasoningSummary: 'concise' })\`; otherwise retain the single verbosity update. This preserves application-before-registration ordering while removing the extra round trip.
