## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:805` (`LEFT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:805`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`  
**Introducing commit:** `ae83b0e4d03115fc5f4573abcc5efc08dac7846a`  
**Mechanism family:** `repeated-work`  
**Performance category:** `ipc`  
**Confidence:** 0.96

**Mechanism:** An experiment-enabled GPT-5.6 session issued a separate `options.update` RPC for reasoning summary after the already-awaited verbosity RPC, serially extending create/resume finalization before session initialization could continue.

**Symptom:** Extra critical-path IPC latency during creation or resumption of experiment-enabled GPT-5.6 sessions.

**Fixed behavior:** GPT-5.6 finalization now performs only the required medium-verbosity update and leaves reasoning-summary selection to the SDK default, removing one awaited runtime RPC from each affected create or resume launch.

**Evidence:** Base line 805 awaited `session.rpc.options.update({ reasoningSummary })`. `_finalizeSession` was awaited by both `_createSession` and resume paths, and `CopilotAgentSession.initializeSession` awaits `launcher.launch` before registering the SDK event interest or exposing the initialized session. The deleted `_applyGpt56Customizations` called verbosity first and then this reasoning-summary update, so experiment-enabled GPT-5.6 create/resume launches incurred an additional serialized RPC to the Copilot runtime subprocess. The updated create/resume test expectation drops exactly that fourth options update while retaining script-safety, sandbox, and verbosity updates.
