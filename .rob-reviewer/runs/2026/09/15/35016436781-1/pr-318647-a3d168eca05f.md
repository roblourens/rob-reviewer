### 1. [medium] Dispose the sheet shell when body rendering throws

**Finding ID:** `PERF-33F81D8AEEB5`  
**Location:** <code>src/vs/sessions/browser/parts/mobile/mobilePickerSheet.ts:425</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** mounted overlay DOM nodes, Gesture targets, window keydown listener, visualViewport resize/scroll listeners, and any body DOM appended before the throw  
**Scaling:** Each failed invocation retains one additional sheet subtree and three global event listeners indefinitely; later viewport and key events fan out across all leaked shells.  
**Outcome:** unbounded retained memory and increasing UI-event CPU work after repeated failed sheet opens  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this PR there was no arbitrary-body content-sheet renderer path, so a caller renderer could not fail after this helper mounted a shell and strand its cleanup store.  
**Changed behavior:** The new content-sheet path builds and mounts the shell, then directly invokes renderBody inside the Promise executor without failure cleanup; a synchronous throw rejects the promise while leaving the shell live in the document.  
**Confidence:** 0.98 — The Promise executor invokes the caller-controlled renderer synchronously after buildMobileSheetShell has appended the overlay and registered window/visualViewport listeners. JavaScript converts a renderer throw into a rejected promise, but no code reaches shell.close or disposables.dispose, and the function returns no other handle. The only uncertainty is how often a renderer fails; the leak mechanism and per-failure growth are direct.

**Causal diff evidence:** Added line 425 invokes the new caller-controlled renderBody after lines 413-420 create the mounted shell, with no try/finally or rejection cleanup around the call.

If a sheet body renderer throws while constructing a confirmation, review, or preview sheet, catching/retrying the rejected open leaks the previous overlay and its global listeners. Repeated attempts grow DOM memory and make every viewport resize/scroll and Escape key event process more handlers.

**Evidence:** buildMobileSheetShell appends the overlay and registers backdrop, window keydown, and visualViewport listeners in shell.disposables. Added line 425 calls renderBody only afterward. The sole normal cleanup path is shell.close(), but a throw skips lines 426-428 and close is never invoked; the Promise constructor only rejects and does not dispose captured resources.

**Suggested direction:** Wrap the renderer invocation in a cleanup-and-rethrow path that immediately disposes/removes the newly mounted shell (or add an abort method for construction failures), then rethrow so callers still receive the original rejection. Preserve normal ownership by adding a successfully returned body disposable to shell.disposables.
