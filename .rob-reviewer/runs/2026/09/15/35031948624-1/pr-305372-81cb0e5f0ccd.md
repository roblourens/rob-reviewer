# Performance review: agenthost: customization syncing data flow

[PR #305372](https://github.com/microsoft/vscode/pull/305372) at `81cb0e5f0ccd2fe5b815e0d9d95be6a6ad475abe`

## Findings (4)

### 1. [high] Bound concurrent plugin-tree copies

**Finding ID:** `PERF-877521C286C8`  
**Location:** <code>src/vs/platform/agentHost/node/agentPluginManager.ts:80</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>concurrency-burst</code>  
**Resource:** Reverse-RPC browse/fetch calls, concurrent filesystem reads/writes, base64 payload bytes, and transient buffers  
**Scaling:** Peak work scales with the number of selected plugins times the breadth of their directory trees; the per-URI sequencer does not limit different plugin URIs, and FileService concurrently copies every sibling at each directory level.  
**Outcome:** A burst of IPC/network traffic, filesystem I/O, allocation and GC pressure can saturate the client and agent host and delay session readiness or the first prompt.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this PR, the agent host did not copy client customization directories over reverse RPC, so selecting or connecting an agent could not create this cross-plugin filesystem burst.  
**Changed behavior:** A single sync now maps every customization into Promise.all. Each task calls \_fileService.copy on a reverse-RPC-backed provider; FileService.doCopyFolder in turn launches every child copy concurrently.  
**Confidence:** 0.99 — The changed code explicitly starts one copy per customization with Promise.all, and the traced FileService cross-provider copy recursively starts all siblings concurrently. The only uncertainty is how large users' selected plugin trees are, which affects severity magnitude rather than the mechanism.

**Causal diff evidence:** Added line 80 constructs Promise.all(customizations.map(...)); the added \_syncPlugin call at line 120 copies the whole plugin tree. The new reverse provider maps each directory listing and file read to browseDirectory/fetchContent RPCs, while FileService.doCopyFolder uses Promises.settled(sourceFolder.children.map(...)).

On the first sync or any sync without a nonce, selecting several plugins—especially plugins containing many files—can launch many simultaneous reverse RPCs and whole-file encodes. CopilotAgent's \_lastSynced promise is awaited when creating/resuming or sending to a session, so the burst can surface as long first-message latency in addition to client/host CPU and memory spikes.

**Evidence:** AgentPluginManager.syncCustomizations queues only by ref.uri, so separate plugin URIs run together. \_syncPlugin performs a cross-provider recursive copy. ProtocolServerHandler sends one reverse request for each browse/fetch, and RemoteAgentHostProtocolClient reads and base64-encodes each file. No shared limiter exists across plugin keys or recursive child reads.

**Suggested direction:** Keep per-URI serialization, but add a shared bounded concurrency limiter around plugin copies (and, if needed, recursive file transfers), so only a small number of trees/files are in flight while preserving ordering for each URI.

### 2. [high] Cap hook subprocess output before buffering it

**Finding ID:** `PERF-19B3334A8B0D`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:153</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Unbounded stdout/stderr strings and their intermediate allocations in the agent-host heap  
**Scaling:** Retained bytes grow with aggregate subprocess output per hook invocation and multiply across configured commands, tool events, and concurrently active sessions.  
**Outcome:** Heap growth, GC pressure, event-loop stalls, and possible agent-host out-of-memory termination; even outputs that are never consumed are retained until the subprocess exits.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this PR, the Copilot agent host did not execute plugin lifecycle hooks or retain their subprocess output.  
**Changed behavior:** Each newly supported hook process pipes both output streams and concatenates every chunk into strings. Post-tool, prompt, session-start/end, and error handlers discard the returned stdout but still buffer it fully.  
**Confidence:** 0.99 — The new listeners append every stdout and stderr chunk until process exit, and all mapped lifecycle handlers await this helper. The 30-second timeout bounds duration but not emitted bytes; only the prevalence of very verbose hooks is uncertain.

**Causal diff evidence:** Added lines 153-154 append all stdout and stderr data without a byte limit. Added hook handlers at lines 253, 269, 284, 299, and 314 await executeHookCommand while ignoring its result.

A common verbose hook such as a build/test command—or an accidentally unbounded producer—can emit hundreds of MB during the default 30 seconds, causing severe GC pauses or crashing the agent host while a prompt/tool call waits.

**Evidence:** spawn uses piped stdout/stderr and only a time-based timeout. A command can emit arbitrarily many bytes within that interval; repeated string appends retain that output until close. Every mapped lifecycle callback runs commands sequentially on the request/tool/session critical path, and different sessions have no shared output budget.

**Suggested direction:** Enforce a small byte cap while reading stdout/stderr and terminate/reject the child when exceeded. For hook types whose output is ignored, drain without retaining it; for pre-tool JSON and errors, retain only a bounded buffer/prefix.

### 3. [high] Sync customizations once per client, not once per session

**Finding ID:** `PERF-42B00FD746B9`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:234</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** Recursive reverse-RPC filesystem calls, copied bytes, local filesystem writes, and repeated plugin parsing CPU  
**Scaling:** For S active sessions, P selected direct plugins, and F files/directories per plugin, one customization change performs roughly S×P whole-tree copies/parses and corresponding boundary calls; opening additional existing/new sessions repeats unchanged work again.  
**Outcome:** Excessive IPC and filesystem work, lower throughput, and delayed first-message/session latency while the globally serialized plugin sync queue drains.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before the PR, activeClientChanged did not carry customizations and session registration/observable updates did not initiate any plugin copying or parsing.  
**Changed behavior:** Every customization observable update now dispatches activeClientChanged separately for every active session. AgentSideEffects treats each session action as a fresh agent-level sync, and PluginController serializes but does not deduplicate those identical requests.  
**Confidence:** 0.99 — The new autorun visibly iterates every mapped session, and the complete call path from each dispatch to setClientCustomizations, whole-tree copy, and parse is present in the diff. Direct plugin refs demonstrably omit nonce, so the cache cannot eliminate these repeated copies.

**Causal diff evidence:** Added line 234 loops over \_sessionToBackend and added line 237 dispatches the same refs for each owned session. Added session-open paths also dispatch the current set. AgentSideEffects then calls agent.setClientCustomizations for every action, and PluginController invokes syncCustomizations plus parsePlugin each time.

With several open agent sessions, changing one selected plugin or reopening sessions repeatedly transfers and reparses the same directories. A user with only a few sessions and nontrivial plugins can wait behind multiple serialized copies before a prompt proceeds.

**Evidence:** The customization data is agent/client scoped, yet the changed handler publishes it per session. AgentPluginManager skips a copy only when ref.nonce matches; both new \_resolveCustomizations implementations create direct plugin refs with uri/displayName and no nonce. Therefore unchanged direct plugins are recopied. CopilotAgent.sendMessage awaits PluginController.\_lastSynced, making queued duplicate syncs reachable from the interaction critical path.

**Suggested direction:** Own and deduplicate customization synchronization at the client/agent connection level, keyed by client ID plus a stable customization revision/set. Publish the resulting statuses into each session without rerunning copy/parse, and give direct plugin refs a stable revision or retain the last applied set in-process.

### 4. [medium] Coalesce customization selection updates before rebuilding and syncing

**Finding ID:** `PERF-A3B0E8111345`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts:188</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>missing-coalescing</code>  
**Resource:** Repeated source-file reads, in-memory tree deletion/writes, reverse-RPC plugin copies, parsing work, and action serialization  
**Scaling:** For K quick checkbox changes and M selected individual files, the client can perform up to O(K×M) bundle I/O; each intermediate published set then fans out across S sessions and queues another plugin sync.  
**Outcome:** Redundant I/O/CPU and a growing serialized sync backlog that delays customization availability and subsequent first-message latency.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before the PR there was no checkbox-driven customization bundling or agent-host synchronization pipeline.  
**Changed behavior:** Every selection event immediately invokes async updateCustomizations without cancellation, sequencing, or latest-value coalescing. SyncedCustomizationBundler deletes and rewrites the complete selected-file tree, and each completion calls customizations.set even if a newer selection is already being processed.  
**Confidence:** 0.98 — Each toggle synchronously fires onDidChange, this added listener starts an unawaited full resolution, and every completion publishes a fresh array. The bundler rebuild and downstream serialized sync paths are directly traced; only how rapidly and how many items users select varies.

**Causal diff evidence:** Added line 188 subscribes onDidChange with an unawaited updateCustomizations call. toggleUri fires once per checkbox action; updateCustomizations calls \_resolveCustomizations, whose bundle path deletes/rebuilds all selected files, then publishes a new refs array. The remote contribution adds the same pattern.

Selecting several customizations in succession can launch overlapping full bundle rebuilds and enqueue every intermediate plugin set for agent-host sync. Users can see sustained disk/IPC work and delayed prompt readiness long after they finish selecting items.

**Evidence:** SyncedCustomizationBundler.bundle deletes its authority root, writes the manifest, then reads/writes every selected file sequentially. PluginController serializes downstream syncs via \_lastSynced rather than superseding obsolete sets, so rapid events accumulate rather than collapse.

**Suggested direction:** Use a latest-value delayer/sequencer shared by the local and remote contributions: debounce/coalesce selection changes, cancel or ignore obsolete bundle generations, and publish only the newest resolved set. Preserve one final sync after the user stops changing the selection.

### Scenario 1: Selecting several local files or plugins for synchronization from the customization UI

- Critical path: Checkbox handling itself is not awaited, but each selection must be resolved and published before the agent sees it; all queued PluginController syncs must complete before Copilot session creation/getAppliedPlugins or sendMessage/needsSessionRefresh can progress.
- Scaling input: K rapid checkbox changes, M currently selected individual files, P selected plugin roots, S active sessions, and F files/directories in each plugin tree.
- Effective concurrency: Each toggle starts an unawaited updateCustomizations, so K bundle resolutions may overlap. Each published set fans out to S sessions. PluginController serializes whole sync requests globally, but AgentPluginManager starts P plugin copies concurrently and FileService recursively starts all sibling file operations concurrently.
- Cache behavior: The synthetic individual-file bundle gets a content nonce, allowing the server copy to hit after the first identical bundle, but the client still rereads and rewrites every selected file to recompute it. Direct installed-plugin refs carry no nonce, so every published intermediate set is a cold whole-tree copy even when unchanged. No in-flight/latest-set coalescing exists.
- Mechanism confidence: High: event, bundle, per-session action, reverse-RPC copy, cache-key, and serialization paths are all directly present in changed code.
- Magnitude uncertainty: Typical selection counts and plugin tree sizes vary, but multi-selection and multiple open sessions are normal and the multiplicative work is explicit.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentCustomizationSyncProvider.ts:103</code>: Persist the full selected-entry array to profile storage; cardinality: One storage write per checkbox toggle; payload grows with the selected set.
    - Introduced by diff: true; previous behavior: No customization sync selection was persisted.; critical-path effect: Synchronous event handling performs the storage call before notifying listeners, but the dominant downstream work is asynchronous.
  - filesystem at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/syncedCustomizationBundler.ts:106</code>: Delete/rebuild the synthetic plugin and read every selected source file; cardinality: M source reads and M destination writes per update; without coalescing this becomes up to K×M during rapid selection.

  - IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:234</code>: Dispatch activeClientChanged and customization status actions; cardinality: One client action per active session for every published generation, followed by loading, incremental, and final status actions.

### Scenario 2: Opening, reconnecting to, or sending the first prompt in agent sessions while customizations are selected

- Critical path: New and existing sessions dispatch the current customization set. CopilotAgent.createSession/\_resumeSession awaits getAppliedPlugins, and sendMessage awaits needsSessionRefresh; both await PluginController.\_lastSynced, so queued copy/parse work blocks user progress.
- Scaling input: Number of opened/reconnected sessions S, selected plugins P, total plugin tree entries F, custom agents A, and queued prior customization generations.
- Effective concurrency: Identical session-triggered syncs are globally serialized by PluginController, increasing latency linearly with S. Within each sync, different plugins and sibling files are concurrent without a shared bound. Custom agent prompt files are read sequentially during each session factory call.
- Cache behavior: Synthetic refs can hit the nonce cache, while direct plugin refs omit nonce and always recopy. Parsed plugin results are replaced after every sync rather than reused by stable set/revision. No negative cache is involved.
- Mechanism confidence: High for repeated session sync and prompt blocking; high that metadata writes are off-path and not a regression requiring a finding.
- Magnitude uncertainty: The direct-plugin tree size and count of concurrently open session models vary; metadata fallback prevalence is low and was not reported.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:1299</code>: Create/subscribe session and dispatch activeClientChanged; cardinality: Once per newly created session and once per loaded existing session; the customization dispatch is newly added.
    - Introduced by diff: true; previous behavior: Session creation/subscription existed, but it did not trigger customization synchronization.; critical-path effect: The dispatch itself is fire-and-forget, but the resulting PluginController promise is observed by subsequent create/resume/send paths.
  - filesystem at <code>src/vs/platform/agentHost/node/agentPluginManager.ts:120</code>: Copy selected plugin trees to agent-host storage and parse manifests/components; cardinality: P whole-tree copies and P parsePlugin calls per session-triggered sync when refs lack nonces.
    - Introduced by diff: true; previous behavior: No client plugin copy or agent-host parse occurred on session claims.; critical-path effect: Queued in \_lastSynced and awaited before plugin-aware session creation/resume or message send.
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:79</code>: Read each custom-agent Markdown prompt; cardinality: A sequential reads per create/resume factory invocation.
    - Introduced by diff: true; previous behavior: Custom-agent files were not loaded into the Copilot SDK session.; critical-path effect: Directly awaited before the SDK creates or resumes the session.

### Scenario 3: Executing plugin lifecycle hooks during prompts, tool calls, session start/end, and errors

- Critical path: Each SDK hook callback awaits every configured command sequentially before the corresponding lifecycle event proceeds. Pre/post-tool and prompt hooks therefore directly extend prompt/tool latency.
- Scaling input: Number of matching hook commands H, invocation frequency T, concurrent sessions C, command duration, and total stdout/stderr bytes B.
- Effective concurrency: Commands are sequential within one lifecycle callback, but callbacks in different sessions can spawn subprocesses concurrently. There is no global process/output limiter or backpressure beyond OS pipes.
- Cache behavior: No caching or coalescing applies; hooks execute on every matching lifecycle event.
- Mechanism confidence: Very high: both output streams are concatenated without a byte cap and all handlers await the helper.
- Magnitude uncertainty: Most hooks are likely quiet, but verbose build/test hooks and accidental unbounded output are realistic; exact output volume affects severity, not the unbounded mechanism.
- Expensive boundaries:
  - subprocess at <code>src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:142</code>: Spawn a shell for each configured hook command; cardinality: H subprocesses per hook event, repeated across T tool/prompt/session events and concurrent sessions.
    - Introduced by diff: true; previous behavior: The Copilot agent host did not execute synced plugin hooks.; critical-path effect: Each command is awaited sequentially; default timeout is 30 seconds per command.
  - serialization at <code>src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:153</code>: Serialize hook input and buffer all child stdout/stderr into strings; cardinality: One JSON serialization and up to B retained output bytes per command; most hook types discard stdout after buffering.
    - Introduced by diff: true; previous behavior: No hook process output was retained by this agent-host path.; critical-path effect: Buffer growth and GC occur while the awaited hook is on the lifecycle critical path.
- Verdict: Reportable: unbounded output retention can cause GC stalls or OOM, including for hook types that never consume stdout.

### Scenario 4: Browsing and updating the customization management lists for an active remote/local agent harness

- Effective concurrency: Refresh calls are not explicitly sequenced, so provider/status/selection events can overlap. Virtualized list rendering bounds DOM nodes, and plugin-list refresh only refilters in-memory plugins outside marketplace mode.
- Cache behavior: Prompt discovery may reuse service-internal state, but this diff adds no dedicated cache. Selection checks use an in-memory map. Remote item status is derived from current session state.
- Mechanism confidence: High that refreshes occur; insufficient evidence that this UI-only work independently causes meaningful jank beyond the separately reported sync pipeline.
- Magnitude uncertainty: The prompt service's warm-cache behavior and typical list size are not established strongly enough to attribute a separate UI regression.
- Expensive boundaries:

### Scenario 5: Copying a client-hosted plugin through the new reverse filesystem protocol

- Critical path: Directory browse and file fetch responses are required by FileService.copy; plugin parsing and plugin-aware session progress wait for the entire copy.
- Scaling input: Directory count D, file count F, file bytes B, selected plugin count P, and active copy generations.
- Effective concurrency: AgentPluginManager runs plugin roots concurrently and FileService runs sibling copies concurrently. Each request remains pending until a response or connection close; no explicit timeout exists, but the main reported issue is the unbounded aggregate burst.
- Cache behavior: A matching nonce skips the copy completely. Direct installed plugins have no nonce and therefore always take the cold path. The cache stores up to 20 plugin entries but does not cap input concurrency.
- Mechanism confidence: Very high for per-entry boundary cardinality, whole-file encoding, cache conditions, and concurrency.
- Magnitude uncertainty: Plugin directory layouts vary and the transport may be local or remote, affecting absolute duration. The request-timeout risk was not reported separately because prevalence of indefinitely hanging providers is less certain.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/protocolServerHandler.ts:236</code>: Server-to-client browseDirectory JSON-RPC; cardinality: Approximately D calls per uncached plugin tree.
    - Introduced by diff: true; previous behavior: No reverse filesystem request path existed.; critical-path effect: Each directory traversal waits for the client response.
  - filesystem at <code>src/vs/platform/agentHost/electron-browser/remoteAgentHostProtocolClient.ts:277</code>: Client fileService.resolve/readFile for server requests; cardinality: One resolve per browsed directory and one full read per fetched file.
    - Introduced by diff: true; previous behavior: The remote-agent protocol client did not serve filesystem reads to the server.; critical-path effect: Responses cannot be sent until each local/remote provider operation completes.
  - serialization at <code>src/vs/platform/agentHost/electron-browser/remoteAgentHostProtocolClient.ts:290</code>: Base64-encode each complete file into a JSON-RPC response; cardinality: One full-file encoding per fetched file, producing roughly 4/3 B payload bytes plus transient buffers.
    - Introduced by diff: true; previous behavior: No client-file payload encoding occurred on this protocol.; critical-path effect: Encoding and transfer are required before each target write can finish.
- Verdict: Reportable as part of the concurrent-copy and repeated-session-sync findings; the reverse protocol itself is necessary, so the actionable regressions are scheduling and deduplication rather than its existence.
