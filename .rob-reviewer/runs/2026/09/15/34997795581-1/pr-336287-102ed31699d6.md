**Relevant issue families:** eager-work, boundary-fanout, concurrency-burst, cache-lifecycle, cleanup-lifecycle

### Scenario 1: Agents Window startup and dynamic editor-association registration

- Critical path: The static configuration registers immediately; the dynamic schema rebuild waits for installed extensions and runs after registration changes or the Markdown-default setting change. The changed helper performs constant-size object construction on this path.
- Scaling input: Registered editor count controls the pre-existing dynamic schema rebuild; the diff adds one constant HTML association independent of that count.
- Effective concurrency: Dynamic registration events are already debounced; configuration-setting changes invoke one synchronous rebuild. The diff does not alter scheduling or concurrency.
- Cache behavior: No cache or remote lookup is involved. Static and dynamic defaults are reconstructed when their existing registration paths run.
- Mechanism confidence: High confidence that no meaningful startup regression is introduced because the changed work is constant and surrounding editor enumeration/re-registration is unchanged.
- Magnitude uncertainty: None material: the added work is one platform boolean read and one object property assignment.
- Expensive boundaries: none found
- Verdict: No reportable regression. The startup/configuration path gains only constant-size in-process work.

### Scenario 2: Opening a local HTML file in the desktop Agents Window

- Critical path: Editor resolution now selects workbench.editor.browser. Its factory creates a lazy BrowserEditorInput and immediately starts resolve; visible browser content depends on main-process browser-view creation and file URL navigation, although createEditorInput itself does not await page loading.
- Scaling input: One native browser view per distinct concurrently open HTML resource. Reopening the same resource while its editor is open is deduplicated by singlePerResource; opening N distinct HTML files can create N views.
- Effective concurrency: The normal single-file user action creates one view. There is no global limiter for distinct files, so an external multi-open request could create views concurrently, but the diff adds no collection loop or fan-out caller and each view is the requested preview renderer.
- Cache behavior: Cold open creates a BrowserEditorInput, main-process view, and navigation. Warm same-resource opens reuse the existing editor while open. Closing disposes the model/native view; a later reopen creates a fresh view. Browser session state may be shared, but native views are not cached after close.
- Mechanism confidence: High confidence in the changed routing and boundary creation; lower confidence that realistic cardinality makes it a regression rather than the inherent cost of the requested HTML preview behavior.
- Magnitude uncertainty: WebContents memory/startup cost and page subresource count vary by platform and document, and no changed caller establishes bulk opening as a normal Agents Window workflow.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts:\_getOrCreateLazy</code>: Proxy call to the main process getOrCreateBrowserView.; cardinality: One call per newly created browser editor for a distinct HTML resource; same-resource opens are deduplicated while open.
    - Introduced by diff: true; previous behavior: Without the new Agents Window HTML association, ordinary HTML opens resolved to the prior default text editor and did not call the browser-view main-process service.; critical-path effect: Required to create the browser model; started eagerly during editor resolution, with the editor able to show loading state while navigation continues.
  - other expensive boundary at <code>src/vs/platform/browserView/electron-main/browserView.ts:BrowserView constructor</code>: Constructs an Electron WebContentsView and attaches it to the window.; cardinality: One native WebContentsView per distinct open HTML browser editor.
    - Introduced by diff: true; previous behavior: The prior default text-editor path did not allocate a WebContentsView.; critical-path effect: Required before the Integrated Browser can render the file.
  - filesystem at <code>src/vs/platform/browserView/electron-main/browserView.ts:loadURL</code>: Electron webContents loads the local file:// HTML document and any page-defined subresources.; cardinality: One top-level navigation per cold browser-editor open, plus subresource requests determined by the HTML page.
    - Introduced by diff: true; previous behavior: The prior text editor read the source through the text-file/model path and did not execute the document or load its browser subresources.; critical-path effect: The preview is not usable until the document load makes progress; navigation is asynchronous relative to returning the editor input.
- Verdict: No reportable performance bug. The heavier boundary is the intentional renderer needed for the new default preview, same-resource work is deduplicated, resources are disposed, and the diff introduces no realistic fan-out or redundant creation mechanism.

### Scenario 3: Opening HTML diff editors in the Agents Window

- Critical path: Diff resolution uses workbench.diffEditorAssociations, whose changed helper intentionally contains only the Markdown rule, so HTML diffs continue through their existing editor resolution path.
- Scaling input: One resolution per diff open; the number of files shown in the diff does not add browser views through this change.
- Effective concurrency: Unchanged from the pre-diff diff-editor path.
- Cache behavior: No browser-view cache is reached by this change for HTML diffs.
- Mechanism confidence: High confidence from the separate diff-association helper and resolver's diff association selection.
- Magnitude uncertainty: None material for the changed code.
- Expensive boundaries: none found
- Verdict: No regression. The change explicitly avoids routing HTML diffs through Integrated Browser.

### Scenario 4: Opening HTML in a web-hosted Agents Window

- Critical path: The default helper checks isWeb and omits the Integrated Browser association, so web HTML opens remain on the existing editor path.
- Scaling input: One constant platform check during association construction; HTML-open cardinality does not reach browser-view creation.
- Effective concurrency: Unchanged.
- Cache behavior: No new cache or browser-view service is reached.
- Mechanism confidence: High confidence because the changed condition directly gates the association on \!isWeb.
- Magnitude uncertainty: None material.
- Expensive boundaries: none found
- Verdict: No regression. Integrated Browser is unavailable in web and the new default is not registered there.

**Summary:** Reviewed the complete two-file diff and traced startup/configuration, desktop HTML open, HTML diff, and web scenarios through editor resolution, main-process IPC, native WebContents creation, file navigation, reuse, concurrency, and disposal. No high-confidence actionable performance regression was found; the only meaningful added cost is the intentional browser renderer required by the feature, bounded to distinct open HTML editors and cleaned up on close.
