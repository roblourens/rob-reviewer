## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `extensions/copilot/src/platform/endpoint/node/responsesApi.ts:663` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/src/platform/endpoint/node/responsesApi.ts:665`  
**Introducing path:** `extensions/copilot/src/platform/endpoint/node/responsesApi.ts`  
**Introducing commit:** `9497c551b1ffb03c18fb5271aeb38733956938f3`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.96

**Mechanism:** A prefix heuristic discarded valid encrypted Responses reasoning with non-rs IDs while serializing assistant history. In multi-round tool use, each following model request therefore lacked the opaque reasoning state and had to regenerate reasoning already completed in the prior round.

**Symptom:** Responses-backed agent/tool loops using non-rs reasoning IDs incur extra reasoning-token generation and longer sequential model turns because prior reasoning is omitted from replay.

**Fixed behavior:** The new envelope carries the producing API, and the Responses serializer now admits encrypted reasoning whenever originApi is 'responses' regardless of identifier prefix, while retaining the prefix fallback only for legacy untagged history. This restores prior reasoning to each subsequent Responses request and avoids repeated model reasoning work.

**Evidence:** In the base revision, extractThinkingData admitted encrypted reasoning only when isResponsesReasoningId returned true, and base line 665 implemented that as id.startsWith('rs'). The changed regression tests exercise a Responses-origin item with the production-style non-rs id CzDhIBSZ31VSyW6rYILnFerwKDkArecaC and show that it must be serialized as a reasoning item. createResponsesRequestBody invokes extractThinkingData for every assistant message before ChatMLFetcher sends the next Responses network request, and the tool loop can make repeated sequential requests (normally configured around 15, with autopilot extending up to 200). Dropping the opaque prior reasoning on each subsequent tool round makes the model re-derive that reasoning rather than resume it, increasing generated reasoning tokens and round latency.
