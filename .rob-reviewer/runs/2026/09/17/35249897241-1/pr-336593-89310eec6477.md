<summary>Reviewer scenario analysis</summary>

**Relevant issue families:** synchronous-ui-work, eager-work, cache-lifecycle

### Scenario 1: Open the unified workspace picker and move the pointer across the Remote row

- Critical path: Picker progress requires synchronous construction of the in-memory item model and initial list layout. Hovering Remote now schedules submenu creation after the standard 500 ms delay; transient pointer crossings cancel before submenu DOM construction, so that work is off the critical path unless the pointer remains.
- Scaling input: At most 10 Agents recents plus the service's cached, deduplicated VS Code recents (capped at 10), together with registered provider browse/manage actions and remote hosts. Submenu width measurement falls back to 380 px at 50 or more total items.
- Effective concurrency: Picker construction is synchronous. Submenu hover uses one replaceable timeout; moving to another row cancels the prior show, so there is no aggregate creation burst.
- Cache behavior: Agents recents come from profile storage and VS Code recents come from the service's cached \_vsCodeRecentFolders array. On a cold history load the picker uses the currently available cache and is refreshed by the existing event; warm opens reuse the loaded cache. The diff changes neither keys, invalidation, misses, nor coalescing.
- Mechanism confidence: High: the hover scheduler, cancellation, history caps, and synchronous DOM layout path are explicit in the traced code.
- Magnitude uncertainty: Provider counts and label lengths vary, but recent-history cardinality and the rendered submenu viewport are bounded.
- Expensive boundaries: none found
- Verdict: No regression. Removing submenuPointerIntent changes Remote hover from immediate synchronous submenu construction to delayed, cancellable construction, reducing eager UI work.

### Scenario 2: Open the Remote submenu by click or Enter and display it near the viewport edge

- Critical path: The explicit activation synchronously creates the nested ActionListWidget, lays it out, measures row widths with DOM geometry reads, positions the panel, and focuses the nested widget for keyboard activation. No external boundary must complete before the submenu appears.
- Scaling input: Work scales with the effective remote submenu item count, while DOM rendering remains virtualized to the viewport. The new vertical calculation can expose up to the screen's worth of rows instead of one row; width remains viewport-clamped, and lists of 50 or more use the existing 380 px width shortcut.
- Effective concurrency: One submenu widget exists at a time; showing another clears and disposes the previous per-submenu resources. Activation is synchronous and serialized on the UI thread.
- Cache behavior: The submenu consumes actions and filter items already assembled when the parent picker opened; it performs no cache lookup or refresh. Cold and warm behavior are therefore identical for this activation step.
- Mechanism confidence: High: construction, computeListHeight, computeMaxWidth, geometry reads, viewport clamping, and list virtualization are directly traced.
- Magnitude uncertainty: Actual row count and viewport size vary, but both the history source and visible DOM row count are bounded. Wider labels can increase the chosen internal width below 50 items, but do not add width-measurement passes compared with the capped pre-diff behavior.
- Expensive boundaries: none found
- Verdict: No reportable regression. Enter adds this bounded work only on deliberate activation; click already performed it. Removing maxWidth changes the resulting width but not the existing measurement pass, and the vertical shift intentionally uses otherwise available viewport space without rendering an unbounded list.

### Scenario 3: Filter or resize an open Remote submenu

- Critical path: Typing filters the already-created in-memory item list and requests a synchronous nested-list relayout. Window resize invokes the stored submenu layout function directly; neither path waits on external work.
- Scaling input: Filtering and height recomputation scale linearly with the bounded submenu item set; rendered rows remain constrained to the available viewport.
- Effective concurrency: Input events execute serially on the UI thread. The nested layout request is immediate, while resize observation for non-list hover content is animation-frame coalesced; this changed submenu uses the list path.
- Cache behavior: Filtering operates on \_allMenuItems and does not query or invalidate workspace history. There is no cold-cache retry or negative-cache behavior.
- Mechanism confidence: High: filter layout events and resize ownership are explicit in ActionListWidget.
- Magnitude uncertainty: Rapid typing or resize frequency is device-dependent, but the diff adds only constant-time desired-height arithmetic to each existing layout and does not add a new observer or boundary.
- Expensive boundaries: none found
- Verdict: No regression. The changed geometry calculation does not add collection-wide DOM measurement or external work per event.

### Scenario 4: Select a remote workspace after opening the submenu with the keyboard

- Critical path: After a separate child-row activation, the submenu action populates the existing parent item and dispatches selection. A disconnected provider connection and any local file existence validation are sequentially awaited before selection can finish; these operations are not performed merely by the newly supported Enter-to-open action.
- Scaling input: One selected child produces at most one provider connection attempt and at most one file existence check. Browse actions similarly execute only the single selected provider action, not one call per listed workspace.
- Effective concurrency: Selection is sequential and generation-guarded. provider.connect completes before validation, and no Promise.all fan-out is introduced.
- Cache behavior: Connected providers skip provider.connect on warm state; already-loaded submenu data is reused. The diff does not alter connection state caching, recent-history caching, or failure retry behavior.
- Mechanism confidence: High: the submenu delegate, dispatch path, sequential awaits, and boundary calls are directly traced.
- Magnitude uncertainty: Remote connection duration varies by provider, but call cardinality and its placement after explicit child selection are clear.
- Expensive boundaries:
  - network at <code>src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts:\_connectProviderOnDemand</code>: Connect the selected remote provider on demand; cardinality: Zero when already connected; otherwise one call for the single selected workspace
    - Introduced by diff: false; previous behavior: The same call followed child selection after click or existing submenu keyboard navigation; the diff only lets Enter open the submenu.; critical-path effect: Blocks completion of the selected remote workspace action, but not submenu opening
  - filesystem at <code>src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts:\_canSelectWorkspace</code>: Check whether a selected file-scheme workspace exists; cardinality: At most one exists call for the single selected file-scheme workspace
    - Introduced by diff: false; previous behavior: The same validation ran for remote submenu selections reached through existing pointer or ArrowRight activation.; critical-path effect: Blocks final selection validation, but not submenu opening
- Verdict: No regression. The PR does not move remote connection or filesystem validation onto Enter-to-open; those boundaries remain behind a separate explicit child selection and retain cardinality one.
