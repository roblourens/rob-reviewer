### Scenario 2: Scroll the Tools inventory or a customization migration category with enough sections to overflow the pane.

- Critical path: Each wheel/scroll input updates the native scrollTop and overlay scrollbar position. No virtualized-row layout, DOM rebuild, filesystem work, IPC, or network request is scheduled by the added scroll listeners.
- Scaling input: Scroll-event frequency and content height. Each added listener performs one scrollTop read and one constant-time setScrollPosition; Scrollable.\_setState exits immediately when the browser event reflects the already-current position.
- Effective concurrency: Browser scroll events are serialized on the UI thread. Layout remains separately coalesced to the next animation frame and is not triggered by these listeners.
- Cache behavior: No cache is involved. DomScrollableElement retains only current dimensions and position; the added disposable listeners are released with their owning editor/widget.
- Mechanism confidence: High: the event path was traced through DomScrollableElement.setScrollPosition and Scrollable.\_setState.
- Magnitude uncertainty: High-frequency touchpad input can generate many events, but direct inspection proves the synchronization is O(1), state-equality suppresses duplicate emissions, and the same pattern is established in adjacent customization lists.
- Expensive boundaries: none found
- Verdict: No reportable synchronous-UI regression. The bridge neither creates a feedback loop nor performs layout/allocation per scroll event.

### Scenario 3: Resize the customization pane while Tools or a migration category is visible.

- Critical path: Resize observation schedules section measurement and WorkbenchList layout for the next animation frame, followed by one scanDomNode to update overlay scrollbar dimensions.
- Scaling input: Number of visible virtualized sections and entries used to aggregate row heights. The wrapper change does not increase section or entry cardinality.
- Effective concurrency: Tools and migration layout callbacks are each coalesced to a single pending animation-frame disposable, preserving prior backpressure.
- Cache behavior: No cache behavior changes. Existing per-section scroll positions are preserved across layout as before.
- Mechanism confidence: High: both schedule/layout paths and ResizeObserver ownership were inspected.
- Magnitude uncertainty: Pane resize frequency depends on user interaction, but the diff does not add observers or extra layout callbacks; it changes only the measured scroll target.
- Expensive boundaries: none found
- Verdict: No reportable layout regression. Work remains frame-coalesced and has the same collection scaling as before.
