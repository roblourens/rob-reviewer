### Scenario 1: Open a workbench or Sessions multi-diff editor using the default no-cards or experimental cards presentation

- Critical path: The existing input resolves resources and text models, creates one retained DiffEditorViewModel per document, waits for initial diffs (or the existing timeout), then the virtualized widget creates templates for the rendered viewport. The diff only adds synchronous variant lookup and presentation configuration to this path.
- Scaling input: Changed-resource count controls existing model-resolution and diff-computation cardinality; rendered DOM remains bounded by the virtualized viewport/template pool rather than all files.
- Effective concurrency: Original and modified model references resolve in parallel per resource, document promises are joined together, and diff view models may compute concurrently. The PR does not alter this existing concurrency or add a limiter/burst.
- Cache behavior: MultiDiffEditorInput lazily creates and retains one view model; DocumentDiffItemViewModel retains diff results. Variant choice does not change keys, cold loading, or warm reuse.
- Mechanism confidence: High: the changed constructor options feed the same retained view models into a virtualized widget, while model resolution and diff computation are unchanged.
- Magnitude uncertainty: Exact model-load and diff durations depend on resource schemes, file sizes, and providers, but none of those costs or cardinalities is introduced or amplified by the changed presentation path.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorInput.ts:\_createModel</code>: Resolve original and modified text-model references for each changed resource; cardinality: Up to two model-reference resolutions per resource; the two sides are grouped with Promise.allSettled and all document promises are subsequently joined.

- Verdict: No reportable regression. Initial card rendering adds bounded local DOM styling/disclosure controls but no new filesystem, IPC, network, or diff-computation fan-out.

### Scenario 2: Scroll through a card multi-diff containing many files and many unchanged regions

- Critical path: The compressed virtualized scroll view synchronously binds and renders only viewport-adjacent DiffEditorItemTemplates. Each rendered compact diff creates disclosure view zones and overlay DOM for its unchanged regions; hidden file items release bindings unless focus/keep-alive requires retention.
- Scaling input: Cost scales with unchanged-region count inside the currently instantiated diff-editor templates and with the number of viewport templates, not the total number of files after virtualization.
- Effective concurrency: Rendering and DOM/layout updates are synchronous on the UI thread and serialized by scroll/layout processing; no subprocess, IPC, filesystem, database, or network operations are added.
- Cache behavior: The virtualized template pool reuses up to a bounded set of inactive templates and disposes excess templates; disclosure observables and listeners are owned by and disposed with each template.
- Mechanism confidence: High: VirtualizedItemManager bounds file-template instantiation, reader stores dispose rerendered breadcrumb listeners/hovers, and overlay widgets are disposed with templates.
- Magnitude uncertainty: A pathologically fragmented single-file diff can contain many disclosures, but the added nodes/listeners are small, local, and required by the persistent disclosure design; no evidence shows a realistic frame-time regression.
- Expensive boundaries: none found
- Verdict: No reportable regression. The added per-region DOM and delayed-hover registrations are bounded to rendered templates and are not repeated per frame or leaked across virtualization.

### Scenario 3: Expand or collapse unchanged lines using the compact disclosure

- Critical path: A click or key event synchronously updates one UnchangedRegion, recalculates its hidden ranges/view zones and disclosure DOM, and relayouts the owning diff editor while preserving the scroll anchor where applicable.
- Scaling input: A single interaction affects one unchanged region in one rendered editor; DOM rebuilding scales with that region's breadcrumb depth, while editor relayout scales with the revealed line range.
- Effective concurrency: The event and observable updates are serialized on the UI thread; no external operations are launched.
- Cache behavior: Breadcrumb items come from the existing outline source; added delayed hovers are lazy and autorun-owned registrations are replaced and disposed on each rerender.
- Mechanism confidence: High: the changed handlers call showAll/collapseAll only for their owning UnchangedRegion and listener ownership is explicit.
- Magnitude uncertainty: Large revealed ranges can make the pre-existing editor relayout expensive, but the PR does not add repeated reveal operations or broaden one interaction to all files/regions.
- Expensive boundaries: none found
- Verdict: No reportable regression. Persistent controls intentionally retain a small disclosure row after expansion, with bounded lifecycle and no fan-out.

### Scenario 4: Change multiDiffEditor.experimental.variant while a multi-diff editor is open

- Critical path: The configuration event synchronously disposes the old MultiDiffEditorWidgetImpl, creates a replacement, restores view state, reattaches the existing MultiDiffEditorViewModel, and recreates the content overlay. This work is on the setting-change UI path but not on ordinary scrolling, typing, startup, or rendering updates.
- Scaling input: Reconstruction cost scales with currently instantiated virtualized templates and local view-item metadata; it does not scale model loads or initial diff computations with total resource count because the existing view model is reused.
- Effective concurrency: Replacement is synchronous and serialized in one configuration autorun; observableConfigValue filters unrelated configuration events and setVariant coalesces identical values.
- Cache behavior: The retained MultiDiffEditorViewModel preserves text-model references and computed diff state. The old widget/template pool is deliberately disposed and a fresh local pool is created; no negative cache or external fetch is involved.
- Mechanism confidence: High: \_replaceWidgetImpl detaches and reuses the same view model, and the virtualized manager bounds active templates.
- Magnitude uncertainty: A variant toggle can produce a brief one-time UI cost in a densely rendered viewport, but it is a rare explicit/experiment configuration event and evidence does not establish material latency.
- Expensive boundaries: none found
- Verdict: No reportable regression. Full local reconstruction is intentional for live variant changes, properly cleaned up, and does not repeat expensive model or diff boundaries.

No high-confidence diff-introduced performance issue met the reporting threshold; expensive model-loading and diff-computation boundaries are unchanged, while added UI work is virtualized, event-bounded, and disposed.
