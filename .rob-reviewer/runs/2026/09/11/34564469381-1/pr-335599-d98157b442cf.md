**Relevant issue families:** boundary-fanout, repeated-work, missing-coalescing, cleanup-lifecycle, cache-lifecycle, concurrency-burst, synchronous-ui-work

### Scenario 1: Open or switch the Agents Window chat input to a running remote AHP session and render dedicated and generic configuration chips.

- Critical path: The active session resource is resolved to its owning connection, then a session-state subscription must hydrate before chips can render. A connection change can re-run resolution and local schema synchronization; only a changed/failed target reacquires the subscription.
- Scaling input: The number of rendered generic schema properties determines local picker objects/listeners, but not wire subscription count; effective boundary cardinality remains one per active session/connection after ref-counting.
- Effective concurrency: A single shared subscribe request is initiated for the active session. On creation retry, the first reacquisition replaces the errored cache entry and later chip reacquisitions share the pending replacement.
- Cache behavior: AgentSubscriptionManager caches subscriptions by resource while referenced. Warm per-property acquisitions share the existing state; errored subscriptions are evicted and retried once after a matching SessionAdded notification.
- Mechanism confidence: High confidence in the shared-subscription behavior and connection-event call path from AgentHostConnectionsService through the lane and picker listeners.
- Magnitude uncertainty: Third-party schemas could expose more generic fields, increasing local listeners and render work, but expected schemas are small and no concrete large-cardinality case establishes a user-visible regression.
- Expensive boundaries:
  - network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostGenericConfigChips.ts:\_reattach</code>: Subscribe to the owning remote host's session state.; cardinality: One wire subscription per active backend session and connection; the lane and its per-property pickers acquire ref-counted references to the same AgentSubscriptionManager entry.
    - Introduced by diff: true; previous behavior: Remote resources did not resolve through the owning host, so usable remote generic controls were absent; local sessions subscribed through the ambient host.; critical-path effect: The initial snapshot gates remote chip rendering; subsequent consumers share the hydrated subscription.
- Verdict: No reportable regression: the new remote boundary is required for the feature and remains coalesced to one subscription rather than fanning out per chip.

### Scenario 2: Open and filter a mutable dynamic configuration picker on a remote session.

- Critical path: Opening waits for sessionConfigCompletions before showing dynamic options; filter updates are delayed by 200 ms and the latest result is applied by the action-list cancellation guard.
- Scaling input: Request count scales with user pauses longer than 200 ms while typing, not raw keystrokes; provider result size controls returned serialization and rendering.
- Effective concurrency: Usually one request after typing settles; multiple requests can overlap when remote latency exceeds the interval between debounced queries, matching the pre-existing picker scheduling semantics.
- Cache behavior: No completion cache is used. The Delayer coalesces pending keystrokes, and stale action-list results are ignored through cancellation tokens, although transport work already started is not cancelled.
- Mechanism confidence: High confidence in the RPC and debounce path, but insufficient evidence that routing the required request to its authoritative remote provider creates an actionable regression rather than the intended feature cost.
- Magnitude uncertainty: Remote latency and provider-specific completion cost vary; current in-repository mutable dynamic schemas do not demonstrate a realistically severe generic-field workload.
- Expensive boundaries:
  - network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts:\_getItems</code>: Request dynamic session configuration completions from the session's owning remote host.; cardinality: One request on picker open and at most one request per query that remains unchanged for the 200 ms delay; requests already in flight are not transport-cancelled.
    - Introduced by diff: true; previous behavior: The same picker path called sessionConfigCompletions on the ambient connection; remote sessions did not have a usable correctly routed picker.; critical-path effect: The initial request gates popup presentation; filter requests gate refreshed option rows.
- Verdict: No finding: the changed boundary is necessary to obtain authoritative remote options, is user-triggered and debounced, and the diff does not increase request frequency relative to the existing picker behavior.

### Scenario 3: Select a mutable configuration value on a running remote session.

- Critical path: The selection dispatches one SessionConfigChanged action to the owning connection, then re-resolves the schema/config on that same host before publishing the local overlay update.
- Scaling input: Boundary work scales with deliberate configuration selections, not schema property count or session history.
- Effective concurrency: Selections can create overlapping resolve requests, but per-session sequence checks ensure only the latest result is committed; normal picker interaction serializes individual choices through closing the picker.
- Cache behavior: The resolved overlay is cached per session resource and invalidated when its connection/backend identity changes or when the chat session is disposed.
- Mechanism confidence: High confidence in dispatch and resolve cardinality from the changed call path and tests.
- Magnitude uncertainty: Provider resolve cost is variable, but cardinality is one per explicit selection and no hot-loop trigger is present.
- Expensive boundaries:
  - network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts:\_setValue</code>: Send the configuration mutation to the remote session.; cardinality: One dispatch per accepted user selection.
    - Introduced by diff: true; previous behavior: The write targeted the ambient host and therefore was unusable for a remote-owned session.; critical-path effect: The picker is hidden before dispatch; the mutation is the authoritative write.
  - network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostUntitledProvisionalSessionService.ts:refreshResolvedConfig</code>: Resolve the resulting configuration schema and values on the owning host.; cardinality: One resolve request per accepted user selection; request sequence checks discard stale responses.
    - Introduced by diff: false; previous behavior: The same post-write resolve call existed, but always used the ambient host; the diff reroutes it to the owning connection.; critical-path effect: The request gates the refreshed local overlay but not hiding the picker or issuing the mutation.
- Verdict: No reportable regression: the remote calls replace incorrectly routed ambient calls and remain bounded to one write plus one refresh per user action.

### Scenario 4: Remote host connect, disconnect, reconnect, or session-resolution policy change while a session is displayed.

- Critical path: AgentHostConnectionsService broadcasts a resolution change. Pickers compare the active resource, connection, and backend identity; unchanged dedicated pickers retain their open state, while changed targets dispose references and reacquire the new owning subscription. Cached config overlays are scanned and only invalidated when their identity changed.
- Scaling input: Local identity-check work scales with active picker count and cached configured sessions; wire work scales with affected active session identities, effectively one for the displayed session.
- Effective concurrency: Resolution event listeners run synchronously, but ref-counted subscription acquisition coalesces them to one pending server subscription.
- Cache behavior: Unchanged subscription references and overlays remain warm. Changed identities clear the relevant overlay and errored subscriptions are replaced; chat-session disposal removes cached resolution entries.
- Mechanism confidence: High confidence that unrelated changes incur only local checks and affected targets share the boundary request.
- Magnitude uncertainty: A workspace with many remote hosts or a third-party schema with many generic fields increases local identity checks, but connection lifecycle events are infrequent and inspected code provides no realistic threshold for visible impact.
- Expensive boundaries:
  - network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts:\_reattach</code>: Re-subscribe to session state when the owning connection/backend identity actually changes.; cardinality: At most one shared wire subscription for the active session after all picker references reacquire.
    - Introduced by diff: true; previous behavior: The controls did not follow owning remote connection changes.; critical-path effect: Hydration gates controls after reconnect; unrelated host changes perform local identity checks only.
- Verdict: No finding: lifecycle work is bounded and expensive subscription work is coalesced; cleanup paths remove listeners, references, and cached session entries.

### Scenario 5: Use local untitled/provisional session configuration before the first message.

- Critical path: Initial schema resolution and provisional session creation continue on the ambient connection; edits are serialized by the existing per-session queue and re-resolve configuration before completing.
- Scaling input: Work scales with the existing count of picker consumers for a local draft; the PR does not increase that count for the local scenario.
- Effective concurrency: Existing initial resolutions may run concurrently; provisional config writes remain serialized per session by SequencerByKey.
- Cache behavior: Per-picker initial results are retained for the current draft and cancelled/cleared on session change; provisional resolved config is cached by session.
- Mechanism confidence: High confidence from before/after diff comparison.
- Magnitude uncertainty: The pre-existing per-picker initial resolution multiplicity was not introduced or materially amplified by this PR.
- Expensive boundaries:
  - ipc at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatInputPicker.ts:\_refreshInitialResolved</code>: Resolve initial local session configuration through the ambient agent host.; cardinality: Existing dedicated pickers and the generic lane can each request initial schema data for a new draft; this multiplicity predates the routing change.
    - Introduced by diff: false; previous behavior: The same ambient resolve path and provisional creation behavior existed before the diff.; critical-path effect: Results gate initial chip content, while provisional creation remains eager as before.
- Verdict: No finding because the local provisional boundary count and scheduling are unchanged by this PR.

**Summary:** Completed the performance pass over all 10 changed files and traced remote rendering, dynamic completion, mutation/re-resolution, reconnect, retry, cache, and local provisional paths. The new remote operations are required feature boundaries, session subscriptions are ref-counted and coalesced, query work retains the existing debounce behavior, and added caches/listeners have disposal or invalidation paths. No high-confidence diff-introduced performance regression was found.
