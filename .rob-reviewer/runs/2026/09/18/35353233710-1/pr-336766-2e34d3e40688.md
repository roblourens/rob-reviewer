### Scenario 1: Mark a session as done from the Sessions list or archive nudge with confetti enabled

- Critical path: The click synchronously reads the target bounds, appends one overlay with 24 particles, and starts 24 Web Animations before dispatching/awaiting the archive command. The animations then run off the command's critical path; the PR changes their duration, not the synchronous particle count or archive service ordering.
- Scaling input: One burst per clicked archive action, independent of the number of sessions in the list. A normal row/nudge click targets one session; any provider persistence scales with selected archive targets but is unchanged by this diff.
- Effective concurrency: Each click creates an independent overlay; there is no coalescing. The archive action serially awaits provider operations for multiple targets. The PR extends the overlap window from a fixed 2-second cleanup to at most 2.58 seconds but does not increase per-trigger concurrency.
- Cache behavior: No animation cache is involved. Session/provider caches and persistence behavior are unchanged; cold versus warm provider state does not alter the 24-particle animation cardinality.
- Mechanism confidence: High: the changed duration ranges, fixed 24-particle count, cleanup deadline, click dispatch order, and provider call path are directly visible in code.
- Magnitude uncertainty: Exact compositor/GPU cost varies by platform, and deliberate rapid repeated clicks can retain roughly 29% more overlapping overlays due to the longer cleanup window. The default setting is off and ordinary use is one bounded burst, so no concrete user-visible regression is established.
- Expensive boundaries:
  - other expensive boundary at <code>src/vs/base/browser/ui/animations/animations.ts:createOverlay/triggerConfettiAnimation</code>: One synchronous getBoundingClientRect, 25 DOM nodes, and 24 compositor-eligible transform/opacity animations; cardinality: Once per enabled click; 24 particle animations per burst
    - Introduced by diff: false; previous behavior: The same layout read, overlay, 24 nodes, and animations already occurred; particles ran for 0.9-1.3 seconds and the overlay was removed at 2 seconds. They now run for 1.98-2.48 seconds and are removed by 2.58 seconds.; critical-path effect: DOM creation and animation setup occur before the archive command starts; the longer playback is off the archive completion critical path
  - IPC/filesystem/network at <code>src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts:BaseArchiveSessionAction.run -&gt; ISessionsManagementService.archiveSession</code>: Provider-specific session archive persistence, including local host fan-out or remote detached-worktree state updates; cardinality: One serial provider operation per selected archive target; commonly one for a row/nudge click
    - Introduced by diff: false; previous behavior: The same provider operation and ordering occurred before the diff.; critical-path effect: Awaited by the archive command, but begins after animation setup and is not delayed by animation playback
- Verdict: No reportable regression. The PR intentionally lengthens a bounded, opt-in visual effect without adding synchronous DOM cardinality or moving provider I/O onto the animation playback path.

### Scenario 2: Upvote a chat response when chat.upvoteAnimation is explicitly set to confetti

- Critical path: The menu action synchronously creates the overlay and starts animations before running the vote action. Vote state update and telemetry logging follow immediately; animation playback is not awaited.
- Scaling input: One 24-particle burst per upvote click. The confetti mode is not the default, and one click affects one response.
- Effective concurrency: Independent clicks can overlap without a limiter, as before. The maximum overlap lifetime rises from 2.0 to 2.58 seconds; there is no collection fan-out.
- Cache behavior: No cache participates in the animation. Configuration lookup and telemetry behavior are unchanged between cold and warm use.
- Mechanism confidence: High for the call order, fixed animation cardinality, and longer lifetime; lower only for platform-specific rendering cost.
- Magnitude uncertainty: Rapid toggle/click behavior could create more simultaneous layers during the extra 580 ms retention window, but no realistic high-frequency trigger or demonstrated jank is present, and confetti requires a non-default user setting.
- Expensive boundaries:
  - other expensive boundary at <code>src/vs/platform/actions/browser/menuEntryActionViewItem.ts:onClick -&gt; src/vs/base/browser/ui/animations/animations.ts:triggerConfettiAnimation</code>: Synchronous target geometry read, DOM allocation, and 24 Web Animations; cardinality: One overlay and 24 animations per click
    - Introduced by diff: false; previous behavior: Identical setup and particle count, with shorter 0.9-1.3 second playback and 2-second cleanup.; critical-path effect: Setup precedes the vote action; playback is off the vote action's critical path
  - network/telemetry at <code>src/vs/workbench/contrib/chat/browser/actions/chatTitleActions.ts:MarkHelpfulAction.run -&gt; ChatServiceTelemetry.notifyUserAction</code>: Logs one vote telemetry event through configured appenders; cardinality: One event per valid upvote action
    - Introduced by diff: false; previous behavior: The same telemetry call occurred after the same animation trigger before the diff.; critical-path effect: Synchronous logging dispatch follows animation setup but does not wait for animation completion
- Verdict: No reportable regression. The visual duration increase is bounded and opt-in, with no added boundary fan-out or critical-path wait.

### Scenario 3: Activate the interactive confetti codicon in the Sessions background

- Critical path: A codicon activation synchronously creates one 24-particle overlay, then announces status and logs one telemetry event. Animation playback continues independently.
- Scaling input: One burst and one telemetry event per deliberate codicon activation; repeated activations are user-click-rate limited but can overlap.
- Effective concurrency: Overlays are independent and uncoalesced both before and after the PR. The changed maximum lifetime allows an additional 0.58 seconds of overlap per burst.
- Cache behavior: No animation cache. Background cell selection changes after activation but does not duplicate a single event.
- Mechanism confidence: High for event cardinality and lifecycle; rendering magnitude is platform-dependent.
- Magnitude uncertainty: A user can intentionally click repeatedly, but the fixed 24-node burst and sub-3-second lifetime do not establish dropped frames or significant retained memory under realistic use.
- Expensive boundaries:
  - other expensive boundary at <code>src/vs/sessions/browser/parts/sessionsPart.ts:activateCodicon -&gt; src/vs/base/browser/ui/animations/animations.ts:triggerConfettiAnimation</code>: Geometry read, overlay/particle DOM creation, and compositor animation startup; cardinality: 24 animations per activation
    - Introduced by diff: false; previous behavior: The same burst existed with shorter particle durations and 2-second overlay cleanup.; critical-path effect: Synchronous setup occurs in the click handler; longer playback is off the handler's remaining status/telemetry work
  - network/telemetry at <code>src/vs/sessions/browser/parts/sessionsPart.ts:activateCodicon</code>: Queues/logs a single codicon activation telemetry event; cardinality: One per activation
    - Introduced by diff: false; previous behavior: Same telemetry event per activation.; critical-path effect: Called after animation startup and does not wait for playback
- Verdict: No reportable regression. The diff increases bounded compositor work duration but not synchronous setup, event count, or telemetry fan-out.

### Scenario 4: Celebrate a chat pet bounce streak reaching the confetti threshold

- Critical path: After a pet lands with at least 20 bounces, the widget computes overlay/pet bounds, positions an anchor, and triggers one confetti burst. No command, IPC, filesystem, database, or network operation is transitively reached by this animation path.
- Scaling input: One burst per qualifying completed bounce streak, not per bounce; each burst has 24 particles.
- Effective concurrency: A subsequent qualifying landing may overlap an existing overlay, but completing another 20-bounce streak is naturally slower than the 2.58-second maximum overlay lifetime in normal interaction. No new concurrency is introduced.
- Cache behavior: No cache is used. The threshold check and anchor reuse are unchanged.
- Mechanism confidence: High: threshold, call path, fixed particle count, and cleanup bounds are explicit.
- Magnitude uncertainty: Exact frame/GPU impact is unknown, but the threshold of 20 bounces makes bursts sparse and prevents realistic accumulation from the changed lifetime.
- Expensive boundaries:
  - other expensive boundary at <code>src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts:\_showBounceConfetti -&gt; src/vs/base/browser/ui/animations/animations.ts:triggerConfettiAnimation</code>: Two caller geometry reads plus the helper geometry read, anchor style writes, 25 DOM nodes, and 24 Web Animations; cardinality: One fixed-size burst per qualifying streak landing
    - Introduced by diff: false; previous behavior: The same geometry reads, nodes, and animation startup occurred; only particle playback and overlay retention are longer.; critical-path effect: Synchronous setup runs during landing completion; playback is asynchronous and does not gate subsequent pet state handling
- Verdict: No reportable regression. The sparse trigger and bounded lifetime make the intentional motion change unlikely to create meaningful accumulation.

The only production performance change is longer playback/retention for an existing fixed-size 24-particle confetti overlay (maximum cleanup 2.58 seconds instead of 2 seconds). Current production callers pass no custom ranges, reduced-motion guards remain in place, relevant settings are off or non-confetti by default, and no subprocess, IPC, filesystem, database, network, collection fan-out, cache, or command wait is introduced.
