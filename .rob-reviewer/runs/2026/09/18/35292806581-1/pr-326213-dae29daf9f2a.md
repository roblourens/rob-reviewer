# Performance review: Add tool search to Copilot agent host

[PR #326213](https://github.com/microsoft/vscode/pull/326213) at `dae29daf9f2a75cf138aff7fe25ef04e402302aa`

## Findings (1)

### 1. [medium] Keep the tool-search corpus out of replayable state

**Finding ID:** `PERF-2A24DF6F6BBC`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:1167</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>unbounded-retention</code>  
**Resource:** Copied tool-name/description objects and their serialized protocol payloads  
**Scaling:** Retained bytes grow with the complete deferred-tool corpus (all deferLoading tools across every configured MCP server) times the number of tool-search ready actions still in the 1,000-envelope replay buffer; canceled searches additionally accumulate one corpus per canceled turn for the session lifetime.  
**Outcome:** Increased renderer/agent-host heap usage, larger reconnect snapshots/replays, and corresponding serialization and GC pressure for sessions with large MCP inventories.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Tool search ranked the extension's local tool registry directly; no tool corpus was copied into an Agent Host action, synchronized chat state, or the server replay buffer.  
**Changed behavior:** Each tool-search invocation maps every deferred SDK tool into a candidate array and attaches that full array to ChatToolCallReady.\_meta so it enters synchronized/replayable state.  
**Confidence:** 0.99 — The added storage point, reducer retention behavior, 1,000-envelope replay buffer, and cancellation path were all traced directly. Exact bytes depend on configured MCP tool counts and description lengths, but the retention and N-tools-per-search scaling are deterministic.

**Causal diff evidence:** The added \`\_meta: toToolCallMeta({ ...(tracked.meta ?? {}), toolSearchCandidates: candidates })\` line is the first point where the previously local-only search corpus is inserted into persistent/replayable Agent Host state.

With tool search enabled and a large MCP inventory, repeated searches retain repeated copies of every tool description. Successful calls remain in ProtocolServerHandler's 1,000-action replay buffer, and canceling a turn while search is running permanently leaves the corpus on that finalized turn, so long sessions can accumulate substantial heap and reconnect payloads.

**Evidence:** \_toToolSearchCandidates() copies every available tool whose deferLoading flag is set, and this added line stores the resulting array in ChatToolCallReady.\_meta. AgentHostStateManager applies that action to chat state, while ProtocolServerHandler unconditionally retains every emitted envelope in \_replayBuffer (capacity 1,000). Although the normal completion path explicitly deletes toolSearchCandidates, old ready envelopes are not rewritten. More importantly, chat reducer endTurn() finalizes interrupted tool calls with tcBase(tc), which preserves tc.\_meta; \_setupClientToolCall cancels its CTS on a terminal turn and handleSettled then returns without dispatching the metadata-clearing completion. Thus cancellation leaves the entire corpus in turns\[\].

**Suggested direction:** Pass the corpus through a targeted non-replayable client-tool request (or store it in a short-lived map keyed by toolCallId) rather than ChatToolCallReady.\_meta, and delete that entry on completion, cancellation, disconnect, and disposal. If the protocol action must remain, strip this transient field before replay buffering and explicitly remove it from terminal canceled/error states.

- Scaling input: N deferred tools after filtering \`deferLoading\`; there is no grouping or deduplication before transport/ranking. Remote embedding work for cold misses is split into ceil(N/100) sequential batches.
- Effective concurrency: One search invocation waits for its own client result. Query embedding requests are not coalesced; missing tool embeddings are coalesced by the shared name-keyed promise map, while each invocation's remote batches are sequential.
- Cache behavior: Cold use initializes the remote precomputed cache and reads the local binary cache. Missing tool embeddings are computed remotely and retained in memory, with a delayed local-file write. Warm searches reuse tool embeddings by name/hash but still compute a fresh query embedding and rebuild/rank the N-item corpus.
- Mechanism confidence: High: the end-to-end handler, transport, cache, and remote batching code were traced.

- Expensive boundaries:

### Scenario 4: Cancel a turn while semantic tool search is running

- Critical path: The client dispatches ChatTurnCancelled, the reducer finalizes every nonterminal tool call as canceled, and the local invocation cancellation token is canceled. The embedding/tool invocation may settle afterward, but its callback returns without dispatching the candidate-stripping completion.
- Scaling input: Complete deferred-tool corpus per canceled search, accumulating with canceled turns retained in a long-lived session.
- Effective concurrency: Cancellation races with the in-flight embedding request. Regardless of which underlying work observes cancellation first, the client settlement callback suppresses completion once its CTS is canceled.
- Cache behavior: Embedding caches do not release the corpus stored on protocol state. Reconnect snapshots include finalized turns and therefore the retained candidate arrays for the current server lifetime.
- Mechanism confidence: Very high: the ready action stores the corpus, endTurn preserves \`\_meta\`, and the cancellation/settlement paths contain no stripping action.
- Magnitude uncertainty: The number of users canceling specifically during search and MCP description sizes vary; the missing cleanup and per-cancel retention are deterministic.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:1941</code>: Sends turn cancellation to the agent host.; cardinality: One cancellation action per canceled turn.
    - Introduced by diff: false; previous behavior: Cancellation already finalized in-flight tool calls, but no full tool corpus existed in their metadata.; critical-path effect: Finalizes the turn promptly, but the reducer preserves tool-call \`\_meta\`.
  - serialization at <code>src/vs/platform/agentHost/node/protocolServerHandler.ts:750</code>: Returns a full chat-state snapshot when replay is unavailable, including retained canceled-turn metadata.; cardinality: One snapshot per restored subscription; payload grows with all retained canceled-search corpora.
    - Introduced by diff: true; previous behavior: Canceled turns contained ordinary small metadata, not every deferred tool description.; critical-path effect: Snapshot transfer and parsing are on reconnect/subscription critical path.
- Verdict: Reportable memory/serialization regression; covered by the submitted finding.
