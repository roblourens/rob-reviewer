**Relevant issue families:** serialization-allocation, boundary-fanout, eager-work, repeated-work, concurrency-burst

### Scenario 1: Cold Copilot client startup and managed-settings diagnostics resolve the packaged SDK/runtime before spawning or importing it.

- Critical path: For a cold agent request, runtime-path resolution must finish before \`RuntimeConnection.forStdio\` can start the Copilot subprocess. Managed-settings diagnostics independently resolves and imports the SDK before its native/network query. Warm \`\_ensureClient\` calls reuse the live client, and concurrent cold callers are coalesced by \`\_clientStarting\`/\`\_ensureClientHealing\`.
- Scaling input: The platform-candidate count is one on macOS/Windows and at most two on Linux; startup frequency is bounded by the coalesced client lifecycle rather than callers.
- Effective concurrency: Three filesystem checks run in parallel per candidate. Client acquisition coalesces concurrent callers, and startup retry remains globally bounded.
- Cache behavior: A live Copilot client is reused for warm calls; startup promises coalesce cold callers. Runtime-path checks have no separate cache, and diagnostics intentionally performs an independent check.
- Mechanism confidence: High: changed file checks, candidate loop, startup caller, and coalescing fields are directly visible.
- Magnitude uncertainty: Filesystem stat latency varies by installation and remote environment, but the diff lowers valid-path operation count and bounds missing-candidate work.
- Expensive boundaries:
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:resolveCopilotRuntimePaths</code>: Tests for the runtime executable, native module, and SDK entry point in each candidate platform package.; cardinality: Three concurrent existence checks for the preferred candidate; Linux can try one additional candidate only when the preferred package is absent. A coalesced cold client start performs this once, while an explicitly requested managed-settings diagnostic performs its own resolution.
    - Introduced by diff: false; previous behavior: A valid candidate required sequential checks for runtime, native module, SDK entry point, and builtin-skills directory, followed by two SKILL.md checks; the diff reduces this to three parallel checks. A missing first candidate can perform up to two more failed stats than the old short-circuit, but this is bounded to three checks and only occurs for an absent preferred package.; critical-path effect: All checks for the selected candidate must complete before client startup or diagnostics can proceed.
  - subprocess at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_ensureClientOnce</code>: Starts the Copilot runtime through \`RuntimeConnection.forStdio\`.; cardinality: One coalesced subprocess per live client lifecycle, with an existing bounded startup self-heal retry.
    - Introduced by diff: false; previous behavior: The same runtime subprocess was started; this diff only removes builtin skill paths from path resolution/session configuration.; critical-path effect: The subprocess must start before sessions can be created or resumed.
  - network at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:getManagedSettingsDiagnostics</code>: Queries native MDM and GitHub managed settings after importing the SDK.; cardinality: One bounded diagnostic query per explicit diagnostics request.
    - Introduced by diff: false; previous behavior: The same diagnostic query ran after a more expensive runtime-path validation.; critical-path effect: Only blocks the requested diagnostics result, not ordinary session progress.
- Verdict: No reportable regression. The normal cold path drops three existence checks and removes sequential dependency; the only adverse edge is two extra parallel stats for an absent preferred package, which is bounded and not a realistic user-visible degradation.

### Scenario 2: Creating or resuming a Copilot session discovers configured skills and assembles outbound model prompts.

- Critical path: Session configuration is built before the SDK \`createSession\`/\`resumeSession\` IPC request. Model prompt assembly and the provider network request occur when the user sends a turn; skill metadata/tool schemas contribute to serialization and input-token processing.
- Scaling input: Cost scales with session create/resume count and model turns; effective explicit skill cardinality is unique directory count after \`toSdkResourceDirectories\` deduplication, reduced by two in this diff.
- Effective concurrency: Each session launch issues one SDK create/resume call. No loop or aggregate burst is added; existing sessions may operate independently.
- Cache behavior: No Agent Host cache is added or defeated. Static prompt prefixes may receive provider-side caching (Anthropic snapshots mark an ephemeral cache-control prefix), but the diff only removes metadata and does not worsen cold or warm behavior.
- Mechanism confidence: High: converter code proves deduplication remains, launcher code proves two paths are removed, and provider snapshots prove smaller outbound prompts/tool lists.
- Magnitude uncertainty: Exact token savings and provider latency vary by model and cache behavior, but all changed mechanisms remove work rather than add it.
- Expensive boundaries:
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:\_buildSessionConfig</code>: The SDK discovers skills from plugin directories and explicit non-file-backed skill directories.; cardinality: Explicit skill directories are deduplicated by \`toSdkResourceDirectories\`; file-backed plugins are represented once through \`pluginDirectories\`. The diff removes exactly two SDK-package builtin skill directories while preserving workspace/client/plugin discovery.
    - Introduced by diff: false; previous behavior: Every create/resume supplied two additional builtin skill directories (\`customize-cloud-agent\` and \`github-pr-media\`) for SDK discovery.; critical-path effect: Skill discovery contributes to session launch and prompt assembly before the session/model request can use those skills.
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:launch</code>: Sends one createSession or resumeSession configuration to the Copilot runtime.; cardinality: One SDK session call per create/resume attempt; no per-skill IPC fan-out is introduced.
    - Introduced by diff: false; previous behavior: The same single session call included two extra builtin skill paths.; critical-path effect: The session call must complete before the session is usable.
  - serialization at <code>src/vs/platform/agentHost/test/node/e2e/providers/\_\_snapshots\_\_/Agent\_Host\_E2E\_\_\_Copilot\_prompts\_gpt-5.prompt.md</code>: Serializes assembled instructions and tool definitions into each provider request.; cardinality: One provider payload per model turn. The changed snapshots show removal of the builtin-skills availability text and the skill tool schema when no remaining skill is available.
    - Introduced by diff: false; previous behavior: Requests advertised the two builtins and included a skill tool definition; the diff removes that metadata, reducing bytes and tokens.; critical-path effect: Payload serialization, transfer, and provider input processing are on the model-response critical path.
  - network at <code>src/vs/platform/agentHost/test/node/e2e/providers/copilotPromptsE2E.integrationTest.ts</code>: Sends the assembled prompt/tool payload to the configured model provider.; cardinality: One request per user/model turn, subject to the provider's existing protocol and prompt caching.
    - Introduced by diff: false; previous behavior: The same provider request carried additional builtin-skill metadata and a skill tool schema.; critical-path effect: The request is the dominant response-latency boundary.
- Verdict: No reportable regression. The feared loss of outer-Set deduplication is neutral because the converter already deduplicates directories; removing the two builtins reduces discovery, serialization, network bytes, and input tokens.

### Scenario 3: Desktop and remote product packaging materializes the target Copilot SDK platform package.

- Critical path: The packaging task ensures the target package is installed, globs its files, filters the stream, and writes the product artifact. This is build-time only and does not block end-user startup after installation.
- Scaling input: The controlling input is file/byte count in one target SDK package, not the number of supported platforms; two directory trees are removed from the copied set.
- Effective concurrency: Desktop and remote packaging each construct one gulp stream for the selected target package; no new per-file subprocess or unbounded parallelism is introduced.
- Cache behavior: Existing node\_modules/package-manager state determines whether ensure work is warm; the diff does not change package keys or installation caching.
- Mechanism confidence: High: both gulp callers and the exclusion glob construction are directly traced.
- Magnitude uncertainty: The exact artifact-byte and build-time reduction depends on SDK package contents, but filtering cannot increase copied file cardinality.
- Expensive boundaries:
  - filesystem at <code>build/lib/copilot.ts:getCopilotRuntimePrebuildFiles</code>: Globs the selected platform package and copies included files into desktop or remote artifacts.; cardinality: One selected SDK package per target build. Work scales with files and bytes under that package; the diff excludes all files under \`builtin/\` and \`builtin-skills/\`.
    - Introduced by diff: false; previous behavior: The selected package glob included both builtin directory trees.; critical-path effect: File enumeration/copying is on the packaging task's critical path, not product runtime.
  - subprocess at <code>build/lib/copilot.ts:ensureCopilotPlatformPackage</code>: Uses the existing npm-package ensure path for cross-target package availability.; cardinality: At most one ensure operation per desktop or remote target packaging invocation.
    - Introduced by diff: false; previous behavior: The same ensure operation ran, then additionally validated two builtin SKILL.md files.; critical-path effect: Package availability must be established before the file stream is created.
- Verdict: No reportable regression. The diff reduces filesystem enumeration/copy volume and packaged artifact size while preserving the required runtime, native module, and SDK entry point.
