# Performance review: sessions: add per-item removal for recorded references and artifacts

[PR #336688](https://github.com/microsoft/vscode/pull/336688) at `a245f680eeaaf2073b7249ca052965d27b74c86a`

## Findings (1)

### 1. [medium] Keep ordinary references out of global PR polling

**Finding ID:** `PERF-B3CE3D6F1595`  
**Location:** <code>src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionArtifacts.ts:121</code> (<code>RIGHT</code>)  
**Performance category:** <code>network</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** GitHub API requests and the retained polling/model objects for each distinct referenced pull request  
**Scaling:** Cost grows with the number of distinct ordinary GitHub pull-request references across all non-archived sessions. Identical coordinates share a model, but each distinct reference starts its own refresh and recurring poll; the session poller launches all distinct refreshes without awaiting or limiting them.  
**Outcome:** Unbounded background GitHub request bursts and recurring network traffic can consume API quota, increase battery/CPU usage, and throttle live PR status updates.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The prior \`if (\!link \|\| \!artifact.isArtifact)\` guard excluded \`isArtifact: false\` references from \`IGitHubInfo\`. They remained simple reference pills and never reached the global GitHub polling contribution; only produced PR artifacts and discovered session associations were refreshed.  
**Changed behavior:** The new \`if (\!link)\` condition promotes every recorded GitHub reference into \`IGitHubInfo\`. \`GitHubPollingContribution\` tracks every non-archived session, iterates \`getGitHubPullRequestRefs\`, and calls \`model.refresh()\`/\`startPolling()\` for each identity. A PR refresh immediately issues pull-request and reviews requests in parallel, then open PRs add CI and review-thread refresh/polling.  
**Confidence:** 0.98 — The changed gate, metadata propagation, global all-session call path, concrete HTTP methods, recurring polling lifecycle, and concurrent scheduling are all directly traced. Exact user prevalence and reference counts are uncertain, which limits severity, but the mechanism and scaling are explicit.

**Causal diff evidence:** The changed RIGHT line 121 replaces the old \`if (\!link \|\| \!artifact.isArtifact)\` filter with \`if (\!link)\`, directly moving all ordinary GitHub references onto the pre-existing global refresh/poll path.

Opening/loading a profile with long-running sessions that accumulated many ordinary PR references now causes a concurrent GitHub API fan-out and keeps those references polling every minute even when their sessions are inactive. This can burn rate limits and create sustained background network work unrelated to the visible session.

**Evidence:** \`partitionSessionArtifacts\` now admits \`isArtifact: false\` GitHub records at line 121 and \`toGitHubInfo\` places them in \`pullRequests\`. The existing \`GitHubPollingContribution\` initializes trackers from all sessions, skips only archived sessions, maps every \`getGitHubPullRequestRefs(gitHubInfo)\` entry, and invokes \`\_pollPullRequest\` in a loop. \`\_pollPullRequest\` calls \`model.refresh()\` without awaiting; \`GitHubPullRequestModel.\_refresh\` performs \`getPullRequest\` and paginated \`getReviews\` via \`Promise.all\`, and open PRs additionally refresh/poll CI and review threads. Artifact collection cardinality is not capped.

**Suggested direction:** Preserve the recorded ID for removal without globally polling ordinary references. For example, keep background polling limited to \`getSessionOwnedGitHubPullRequestRefs\`, and refresh non-owned recorded references only for the active/visible pill (deduplicated by GitHub coordinates and with a concurrency bound).
