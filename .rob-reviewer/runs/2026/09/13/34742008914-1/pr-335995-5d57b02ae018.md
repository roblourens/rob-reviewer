### 1. repeated-work

**Fix location:** `test/sanity/src/uiTest.ts:211` (`RIGHT`)  
**Blamed base line:** `test/sanity/src/uiTest.ts:209`  
**Introducing path:** `test/sanity/src/uiTest.ts`  
**Introducing commit:** `9de7db1a5c6a1196504dc85ace3a219c4e1c537c`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.96

**Mechanism:** A failed Marketplace install blocked the sanity-test critical path on a five-minute success-only timeout before every retry, repeating up to three times despite the UI already exposing failure.

**Symptom:** Transient or visible Marketplace installation failures could leave each affected release sanity target idle for five minutes per attempt, adding up to roughly fifteen minutes before final failure.

**Fixed behavior:** The new Promise.race advances as soon as installation succeeds or an explicit retry/error signal appears, eliminating the unconditional five-minute failure wait before each retry while preserving serial attempts and the existing three-attempt bound.

**Evidence:** In the base revision, each failed install attempt awaited only `uninstallButton.waitFor({ timeout: 5 * 60_000 })`, converted timeout to false, and the surrounding three-attempt loop could not retry until that full timeout elapsed. The changed code races installation success against the scoped install action becoming visible again and the Marketplace message becoming visible, both direct UI signals that the attempt has ended, so failed attempts can leave the critical path immediately. `UITest.run` awaits this method in desktop, server-web, dev-tunnel, and WSL sanity workflows.
