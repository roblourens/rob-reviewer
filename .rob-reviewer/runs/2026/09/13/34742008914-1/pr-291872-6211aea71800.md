## Findings (1)

### 1. [medium] Bound the per-binary codesign fan-out

**Finding ID:** `PERF-D83C91C5BC23`  
**Location:** <code>build/darwin/sign-server.ts:63</code> (<code>RIGHT</code>)  
**Performance category:** <code>subprocess</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** A separate codesign subprocess and secure-timestamp operation for every Mach-O file in both server distributions  
**Scaling:** Critical-path time grows linearly with the number of Mach-O executables and native modules across the regular and web server trees; effective concurrency is one because every spawn is awaited before the next file and the two script invocations are also sequential.  
**Outcome:** Increased macOS production-build latency and reduced release-pipeline throughput, with exposure to accumulated timestamp-service latency or timeouts.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The server and web-server trees were packaged immediately after building, with no per-binary codesign subprocess or timestamp request on this path.  
**Changed behavior:** The new recursive loop scans each complete server tree and awaits \`codesign --timestamp\` once for every Mach-O file; the pipeline invokes the script for the regular server and then the web server before either archive can be packaged.  
**Confidence:** 0.96 — The changed loop, serial await, two callers, package contents, and pre-package critical-path placement are directly visible. Exact wall-clock cost and native-binary count vary by product mix and timestamp-service latency, which affects severity rather than the mechanism.

**Causal diff evidence:** Added line 63 awaits \`spawn('codesign', ...)\` inside the added per-file loop; together with added \`--timestamp\` at line 67 and the two new sequential callers, this changes the prior zero-call path into one boundary call per discovered Mach-O in each server tree.

A production build for each macOS architecture now serializes signing of the Node executable and retained native dependencies/extensions in both server variants. As that native-binary set grows, each subprocess startup and timestamp round trip is added to the packaging critical path instead of overlapping, potentially adding substantial release latency.

**Evidence:** \`packageTask\` in build/gulpfile.reh.ts includes the Node runtime, production dependencies, built-in extensions, and extension dependencies in both server variants; build/.moduleignore explicitly retains many native \`.node\` files and helper executables. Changed line 63 places an awaited process spawn inside the recursive Mach-O loop, and line 67 requests a timestamp. The changed pipeline runs this script twice sequentially at product-build-darwin-compile.yml:222-223 before packaging at lines 247-260.

**Suggested direction:** Collect the Mach-O paths and sign them with a small bounded worker pool (including an explicit concurrency cap compatible with keychain and timestamp-service limits), or omit secure timestamps from this temporary local signature if the subsequent ESRP signing replaces it. Preserve completion before packaging and propagate any worker failure.
