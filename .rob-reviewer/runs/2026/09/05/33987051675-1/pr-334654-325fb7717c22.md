- Critical path: Policy refresh publishes an in-memory observable. New-chat selection synchronously reads that boolean and chooses a session URI; actual Agent Host session creation occurs later when the selected chat session is materialized and is then on the chat-start critical path.
- Scaling input: One routing decision per new/reset chat; policy-source count does not multiply session creation.
- Effective concurrency: Selection is synchronous and constant-time. Agent Host creation remains the existing per-session path; this PR does not add parallel creation, fan-out, or a new listener.
- Cache behavior: The effective sandbox value is retained in AccountPolicyService and exposed through an event-backed observable. Warm Agent Host reuse is owned by the existing Agent Host service; the diff neither invalidates nor bypasses it.
- Mechanism confidence: High that routing changes for a realistic false/true source conflict and reaches the existing Agent Host createSession boundary; low evidence that this safety-required route is an avoidable performance degradation.
- Magnitude uncertainty: The cold-versus-warm cost of an Agent Host session is not quantified, and local-harness relative cost is not established.
- Expensive boundaries:

- Verdict: No reportable performance issue. The one-per-session boundary is the intended mechanism for enforcing the managed sandbox contract, with no evidence of redundant work or a bounded alternative that preserves enforcement.
