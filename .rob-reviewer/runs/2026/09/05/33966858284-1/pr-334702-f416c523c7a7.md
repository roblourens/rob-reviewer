### Scenario 1: Open or switch an Agent Host chat in the workbench chat view/editor and show live input status pills

- Critical path: The widget resolves the Agent Host session, acquires session state, resolves the active changeset, and acquires its state before change counts and metadata-backed pills can appear. Local browser-view enumeration and pill DOM updates are synchronous on this UI path.
- Scaling input: One active Agent Host session/changeset per chat widget, plus scans over known browser views and session metadata collections when those observables change.
- Effective concurrency: Session and changeset subscriptions start asynchronously; the subscription manager coalesces duplicate resource subscriptions by refcount. No unbounded parallel loop is added.
- Cache behavior: Active Agent Host subscriptions are shared while references remain; disposing the widget releases them and the last release unsubscribes. Browser data is local and recomputed on browser-view changes.
- Mechanism confidence: High: the changed gate and the subscription call path are explicit, and subscription-manager sharing/lifecycle are implemented in repository code.
- Magnitude uncertainty: Remote snapshot latency and the number of simultaneously instantiated chat widgets vary, but cardinality is bounded and the pre-PR default already enabled this path.
- Expensive boundaries:
  - IPC/network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts:253</code>: Agent Host protocol state subscription for the session snapshot; cardinality: One logical session resource per active widget; duplicate holders are ref-counted and share one wire subscription.
    - Introduced by diff: false; previous behavior: The subscription already ran with the prior default-true setting; an explicit chat.turnStatusPills=false prevented it.; critical-path effect: The snapshot is required before metadata and changeset selection can resolve, although the rest of the chat remains usable.
  - IPC/network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts:269</code>: Agent Host protocol state subscription for the selected changeset; cardinality: At most one selected changeset per active widget, shared by resource if another consumer already holds it.
    - Introduced by diff: false; previous behavior: The subscription already ran by default; only explicit opt-outs suppressed it.; critical-path effect: The snapshot supplies the live changes count shown above the input.
- Verdict: No reportable regression: the PR intentionally makes an already-default-on, bounded live-status path unconditional. It adds cost only for users who explicitly opted out, without introducing new per-item fan-out or a lifecycle leak.

### Scenario 2: Render and scroll through completed responses in an Agent Host chat history

- Critical path: For each completed response currently rendered by the virtualized list, the renderer creates a turn-pills content part. That part observes per-request diffs before deciding whether to display and eagerly constructs the collapsed file-list widget.
- Scaling input: Number of concurrently rendered completed response rows, and changed files in those rows. Diff aggregation scans all files; nested list rendering shows at most six rows.
- Effective concurrency: Distinct turn subscriptions may start concurrently for visible rows; session/chat subscriptions are coalesced by resource. Rendered parts are disposed when templates are cleared/reused, releasing references.
- Cache behavior: Per-request observables are memoized in a 1000-entry LRU; active resource subscriptions are ref-counted. Warm rows reuse observables and shared snapshots, while cold turns require a changeset snapshot.
- Mechanism confidence: High: renderer gating, provider construction, lazy observable subscription, ref-counting, and virtualized row disposal were traced directly.
- Magnitude uncertainty: Viewport size, row heights, remote latency, and explicit opt-out prevalence vary. The mechanism is real but was already the default behavior.
- Expensive boundaries:
  - IPC/network at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostResponseFileChanges.ts:\_createDiffsObservable</code>: Subscribe to Agent Host session/chat state and the request's turn changeset to resolve authoritative file changes; cardinality: Session and chat resources are shared across rendered rows; one distinct turn-changeset subscription exists per rendered completed turn that supports turn changesets. Virtualization limits concurrency to rendered/template-retained rows rather than total history.
    - Introduced by diff: false; previous behavior: This same fan-out occurred under the old default true. An explicit false setting omitted all turn-pills parts and subscriptions.; critical-path effect: The subscriptions determine whether the summary is visible; rendering the response itself proceeds while snapshots resolve.
- Verdict: No reportable regression: always rendering these summaries is the stated product change, the prior default already did so, and active boundary cardinality is viewport-bounded and coalesced. There is no diff-introduced leak or unbounded history fan-out.

### Scenario 3: Open an Agents Window session whose workspace metadata references GitHub issues

- Critical path: The session toolbar resolves issue references; when the Issues pill is visible it refreshes each issue model immediately so state/icons and rich hover details can update, then keeps open issues on a 15-minute poll schedule.
- Scaling input: Number of distinct GitHub issues referenced by the active session after model-key deduplication.
- Effective concurrency: The autorun invokes refresh for each issue without a batch limiter, but per-key models coalesce duplicate/in-flight requests. Polling is one scheduler per distinct open issue at 15-minute intervals.
- Cache behavior: Cold issues perform a fetch; warm models share the current payload and refresh promise. Recently disposed models restore ETag/payload snapshots from a 100-entry LRU, allowing conditional revalidation.
- Mechanism confidence: High: the changed gate directly controls the autorun, and fetch debounce, ETag caching, polling cadence, and model sharing are explicit.
- Magnitude uncertainty: Sessions normally reference few issues, and only users who had disabled the old default-on setting see newly added requests. Exact API latency and issue counts vary.
- Expensive boundaries:
  - network at <code>src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts:294-306</code>: Fetch/revalidate each referenced GitHub issue and periodically poll open issues; cardinality: One model per distinct referenced issue. Concurrent callers for the same issue share a model and in-flight refresh; repeated on-demand refreshes are suppressed for 60 seconds and disposed snapshots are cached for 100 issues.
    - Introduced by diff: false; previous behavior: The network path already ran when the setting's default true was in effect. Explicit chat.turnStatusPills=false prevented refresh/polling; per-kind Issues visibility still suppresses it after this PR.; critical-path effect: The pill can render from reference metadata before requests complete; live state and hover details update asynchronously, so network work is not blocking the overall view.
- Verdict: No reportable regression: network work is asynchronous, per-kind visibility still gates it, and the diff makes the documented default behavior unconditional rather than introducing a new boundary or scaling pattern.

### Scenario 4: Initialize configuration and session-pill visibility state

- Critical path: Configuration registration no longer installs the chat.turnStatusPills schema, and pill controllers use constant enabled observables plus the existing per-kind visibility memento.
- Scaling input: Constant configuration entries and eight pill kinds.
- Effective concurrency: No asynchronous or concurrent boundary work is introduced on configuration initialization.
- Cache behavior: Per-kind hidden state remains persisted in application-scoped storage; removing the old schema removes its observable configuration listener.
- Mechanism confidence: High: the diff only deletes schema/observable configuration plumbing.
- Magnitude uncertainty: None material; this is constant startup work.
- Expensive boundaries: none found
- Verdict: No performance regression; this slightly reduces configuration registration and listener work.

**Summary:** Reviewed all 12 changed files and traced the always-on input-pill, completed-turn rendering, Agents Window issue polling, configuration, subscription ownership, caching, virtualization, and disposal paths. The PR removes an explicit opt-out, but the prior default already exercised these bounded/coalesced paths; no high-confidence unintended performance regression met the reporting threshold.
