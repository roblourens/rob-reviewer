- Expensive boundaries: none found
- Verdict: No reportable regression. The diff adds only constant-size state per adapter and coalesces unchanged values; it does not introduce an expensive boundary or materially amplify the existing O(session count) refresh.

### Scenario 2: Rendering session rows and active-session changes pills when aggregate counts arrive or change

- Critical path: The adapter transaction publishes the summary, then existing autoruns synchronously read it to rebuild a visible row's details or compute the active changes pill. A real summary change can trigger one render/update just as the prior synthetic changes-array update did.
- Scaling input: One three-number summary per changed session; session-row rendering is limited to rendered elements, while the existing stats-cache autorun scans visible sessions on dependency changes.
- Effective concurrency: Observable updates are transaction-batched and UI reactions run synchronously after the transaction; no new asynchronous fan-out is introduced.
- Cache behavior: Unchanged summaries are suppressed by structural equality. The existing changes-stats cache is bounded to 30 sessions and authoritative provider summaries bypass aggregation of per-file lists.
- Mechanism confidence: High: adapter transaction, session wrappers, list autorun, and stats-cache reader were inspected directly.
- Magnitude uncertainty: Exact visible row count and update frequency vary, but the before/after dependency propagation is equivalent: aggregate changes previously changed the synthetic \`changes\` observable and now change \`changesSummary\`.
- Expensive boundaries: none found
- Verdict: No reportable regression. The change replaces a synthetic one-element changes array with a constant-time summary read and does not increase render cardinality.
