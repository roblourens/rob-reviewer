**Relevant issue families:** cleanup-lifecycle, repeated-work, concurrency-burst, boundary-fanout, cache-lifecycle

### Scenario 1: Open an SCM, chat/session, notebook, or explicit-resource multi-diff editor

- Critical path: Source resolution must complete, then every current document pair's model-reference promises are awaited by Promise.all before the initial document list and downstream diff view models can publish. The added cancellation-token allocation and final boolean check are synchronous constant work; they add no awaited operation.
- Scaling input: N diff items, with at most 2N model-reference acquisitions and one cold underlying load per distinct canonical URI after global reference coalescing; duplicate URIs and already-live models do not create additional underlying loads.
- Effective concurrency: All distinct cold original/modified model loads are launched concurrently by the pre-existing Promise.allSettled calls, and the batch Promise.all waits for all items. There is no limiter, but the diff neither increases this concurrency nor schedules another batch.
- Cache behavior: mapObservableArrayCached reuses promises for stable original/modified URI-pair keys. TextModelResolverService canonicalizes URIs and ReferenceCollection coalesces live and in-flight loads process-wide. Failed acquisitions release their reference and can be retried; the new token does not change positive, negative, or warm-cache behavior.
- Mechanism confidence: High: the production diff adds only cancelOnDispose(reader.store) and an isCancellationRequested check after the existing Promise.all.
- Magnitude uncertainty: Real N, provider latency, and the proportion of remote/virtual URIs vary by source, but the unchanged call path and cardinality are explicit.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/services/textmodelResolver/common/textModelResolverService.ts:ResourceModelCollection.doCreateReferencedObject</code>: Resolve cold file-backed text models through ITextFileService.files.resolve; remote file schemes can transit through their registered provider.; cardinality: At most one underlying cold resolution per distinct canonical file URI; up to 2N acquisitions are coalesced for duplicate/live URIs.
    - Introduced by diff: false; previous behavior: The same model-reference calls, cardinality, concurrent launch, and all-items barrier existed before this PR.; critical-path effect: All current-item model promises must settle before the initial multi-diff document list publishes.
  - IPC at <code>src/vs/workbench/services/textmodelResolver/common/textModelResolverService.ts:ResourceModelCollection.ensureResolvedTextModelContent</code>: Resolve cold virtual-document content through registered ITextModelContentProvider implementations, which may be extension-host backed depending on URI scheme.; cardinality: At most one coalesced cold provider resolution per distinct canonical virtual URI while its reference is live or in flight.
    - Introduced by diff: false; previous behavior: Virtual-content resolution was already performed by createModelReference before the changed lifecycle guard.; critical-path effect: A slow current virtual document delays the all-items publication barrier.
- Verdict: No reportable regression. One small source/token/disposable allocation per active batch is bounded and replaces on recomputation; no boundary, fan-out, serialization, or critical-path wait was added.

### Scenario 2: Refresh or replace a live multi-diff resource list while one or more model resolutions are slow

- Critical path: The newest resource generation still waits for its own current model promises before publishing. Superseded generations may finish in the background, but the new cancellation check prevents them from republishing stale document objects and triggering obsolete downstream diff/render work.
- Scaling input: A changed generation with A newly keyed resource pairs causes up to 2A model acquisitions; stable pair keys reuse cached promises. Multiple rapid generations can have overlapping pre-existing loads for distinct added keys.
- Effective concurrency: Cold loads for newly keyed URIs run concurrently, and generations can overlap because the guard does not cancel I/O. This concurrency was pre-existing; the change only marks an old derived evaluation when its store is disposed.
- Cache behavior: Stable URI-pair promises remain cached by mapObservableArrayCached. Removed-key stores release references; if a load completes after removal, the item callback detects its disposed store and releases the resulting references. Global canonical-URI reference coalescing still applies. The cancellation token itself is disposed/replaced with each derived evaluation.
- Mechanism confidence: High: derived recomputation disposes the previous reader store, cancelOnDispose flips that generation's token, and the added check executes before documents.set.
- Magnitude uncertainty: Refresh burst size and provider duration vary, especially for SCM and chat-driven sources. The maximum avoided stale downstream work depends on how many obsolete documents resolve after replacement.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorInput.ts:documentsWithPromises -&gt; ITextModelService.createModelReference</code>: Resolve models for newly introduced file-backed original/modified URIs.; cardinality: Up to two acquisitions per newly keyed pair, with one cold underlying file/provider load per distinct canonical URI after coalescing; stable keys perform no new acquisition.
    - Introduced by diff: false; previous behavior: The same acquisitions and overlapping generations ran before the PR, but an obsolete completed generation could publish after replacement.; critical-path effect: Only loads belonging to the newest generation gate the desired publication; obsolete loads can complete off that generation's critical path.
  - IPC at <code>src/vs/workbench/services/textmodelResolver/common/textModelResolverService.ts:ensureResolvedTextModelContent</code>: Resolve newly introduced extension-backed virtual documents when their URI content provider is remote to the workbench.; cardinality: One coalesced cold provider request per distinct new canonical virtual URI, subject to provider implementation.
    - Introduced by diff: false; previous behavior: Provider requests were already launched and not cancellable here; the PR does not add or repeat them.; critical-path effect: Current-generation requests delay current publication; superseded requests continue but their result is no longer propagated downstream by the changed guard.
- Verdict: No regression; the change reduces obsolete downstream CPU/rendering and disposed-object retention without increasing boundary cardinality or concurrency. It does not optimize pre-existing uncancelled model loads, but that is not introduced by this diff.

### Scenario 3: Close or dispose a multi-diff editor while document models are still resolving

- Critical path: After disposal there is no user-visible progress path to gate. Existing in-flight resolutions may complete, their per-item disposed stores release references, and the new disposed derived store marks the batch so it cannot publish.
- Scaling input: Up to two already-started model acquisitions per pending resource pair at close time; no new acquisitions are started by disposal or by the added guard.
- Effective concurrency: The already-running pre-existing acquisitions continue at their original concurrency because ITextModelService.createModelReference has no cancellation token on this path. The new token controls only post-await publication.
- Cache behavior: Per-item stores release completed references for removed/disposed entries; ReferenceCollection drops the canonical URI entry at zero references and disposes the resolved model according to text-file lifecycle rules. The guard token and its disposable are themselves released with the derived store.
- Mechanism confidence: High: model acquisition precedes the changed lines, while the added token observes disposal and skips only documents.set.
- Magnitude uncertainty: The number and duration of requests still pending at close depend on source size and provider speed, but no changed mechanism increases them.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/services/textmodelResolver/common/textModelResolverService.ts:ResourceModelCollection.doCreateReferencedObject</code>: Completion of file-backed model resolutions already started before editor disposal.; cardinality: Bounded by the pending distinct cold URIs at disposal; disposal starts zero additional operations.
    - Introduced by diff: false; previous behavior: The same in-flight operations completed after close; before the PR their batch continuation could still attempt publication.; critical-path effect: Off the user-visible critical path after close, though resources remain occupied until the underlying non-cancellable resolution settles.
  - IPC at <code>src/vs/workbench/services/textmodelResolver/common/textModelResolverService.ts:ResourceModelCollection.ensureResolvedTextModelContent</code>: Completion of already-started virtual-document provider requests.; cardinality: Bounded by pending distinct cold virtual URIs at disposal, with reference coalescing.
    - Introduced by diff: false; previous behavior: The PR neither starts nor cancels these requests; it only suppresses their obsolete aggregate publication.; critical-path effect: Off the closed editor's critical path; completion is needed only for cleanup of the acquired reference.
- Verdict: No reportable cleanup or memory regression. The changed lifecycle check prevents stale publication, and all newly allocated cancellation state is bounded to the derived evaluation.

No actionable performance regression was introduced. The PR's demonstrated symptom is correctness corruption/blanking rather than a measured or strongly evidenced shipped performance symptom, so no regression-fix learning record was submitted.
