## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/chat/browser/remoteAgentHost/cloudSandboxAgentHostService.ts:367` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/remoteAgentHost/cloudSandboxAgentHostService.ts:374`  
**Introducing path:** `src/vs/sessions/contrib/providers/remoteAgentHost/browser/cloudSandboxAgentHostService.ts`  
**Introducing commit:** `15a102b9c45a3e2fa9841ef0814b7251e0bd33ee`  
**Mechanism family:** `repeated-work`  
**Performance category:** `network`  
**Confidence:** 0.98

**Mechanism:** The sealed-token wait repeatedly invoked the new-client `/connect` endpoint after an initial client had already been minted, allocating a distinct logical client on every retry while retaining only the last token.

**Symptom:** Fresh sandbox startup with delayed sealed credentials could issue 13 client-mint requests and allocate up to 12 unnecessary remote client identities over the one-minute wait, increasing control-plane work and leaked server-side client state.

**Fixed behavior:** Credential polling retains the initially minted logical sandbox client and refreshes its credentials through `/reconnect`; retry count, 5-second serialization, cancellation, request scope, and ready-token fast path remain unchanged, so delayed startup no longer creates up to 12 surplus remote clients.

**Evidence:** In the base revision, `_awaitSealedToken` called `ICloudSandboxApiService.connect` once every 5 seconds for up to `MAX_SEALED_TOKEN_RETRIES` (12) after `_mintWithWaking` had already obtained an initial token. The API contract states that `connect` mints credentials for a new logical connection, while `reconnect` refreshes credentials for an existing `clientId`; the connection token's `client_id` is the stable identity used for group lanes and reconnect. Thus a startup whose sealed token is delayed could mint the initial client plus 12 additional remote client identities before establishing only the final one. The changed call passes `minted.client_id` to `reconnect`, and the added bounded-retry test asserts one connect followed by 12 reconnects for that same ID.
