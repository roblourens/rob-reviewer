- Scaling input: One target element and one snapshot per helpful click; no per-message or transcript-wide loop is added.

- Cache behavior: Animation settings are read through the existing configuration service. No positive/negative cache behavior changes, and the snapshot is discarded after the click handler completes.
- Mechanism confidence: High confidence that the generic path now reads geometry before the action; insufficient evidence that layout is invalidated or that this causes measurable latency.
- Magnitude uncertainty: A large chat transcript can make a forced layout expensive in principle, but the click necessarily targets an already laid-out footer and this handler performs no preceding DOM mutation. The diff does not establish a dirty-layout trigger.
- Expensive boundaries: none found
- Verdict: No reportable regression. The added work is constant per explicit feedback click and no scaling or expensive boundary amplification is present.

- Cache behavior: No cross-trigger cache exists or is needed. The rect is reused only within one animation invocation, avoiding a duplicate live geometry read for two animation types.
- Mechanism confidence: High confidence that direct-call behavior is equivalent or slightly cheaper and that overlay cleanup remains bounded.
- Magnitude uncertainty: Actual savings from removing the duplicate geometry read depend on browser layout state; there is no evidenced shipped symptom sufficient to classify this PR as a regression fix.
- Expensive boundaries: none found
- Verdict: No regression. The helper refactor preserves fixed allocation/lifecycle behavior and removes a repeated rect query for two animation variants.
