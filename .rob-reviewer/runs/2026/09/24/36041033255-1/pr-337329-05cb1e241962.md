### 1. cleanup-lifecycle

**Fix location:** `src/vs/platform/agentHost/test/node/serverIntegrationTestHelpers.ts:771` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/test/node/serverIntegrationTestHelpers.ts:752`  
**Introducing path:** `src/vs/platform/agentHost/test/node/serverIntegrationTestHelpers.ts`  
**Introducing commit:** `3e7bfbfa333db65e6e264209c6bc69e7676d6e4b`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `memory`  
**Confidence:** 0.98

**Mechanism:** Repeated failed test-server cleanup left one pending exit listener and Promise closure attached to the still-live ChildProcess per attempt, retaining objects and eventually producing EventEmitter listener growth until the process exited.

**Symptom:** Repeated teardown failures accumulated retained exit listeners/closures on a live test server, causing memory growth and eventual MaxListenersExceededWarning overhead.

**Fixed behavior:** The changed finally block always detaches stopServer's exit listener on success or failure, bounding retained listeners and Promise closures to one cleanup invocation instead of accumulating across repeated failed teardown attempts.

**Evidence:** In the base implementation, stopServer registered an 'exit' listener but removed it only in the already-exited branch. If descendant capture or killTree failed while the owned server remained alive, the function rejected after its bounded waits while that listener and its pending Promise closure remained attached. The added repeated-failed-cleanup test exercises this exact path three times and asserts listenerCount('exit') returns to zero after each call; the changed finally block now provides that lifecycle guarantee.
