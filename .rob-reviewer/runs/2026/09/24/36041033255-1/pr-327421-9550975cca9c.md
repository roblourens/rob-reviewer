## Performance regression fixes detected (1)

### 1. cleanup-lifecycle

**Fix location:** `src/vs/platform/agentHost/test/node/protocol/agentHostServer.integrationTest.ts:20` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/test/node/protocol/agentHostServer.integrationTest.ts:18`  
**Introducing path:** `src/vs/platform/agentHost/test/node/protocol/agentHostServer.integrationTest.ts`  
**Introducing commit:** `5a3a2c742334af82ef19db3a5eec93b658628f44`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `subprocess`  
**Confidence:** 0.97

**Mechanism:** Non-awaited child termination let the next protocol suite start while the previous Agent Host process could remain alive for up to its three-second persistence flush, creating transient subprocess, CPU, memory, and filesystem contention between suites.

**Symptom:** Protocol integration runs could carry overlapping Agent Host child processes across suite boundaries, increasing resource contention and contributing to slow or flaky test transitions.

**Fixed behavior:** Protocol suites now end stdin to initiate graceful shutdown and await the child process's exit before suite teardown completes, with a bounded force-kill fallback. This prevents consecutive suites from overlapping Agent Host subprocesses during shutdown.

**Evidence:** Before this PR, suite teardown called ChildProcess.kill() and returned without observing process exit. The server's SIGTERM handler disposes the WebSocket server and then awaits sessionDataService.whenIdle() for up to 3 seconds before process.exit(0), so the next suite could fork and exercise another Agent Host while the prior child was still flushing and disposing. The changed teardown now awaits stopServer(server), whose exit listener is registered before ending stdin and whose promise resolves only when that child exits (or after bounded forced termination). The same corrected pattern is applied across the protocol suites.
