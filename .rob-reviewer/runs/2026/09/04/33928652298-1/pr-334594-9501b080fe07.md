# Performance review: chat: fix GitHub context repository selection

[PR #334594](https://github.com/microsoft/vscode/pull/334594) at `9501b080fe0786fad7aae9020d87f5e472e22148`

## Findings (1)

### 1. [medium] Gate the direct config probe to repository-root callers

**Finding ID:** `PERF-C6BE8E527714`  
**Location:** <code>extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts:201</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** filesystem stat operations  
**Scaling:** The added stat runs once for every uncached local URI passed to getRepositoryFetchUrls; before Git discovery settles, content-exclusion verdicts deliberately are not memoized, so concurrent file checks scale the new I/O with files and checks rather than repositories.  
**Outcome:** excessive filesystem I/O and increased completion, search, review, and prompt latency during Git discovery, especially on network-mounted workspaces  
**PR causality:** <code>introduced</code>  
**Previous behavior:** getRepositoryFetchUrls first joined the shared initial-discovery promise. For an opened repository it then returned Git API state without filesystem I/O; unresolved files reached only the existing fallback stat after discovery.  
**Changed behavior:** Every file-scheme URI now performs and awaits workspace.fs.stat before joining discovery, even when the URI is a file and therefore cannot take the new direct .git/config branch.  
**Confidence:** 0.97 — The changed boundary call, hot transitive callers, no-cache startup condition, and per-file scaling are explicit in code and tests. Exact wall-clock impact varies by filesystem latency, so severity is medium rather than high.

**Causal diff evidence:** RIGHT line 201 newly adds \`await vscode.workspace.fs.stat(uri)\` ahead of the shared discovery wait. No equivalent filesystem operation existed on the opened-repository fast path before the PR.

While repository discovery is pending, content exclusion calls this API for each file and does not cache unsettled verdicts; collection-based prompt/search/review paths can therefore launch a burst of one extra stat per file on their critical path. Warm repository-root and verdict caches reduce later calls, but do not protect this startup window.

**Evidence:** RemoteContentExclusion.isIgnored calls getRepositoryFetchUrls on each repo-cache miss (extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts:187-195), explicitly avoids memoizing while discovery is unsettled (lines 263-271), and documents that a render can request hundreds of verdicts (lines 112-119). Its tests prove repeated Git lookups before discovery and concurrent multi-repository lookups. Numerous completion, search, review, and prompt call sites invoke isCopilotIgnored, including collection paths using Promise.all. The added line awaits a filesystem stat for all local URIs; for normal file inputs the result is not a directory, so this work cannot contribute to the direct-config optimization and execution falls through to the prior flow.

**Suggested direction:** Restrict the direct .git/config fast path to callers that know they are passing a selected repository/workspace root (for example via a root-specific method or option), leaving generic file-based getRepositoryFetchUrls calls on the Git API/discovery path without this preflight stat.

### 1. eager-work

**Fix location:** `extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts:216` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts:202`  
**Introducing path:** `extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts`  
**Introducing commit:** `88a8ef6f793d1b593b47862bd00aab36e88b0733`  
**Mechanism family:** `eager-work`  
**Performance category:** `latency`  
**Confidence:** 0.98

**Evidence:** The changed Agents-window path passes its single local folder URI to the extension command; resolveGitHubContextRepository calls getRepositoryFetchUrls. RIGHT lines 200-216 now read and return direct config before the still-existing wait at line 226. waitForInitialDiscovery shares a raceTimeout with INITIAL\_DISCOVERY\_TIMEOUT\_MS=30,000, while initial discovery waits for every repository HEAD. The added unresolved-metadata tests exercise the URI pass-through path. Base blame identifies commit 88a8ef6f793d1b593b47862bd00aab36e88b0733 as introducing the old wait on base line 202.

- Mechanism confidence: High: the URI pass-through, direct config return before waitForInitialDiscovery, and serialized command/search flow are explicit and tested.

- Mechanism confidence: High: tests cover distinct repositories, duplicate repository ids across roots, and unresolved roots, and the call path is direct.

### Scenario 3: Filter files through remote content exclusions during completion, prompt construction, workspace/text search, or code review

- Critical path: isCopilotIgnored awaits repository resolution and policy loading before a file may be used. Review and feedback paths use Promise.all across changed files; text search can enqueue checks for every hit; completion and prompt paths await checks before producing context.
- Scaling input: On a warm known repository, root metadata and per-file verdict caches eliminate Git lookups. Before Git discovery settles, verdicts are intentionally not memoized, so effective new preflight-stat cardinality is N for N checked local files, including repeats; collection call sites can make N concurrent.
- Effective concurrency: The new pre-discovery filesystem stats have no limiter or per-URI coalescing and can fan out to caller concurrency (for example all changed files under Promise.all, or all queued text-search jobs). Policy network requests are separately coalesced by repository, batched 10 repositories per request, and limited to five concurrent batches. Regex-triggered file reads are limited to 10.
- Cache behavior: Warm \`\_repoRootCache\` reduces repository resolution to once per repository and \`\_ignoreGlobResultCache\` memoizes settled per-file verdicts. During cold/unsettled discovery, repository metadata is absent and negative verdicts are deliberately not memoized; successful policy rules are cached for 30 minutes and in-flight policy fetches are shared.
- Mechanism confidence: Very high: the added awaited stat is unconditional for file-scheme URIs, tests prove repeated lookup while discovery is unsettled, source comments establish hundreds of render-time checks, and multiple production collection paths use Promise.all.
- Magnitude uncertainty: The exact latency of stat varies greatly between local SSDs and network-mounted workspaces, and warm caches sharply reduce frequency after discovery; the uncached per-file mechanism and unbounded caller concurrency are not uncertain.
- Expensive boundaries:
  - filesystem at <code>extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts:201</code>: Preflight \`workspace.fs.stat\` on every local URI before Git discovery/API lookup.; cardinality: One newly added stat per uncached local file check; concurrent startup/search/review collections can therefore issue N stats for N files even when all files belong to one repository.
    - Introduced by diff: true; previous behavior: Callers immediately joined one shared discovery promise; opened repositories then resolved from Git API state without filesystem I/O. Only the pre-existing no-repository fallback performed a later stat.; critical-path effect: Each ignore verdict awaits the stat, and aggregate workflows await all verdicts before progressing.
  - filesystem at <code>extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts:isIgnored</code>: Read up to 1 KB of a file when repository or organization regex rules require content matching.; cardinality: At most one read per uncached file requiring regex evaluation, limited to 10 concurrent reads and keyed by content/rule scope afterward.
    - Introduced by diff: false; previous behavior: Identical limited file-content reads occurred before this PR.; critical-path effect: Existing content-rule evaluation waits for this read.
  - network at <code>extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts:ensureRulesLoaded</code>: Fetch repository/organization exclusion policies from the Copilot API/GitHub-backed endpoint.; cardinality: One effective fetch per missing remote after coalescing, grouped 10 remotes per request with at most five batches in flight; warm rules avoid requests for 30 minutes.
    - Introduced by diff: false; previous behavior: The same coalesced, batched policy loading existed.; critical-path effect: A file verdict waits only for the policies of its effective repository and the non-git scope.
- Verdict: Reportable medium-severity I/O boundary fan-out; the accepted finding is anchored to the added preflight stat.

### Scenario 4: Build ignore patterns for workspace search by bulk-loading discovered Git roots, and resolve workspace organization metadata

- Critical path: Search pattern generation first discovers \`.git/HEAD\` files, then loadRepos resolves every discovered root before policy patterns are available; searches explicitly wait for this. - Scaling input: Bulk pattern generation scales with D discovered repository roots after search deduplication; organization resolution is one root. Each root is passed once to getRepositoryFetchUrls.
- Effective concurrency: loadRepos invokes repository resolution for all D roots with Promise.all, so direct config probes run concurrently. Subsequent policy network work is batched 10 per request and limited to five batches. Organization resolution is serial.
- Cache behavior: loadRepos populates the repository-root metadata cache and policy rules then use the normal 30-minute cache/coalescing. Direct Git-config bytes themselves are not cached. Organization resolution has no method-local cache shown.
- Mechanism confidence: High for boundary placement and concurrency; net cost relative to the Git API root lookup is workload-dependent.
- Magnitude uncertainty: D can be large in workspaces containing many nested repositories, but the new direct probes replace slower discovery/root-resolution work and remain one per discovered root; no evidence establishes a net regression in this bulk-root scenario.
- Expensive boundaries:

  - network at <code>extensions/copilot/src/extension/agents/vscode-node/githubOrgChatResourcesService.ts:getWorkspaceRepositoryOrganization</code>: Fall back to fetching the user's GitHub organizations if local repository remotes and token organization metadata do not identify one.; cardinality: At most one organizations request for the first workspace folder resolution path.

- Verdict: No additional finding: direct root probing is appropriate for root inputs and can shorten the critical path, while the reported bug is specifically its unconditional application to file inputs.
