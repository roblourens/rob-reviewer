- Critical path: Before each test, read and delete one process environment entry; after each test, restore or delete it. These constant-time in-process operations complete on the test critical path, while each test's pre-existing asynchronous work remains unchanged.
- Scaling input: One setup and one teardown invocation per test, so work grows linearly with the suite's hundreds of tests but remains two environment-map mutations per test.
- Effective concurrency: The suite hooks execute around each test under the test runner's suite ordering; they add no promises, workers, queues, IPC, or concurrency burst.
- Cache behavior: No cache is added, bypassed, or invalidated by the hooks; the original environment value is retained only for the current test and restored immediately afterward.
- Mechanism confidence: High: the complete diff adds only process.env read/delete/set operations and removes an equivalent per-test guard from one test.
- Magnitude uncertainty: Exact process.env mutation cost varies by Node.js and platform, but the operations are constant-sized and negligible relative to the existing agent tests.
- Expensive boundaries: none found
- Verdict: No reportable performance regression; the repeated work is bounded, constant-time test harness overhead with no product runtime impact.
