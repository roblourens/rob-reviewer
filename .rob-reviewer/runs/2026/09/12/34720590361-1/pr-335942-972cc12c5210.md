### Scenario 1: Headless rendering and screenshot capture of the full component-fixture catalog

- Critical path: Each fixture initializes its browser-side fixture host, installs leak tracking and virtual time, performs async render/layout, then becomes available for screenshot capture. - Scaling input: The workload contains roughly 1,765 screenshots; within each render cost formerly scaled with the number of disposable allocations and scheduled timers, while the changed successful path scales only with Error capture and bounded virtual events.
- Effective concurrency: A fixture owns one VirtualTimeProcessor whose events are executed serially with explicit 200-event render and 1,000-event teardown caps. The screenshot command's outer concurrency is unchanged by this diff.
- Cache behavior: source-map-support caches fetched maps within the browser context. The new sourceMapsInitialized flag coalesces explicit warm-up to one access per loaded fixture module; lazy Error objects retain unsymbolized capture data until a leak/trace is rendered.
- Mechanism confidence: High: direct call flow from global DisposableTracker and virtual timer wrappers to Error.stack was replaced with retained Error objects and lazy getters; source-map retrieval is explicitly synchronous.
- Magnitude uncertainty: Exact source-map cache reuse depends on browser-page reuse, but the before/after workload measurement and per-allocation mechanism strongly establish the removed cost.
- Expensive boundaries:
  - network at <code>src/vs/workbench/test/browser/componentFixtures/fixtureUtils.ts:153 and fixture initialization near line 1105</code>: source-map-support synchronously fetches generated-script source maps via XMLHttpRequest when Error.stack is formatted; cardinality: Cold cache: source maps needed by the first formatted stack are fetched once per browser/module context and cached by source-map-support; warm successful fixtures perform no per-disposable stack access after this diff. - Cache behavior: Workers/browser contexts may reuse the local server's built assets and OS/browser caches; no cache key, invalidation, or cold/warm behavior changes in the diff.
- Mechanism confidence: High: Playwright config changes only fullyParallel, while each test still opens exactly one local fixture URL.

- Verdict: No reportable regression. The change improves tail utilization without increasing maximum worker concurrency or boundary-call cardinality.
