## Performance regression fixes detected (1)

### 1. synchronous-ui-work

**Fix location:** `src/vs/workbench/browser/parts/activitybar/activitybarPart.ts:603` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/browser/parts/activitybar/activitybarPart.ts:593`  
**Introducing path:** `src/vs/workbench/browser/parts/activitybar/activitybarPart.ts`  
**Introducing commit:** `cb07ba1ab0190fccf97ebfa23ac4b6aa89f52682`  
**Mechanism family:** `synchronous-ui-work`  
**Performance category:** `layout`  
**Confidence:** 0.96

**Mechanism:** A clientHeight geometry read of the rendered global action container ran synchronously inside every vertical Activity Bar layout, including the startup grid layout, and could flush pending style/layout work on the UI thread.

**Symptom:** Main-thread startup and resize layout latency from synchronous browser style/layout resolution in ActivityBarCompositeBar.layout.

**Fixed behavior:** Vertical Activity Bar layout computes reserved global-action height from the two-action in-memory count and static action height/gap inputs, avoiding the synchronous DOM geometry read during startup and later layouts while retaining a single arithmetic calculation per layout.

**Evidence:** In the base revision, ActivityBarCompositeBar.layout synchronously read globalCompositeBar.element.clientHeight on every vertical layout. Workbench layout constructs the Activity Bar as a grid leaf and workbenchGrid.layout invokes part layout on startup; ActivitybarPart.layout then calls ActivityBarCompositeBar.layout. The global action bar has already appended rendered action DOM, so this geometry read sits on the synchronous main-thread startup/layout path and can require style/layout resolution. The changed code replaces that read with GlobalCompositeBar.getHeight(actionHeight, actionGap), which uses the in-memory ActionBar length and the same sizing values published to CSS. Tests explicitly install a throwing clientHeight getter and verify all supported size/gap combinations, corroborating that the DOM measurement is no longer reached.

- Mechanism confidence: High for the added one-shot relayout and its bounded action count; low risk because duplicate events are suppressed and there is no collection or concurrency amplification.
