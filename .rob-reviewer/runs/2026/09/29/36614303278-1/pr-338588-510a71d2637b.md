**Relevant issue families:** synchronous-ui-work, boundary-fanout, repeated-work, cleanup-lifecycle

### Scenario 1: Open the automation dialog for a Git-backed workspace

- Critical path: Rendering creates the isolation/branch picker, then asynchronously opens the selected repository and fetches local branch refs; repository discovery and refs must finish before the branch picker becomes ready, while the rest of the dialog is already rendered.
- Scaling input: One selected workspace folder and its local branch count; branch normalization/rendering scales linearly with refs, unchanged by this diff.
- Effective concurrency: One active logical reload per picker. Folder changes cancel the tracked request and request IDs suppress stale results; main-thread repository opens are globally sequenced. The underlying openRepository call has no cancellation token, but this behavior predates the diff.
- Cache behavior: The view item does not cache folder results. The extension-host Git bridge reuses an existing repository handle for an already-open root, but each reload still crosses IPC; neither cache behavior nor reload frequency changes in this PR.
- Mechanism confidence: High: the complete reload call path and Git service IPC implementation show unchanged boundary cardinality; added work is limited to visibility DOM writes.
- Magnitude uncertainty: Repository startup and branch enumeration duration vary by environment and repository size, but the diff does not increase their count or move them onto a new critical path.
- Expensive boundaries:
  - IPC/filesystem at <code>src/vs/sessions/contrib/automations/browser/automationDialog.ts:reloadRepository</code>: Open or discover the Git repository for the selected folder through IGitService and the extension host.; cardinality: One openRepository call per initial folder observation or distinct folder change; globally serialized by MainThreadGitExtensionService.
    - Introduced by diff: false; previous behavior: The same openRepository call ran with the same cardinality before the diff.; critical-path effect: Determines whether repository controls remain visible and whether branch loading proceeds, but does not block initial dialog rendering.
  - IPC/subprocess at <code>src/vs/sessions/contrib/automations/browser/automationDialog.ts:reloadRepository</code>: Fetch local branch refs via repository.getRefs after successful repository discovery.; cardinality: One getRefs call per successful repository reload, returning the repository's local branches.
    - Introduced by diff: false; previous behavior: The same getRefs call and branch-list processing occurred before the diff.; critical-path effect: Required before the branch picker reaches ready/empty state; asynchronous and cancellable.
- Verdict: No reportable regression. The added visibility update performs bounded style/attribute writes during existing picker updates and does not add repository or refs requests.

### Scenario 2: Open or switch the dialog to a non-Git workspace

- Critical path: The existing asynchronous repository lookup resolves undefined; the changed code marks noRepository, changes plain form state from worktree to workspace, rerenders the small picker, and hides its container.
- Scaling input: One selected folder per change; cost does not scale with files or branches because getRefs is skipped when no repository exists.
- Effective concurrency: One logical lookup per folder observation, with stale results rejected by request ID and cancellation state. Rapid switches may leave pre-existing uncancellable openRepository IPC in flight, but the diff neither adds nor multiplies those calls.
- Cache behavior: No negative cache exists in the view item, so revisiting a non-Git folder causes another lookup both before and after this PR. The mode mutation does not update the folder observable and therefore does not trigger another reload.
- Mechanism confidence: High: selectIsolationMode only mutates form state, while repository reload is driven exclusively by folderUriObs.
- Magnitude uncertainty: The Git extension's negative lookup latency is environment-dependent, but no additional boundary work is introduced.
- Expensive boundaries:
  - IPC/filesystem at <code>src/vs/sessions/contrib/automations/browser/automationDialog.ts:reloadRepository</code>: Ask the Git extension to open or discover a repository for the selected folder.; cardinality: One call for the selected non-Git folder; no subsequent getRefs call.
    - Introduced by diff: false; previous behavior: The same lookup occurred before the diff and also stopped without getRefs when no repository was returned.; critical-path effect: Its result gates hiding the repository-specific controls, but initial dialog interaction remains available.
- Verdict: No reportable regression. The diff adds constant-size DOM mutations and a plain state assignment after an already-existing negative lookup.

### Scenario 3: Rapidly switch workspace folders or target visibility while the dialog remains open

- Critical path: Each distinct folder observation starts the existing reload path; stale repository results are ignored. Visibility changes synchronously update display and aria-hidden, and repository state transitions now repeat those same bounded writes.
- Scaling input: Cost scales with user-driven folder switches and existing repository state transitions, not with rows, frames, or collection size; each transition affects one small control container.
- Effective concurrency: Request IDs and cancellation coalesce authoritative results to the latest folder; main-thread opens serialize. No new timer, listener, queue, or parallel fan-out is added.
- Cache behavior: There is no local positive or negative result cache; service-side repository identity is reused. The PR does not alter invalidation or retry behavior.
- Mechanism confidence: High: observable dependencies, cancellation ownership, and the added state write were traced directly.
- Magnitude uncertainty: Extremely rapid user switching can retain existing uncancellable IPC until completion, but that mechanism and concurrency are pre-existing.
- Expensive boundaries:
  - IPC/filesystem at <code>src/vs/sessions/contrib/automations/browser/automationDialog.ts:reloadRepository</code>: Repository discovery per distinct selected folder.; cardinality: At most one newly initiated call per distinct folder-observable emission, unchanged by this diff.
    - Introduced by diff: false; previous behavior: Identical folder-driven calls, cancellation, and stale-result checks existed before the diff.; critical-path effect: Asynchronous; only the repository-specific control state waits for it.
- Verdict: No reportable regression. Added DOM writes are bounded and contain no geometry reads, forced synchronous layout, retained collection, or new expensive boundary.

Traced dialog rendering, Git repository discovery, refs enumeration, folder switching, visibility updates, cancellation, caching, and picker DOM updates.
