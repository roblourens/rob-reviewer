- Effective concurrency: Two top-level scans run via Promise.all. Cold extension manifest scans within each group also use Promise.all; this concurrency is pre-existing and unchanged.
- Cache behavior: Warm launches read one cache per system/user group from the new per-profile cache directory. Cache inputs include product version/date/commit, source mtimes, language, and translations, so an application update already invalidates the old-build cache; relocation does not add an extra reusable-cache loss on that update. FileService.writeFile creates missing parent directories recursively, so the new nested location persists successfully.
- Mechanism confidence: High: the startup callers, cache hit/miss branches, parent-directory creation, and per-extension filesystem work were traced directly.
- Magnitude uncertainty: Exact extension counts and filesystem latency vary, but no changed mechanism increases cold-scan frequency or manifest-read cardinality after the new cache is populated.

### Scenario 2: Extension install, uninstall, or metadata update invalidates the affected profile's user manifest cache

- Scaling input: Number of install results/events, with one cache-file deletion attempt per result; profile count affects only an in-memory match loop.
- Effective concurrency: Batch install listener invocations remain independently fire-and-forget as before; the diff adds no limiter or new fan-out and does not change aggregate deletion cardinality.
- Cache behavior: Successful invalidation forces the next scan for that profile to be cold, exactly as before. Missing cache files are now treated as an expected negative result rather than logged/rejected.

- Magnitude uncertainty: Large bulk installs can already issue repeated deletion attempts, but that multiplicity is unchanged by the diff.

- Cache behavior: Deletion prevents cache retention after profile removal. Missing cache directories are negative-cache misses handled without retries; there is no long-lived retained map or orphaned handle.
- Mechanism confidence: High: removal ordering and all cache writers were searched; only the two manifest cache filenames currently target profile.cacheHome.
