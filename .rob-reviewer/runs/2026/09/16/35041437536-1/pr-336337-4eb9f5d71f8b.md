## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/base/browser/markdownRenderer.ts:261` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts:182`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`  
**Introducing commit:** `00a718eb5c95e2aebfd6ddd60f11e2f84afb1b09`  
**Mechanism family:** `repeated-work`  
**Performance category:** `rendering`  
**Confidence:** 0.97

**Mechanism:** Each incremental streaming render replaced the markdown target's entire child tree, detaching an unchanged iframe-backed output code block and forcing its browsing context and renderer to initialize again for successive token batches.

**Symptom:** Iframe-backed Mermaid diagrams repeatedly reload and flicker while a response streams, consuming repeated webview rendering work and often preventing the diagram from finishing before the next update.

**Fixed behavior:** The target update now reconciles ordinary markdown nodes while retaining reused synchronous code-block elements and their matching ancestors in the live DOM. Streaming updates still reparse/render markdown, but they no longer detach and reload an unchanged contributed code-block webview.

**Evidence:** The base morpher callback at line 182 invoked the full markdown render on each rAF-buffered streaming update. That render targeted the existing chat markdown node, whose base renderer unconditionally reset all target children; meanwhile ChatOutputRendererService mounts contributed code-block output in a webview element under that target. Even though ChatMarkdownContentPart reused the ChatOutputCodeBlockPart object, resetting the ancestor detached the iframe/webview browsing context on every streamed update. The new reconciliation at markdownRenderer.ts:261 preserves the reused output element and its ancestor chain, and the added browser tests prove that repeated append-only updates retain the same iframe contentDocument and create only one rendered output.
