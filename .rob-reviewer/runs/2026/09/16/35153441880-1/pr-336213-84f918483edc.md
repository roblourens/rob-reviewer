**Fix location:** `src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusEntry.ts:385` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusEntry.ts:385`

**Introducing commit:** `e1d07bbeafbe2c795db2b954a4fc4e0d79b88a74`  
**Mechanism family:** `repeated-work`  
**Performance category:** `network`  
**Confidence:** 0.97

**Mechanism:** With the show-only command, every mouse click on an already open Copilot status dashboard first disposed it on MOUSE\_DOWN and then immediately rebuilt it on CLICK. Dashboard construction always forced an entitlement refresh that bypassed the fresh-data cache, so attempts to close generated needless DOM/listener/interval churn and a fresh network request.

**Symptom:** Clicking the already-open Copilot status icon caused unnecessary dashboard reconstruction and uncached entitlement network refreshes instead of closing it, adding avoidable network traffic and UI/CPU churn.

**Fixed behavior:** The Copilot status entry now uses ToggleTooltipCommand; when the dashboard was pinned at pointer-down, the click only hides/disposes it. This prevents the close interaction from reconstructing the dashboard component tree, re-registering its listeners/interval, and scheduling another uncached entitlement refresh. Reopening still performs the intentional fresh update.

**Evidence:** Base line 385 assigned ShowTooltipCommand. StatusbarEntryItem's existing managed-hover MOUSE\_DOWN handler disposes the visible widget before the CLICK handler executes; ShowTooltipCommand then calls hover.show(), whose triggerShowHover creates a new ManagedHoverWidget and invokes the dashboard content factory. ChatStatusBarEntry's factory instantiates ChatStatusDashboard, whose render() always calls chatEntitlementService.update(token). That reaches forceResolveEntitlement(), which calls defaultAccountService.refresh({ refreshEntitlements: true }); getEntitlements explicitly bypasses its fresh-data cache for that option and performs the entitlement GET. DefaultAccountProvider uses a 100 ms ThrottledDelayer, so only near-simultaneous calls coalesce; ordinary successive clicks can each schedule a fresh uncached request. The changed ToggleTooltipCommand path captures pinned state before MOUSE\_DOWN and, on the closing click, hides/disposes instead of calling show().
