## Findings (1)

### 1. [medium] Avoid animating box-shadow across the full chat editor

**Finding ID:** `PERF-DFED791824DC`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/widget/media/chat.css:36</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Per-frame paint and raster work for a full-height, up-to-950px-wide editor pseudo-element and its blurred shadow  
**Scaling:** The non-composited box-shadow is interpolated every animation frame for the entire request duration; cost grows with editor area, display scale, request duration, and the number of simultaneously visible running chat editors in split groups.  
**Outcome:** Sustained paint/raster load, increased CPU/GPU usage, and dropped frames while an agent is working  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this change there was no whole-editor state pseudo-element. In-progress feedback, when enabled, was confined to the much smaller chat input border; the changed TypeScript also disables that input indicator when the new session indicator is enabled.  
**Changed behavior:** The added keyframes interpolate the shadow blur/color, and the added in-progress rule runs them infinitely on an absolutely positioned pseudo-element inset over the entire \`.interactive-session\`, which is \`height: 100%\` and can be 950px wide.  
**Confidence:** 0.96 — The changed selector, full-widget dimensions, state call path, infinite lifetime, and per-frame paint mechanism are explicit in the code. Exact milliseconds vary by GPU, display scale, editor size, and number of split groups, which affects severity but not the mechanism.

**Causal diff evidence:** RIGHT lines 29-37 add box-shadow interpolation between two values, and RIGHT line 60 applies it as an infinite 1.4s animation to the new full-session pseudo-element. RIGHT \`chatWidget.ts:977\` disables the prior input-only indicator when this feature is active, making this newly added broad animation the replacement.

With \`chat.experimental.sessionStateIndicator.enabled\` enabled, every visible running chat editor continuously repaints a full-editor shadow. Long agent runs or multiple running sessions in split editor groups can consume rendering capacity and make scrolling, typing, and other workbench animations jank.

**Evidence:** \`.interactive-session\` is defined at \`chat.css:6-12\` as \`height: 100%\`, \`max-width: 950px\`, and positioned; the new pseudo-element uses \`inset: 0\` at lines 42-44. \`chatWidget.ts:1003-1018\` maps \`requestInProgress\` to \`chat-state-in-progress\`, while lines 2774-2782 subscribe to accumulated view-model changes for streamed responses. CSS \`box-shadow\` interpolation is paint/raster work rather than a compositor-only opacity/transform update, so it repeats at display frame cadence independently of model-event batching.

**Suggested direction:** Keep the shadow geometry static and pulse only compositor-friendly opacity, for example with two pre-styled pseudo-elements or a nested layer whose opacity is animated; avoid interpolating \`box-shadow\` itself across the full editor.
