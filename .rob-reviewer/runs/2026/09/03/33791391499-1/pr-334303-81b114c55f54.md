# Performance review: Improve customization message UI and migration behavior

[PR #334303](https://github.com/microsoft/vscode/pull/334303) at `81b114c55f544144a89ac8943b2640ce949d6b26`

## Findings (1)

### 1. [medium] Keep full customization enumeration off the first-send critical path

**Finding ID:** `PERF-8A88C92F9115`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts:74</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** agent-host filesystem RPCs and markdown-file reads  
**Scaling:** On a cold provider cache, work grows with the number of installed plugins and their customization files: each plugin expands four canonical directories and reads metadata for every skill plus every agent/instruction markdown file. Expansions are launched concurrently; warm calls avoid plugin expansion until a plugin nonce/label changes, but still rebuild the full item collection.  
**Outcome:** The first request in each Summary-mode chat cannot proceed to agent dispatch until the slowest new enumeration completes, increasing first-response latency and creating an IPC/I/O burst; cancellation does not stop it because the added call uses CancellationToken.None.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this PR, customization hint collection awaited only the three migration computations. No hint mode invoked provideChatSessionCustomizations, so sending a chat request did not trigger full plugin-content expansion for summary counts.  
**Changed behavior:** Summary mode now calls provideChatSessionCustomizations from computeMigrationHint. ChatService awaits that hint together with hooks/instructions before building and dispatching the agent request.  
**Confidence:** 0.97 — The added invocation, its O(plugins + files) remote-filesystem implementation, and the await-before-dispatch call path are explicit. Only prevalence and exact duration are uncertain because the mode must be enabled and the expansion cache must be cold or invalidated.

**Causal diff evidence:** RIGHT line 74 adds \`harness.itemProvider?.provideChatSessionCustomizations(sessionResource, CancellationToken.None)\` only for the new summary mode, placing the full enumeration on a path that previously performed no such provider call.

With Summary enabled and a cold cache—for example, the first chat after startup with several remote agent-host plugins—the user's first send waits for directory resolution/listing and per-file metadata reads across all plugins before the agent starts responding.

**Evidence:** The added line calls the harness item provider with CancellationToken.None. AgentCustomizationItemProvider.provideChatSessionCustomizations expands every plugin via Promise.all; AgentCustomizationContentExpander resolves agents/skills/commands/rules and reads each skill and agent/rule markdown file. vscode-agent-host filesystem operations map to remote resourceResolve/resourceList/resourceRead calls. In ChatService.sendRequest, collectCustomizationMigrationHint is awaited in Step 2 before Step 4 constructs the agent request and before provider invocation.

**Suggested direction:** Do not await full item-provider enumeration before dispatching the chat request. Reuse/coalesce an invalidatable provider-item snapshot that is warmed outside the send path, or publish the summary notification after agent dispatch; also pass the request cancellation token so abandoned sends stop outstanding scans.

### Scenario 3: Click Review customizations from a migration hint and open the migration page

- Critical path: The command opens/focuses the management editor, then the new migration branch awaits showCustomizationMigrationPage; that method refreshes migration information before selecting and rendering the first enabled category.
- Scaling input: Enabled migration categories and their candidate prompt files. One explicit refresh is added per migration deep-link click; editor creation/session autoruns may already have an in-flight refresh.
- Effective concurrency: Editor-created/session-triggered refreshes and the explicit refresh can overlap. A sequence number suppresses stale commits but does not cancel prior work; cached prompt-list promises can coalesce the main filesystem discovery, while source-folder computations may repeat.
- Cache behavior: PromptsService caches prompt-list promises with watcher invalidation. Migration results themselves are not cached in the editor, but agent-host provideSourceFolders is derived from already-materialized customization state. Reopening an existing editor still performs one explicit freshness refresh.
- Mechanism confidence: High that an extra refresh is invoked; low that it causes additional expensive boundary work after cache/coalescing.
- Magnitude uncertainty: Whether the explicit refresh duplicates a cold filesystem scan depends on cache initialization and timing. The common agent-host destination lookup is in-memory, so a concrete user-visible regression from the extra refresh is not established.
- Expensive boundaries:
  - filesystem at <code>src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts:1145-1151</code>: List agent, instruction, and prompt files to compute migration candidates; cardinality: Up to three prompt-type list requests per refresh; overlapping calls generally share PromptsService cached promises after cache initialization.
    - Introduced by diff: true; previous behavior: Opening the editor initialized migration data asynchronously but did not await another refresh specifically to deep-link into migration.; critical-path effect: The explicit refresh is awaited before the migration page is shown.
  - other at <code>src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationServiceImpl.ts:124-140</code>: Compute writable destination source folders from active agent-host customization state; cardinality: Once per distinct target type for each overlapping refresh; based on in-memory session customization arrays for the agent-host provider.
    - Introduced by diff: false; previous behavior: Existing editor migration refreshes already performed these lookups.; critical-path effect: Awaited by each computeMigration, but does not cross a remote boundary for the active agent-host implementation.
- Verdict: No finding: the refresh is bounded to a deliberate user click and is needed for fresh category selection; available evidence does not prove a material extra I/O or latency regression beyond cached/coalesced work.
