## Performance regression fixes detected (1)

### 1. cleanup-lifecycle

**Fix location:** `src/vs/workbench/contrib/mcp/electron-browser/mcpGatewayService.ts:65` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/mcp/electron-browser/mcpGatewayService.ts:67`  
**Introducing path:** `src/vs/workbench/contrib/mcp/electron-browser/mcpGatewayService.ts`  
**Introducing commit:** `6e029c339f143aaac2a3c27ec58028ede04d6a26`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `memory`  
**Confidence:** 0.99

**Mechanism:** Each local gateway disposal previously sent `[gatewayId]` to a channel expecting `gatewayId`, causing cleanup to miss every string-keyed entry. One route and its event/session state remained per configured MCP server, and the HTTP listener could remain open until client disconnect or process shutdown; repeated create/dispose cycles accumulated this retained state.

**Symptom:** Disposed local gateways retained per-server routes, sessions and event listeners and continued processing server-change events; the gateway HTTP server also remained alive when these leaked routes were the last routes.

**Fixed behavior:** The changed line calls the channel directly with the scalar gateway ID expected by McpGatewayChannel, allowing it to dispose the per-gateway event forwarder, remove client tracking, clean all per-server routes and sessions/listeners, and stop the shared HTTP server when the last route is gone.

**Evidence:** The base line invokes disposeGateway through ProxyChannel.toService. ProxyChannel.toService sends method arguments as an array (`channel.call(propKey, methodArgs)`), while McpGatewayChannel's manual `call` implementation casts its raw `args` to `string`. The resulting one-element array does not equal the string key used by `_gatewayDisposables`, `_clientGateways`, or McpGatewayService's `_gatewayRoutes`, so the service returns as an unknown gateway without running `_cleanupGateway`. The extension-host API reaches this path whenever a locally created McpGateway is disposed, via ExtHostMcp.dispose -&gt; MainThreadMcp.$disposeMcpGateway -&gt; result.dispose.
