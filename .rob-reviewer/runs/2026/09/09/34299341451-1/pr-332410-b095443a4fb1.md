# Performance review: agentHost: centralize session and chat catalog metadata

## Findings (1)

### 1. [medium] Scope completion waits to the originating turn

**Finding ID:** `PERF-D7FEC541AF6A`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:5342</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>cleanup-lifecycle</code>  
**Resource:** CPU diff work and session-database/file-edit persistence represented by stale completion promises  
**Scaling:** The delay is the longest unresolved completion retained from any earlier aborted turn; its cost grows with edited file size, persistence latency, and the number of aborted edits still settling.  
**Outcome:** blocked replacement-turn completion and increased visible end-of-turn latency  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before the PR, tool-completion callbacks could continue asynchronously, but session idle did not wait on a shared completion set, so an old aborted turn's file-edit processing could not block a later turn's idle transition.  
**Changed behavior:** Tool completion callbacks are now tracked in one set for the lifetime of the session wrapper, and every normal idle waits for all entries in that set, regardless of which turn created them.  
**Confidence:** 0.97 — The set scope, await, and deletion lifecycle are explicit in the changed code. The added tests demonstrate that an aborted turn may retain an unresolved completion and that a replacement turn can be installed while it remains pending. takeCompletedEdit directly proves the awaited operation includes diff computation and SQLite persistence. Only the exact duration varies with edited-file size and storage speed.

**Causal diff evidence:** RIGHT line 5342 newly awaits the entire session-scoped pendingToolCompletions set before handling every non-aborted idle; the set is populated at RIGHT line 5333 and entries are removed only when each completion settles.

After aborting an edit and immediately sending a replacement prompt, the replacement turn can appear stuck at completion until unrelated cleanup from the cancelled turn finishes, increasing end-of-turn latency in proportion to the slowest outstanding prior edit.

**Evidence:** An aborted idle intentionally skips the await, but it also leaves the old promise in pendingToolCompletions until finally. A replacement turn can then start, as exercised by the added replacement-turn test. When that replacement emits a normal idle, line 5342 awaits the old promise too. FileEditTracker.takeCompletedEdit computes a text diff, stores before/after bytes in the session database, and records attribution, so this can be nontrivial work for large edits or slow storage.

**Suggested direction:** Track completion promises by their captured turn and await only the current turn's set. On abort, detach that turn's entries from the idle barrier while still allowing their cleanup/persistence promises to settle.

### Scenario 6: Abort an editing turn and immediately run a replacement turn

- Critical path: For every non-aborted idle, Promise.allSettled over the entire set must complete before the active turn can emit ChatTurnComplete and clear. This places stale prior-turn work directly on a replacement turn's completion path.
- Scaling input: Outstanding edited files from aborted turns; latency is dominated by the slowest retained completion and grows with file size and persistence duration.
- Effective concurrency: Tool completion handlers may already run concurrently. Promise.allSettled does not add work but joins every outstanding session-level handler, so the replacement turn is gated by the slowest one regardless of ownership.
- Cache behavior: There is no cache involved. Completion promises remain in a session-wide set until each asynchronous handler settles; aborting a turn skips the wait but does not remove that turn's entries from the future idle barrier.
- Mechanism confidence: Very high: changed set scope and await are explicit, tests show an unresolved aborted completion can coexist with a replacement turn, and the transitive expensive work is directly implemented in FileEditTracker.
- Magnitude uncertainty: The exact delay depends on edited-file size and database/storage latency, but the cross-turn dependency is deterministic whenever a replacement reaches normal idle before the aborted completion settles.
- Expensive boundaries:
  - database at <code>src/vs/platform/agentHost/node/shared/fileEditTracker.ts takeCompletedEdit, awaited from src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:5342</code>: Compute before/after diffs and store file-edit bytes/metadata in the session database.; cardinality: One session-database file-edit persistence per completed edited file, plus diff computation; a replacement idle waits for all unresolved entries, including those from earlier aborted turns.
    - Introduced by diff: true; previous behavior: The asynchronous tool-completion callback performed this work, but idle did not await a shared session-wide set, so an aborted turn's unfinished persistence did not gate a later turn.; critical-path effect: The newly added session-wide await blocks replacement-turn completion until unrelated prior-turn work settles.
  - other expensive boundary at <code>src/vs/platform/agentHost/node/shared/fileEditTracker.ts takeCompletedEdit</code>: Compute text diff counts and attribution data for edited file contents.; cardinality: Once per edited file consumed by the tool completion.
    - Introduced by diff: true; previous behavior: Diff work existed, but was not newly joined to later turns' idle transitions.; critical-path effect: CPU diff duration becomes part of the replacement idle barrier when the promise originated in an aborted turn.
- Verdict: Reported: the session-scoped completion barrier incorrectly carries cancelled-turn diff/database work onto the replacement turn's normal idle critical path.
