# Performance review: agentHost: change default settings for Codex harness

[PR #335259](https://github.com/microsoft/vscode/pull/335259) at `3c57460a5e57b3fa4a8788d8c73c0a81204600e0`

## Findings (1)

### 1. [medium] Defer the Codex account probe until Codex is used

**Finding ID:** `PERF-F84CA9A04BD5`  
**Location:** <code>src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts:295</code> (<code>RIGHT</code>)  
**Performance category:** <code>startup</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** A native Codex app-server subprocess, proxy resources, temporary-directory filesystem operations, and account-probe IPC/network work  
**Scaling:** The added cost occurs once per agent-host process lifetime for every eligible Insiders window/remote host with AI enabled and a warm Codex SDK cache, including users who never open Codex; concurrent editor starts each repeat it in their own host.  
**Outcome:** Increased startup CPU, memory, filesystem I/O, and process contention, with the probe allowed to run for up to 30 seconds.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** With the default false, ordinary Insiders startup did not register Codex unless the user or an experiment explicitly enabled it, so constructing the provider and its startup account probe were absent for default users.  
**Changed behavior:** The new non-Stable default is forwarded by the starter, causes agentHostMain to instantiate CodexAgent during agent-host prewarm, and the constructor immediately queues \_probeAccountAtStartup.  
**Confidence:** 0.99 — The setting-to-env-to-registration call path and unconditional constructor microtask are explicit. The warm-cache guard bounds the trigger rather than making it speculative; exact wall-clock cost varies by machine and account state, which is reflected in medium severity.

**Causal diff evidence:** RIGHT line 295 changes the provider setting from default false to product.quality \!== 'stable'; this is the gate consumed by the starter and registration path that newly constructs CodexAgent for default Insiders users.

On an Insiders startup where AI features are enabled and the Codex SDK is already cached, BlockRestore prewarming now launches a native Codex process even if the user never selects Codex. \_probeAccountAtStartup resolves the SDK, creates proxy/temp resources, spawns the binary, performs the initialize/account handshake (and signed-in account metadata requests), then tears it down, potentially contending with editor restoration for up to the 30-second timeout.

**Evidence:** AgentHostPrewarmContribution runs at WorkbenchPhase.BlockRestore and calls startAgentHost. ElectronAgentHostStarter forwards AgentHostCodexAgentEnabledSettingId; agentHostMain registers new CodexAgent when true. CodexAgent's constructor queueMicrotask-calls \_probeAccountAtStartup, which on a warm SDK invokes \_startRawConnection with CODEX\_STARTUP\_ACCOUNT\_PROBE\_TIMEOUT\_MS=30\_000. \_startRawConnection creates a sandbox temp directory and calls child\_process.spawn for the native Codex app-server before the account handshake and cleanup.

**Suggested direction:** Keep the provider/routing defaults if desired, but make registration passive: do not run \_probeAccountAtStartup merely because the provider is enabled. Trigger the one-off account probe lazily when a Codex account surface or Codex session is first requested, and coalesce that first-use probe with persistent connection startup.
