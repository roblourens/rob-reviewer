## Performance regression fixes detected (1)

### 1. serialization-allocation

**Fix location:** `test/unit/browser/index.js:94` (`RIGHT`)  
**Blamed base line:** `test/unit/browser/index.js:94`  
**Introducing path:** `test/unit/browser/index.js`  
**Introducing commit:** `cf4e4c17544486f6442cb91eeb8f1acfc36d1339`  
**Mechanism family:** `serialization-allocation`  
**Performance category:** `io`  
**Confidence:** 0.92

**Mechanism:** The CI Browser unit runner attached Mocha's verbose Spec reporter in addition to the JUnit reporter, serializing and writing full suite/test descriptions to the captured console for every test result.

**Symptom:** A representative 2,700-test Browser subset produced 2,761 console lines and 177 KB of captured output, adding unnecessary CI logging and ingestion work.

**Fixed behavior:** Browser CI now emits compact dot progress to stdout while preserving the full JUnit artifact, reducing per-test console serialization and log ingestion volume.

**Evidence:** The changed CI-only branch replaces Mocha's Spec console reporter at test/unit/browser/index.js:94 with Dot while leaving MochaJUnitReporter attached immediately below, so detailed test results remain in JUnit. The Browser unit workflows invoke this branch with --tfs. Spec serializes suite and test titles for each result; the PR's same-2,700-test comparison records 2,761 lines/177 KB before versus 263 lines/80 KB with Dot, directly tying the old reporter to repeated CI log output.

- Effective concurrency: The integration shell script runs its eight sections serially. Smoke suites install a per-suite Application start/stop handler and Mocha runs them serially by default, so startup work is repeated rather than overlapped; there is no concurrency burst.

The old prelaunch still re-entered filesystem/version/control-file checks for every source server, with network downloads possible only on a cold or stale built-in cache. ### Scenario 2: Remote integration tests using vscode-test-resolver

- Critical path: Each of the eight sequential remote integration sections launches Electron, resolves the test authority, starts one server, and waits for its listening port before that section can run. Server and shell-environment startup are on the critical path.

- Effective concurrency: The remote integration scripts invoke sections serially and kill the app between sections. One resolver-owned server is launched per section; there is no parallel fan-out.

Source jobs use the already-built source server; built-server mode uses VSCODE\_REMOTE\_SERVER\_PATH or downloads only when absent, behavior unchanged by this diff.
- Mechanism confidence: High: the remote scripts enumerate eight serial app launches, each resolver spawns a server, and the added argument reaches the explicit shellEnv short-circuit.
- Magnitude uncertainty: Shell startup duration depends on runner dotfiles; Windows receives no speedup because the implementation already skips there.

### Scenario 4: Browser unit-test result reporting in CI

- Critical path: Mocha invokes the console and JUnit reporters synchronously as each test completes; captured stdout and final JUnit generation are part of runner/job completion.
- Scaling input: Approximately 2,700 Browser tests in the cited subset, with console work growing per emitted test result and suite transition.
- Effective concurrency: Each OS Browser job runs one configured browser runner; reporter callbacks serialize on the Mocha event stream.
- Cache behavior: Reporting has no result cache. The compact console stream is regenerated every run; the detailed JUnit artifact remains unchanged and is written once for the runner.
- Mechanism confidence: High: the reporter branch is selected by --tfs in every Browser unit workflow, and the detailed JUnit reporter is unchanged. The old mechanism was recorded as an internal regression fix after blame identified its introducing commit.
- Magnitude uncertainty: Wall-clock savings depend on CI log transport; the same-test comparison establishes a reduction from 2,761 to 263 console lines and 177 KB to 80 KB.
- Expensive boundaries:
  - serialization at <code>test/unit/browser/index.js:withReporter</code>: Format test progress for the captured CI console.; cardinality: One reporter event stream per Browser runner with output proportional to test results; Spec emitted full hierarchy/title text while Dot emits compact progress.
    - Introduced by diff: false; previous behavior: The CI --tfs branch attached Spec plus MochaJUnitReporter. The diff replaces only Spec with Dot.; critical-path effect: Reporter formatting/writes occur during test execution; changing reporters reduces synchronous output volume without delaying artifact availability.
  - filesystem at <code>test/unit/browser/index.js:withReporter</code>: Write the detailed Mocha JUnit XML result artifact.; cardinality: One XML report per platform/architecture/browser/test label.
    - Introduced by diff: false; previous behavior: The same MochaJUnitReporter and output path were used.; critical-path effect: Remains part of result reporting and preserves detailed diagnostics.
- Verdict: No reportable regression. The change reduces per-test console serialization while preserving the full machine-readable report.
