### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/agentHostSessionTitleController.ts:519` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/agentHostSessionTitleController.ts:524`  
**Introducing path:** `src/vs/platform/agentHost/node/agentHostSessionTitleController.ts`  
**Introducing commit:** `274239ff17a15514f74288e0f8fb21eaccce599b`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.96

**Mechanism:** Active-agent title handling put an awaited session-database metadata read and a mandatory rename\_chat tool instruction on outgoing turns for independent side chats, adding I/O and an avoidable tool round-trip before the side answer could settle.

**Symptom:** Agent Host side questions incurred unnecessary response latency from title metadata lookup and automatic rename-tool execution even though these transient side chats do not need a rename reminder.

**Fixed behavior:** Side-chat turns now return before persisted title metadata I/O and before injecting the mandatory rename\_chat instruction, removing the unnecessary database read and rename tool/agent continuation from each eligible side-chat response path.

**Evidence:** SessionTitleContribution.onOutgoingTurn synchronously awaits prepareInstructionForAgent on every outgoing Agent Host turn. In the base revision, eligible independent chats then awaited \_readPersistedTitleMetadata, which opens the session database and reads metadata, and could return CHAT\_RENAME\_REMINDER, an instruction explicitly requiring the agent to invoke rename\_chat. The added SideChat-origin guard at RIGHT line 519 exits before both operations; the added test seeds an automatic side-chat title and verifies the outgoing instruction is now undefined. blame\_base\_line attributes the old metadata/reminder path to 274239ff17a15514f74288e0f8fb21eaccce599b.
