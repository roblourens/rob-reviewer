### Scenario 1: First Agent Host connection from a remote editor or Agents window to the default lazy server-owned host

- Critical path: The client awaits the already-established remote authority's resolver result, then the renderer-to-server connect IPC, server endpoint resolution, cold Agent Host process readiness, and the per-context upstream socket connection. Resolver lookup and IPC are on the critical path; cold process startup was already on this path before the change.
- Scaling input: One connection per workbench window/context (realistically editor and Agents windows), with environment serialization proportional to the resolver/debug environment key count. Effective startup cardinality is one because ServerAgentHostManager coalesces ensureStarted().
- Effective concurrency: Different renderer contexts can resolve the endpoint concurrently. Each invokes the endpoint callback, but all calls share ServerAgentHostManager.\_startPromise; after readiness, each context opens its own upstream connection as it did before the diff.
- Cache behavior: IRemoteAuthorityResolverService keeps one DeferredPromise per authority, so normal initial Agent Host use reads the authority already resolved to establish the remote workbench connection. The Agent Host manager caches the successful process start; no separate negative cache is introduced.
- Mechanism confidence: High: resolver caching, process-start coalescing, per-context socket ownership, and before/after IPC cardinality are explicit in the traced implementations.
- Magnitude uncertainty: Environment records can vary in size, but realistic resolver environments are bounded process-environment maps and are serialized only once per transport attempt; no evidence shows payload size or window count sufficient for material latency or allocation pressure.
- Expensive boundaries:

### Scenario 2: Automatic Agent Host transport reconnect after an upstream drop

- Critical path: Reconnect backoff is followed by transport construction, cached authority resolution, connect IPC, server endpoint callback, and a replacement upstream socket. If the Agent Host is alive, ensureStarted returns its settled promise; if it crashed, the manager's existing recovery startup is awaited.
- Scaling input: One attempt at a time per protocol client under its reconnect state machine; cost scales with bounded retry attempts and the number of active workbench windows, not session or chat count.
- Effective concurrency: The protocol client prevents concurrent attempts per client. Editor and Agents windows may reconnect concurrently, but Agent Host process startup remains globally coalesced; each retains its independently required upstream socket.
- Cache behavior: Each attempt calls resolveAuthority, but the resolver returns the same cached/settled per-authority promise unless the broader remote connection subsystem clears it. This does not independently repeat remote resolver extension work. The latest environment snapshot is retained for process crash recovery.
- Mechanism confidence: High: the reconnect state machine constructs and awaits one transport at a time, resolver requests are keyed by authority, and manager startup is shared.
- Magnitude uncertainty: Actual disconnect frequency is workload/environment dependent, but attempt serialization and resolver/startup coalescing are explicit, leaving no realistic fan-out mechanism introduced by the change.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/browser/agentHostIpcChannelTransport.ts:75</code>: Reconnect sends connect IPC with the current cached resolver environment.; cardinality: One per reconnect attempt per protocol client, matching the existing connect call frequency.
    - Introduced by diff: false; previous behavior: Reconnect already issued the connect IPC; the diff adds the environment payload and cached resolver lookup.; critical-path effect: Blocks opening the replacement transport.
  - network at <code>src/vs/server/node/agentHostChannel.ts LazyUpstreamConnection.\_connect</code>: Opens the replacement upstream socket for the reconnecting renderer context.; cardinality: One socket attempt per reconnect attempt.
    - Introduced by diff: false; previous behavior: The replacement LazyUpstreamConnection already opened one socket per reconnect.; critical-path effect: Directly blocks protocol reconnection.
  - subprocess at <code>src/vs/server/node/serverAgentHostManager.ts:144</code>: Restarts Agent Host only when the managed process has failed.; cardinality: At most one shared process start across concurrent renderer reconnects; existing restart budget is five.
    - Introduced by diff: false; previous behavior: Crash recovery and startup coalescing already existed; the diff changes only which retained environment is used.; critical-path effect: Only on host crash; ordinary socket reconnects reuse the settled startup promise.
- Verdict: No reportable regression. Fresh environment capture adds bounded per-attempt serialization, while no new network, subprocess, or resolver fan-out is introduced.

### Scenario 3: Connection through an explicitly configured or externally managed Agent Host bridge

- Critical path: The renderer resolves the cached authority and sends connect IPC; AgentHostChannel uses the fixed endpoint and opens the configured upstream connection. No server-owned process launch occurs on this path.
- Scaling input: One connection per renderer context or reconnect attempt; environment map size controls added IPC bytes, but it is ignored by the fixed endpoint.
- Effective concurrency: Each renderer context owns one upstream connection. There is no process-start concurrency because the fixed endpoint bypasses the starter and manager.
- Cache behavior: Authority resolution remains the shared per-authority promise. The fixed endpoint has no launch environment cache because the overrides are intentionally not applied externally.
- Mechanism confidence: High: fixed endpoints return before consulting options and tests confirm options are not forwarded to externally managed upstreams.
- Magnitude uncertainty: The added payload size varies by resolver environment, but it is a single process-environment record per connection and causes no downstream launch or remote fan-out.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/browser/agentHostIpcChannelTransport.ts:75</code>: Sends connect plus environment options to the server bridge.; cardinality: One per transport attempt.
    - Introduced by diff: false; previous behavior: The same IPC request was made without the options payload.; critical-path effect: Required to request the existing bridge connection.
  - network at <code>src/vs/server/node/agentHostChannel.ts LazyUpstreamConnection.\_connect</code>: Opens the configured external Agent Host WebSocket/TCP/Unix socket.; cardinality: One per renderer context or reconnect attempt.
    - Introduced by diff: false; previous behavior: The same upstream connection was opened with the same cardinality; connection options do not reach the external host.; critical-path effect: Blocks transport readiness.
- Verdict: No reportable regression. Only bounded IPC serialization is added; external network and connection cardinality are unchanged.

### Scenario 4: Managed Agent Host crash recovery using the retained resolver environment

- Critical path: The existing crash handler invokes a single coalesced process restart; NodeAgentHostStarter resolves shell environment, merges process/shell/resolver/launcher maps, removes the stale socket, and starts the child. Renderer reconnection subsequently opens its socket.
- Scaling input: Environment merge work is linear in the combined environment key count once per process launch. Restart count remains bounded by the existing five-attempt budget.
- Effective concurrency: ServerAgentHostManager owns one restart promise globally. Concurrent renderer activity cannot create additional child launches.
- Cache behavior: setEnvironment snapshots the most recently supplied overrides; the snapshot is replaced on a later connection and reused for crash recovery. It is bounded to one environment map rather than accumulating versions.
- Mechanism confidence: High: one \_environment field replaces its prior snapshot, merge work is linear, and the manager bounds and coalesces launches.
- Magnitude uncertainty: Environment cardinality varies, but it is bounded and only one snapshot is retained; there is no lifetime growth or per-session multiplication.
- Expensive boundaries:
  - subprocess at <code>src/vs/platform/agentHost/node/nodeAgentHostStarter.ts:167</code>: Starts the replacement Agent Host process with merged environment values.; cardinality: One child per recovery attempt, globally coalesced and bounded by the existing restart limit.
    - Introduced by diff: false; previous behavior: The same recovery launches occurred; the diff augments the child environment and performs linear map merging.; critical-path effect: Recovery cannot complete until the process is ready.
  - filesystem at <code>src/vs/platform/agentHost/node/nodeAgentHostStarter.ts:164</code>: Removes the stale Unix socket before restart.; cardinality: Once per actual restart attempt.
    - Introduced by diff: false; previous behavior: Identical stale-socket cleanup already ran before each launch.; critical-path effect: On the restart critical path.
- Verdict: No reportable regression. The change retains one bounded snapshot and adds linear environment merging to already-expensive, infrequent process starts without increasing restart cardinality.
