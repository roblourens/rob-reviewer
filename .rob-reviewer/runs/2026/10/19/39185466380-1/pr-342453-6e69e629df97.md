### Scenario 1: Send a turn on a warm local or scoped Copilot chat whose credential is unchanged

- Critical path: AgentSideEffects resolves the working directory, then awaits concurrent changeModel/changeAgent requests; CopilotAgent serializes them on the per-chat queue before prepareTurn/send can progress. The new credential-boundary calls complete synchronously apart from an already-resolved async return when no credential exists or the scoped credential and startup configuration are current.
- Scaling input: One model update when the message specifies a model and one agent update per turn, both for one chat; effective cardinality is two serialized selection operations, not collection-wide fan-out.
- Effective concurrency: Promise.all starts model and agent selection together, but \_queueChatTurn/\_queueChat serialize both by chat sequencer key. Different chats remain independent, as before.
- Cache behavior: The warm scoped client, credential pin, and live session are reused when the captured credential is current. The added checks do not invalidate these caches. Local chats have no scoped credential and return immediately from the boundary.
- Mechanism confidence: High: the caller, per-chat sequencer, credential fast path, and selection methods are directly traced.
- Magnitude uncertainty: Configuration reads and one small credential clone are newly repeated for model and agent selection, but they are bounded in-memory work and do not establish a user-visible regression.
- Expensive boundaries:
  - IPC/network at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_changeModelOnce</code>: Resolve managed model policy and call the live SDK session's model-selection RPC; cardinality: At most one managed-settings resolution and one setModel call for the turn's model update; resolver caching remains unchanged.
    - Introduced by diff: false; previous behavior: The same policy resolution and setModel operations ran before the diff.; critical-path effect: Awaited before the turn send; this was already on the selection critical path.
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_changeAgentOnce</code>: Call the live SDK session's agent select/deselect RPC; cardinality: One agent selection call per turn.
    - Introduced by diff: false; previous behavior: The same setAgent operation ran before the diff.; critical-path effect: Awaited before the turn send; unchanged.
- Verdict: No reportable regression. Warm selection adds only bounded credential/config comparisons and preserves all existing boundary cardinality.

### Scenario 2: Continue a Mission Control chat on desktop after credential rotation, expiry, or legacy-to-scoped adoption

- Critical path: Before the turn can send, AgentSideEffects awaits changeModel/changeAgent. The first queued selection applies the current operation's credential, destroys the stale live session, stops the old scoped client when present, starts a replacement scoped runtime, resumes the persisted chat, and applies selection. The second queued selection observes and reuses that replacement.
- Scaling input: One affected chat and one captured credential revision per operation. Even though two selection calls are issued, replacement cardinality is one per changed credential per chat because the queue serializes them and the first updates the scoped client/pin.
- Effective concurrency: Model and agent requests are initiated together but execute serially for the chat. Separate chats can replace independently, matching the existing per-chat send/prepare behavior; the diff adds no cross-chat fan-out loop or new aggregate scheduler.
- Cache behavior: A changed/expired credential invalidates only that chat's live session and scoped client. The replacement is retained and reused by the second selection, prepareTurn, and send. The captured credential source is a stable per-operation snapshot, so repeated capture does not mint distinct revisions.
- Mechanism confidence: High: changed lines call the boundary inside the serialized queue; helper logic and regression tests prove one old stop and one new launch, with the second selection using the replacement.
- Magnitude uncertainty: Subprocess stop/start and session resume duration vary by machine and network, but total replacement cardinality through a turn is unchanged. A standalone selection with no subsequent send performs replacement earlier, which is necessary to apply selection to the authoritative runtime and is not a demonstrated avoidable regression.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_applyChatCredentialBoundary -&gt; \_destroyLiveSession</code>: Destroy the stale SDK chat session; cardinality: Once for the affected live chat.
    - Introduced by diff: true; previous behavior: Selection accessed the retained runtime; the existing prepareTurn/send credential boundary performed this destruction later in the same send workflow.; critical-path effect: Now completes during the first selection before send; required so selection does not access the stale runtime.
  - subprocess at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_applyChatCredentialBoundary / \_ensureClientForChat</code>: Stop the old scoped Copilot client and start a replacement credential-scoped client; cardinality: At most one stop/start pair for the changed revision on the chat; legacy-to-scoped adoption starts one scoped client without stopping a scoped predecessor.
    - Introduced by diff: true; previous behavior: The existing send/prepare credential boundary stopped and replaced the runtime after selection rather than before it.; critical-path effect: Moved from prepareTurn/send to the first selection for this workflow; still exactly one replacement before the turn can run.
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_ensureResolvedChatSession -&gt; session resume path</code>: Resume the persisted SDK session backing after replacement; cardinality: One resume for the affected chat; the second selection reuses it.
    - Introduced by diff: true; previous behavior: The same backing was resumed after credential replacement at prepare/send time.; critical-path effect: Moved earlier into selection and remains required before the ensuing send.
  - IPC/network at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_ensureResolvedChatSession, \_changeModelOnce, \_changeAgentOnce</code>: Initialize the replacement runtime/session and apply model or agent selection; cardinality: One runtime/session initialization, followed by the existing selection calls.
    - Introduced by diff: true; previous behavior: Selection ran against the old runtime, then send preparation replaced and initialized the runtime, potentially losing that selection.; critical-path effect: Awaited in selection rather than later preparation; checkpoint capture can continue independently in the caller.
- Verdict: No reportable regression. The diff moves one already-required credential replacement earlier in the continuation critical path and coalesces concurrent selection updates through the existing per-chat queue.

### Scenario 3: Selection with an unavailable sponsor or a different sponsor while the runtime is busy

- Critical path: Credential capture rejects an unavailable credential before applying the boundary. For a valid but different credential on a busy session, the boundary detects active work and throws before destroying the session or stopping the client.
- Scaling input: One selection request for one chat; no collection multiplicity.
- Effective concurrency: The request waits for its per-chat queue position. Active turn/subagent state prevents replacement; no additional work is spawned.
- Cache behavior: Existing live session and client remain intact on rejection; no negative cache or new retained state is created.
- Mechanism confidence: High: the capture and busy guards precede destroy/stop, and changed tests assert no additional launch, stop, policy, model, or agent calls.
- Magnitude uncertainty: None material for performance; only bounded validation work occurs.
- Expensive boundaries: none found
- Verdict: No reportable regression. Failure paths avoid subprocess, IPC, filesystem, and network work introduced by the credential replacement.

### Scenario 4: Change model or agent on a provisional chat before its first materialization

- Critical path: The provisional branch updates in-memory model/agent state and does not execute the newly added credential boundary. Materialization remains deferred until existing prepare/send behavior requests it.
- Scaling input: One in-memory update per selection for one provisional chat.
- Effective concurrency: Operations are serialized by the same per-chat queue; no runtime creation occurs.
- Cache behavior: The provisional record remains the lazy cache of selection state. No scoped client or live session is eagerly allocated by the diff.
- Mechanism confidence: High: both changed methods place the new boundary exclusively in the non-provisional branch.
- Magnitude uncertainty: None material.
- Expensive boundaries: none found
- Verdict: No reportable regression. The diff preserves lazy materialization and adds no eager process, I/O, or network work for provisional chats.

**Summary:** Completed the performance pass over all three changed files and all diff pages. Traced credential capture, per-chat queueing, runtime destruction/startup/resume, selection callers, warm/cold cache behavior, and concurrency. The new boundary is a bounded no-op on current/local/provisional paths and performs one serialized replacement for a changed credential, moving work already required by prepare/send earlier rather than increasing end-to-end boundary cardinality. No valid performance finding or regression-fix learning record was warranted.
