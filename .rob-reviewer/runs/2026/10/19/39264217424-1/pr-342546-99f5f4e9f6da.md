### Scenario 2: Moving a single-chat session whose source has not been loaded since host restart

- Critical path: One existing renderer-to-host moveSession request enters the global chat-move sequencer. The newly added source restore must finish, then the existing destination restore/catalog preparation/database validation and move commit complete before the user-visible move returns.
- Scaling input: Exactly one source and one destination per explicit drag/drop. The added work is one source-session restore on a cold source; it does not scale with the number of rows. A provider metadata miss can trigger the existing provider-catalog enumeration, whose cost scales with that provider's catalog size.
- Effective concurrency: All chat/session moves are serialized by \_chatMoveSequencer. Restore work is coalesced per session by \_restoreSessionInFlight, and resident sessions bypass restoration. Session residency is bounded by the default limit of 10 and reconciliation/eviction.
- Cache behavior: Warm source and target states skip restore. Concurrent restores of the same cold session join one promise. Successful restores become resident but are governed by AgentSessionResidency; failed metadata lookup may warm the existing provider catalog rather than repeating independent work per row.
- Mechanism confidence: High: the added await is directly on the explicit move path, and restore's database/provider boundaries, per-session coalescing, resident fast path, global move sequencer, and residency cap are all explicit in code.
- Magnitude uncertainty: Cold provider restore duration varies; a large legacy provider catalog can be slow on a metadata miss. The feature is default-off and the path is one explicit move, not list rendering or startup.
- Expensive boundaries:

### Scenario 3: Moving a chat whose source session is not resident

- Critical path: The explicit moveChat request enters the same global sequencer. For a session destination, the newly added source restore completes before existing validation, target restore, catalog snapshot reads, folder/worktree preparation, and commit. Promotion to a new session returns before the new restore call and is unchanged.
- Scaling input: One source restore per cold source session and at most one target restore per explicit move; existing subtree/folder work scales with the moved chat subtree, not with all listed sessions.
- Effective concurrency: Globally serialized moves; per-session restore coalescing prevents duplicate concurrent source hydration. No new parallel burst is introduced.
- Cache behavior: Resident sources skip the added restore. Cold successful restores are retained within the bounded residency cache; in-flight restores are joined. Promotion-to-new-session does not invoke the new source restore branch.
- Mechanism confidence: High: branch placement proves new-session promotion is unaffected and cold session-destination moves add exactly one guarded source restore.
- Magnitude uncertainty: The UI prevalence of stale/unloaded source requests and provider restore duration are not measured.
- Expensive boundaries:
  - database at <code>src/vs/platform/agentHost/node/agentService.ts:\_moveChat/\_restoreForMove</code>: Hydrate source registry/catalog/session state before validating and moving its chat.; cardinality: One coalesced restore for one cold source per explicit move.
    - Introduced by diff: true; previous behavior: The move validation read absent state and refused; it did not hydrate the source.; critical-path effect: Added to the critical path only when the source is not resident.
  - filesystem at <code>src/vs/platform/agentHost/node/agentService.ts:\_restoreSessionState</code>: Provider metadata lookup/materialization during cold source restore.; cardinality: One provider lookup/materialization for the cold source, with existing catalog fallback on a miss.
    - Introduced by diff: true; previous behavior: No source provider restore occurred on this previously refused path.; critical-path effect: Blocks that explicit cold-source move.
  - database at <code>src/vs/platform/agentHost/node/agentService.ts:\_moveChat</code>: Existing target restore, grouped catalog snapshot reads, and move persistence.; cardinality: One target and one grouped source/target operation per move, plus existing moved-subtree persistence.
    - Introduced by diff: false; previous behavior: Already performed for successful moves with resident sources.; critical-path effect: Existing successful-move critical path.
- Verdict: No reportable regression. This is deferred, bounded first-use work that enables a previously unsupported cold-source operation, with no per-row or per-chat fan-out beyond existing restore semantics.
