# Performance review: automations: remember folders selected in workspace picker

[PR #340326](https://github.com/microsoft/vscode/pull/340326) at `2b9698d034ceba29389d8995c8916c95fc646a8d`

## Findings (1)

### 1. [medium] Do not start a hidden new-session backend when recording an automation pick

**Finding ID:** `PERF-BA2923EFA6EE`  
**Location:** <code>src/vs/sessions/contrib/automations/browser/automationDialog.ts:1845</code> (<code>LEFT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** An additional hidden draft session, including agent-host config/branch RPCs and an eager backend session creation  
**Scaling:** Each accepted automation selection that changes the checked folder emits one shared recents event; while the covered NewChatView remains alive and has not been explicitly picked, every such event can replace its draft and eagerly create another backend. Rapidly trying several folders repeats this startup/churn once per accepted pick.  
**Outcome:** Unnecessary backend startup, IPC/network work, and session replacement add resource contention and can delay the automation draft that the user actually selected.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** AutomationsWorkspacePicker overrode \_shouldPersistSelection() to return false, so its accepted picks did not call addRecentWorkspace, did not broadcast onDidChangeRecentWorkspaces, and only the automation draft synchronizer created a session for the selected target.  
**Changed behavior:** Deleting the override makes the automation picker inherit true. WorkspacePicker.\_selectFolder now calls addRecentWorkspace; \_persistRecentWorkspaces synchronously fires onDidChangeRecentWorkspaces, causing other live WorkspacePickers to run \_restoreAutomaticSelection.  
**Confidence:** 0.98 — The complete synchronous event and session-creation path is present in repository code, the hidden NewChatView lifetime is explicitly preserved by the custom-view visibility implementation, and agent-host eager backend creation is explicit. Provider-specific backend cost varies, which affects magnitude but not the extra creation mechanism.

**Causal diff evidence:** Removing AutomationsWorkspacePicker.\_shouldPersistSelection() at the deleted line changes its return value from false to the inherited true, newly activating the shared persistence/event path for automation selections.

Open Automations from the Agents window and choose a different folder while the default new-session composer is covered by the custom view. SessionsPart only marks that composer invisible rather than disposing it, so its picker consumes the history event, fires onDidSelectWorkspace, and NewChatWidget.openNewSession creates a second, unseen draft. Agent-host providers then resolve config/load branches and call eagerCreate in addition to the intended automation session.

**Evidence:** The deleted override is the only guard preventing inherited persistence. The resulting call path is WorkspacePicker.\_selectFolder -&gt; SessionsRecentWorkspacesService.addRecentWorkspace -&gt; \_persistRecentWorkspaces -&gt; onDidChangeRecentWorkspaces -&gt; hidden WorkspacePicker.\_restoreAutomaticSelection -&gt; onDidSelectWorkspace -&gt; NewChatWidget.\_onWorkspaceSelected -&gt; SessionsService.openNewSession -&gt; SessionsManagementService.createNewSession -&gt; provider.createNewSession. BaseAgentHostSessionsProvider.\_createDraftSession explicitly invokes \_startNewSessionBackend, which resolves config, loads branches, and calls newSession.eagerCreate(connection). Workbench.\_applyCustomViewGridVisibility merely calls SessionsPart.setContentVisible(false); NewChatView remains constructed and only updates its visibility observable, so this listener is live while the Automations custom view and dialog are open.

**Suggested direction:** Keep storing the checked recent workspace, but prevent external history restoration from creating a draft in a suspended NewChatView—for example, apply the restored selection silently while inputVisible is false and defer \_onWorkspaceSelected until that view becomes visible, or make the recents notification source-aware so inactive consumers do not run session-creation side effects.
