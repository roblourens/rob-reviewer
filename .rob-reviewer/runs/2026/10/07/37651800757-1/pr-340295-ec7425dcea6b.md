### Scenario 2: Focus, open, and close the application menubar while the window/title bar is inactive

- Critical path: The existing MenuBar focus-state transition synchronously emits a boolean; the new listener toggles one class, and CSS updates opacity for the fixed-size title-bar container. This is on the interaction path, but only on transitions into or out of focused/open state, not per menu item, frame, or pointer movement.
- Scaling input: One class mutation and one title-bar style/compositing update per focus-state transition; work is independent of workspace size and menu action count.
- Effective concurrency: Single synchronous UI-thread event handling; no burst, loop, or unbounded scheduling is introduced.
- Cache behavior: No application cache is involved; normal browser selector/style caching may apply equally across repeated transitions.
- Mechanism confidence: High: MenuBar suppresses identical focus states and fires only after state changes; the added callback performs a single classList.toggle.
- Magnitude uncertainty: Exact repaint/compositor behavior depends on browser and platform, but the affected region is the bounded title bar and transition frequency is user-driven and low.
- Expensive boundaries: none found
- Verdict: No reportable regression: the bounded style invalidation is necessary for the intended visual/stacking behavior and does not scale with realistic collection size or run at frame frequency.

### Scenario 3: Remove or reinstall the custom menubar after menu-bar visibility configuration changes

- Critical path: Uninstall clears the existing disposable stores and menubar, then the diff synchronously removes the focus class before removing the menubar DOM. No external operation blocks progress.
- Scaling input: Constant work per infrequent configuration-driven uninstall; one listener and one class token are cleaned up.
- Effective concurrency: Serialized synchronous configuration handling on the UI thread; no concurrency or pending work is added.
- Cache behavior: No cache behavior is changed.
- Mechanism confidence: High: the listener is registered in customMenubarDisposables, cleared before control disposal, and the class is explicitly removed.
- Magnitude uncertainty: Configuration changes are user-driven and rare; there is no meaningful scale uncertainty.
- Expensive boundaries: none found
- Verdict: No reportable regression: cleanup prevents retained listeners/stale styling and adds only constant DOM work.
