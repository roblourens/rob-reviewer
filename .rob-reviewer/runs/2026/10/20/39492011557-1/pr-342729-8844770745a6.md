Test execution itself remains the dominant critical path.
- Scaling input: Changed-file pagination scales by one request per 100 files; full test cardinality is fixed at 21 expanded jobs and reporter cardinality at 15 checks.
- Effective concurrency: After the single Detect Changes job completes, the same 21 expanded test jobs can run independently across Linux, macOS, and Windows; smoke tests remain two shards per OS. The reporter expands to 15 independent Ubuntu jobs only after all 18 calling-job IDs (21 matrix-expanded jobs) settle.
- Cache behavior: Detector results are computed once and shared as job outputs; failures, empty lists, and incomplete lists fail open to full tests. Existing dependency and built-in-extension caches inside reusable workflows are unchanged for both warm and cold runs.
- Mechanism confidence: High: the new needs edges, fixed matrix cardinalities, API pagination, and reporter fan-in are explicit in the workflow.
- Magnitude uncertainty: Runner queue time and reporter startup duration vary, but the added gate and reporter hop are bounded and small relative to the unchanged full test matrix.
- Expensive boundaries:
  - network at <code>.github/workflows/pr.yml:23 and .github/actions/detect-changes/detect.ts:listChangedPaths</code>: Sparse checkout of the detector plus GitHub pull-request changed-file pagination; cardinality: One sparse checkout and ceil(changed-file-count/100) API pages per workflow run, shared by every path rule

### Scenario 2: Documentation-, cli/-, or copilot\_shim/-only pull request

- Critical path: Detect Changes is the only prerequisite for core checks. Once it classifies every path as skippable, all 21 expanded core test jobs are omitted and 15 short reporter jobs establish the required check names.
- Scaling input: Classification scans each changed and previous rename path against three core rules; realistic cardinality is the GitHub changed-file list, with early find termination per rule.
- Effective concurrency: One detector runs first; no core test runner is provisioned. Fifteen bounded reporter jobs may then run concurrently.
- Cache behavior: There is no persistent detector cache; one computed output set is coalesced across all jobs. Lookup failure, truncation, or an empty list disables skipping rather than repeatedly retrying.
- Mechanism confidence: High: job-level conditions consume the three detector outputs and omit every core job when all paths are skippable.
- Magnitude uncertainty: Exact runner-minute savings depend on cache warmth and queue time, but removal of 21 heavyweight jobs is mechanically certain.
- Expensive boundaries:
  - network at <code>.github/workflows/pr.yml:changes</code>: Sparse checkout and changed-file API pagination; cardinality: One sparse checkout plus ceil(changed-file-count/100) API pages
    - Introduced by diff: false; previous behavior: The detector already ran for other path-filtered jobs, but its result did not suppress core tests.; critical-path effect: Required to prove all changed paths are skippable; it replaces the much longer test critical path.
  - other at <code>.github/workflows/pr.yml core test jobs</code>: Core test job scheduling and execution; cardinality: Zero after the diff versus 21 expanded test jobs before the diff
    - Introduced by diff: true; previous behavior: All Electron unit/integration/smoke, browser unit/integration/smoke, and remote jobs ran regardless of these changes.; critical-path effect: The expensive cross-platform test boundaries are removed entirely for this scenario.
  - other at <code>.github/workflows/pr.yml:required-checks</code>: Required-check reporter scheduling; cardinality: 15 short jobs after detection versus six reporters plus 21 full tests previously

- Verdict: Performance improvement, not a regression. The diff replaces large fixed CI fan-out with one existing detector and bounded reporters.
