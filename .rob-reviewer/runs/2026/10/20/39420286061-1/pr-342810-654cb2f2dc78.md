# Performance review: agentHost: don't forward runtime-loaded user instructions as instructionDirectories

[PR #342810](https://github.com/microsoft/vscode/pull/342810) at `654cb2f2dc78b867ff249bf3bcddd0af70ac8988`

No high-confidence performance findings.

## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:10051` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:10037`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`  
**Introducing commit:** `a2ebe4a78af09ae0b78878e852eb9cadd697d752`  
**Mechanism family:** `repeated-work`  
**Performance category:** `network`  
**Confidence:** 0.96

**Mechanism:** Each launched or resumed chat session passed the Copilot-home instruction directory explicitly while SDK config discovery independently loaded it, duplicating filesystem loading and retaining/serializing the same instruction text twice in the model system prompt. Cost scaled with total user-instruction bytes and with sessions/turns that carry the prompt.

**Symptom:** User instruction content appeared twice in the system message, consuming duplicate prompt bytes/tokens and increasing model-request latency and context usage for sessions with user instructions.

**Fixed behavior:** Session plugin projection now excludes rules beneath the runtime-owned &lt;COPILOT\_HOME&gt;/instructions directory, while retaining workspace and additional-root instruction directories. The SDK therefore performs only its native user-instruction load instead of also receiving the same directory explicitly.

**Evidence:** At the blamed base line, \_appliedPlugins projected every discovered rule into the synthetic session plugin. copilotSessionLauncher.ts then flattens those instructions through toSdkInstructionDirectories and passes the resulting directories to createSession while enableConfigDiscovery is true. The changed test exercises the real warm-chat launch path and proves that the Copilot-home directory previously reached instructionDirectories alongside the workspace directory; the added predicate removes only rules under &lt;COPILOT\_HOME&gt;/instructions. The changed code and PR's measured system.message behavior establish that the runtime also discovers this user directory, so the old launch loaded the same user instruction content twice.
