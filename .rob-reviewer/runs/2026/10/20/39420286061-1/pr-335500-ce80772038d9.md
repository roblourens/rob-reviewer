# Performance review: agentHost: Exclude SDK-native skills from directory discovery

[PR #335500](https://github.com/microsoft/vscode/pull/335500) at `ce80772038d90f96f2ce4c8b6aa80702bb1afc13`

## Findings (1)

### 1. [medium] Coalesce plugin-root lookup before walking every child

**Finding ID:** `PERF-71E80394F77B`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:775</code> (<code>RIGHT</code>)  
**Performance category:** <code>startup</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** filesystem existence checks  
**Scaling:** For N distinct SDK-reported plugin agent/rule/skill files, findPluginRoot performs a serial ancestor walk for each file; each ancestor incurs up to three sequential exists calls, so the new filesystem work grows as O(N × path depth) even when all N files belong to one plugin root.  
**Outcome:** increased session-creation and customization-refresh latency from serialized filesystem I/O  
**PR causality:** <code>introduced</code>  
**Previous behavior:** SDK-native plugin results were converted directly into directory children (with only the existing per-skill file read); discovery did not walk filesystem ancestors for every plugin agent, rule, and skill.  
**Changed behavior:** Every plugin-sourced agent, rule, and skill URI is added to pluginFiles, then this loop awaits findPluginRoot separately for each exact file before deduplicating the resulting roots.  
**Confidence:** 0.96 — The changed loop, exact-file cardinality, sequential awaits, filesystem boundary, and startup await chain are explicit in code. Exact wall-clock impact varies with plugin count and filesystem cache, which is why severity is medium rather than high.

**Causal diff evidence:** The added \`for (const file of pluginFiles) { const root = await this.findPluginRoot(file, token); }\` loop at lines 774-775 precedes root deduplication; the added findPluginRoot implementation checks three manifest locations at every ancestor.

Opening a chat/session with installed plugins, or refreshing customizations, waits for 4-7 serialized stats for each typical agent/rule/skill path; plugins with many contributions or users with several plugins add proportional I/O latency before customizations or the SDK session can be published.

**Evidence:** pluginFiles is an exact-URI ResourceSet populated by discoverAgents, discoverRules, and discoverSkills. At line 775 each URI is processed serially. findPluginRoot (lines 815-833) starts at that file's directory and issues up to three awaited IFileService.exists calls per ancestor. Only after all walks does pluginRoots deduplicate common roots. SessionDiscoveredEntry.\_refresh awaits discover, and both getCustomizationsSettled (used by getChatCustomizations) and getAppliedPlugins (used by session snapshots) await that refresh, placing these checks on chat/session startup. One plugin with multiple agents, rules, and nested skills therefore repeats the same root/ancestor probes.

**Suggested direction:** Within one discovery pass, memoize/coalesce ancestor-to-root resolution (including in-flight and negative results) so sibling files reuse the first walk, then deduplicate roots before parsing. Preserve cancellation and avoid unbounded parallel stats.


## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:601` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:975`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts`  
**Introducing commit:** `74be51b68f68dad9c4117f9713441521978d83f3`  
**Mechanism family:** `repeated-work`  
**Performance category:** `io`  
**Confidence:** 0.95

**Mechanism:** Each SDK-native plugin child that was outside SDK discovery directories entered toDirectoryCustomizations and emitted an error-level invariant log on every discovery refresh, producing repeated log formatting and sink I/O proportional to plugin children and refreshes.

**Symptom:** Large volumes of repeated SessionCustomizationDiscovery invariant errors and corresponding log I/O during customization refreshes.

**Fixed behavior:** Plugin-sourced agents, rules, and skills are now collected into plugin containers and filtered out before directory grouping, so they no longer hit the fallback/error path; the fallback diagnostic is also downgraded to trace for genuinely unexpected directory-backed entries.

**Evidence:** The old base line 975 logged at error inside the per-customization fallback branch. The added filters at lines 601-603 remove plugin children from all three directory-grouping calls after source-tagged entries are collected, while line 982 changes any remaining invariant diagnostic to trace. SessionDiscoveredEntry reruns discovery on watched file and root-config changes, so the old per-child log repeated across refreshes.
