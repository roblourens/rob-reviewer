## Findings (1)

### 1. [medium] Keep the split worker within the existing concurrency cap

**Finding ID:** `PERF-1DDC7679D4AC`  
**Location:** <code>test/integration/agentHost/runner.ts:64</code> (<code>RIGHT</code>)  
**Performance category:** <code>subprocess</code>  
**Mechanism family:** <code>concurrency-burst</code>  
**Resource:** one additional concurrent Electron test process plus its Agent Host/provider subprocesses, CPU, memory, and filesystem I/O  
**Scaling:** Default concurrency is min(suites.length, availableParallelism); this added suite raises the aggregate from 6 to 7 workers whenever availableParallelism is at least 7, including the normal unqualified CI invocations.  
**Outcome:** higher peak CPU and memory pressure and I/O contention, which can reduce test throughput or cause timeouts/OOMs on shared CI agents  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The six-entry suite array made the default runner start at most six suite subprocesses; Copilot coverage used one worker.  
**Changed behavior:** The added copilot-runtime suite creates a seventh independently spawned process, and the unchanged default-jobs calculation now permits seven concurrent workers.  
**Confidence:** 0.97 — The runner derives its default job count directly from suites.length, CI invokes it without --jobs, and the diff increases the suite array from six entries to seven by adding a second Copilot worker. On hosts exposing at least seven CPUs, all seven suite subprocesses therefore start concurrently; exact contention severity depends on runner capacity, but the mechanism and trigger are direct.

**Causal diff evidence:** The added \`id: 'copilot-runtime'\` suite at RIGHT line 64 is a new independently spawned suite; with the unchanged \`defaultJobs = Math.min(suites.length, availableParallelism...)\`, it increases default process concurrency by one.

Running the standard Agent Host E2E command in GitHub/Azure or locally on a machine with at least seven CPUs now launches seven heavyweight workers at once rather than six. Each worker starts Electron-backed tests and Agent Host/provider processes, increasing peak resource contention even though the Copilot title filters are disjoint.

**Evidence:** CI scripts call runner.ts without --jobs, parseArguments computes defaultJobs as min(suites.length, availableParallelism), and main creates exactly jobs concurrent workers that each call runSuite/spawn. The changed suite array adds copilot-runtime while retaining all prior entries, so the default aggregate rises from six to seven.

**Suggested direction:** Preserve the split and coverage but cap the implicit default at the previous six workers (or pass an explicit six-worker cap from CI); keep higher concurrency an explicit --jobs opt-in.
