# Performance review: ci: run Monaco Editor checks only on pull requests

[PR #342753](https://github.com/microsoft/vscode/pull/342753) at `63277aeb066812d08e73ca2916e38e455f46b90f`

## Findings

No high-confidence performance findings.

## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `.github/workflows/monaco-editor.yml:4` (`LEFT`)  
**Blamed base line:** `.github/workflows/monaco-editor.yml:4`  
**Introducing path:** `.github/workflows/monaco-editor.yml`  
**Introducing commit:** `d1e59b8fc534fd31a0065820f8697bab503ec28c`  
**Mechanism family:** `repeated-work`  
**Performance category:** `subprocess`  
**Confidence:** 0.97

**Mechanism:** Each merge to main or release/\* generated a second heavyweight Monaco CI run after the pull-request run, repeating dependency/cache/network setup and all compile, bundle, and test subprocesses.

**Symptom:** Unnecessary post-merge runner time, subprocess work, network/cache traffic, and potential GitHub Actions queue contention on every matching push.

**Fixed behavior:** The workflow now triggers only for pull requests to main or release branches, eliminating one full post-merge CI job per matching branch push while preserving the pre-merge check.

**Evidence:** Base line 4 registered `push` for main/release branches in addition to the unchanged pull\_request trigger. The same workflow contains a single job that checks out the repository, restores or installs dependencies, downloads Playwright, runs multiple Monaco compile/distribution/type checks, bundles with webpack, compiles tests, and runs tests. Thus merging a checked PR caused another full run of the same heavyweight job on the resulting branch push; the PR deletes that push trigger while retaining PR validation. Blame identifies the trigger as introduced by d1e59b8fc534fd31a0065820f8697bab503ec28c.
