# Performance review: Move Monaco Editor checks to a separate GH action

[PR #144786](https://github.com/microsoft/vscode/pull/144786) at `d1e59b8fc534fd31a0065820f8697bab503ec28c`

## Findings (1)

### 1. [medium] Remove the duplicate Playwright browser download

**Finding ID:** `PERF-9BB17C71A82F`  
**Location:** <code>.github/workflows/monaco-editor.yml:56</code> (<code>RIGHT</code>)  
**Performance category:** <code>network</code>  
**Mechanism family:** <code>boundary-fanout</code>  
**Resource:** Playwright browser archive bytes, extraction CPU, and runner disk I/O  
**Scaling:** The cost is one extra installation of Playwright's full default browser set for every matching pull\_request and push workflow event; retries can repeat the network operation on failures.  
**Outcome:** increased CI latency and excessive network/disk work  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The CI hygiene job installed Playwright once and then ran the Monaco ESM and browser tests that consumed those browsers.  
**Changed behavior:** The new Monaco workflow installs Playwright for the moved browser tests, but the original CI hygiene job still unconditionally installs the same default browser set even though all Monaco browser consumers were removed from that job.  
**Confidence:** 0.98 — The workflow call count, script implementation, moved consumers, and absence of a browser-directory cache are directly visible. Exact download duration varies by runner/network, but the duplicated boundary and its placement before hygiene checks are certain.

**Causal diff evidence:** \`.github/workflows/monaco-editor.yml:56\` adds a new unconditional browser installation while the same diff removes every Monaco browser-check step from the old hygiene job but leaves that job's existing \`yarn playwright-install\` in place, increasing the scenario from one installation to two.

Every PR and matching push now downloads/extracts the default Playwright browsers twice on separate Ubuntu runners. The second, now-unused installation remains on the hygiene job's critical path, delaying that required result and consuming additional runner/network capacity.

**Evidence:** Line 56 invokes \`yarn playwright-install\`; package.json maps this to \`installDefaultBrowsersForNpmInstall()\`. The only Playwright consumers in \`test/monaco\` are the moved \`esm-check\` and editor tests. After the diff, the remaining hygiene steps are hygiene/layering/build/eslint/TypeScript checks, and repository searches show no Playwright use in those hygiene/layering commands. The cache action stores only \`\*\*/node\_modules\`, not Playwright's browser installation directory.

**Suggested direction:** Keep line 56 for the Monaco tests, but remove the now-unused \`Download Playwright\` step from \`.github/workflows/ci.yml\` so each event installs the browser set only in the workflow that consumes it.
