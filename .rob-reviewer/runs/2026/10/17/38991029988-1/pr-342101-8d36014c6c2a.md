### Scenario 1: Invoke \`copilot\` when an eligible Copilot CLI is already installed

- Critical path: The shim performs its existing PATH and official-install-directory discovery, then immediately execs/supervises the discovered CLI. \`prepare\_workflow\` returns before \`request\_install\`, so the new Linux policy-file and macOS preferences readers are off this critical path.
- Scaling input: Number of distinct PATH directories, unchanged by the diff; the added package symlink only makes the existing shim available system-wide.
- Effective concurrency: Single synchronous shim process followed by one final CLI process; no fan-out or added parallel work.
- Cache behavior: Discovery is intentionally per invocation and has no cross-process cache. The new policy readers are not reached after a successful candidate discovery.
- Mechanism confidence: High: control flow returns a launch action before any policy call, as corroborated by the added policy-read tests.
- Magnitude uncertainty: Filesystem timing varies with PATH composition, but the diff adds no work to this path.
- Expensive boundaries:
  - filesystem at <code>copilot\_shim/src/app.rs \`prepare\_workflow\` and copilot\_shim/src/candidate.rs \`discover\`</code>: Inspect PATH candidates and the supported fallback installation directory.; cardinality: One pass over distinct PATH directories plus at most one fallback directory; unchanged by the diff.
    - Introduced by diff: false; previous behavior: The same candidate discovery occurred before the PR.; critical-path effect: Must complete before selecting and launching the real CLI.
  - subprocess at <code>copilot\_shim/src/app.rs \`launch\_candidate\`</code>: Replace/supervise the shim with the selected Copilot CLI.; cardinality: Exactly one final CLI launch.
    - Introduced by diff: false; previous behavior: The same final launch occurred before the PR.; critical-path effect: This is the requested product execution.
- Verdict: No regression: normal launches of an installed CLI do not pay the new policy-read cost.

### Scenario 2: Invoke \`copilot\` when no eligible CLI is installed, including macOS interactive installation

- Critical path: After existing PATH and fallback discovery miss, the shim synchronously reads policy. Linux reads and parses \`/etc/vscode/policy.json\` once; macOS performs up to four CFPreferences reads and stops at the first disabling value. If allowed, the existing prompt/download/installer workflow proceeds; if disabled, the new check short-circuits that expensive work.
- Scaling input: Linux parsing scales with policy-file bytes; macOS remains fixed at four domains. Realistic policy files are small, and the path is reached only after CLI discovery misses.
- Effective concurrency: One shim process; policy reads are serial and bounded. Existing downloader and installer subprocesses remain serial fallback routes rather than concurrent fan-out.
- Cache behavior: Policy is deliberately uncached so each process observes administrator changes. Linux failures/missing/invalid JSON fail open; macOS values are copied and released per query. No shared cache misses or retained keys are introduced.
- Mechanism confidence: High: the new local reads and their placement are explicit in \`request\_install\`, setup probe/install, and policy tests.
- Magnitude uncertainty: Exact local read latency is platform-dependent, but the bounded work is small relative to a missing-CLI prompt/download and can remove that work under a disabled policy.
- Expensive boundaries:
  - filesystem at <code>copilot\_shim/src/policy.rs \`linux\_copilot\_cli\_command\_disabled\_at\`</code>: Read and parse the Linux policy JSON file.; cardinality: One file read per fresh missing-CLI invocation that reaches an installation decision.
    - Introduced by diff: true; previous behavior: Non-Windows shims returned \`false\` without reading a policy file.; critical-path effect: Synchronous before prompting or starting an installer; a disabled policy avoids all later network and subprocess work.
  - other at <code>copilot\_shim/src/policy.rs \`macos\_copilot\_cli\_command\_disabled\_with\`</code>: Query effective preferences for Stable, Insiders, Exploration, and OSS domains.; cardinality: One to four synchronous preference lookups, stopping when a false boolean is found.
    - Introduced by diff: true; previous behavior: The macOS shim did not read native policy.; critical-path effect: Synchronous before installation, but bounded to four scalar local lookups.
  - network at <code>copilot\_shim/src/install.rs \`run\_installer\` and setup install routes</code>: Resolve/download the Copilot CLI installer or release payload.; cardinality: Existing serial route/fallback behavior; zero calls when policy disables installation.
    - Introduced by diff: false; previous behavior: Allowed missing-CLI invocations already used these network routes.; critical-path effect: Existing dominant installation work after consent/policy allows it.
  - subprocess at <code>copilot\_shim/src/install.rs \`run\_installer\`</code>: Run curl/wget and then the downloaded Bash installer on Unix.; cardinality: Existing bounded serial attempts; Linux now avoids the prior extra PATH-filter discovery before Bash.
    - Introduced by diff: false; previous behavior: The same installer subprocesses ran before; Linux previously prepared a filtered PATH first.; critical-path effect: Existing installation critical path when policy allows installation.
- Verdict: No reportable regression: the added synchronous work is bounded policy enforcement on the missing-CLI path and can suppress much larger existing installer work.

### Scenario 3: Install, upgrade, reconfigure, or remove VS Code DEB/RPM packages

- Critical path: Package-manager lifecycle scripts run the embedded helper synchronously. The helper checks link state, invokes an edition shim in \`--vscode-shim policy\` mode, and performs guarded local link mutation. Package configuration/removal waits for these steps.
- Scaling input: Fixed edition set of two and one shared link, independent of package payload size or user data.
- Effective concurrency: Package hooks are serialized by the package manager. Each helper call launches one policy shim normally and at most two in hand-over paths; no unbounded concurrency or per-file fan-out exists.
- Cache behavior: Each package hook re-reads policy and debconf state so upgrades/reconfiguration apply current administrator choices. There is no long-lived process or retained cache; hand-over is limited to two known editions.
- Mechanism confidence: High: helper control flow, templates, and lifecycle tests establish exact subprocess and filesystem cardinality.
- Magnitude uncertainty: Process startup and package-manager baseline duration vary, but added work is fixed and rare compared with package installation/removal itself.
- Expensive boundaries:
  - subprocess at <code>resources/linux/copilot-link.sh \`vscode\_copilot\_link\_query\_policy\`</code>: Launch the packaged Rust shim to evaluate native policy.; cardinality: One launch for ordinary install/remove; up to two fixed launches when ownership is released or handed over between the two editions.
    - Introduced by diff: true; previous behavior: Package lifecycle scripts did not query Copilot shim policy or manage \`/usr/bin/copilot\`.; critical-path effect: Package configuration/removal waits for the bounded local process exits.
  - filesystem at <code>resources/linux/copilot-link.sh link inspection/replacement helpers</code>: Stat/readlink the shared entry and atomically create, replace, or remove a recognized symlink using a temporary sibling directory.; cardinality: A fixed number of operations against \`/usr/bin/copilot\` and at most two known edition targets per hook.
    - Introduced by diff: true; previous behavior: No shared Copilot command link was managed by these package hooks.; critical-path effect: Synchronous but bounded local filesystem work in package lifecycle.
  - ipc at <code>resources/linux/debian/postinst.template and postrm.template via debconf \`db\_input\`, \`db\_go\`, and \`db\_get\`</code>: Read or apply the DEB add-command preference.; cardinality: A fixed question/query for Stable or Insiders; OSS and unrecognized editions no-op.
    - Introduced by diff: true; previous behavior: No Copilot command debconf preference existed.; critical-path effect: Part of DEB configuration/removal; normal installs use the default at medium priority.
- Verdict: No reportable regression: the feature necessarily adds bounded local work to infrequent package hooks without collection scaling, network access, or concurrency bursts.
