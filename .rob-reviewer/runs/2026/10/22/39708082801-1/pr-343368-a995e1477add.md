## Findings (1)

### 1. [medium] Avoid rebuilding every changed-file tree on Toggle Details

**Finding ID:** `PERF-38FA331216F6`  
**Location:** <code>src/vs/sessions/contrib/layout/browser/desktop/desktopExistingSessionStrategy.ts:643</code> (<code>RIGHT</code>)  
**Performance category:** <code>rendering</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** CPU work, tree-model objects, resource-label objects, and DOM/list widget objects for every changed file  
**Scaling:** Each transition from hidden to shown synchronously reconstructs the file-list widget and calls setChildren over all N diff items; the profile-scoped storage event is shared, so the work is multiplied by each live multi-diff editor pane observing the setting. Repeated Toggle Details invocations repeat that O(N) construction.  
**Outcome:** Main-thread UI latency and GC pressure when showing the list, potentially producing a visible pause for multi-diffs containing hundreds or thousands of changed files.  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** In a Sessions window, Toggle Details only changed the auxiliary detail panel; it did not write the shared multi-diff file-list preference or synchronously rebuild changed-file trees. The existing Toggle Files caller is excluded from Sessions windows.  
**Changed behavior:** The added branch routes the commonly used Toggle Details command/keybinding through toggleMultiDiffEditorFileList. Its synchronous profile-storage notification causes MultiDiffEditorWithFileListWidget to recreate MultiDiffEditorFileList on show; that constructor immediately maps all diff items (and builds a ResourceTree in tree mode) before setChildren returns.  
**Confidence:** 0.93 — The added command path, synchronous storage-event fanout, clear/recreate lifecycle, and full-collection traversal are directly traced in repository code. Exact pause duration depends on changed-file count and number of live multi-diff panes, but the repeated O(N) main-thread mechanism is deterministic.

**Causal diff evidence:** Added RIGHT line 643 is the new Sessions-window caller of toggleMultiDiffEditorFileList; the preceding context-match branch did not exist before the PR, so Toggle Details previously followed only that.toggleDetails() and never triggered the shared file-list reconstruction path.

With a large generic multi-diff open in the Sessions editor area, hide the file list and invoke Toggle Details again. The command now blocks while rebuilding the complete file tree; repeating the command repeats the allocation and traversal, and multiple live editor groups react to the same profile event.

**Evidence:** The changed call at line 643 writes/removes multiDiffEditor.fileListHidden. observableMultiDiffEditorFileListVisible subscribes to that profile key for every editor. MultiDiffEditorWithFileListWidget's visibility autorun clears its MultiDiffEditorFileList when disabled and createInstance()s a new one when enabled. The new list's constructor derives the full viewModel.items array and synchronously runs getFileListElements(currentItems, ...), then \_tree.setChildren(...). getFileListElements maps every item in list mode and additionally creates a ResourceTree/path nodes in tree mode; no item-count cap is present.

**Suggested direction:** Preserve the MultiDiffEditorFileList instance while disabled and only toggle the split-view visibility, rebuilding it when the underlying view model or mode actually changes; if releasing the hidden tree is required for memory, defer/chunk creation off the command stack and coalesce repeated visibility changes. Keep the shared persisted visibility semantics and group routing unchanged.
