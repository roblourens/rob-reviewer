# Performance review: Support Compare Agents in empty local repositories

[PR #343626](https://github.com/microsoft/vscode/pull/343626) at `9070b2fee97ad8daab96f4966ad779be662f2a22`

## Findings (1)

### 1. [medium] Reuse one unborn-repository snapshot across comparison attempts

**Finding ID:** `PERF-166F339587D0`  
**Location:** <code>src/vs/platform/agentHost/node/shared/worktreeIsolation.ts:1210</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Git subprocesses, full working-tree filesystem scans, temporary-index writes, and blob hashing/staging  
**Scaling:** For a comparison with A attempts and F non-ignored files in the unborn repository, this performs A full status/stage/write-tree captures, so source-tree work grows O(A × F); A is 2–10 and creation is serialized per repository.  
**Outcome:** Comparison startup is blocked by repeated filesystem and Git work before all agent requests can start, producing avoidable launch latency and I/O/CPU pressure.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Comparisons without a remote were rejected, so the unborn local-repository path did not perform this snapshot work. Existing committed-repository worktree creation starts from the selected branch and does not capture the source tree for every attempt.  
**Changed behavior:** Each attempt whose selected branch is still unborn calls captureWorkingTreeAsTree and commitTree before its worktree is added. Creating the first attempt's generated branch does not create the selected source branch, so every later attempt enters the same block.  
**Confidence:** 0.99 — The attempt bound, first-send call path, repository-wide serialization, unchanged unborn source branch, and capture subprocesses are explicit in code. Exact duration varies with repository size and filesystem, which limits severity rather than confidence in the mechanism.

**Causal diff evidence:** The added call at worktreeIsolation.ts:1210 places a complete source-tree capture inside the per-session worktree-creation callback; that callback executes once for every comparison attempt, while the same added block leaves the source branch unborn and therefore repeats for subsequent attempts.

Starting Compare Agents in a newly initialized repository with many files rescans and stages the identical source tree once per selected model (up to ten times), and the repository-scoped worktree sequencer makes those captures additive on the launch critical path.

**Evidence:** startComparison maps all 2–10 attempts to createAndSendNewChatRequest and waits for Promise.all (sessionComparisonService.ts:103–178). First send calls resolveOnFirstSend (agentService.ts:1868–1884). All creations for one repository are queued by \_worktreeCreationSequencer (worktreeIsolation.ts:1167), and each queued callback independently reaches the added capture at line 1210 because selectedBranch remains unborn. captureWorkingTreeAsTree runs \`git status --untracked-files=all\`, builds a temporary index, stages every reported path with \`git add\`, and runs \`write-tree\` (agentHostGitService.ts:1047–1090, 806–810, 845–856). There is no cache or comparison-level coalescing.

**Suggested direction:** Capture the unborn baseline once at comparison setup and pass/reuse that commitish for all attempts, or add a repository-scoped snapshot lifetime/invalidation mechanism so attempts from one launch share one capture while later launches still observe source edits.
