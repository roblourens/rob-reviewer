### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/chat/browser/pluginSources.ts:101` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/pluginSources.ts:101`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/pluginSources.ts`  
**Introducing commit:** `0485c21d6bfd5cbb02bbafaf09da31eaf713ad01`  
**Mechanism family:** `repeated-work`  
**Performance category:** `subprocess`  
**Confidence:** 0.92

**Mechanism:** A successful first install of each SHA-pinned GitHub/Git URL plugin ran a redundant second exact-commit checkout after the clone path had already checked out and verified that commit, adding three serialized Git subprocesses and a duplicate worktree checkout.

**Symptom:** SHA-pinned plugin installation remained blocked on redundant Git process startup, object resolution, worktree checkout, and final HEAD verification after the clone itself had completed the same work.

**Fixed behavior:** For a newly cloned SHA-pinned source, the changed code performs one `rev-parse HEAD` and skips `_checkoutRevision` when the clone already materialized the requested SHA; mismatches still retain the exact-commit checkout and verification path, and existing cached repositories retain their prior checkout behavior.

**Evidence:** Base `AbstractGitPluginSource.ensure` unconditionally called `_checkoutRevision` immediately after `_cloneRepository`. For SHA pins, `NativePluginGitCommandService.cloneRepository` delegates to `LocalGitService.clone`, whose pinned path already fetches the SHA and calls `checkoutCommit`; `LocalGitService.checkoutCommit` performs `rev-parse <sha>^{commit}`, `checkout --detach`, and `rev-parse HEAD`. The base outer checkout therefore repeated all three subprocesses on the install critical path after the clone had already checked out and verified the same SHA. The changed condition first reads HEAD and skips that second checkout when it matches.
