**Relevant issue families:** repeated-work, missing-coalescing, concurrency-burst

### Scenario 1: Default installed-package one-shot build and watch

- Critical path: Package command resolution, manifest generation, and the esbuild bundle must complete before output is usable. In watch mode, the existing 100 ms event debounce precedes each rebuild.
- Scaling input: Source-change event waves; normally one effective rebuild per wave after debouncing.
- Effective concurrency: One timer coalesces events arriving before a build starts, but there is no in-flight build sequencer. The diff does not broaden the default installed-package watch root.
- Cache behavior: Without the override, resolveMarkdownEditorPackage returns import.meta.resolve directly. Imported command modules are keyed by mtime and cached; no new package filesystem validation occurs.
- Mechanism confidence: High: the unset-environment branch and unchanged default watch target are explicit.
- Magnitude uncertainty: Exact bundle duration varies, but the default path adds no scaling work.
- Expensive boundaries:
  - filesystem at <code>extensions/esbuild-common.mts:110 and extensions/markdown-language-features/esbuild.markdownEditor.mts:35</code>: Parcel recursively watches extension source and the installed commands-export directory.; cardinality: One subscription per configured root and normally one callback wave per save.
    - Introduced by diff: false; previous behavior: The same source and commands-export roots were watched; the diff only adds nested node\_modules and .git exclusions.; critical-path effect: A matching event schedules the full rebuild required for updated output.
  - subprocess/IPC at <code>extensions/esbuild-common.mts:98</code>: Run the full minified esbuild bundle through the esbuild service.; cardinality: One full build per debounced event wave in the normal default path.
    - Introduced by diff: false; previous behavior: The same full build ran after watched changes.; critical-path effect: The output is unavailable until this completes.
- Verdict: No reportable regression on the installed-package path.

### Scenario 2: One-shot Markdown editor build with a local override

- Critical path: Override validation and command-export resolution run before watcher/build setup; manifest generation then resolves the package again before the full bundle.
- Scaling input: A single selected package and its package.json/commands export; cardinality is constant rather than package-file-count dependent.
- Effective concurrency: The initial resolver runs serially, then manifest generation runs before the single full build. No burst occurs.
- Cache behavior: Selection is not cached, so the one-shot build validates and resolves twice; the esbuild service can be shared within the process, and the work remains bounded.
- Mechanism confidence: High for the calls and cardinality; low evidence that the bounded resolver overhead is user-significant.
- Magnitude uncertainty: The two extra resolutions add constant startup latency, but their tiny inputs do not establish a material regression.
- Expensive boundaries:
  - filesystem at <code>extensions/markdown-language-features/scripts/markdownEditorPackage.mts:18</code>: realpath the override and read/parse package.json.; cardinality: Twice in a normal override build: initial selection and manifest command loading.
    - Introduced by diff: true; previous behavior: Installed resolution used import.meta.resolve without override validation.; critical-path effect: Both calls block build progress.
  - subprocess/IPC at <code>extensions/markdown-language-features/scripts/markdownEditorPackage.mts:26</code>: Invoke esbuild.build to resolve the commands export, then invoke esbuild for the actual bundle.; cardinality: Two tiny resolver builds plus one full bundle for a one-shot override build.
    - Introduced by diff: true; previous behavior: No resolver builds were needed; only the required full bundle ran.; critical-path effect: Serial resolver calls precede the required full build.
- Verdict: No finding: extra startup work is constant and small relative to the required bundle.

### Scenario 3: Local package source edit with pnpm dev and watch-markdown-editor

- Critical path: The package compiler must write dist, then the final VS Code webview bundle must consume it. A bundle triggered directly by source is off the useful critical path but competes with both required stages.
- Scaling input: Source saves and distinct source/generated-output event waves. Effective multiplicity is one unnecessary full build plus the required build when compiler output arrives more than 100 ms after the source event; spaced output waves can queue more.
- Effective concurrency: The 100 ms timer only coalesces events before buildOnce starts. Once the first build waits in the 2 s manifest debounce, later events start more buildOnce calls; these share the manifest promise and can launch full esbuild builds concurrently when it resolves. There is no in-flight limiter.
- Cache behavior: The manifest debounce coalesces command loading, but does not coalesce the enclosing full builds. Stable module URLs are cached; full bundles are not.
- Mechanism confidence: High: dist-only consumption, the separate compiler, broad recursive root, debounce timings, and lack of in-flight serialization are explicit.
- Magnitude uncertainty: Compiler duration and watcher event grouping vary by machine, affecting prevalence and exact delay, but a greater-than-100-ms package compile is realistic.
- Expensive boundaries:
  - filesystem at <code>extensions/markdown-language-features/esbuild.markdownEditor.mts:36</code>: Recursively watch the entire override package, including unconsumed TypeScript source and generated dist.; cardinality: Source event wave plus one or more generated-output waves per save.
    - Introduced by diff: true; previous behavior: The watch target was the directory containing the resolved built commands export.; critical-path effect: Source events schedule work before consumable dist changes exist.
  - subprocess/IPC at <code>extensions/esbuild-common.mts:98</code>: Run a complete production/minified webview bundle for each started event wave.; cardinality: Two or more full builds per save when source and dist events cross the 100 ms start threshold, versus one required build previously.
    - Introduced by diff: true; previous behavior: Unconsumed source edits did not directly trigger the VS Code bundle; generated built-export changes did.; critical-path effect: The extra build consumes CPU/I/O and may run concurrently with the package compiler and final bundle, delaying usable output.
- Verdict: Reportable medium repeated-work/concurrency regression. report\_finding was attempted but the reporting tool returned execution failures.

### Scenario 4: Direct manifest generation/check with a local override

- Critical path: Package validation, commands-export resolution, command module load, and manifest read/update all complete before the command exits.
- Scaling input: One package and the command contribution collection; no per-package-file fan-out.
- Effective concurrency: Manifest files are read and conditionally written in parallel; package resolution is one serial call.
- Cache behavior: No cross-process cache. Within the short-lived command, one command module is imported using its mtime.
- Mechanism confidence: High for the added boundary, but insufficient evidence of material impact.
- Magnitude uncertainty: Exact resolver startup time varies; cardinality is fixed.
- Expensive boundaries:
  - filesystem at <code>extensions/markdown-language-features/scripts/updateMarkdownEditorPackageJson.mts:262 and :334</code>: Validate package.json, stat/import commands, and read or conditionally write the two extension manifests.; cardinality: One package validation, one commands stat/import, two manifest reads, and up to two writes per invocation.
    - Introduced by diff: true; previous behavior: Command loading used import.meta.resolve; manifest reads/writes were unchanged.; critical-path effect: All reads and command loading are required before comparison/output.
  - subprocess/IPC at <code>extensions/markdown-language-features/scripts/markdownEditorPackage.mts:26</code>: Use a tiny esbuild build to resolve the local commands export.; cardinality: Once per direct generator invocation.
    - Introduced by diff: true; previous behavior: No esbuild resolver build was performed.; critical-path effect: Adds bounded latency before command loading.
- Verdict: No finding because the added resolver work is bounded to one invocation.

**Summary:** Reviewed all six changed files and traced default/override builds, watch rebuilds, and manifest generation. One medium package-root watch regression was identified; repeated report\_finding calls failed at tool execution. No regression-fix learning record was warranted.
