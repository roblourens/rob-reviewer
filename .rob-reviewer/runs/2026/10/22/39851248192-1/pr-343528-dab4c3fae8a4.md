<summary>Reviewer scenario analysis</summary>

**Relevant issue families:** synchronous-ui-work, cleanup-lifecycle, eager-work

### Scenario 1: Agents window startup and construction of title bars, composer controls, banners, and automation form controls

- Critical path: DOM/control construction and registration of shared hover delegates/listeners complete synchronously before each surface is interactive; hover widget creation and content rendering remain off the startup critical path until pointer or focus interaction.
- Scaling input: Number of persistent controls on the visible surface, realistically tens; sharing delegates reduces delegate cardinality across adjacent toolbars and picker groups.
- Effective concurrency: Single UI-thread construction; each surface owns one shared instant-hover delegate where grouping was added, with no asynchronous fan-out or work queue.
- Cache behavior: Delegates persist for the owning widget/dialog and are reused warm across adjacent controls; no data cache, cache miss, negative cache, or coalescing behavior is changed.
- Mechanism confidence: High confidence from tracing createInstantHoverDelegate, WorkbenchHoverDelegate, setupManagedHover, and owning DisposableStore lifetimes.
- Magnitude uncertainty: Exact listener setup cost is unmeasured, but control cardinality is bounded and no heavyweight content is eagerly created.
- Expensive boundaries: none found
- Verdict: No reportable regression: added listener/delegate setup is bounded, disposed with its owner, and hover widgets are lazily created on interaction.

### Scenario 2: Moving the pointer among grouped title-bar, composer, automation, artifact, comparison, and prompt-option controls

- Critical path: After the initial configured delay, pointer movement invokes the existing hover service on the UI thread; same-group transitions can use zero delay, but only one top-level hover stack is active.
- Scaling input: One hovered target at a time among a bounded adjacent control group; cost scales with pointer transitions, not total repository/session data.
- Effective concurrency: Event-driven and effectively serialized by the hover service/current-hover state; no concurrent subprocess, IPC, filesystem, database, or network work.
- Cache behavior: The shared delegate retains only recent hide time and current hover disposables for its owner; hover identity/current state prevents duplicate top-level creation, and disposal clears listeners.
- Mechanism confidence: High confidence from HoverService and WorkbenchHoverDelegate call paths plus changed lifecycle grouping.
- Magnitude uncertainty: Rendering cost depends on hover content, but the diff primarily changes placement/grouping and does not add expensive content generation.
- Expensive boundaries: none found
- Verdict: No reportable regression: the diff changes hover timing and placement without increasing expensive-work cardinality or concurrency.

### Scenario 3: Rendering and recycling session-list, AI customization, and extension-list rows

- Critical path: Visible row rendering synchronously registers a delayed-hover listener/map entry; the actual hover DOM is created only if the user hovers. Row rendering itself does not cross an external boundary.
- Scaling input: Effective cardinality is the number of rendered/recycled visible rows, not the full session, customization, or extension collection.
- Effective concurrency: Single UI-thread virtualized list/tree rendering; row templates clear elementDisposables before reuse and dispose them when templates are destroyed.
- Cache behavior: Virtualized templates are reused; hover registrations are replaced through elementDisposables, and HoverService map entries are removed on disposal. No cold/warm backend cache behavior changes.
- Mechanism confidence: High confidence from renderer lifecycle and HoverService disposal tracing.
- Magnitude uncertainty: Visible-row counts and rerender frequency vary, but registrations are bounded and equivalent delayed-hover machinery already existed on session rows.
- Expensive boundaries: none found
- Verdict: No reportable regression: replacing native or element-positioned tooltips with custom mouse hovers adds bounded per-visible-row setup with explicit cleanup, not unbounded retention or collection-wide eager rendering.

### Scenario 4: Opening and interacting with a mobile picker sheet or mobile title-bar changes pill

- Critical path: Sheet construction and changes-pill render update tooltip strings and register managed/delayed hover handlers synchronously; popup rendering remains deferred until hover/focus.
- Scaling input: A small bounded set of sheet header actions and one changes pill; changes aggregation remains the pre-existing linear scan of changed files and is not increased by hover setup.
- Effective concurrency: Single UI-thread interaction with one shared delegate per sheet and one delayed hover for the pill; no asynchronous burst.
- Cache behavior: The sheet-scoped delegate and handlers are disposed on close; tooltip text is held only for the owning component lifetime.
- Mechanism confidence: High confidence from changed shell construction and component disposal ownership.
- Magnitude uncertainty: Mobile action counts vary but are structurally small; no evidence of large dynamic header collections.
- Expensive boundaries: none found
- Verdict: No reportable regression: custom hover setup replaces native titles with bounded lifecycle-owned listeners and does not add external work.
