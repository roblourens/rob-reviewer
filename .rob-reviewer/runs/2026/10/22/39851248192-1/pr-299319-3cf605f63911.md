### 1. cleanup-lifecycle

**Fix location:** `src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts:917` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts:908`  
**Introducing path:** `src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts`  
**Introducing commit:** `3bc832a220f0b2fb6375a197a46f0131d36f8767`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `io`  
**Confidence:** 0.98

**Mechanism:** Each uninstall discarded the only installed-plugin reference while leaving the cloned repository or npm/pip package tree on disk indefinitely. Repeated install/uninstall cycles, especially across distinct direct-source plugins, therefore accumulated filesystem bytes and directory entries without a lifecycle cleanup path.

**Symptom:** Agent plugin cache disk usage grew monotonically across uninstall cycles, with later cache scans and filesystem maintenance operating over retained plugin trees.

**Fixed behavior:** Uninstall still removes plugin metadata immediately, then asynchronously resolves and recursively deletes the direct source's cache directory and prunes empty parents. Relative marketplace paths remain untouched because they share a repository cache.

**Evidence:** In the base revision, MarketplaceAgentPluginDiscovery's remove callback only called removeInstalledPlugin(entry.pluginUri), which removes the persisted metadata entry. Direct GitHub/Git URL/npm/pip installs place cloned repositories or package trees under cacheHome/agentPlugins, and no other base-revision removal path deletes those source-owned directories. The PR adds cleanupPluginSource at RIGHT line 917; getCleanupTarget identifies the source-owned cache directory and cleanupPluginSource recursively deletes it after uninstall.
