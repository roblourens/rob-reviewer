### Scenario 2: Showing the Sessions customizations navigation shortcut and reacting to ignored/restored migration groups

- Critical path: When the treatment navigation is enabled, the state starts one asynchronous migration hint computation and temporarily clears availability. Sessions rendering and navigation remain usable; only the migration badge/shortcut waits.

- Effective concurrency: Each navigation state serially replaces its autorun generation and cancellation token. It may overlap with one active migration notice because these are independent consumers; there is no per-row or per-session fan-out.

### Scenario 3: Ignoring or restoring migration categories in the customization management editor

- Critical path: After confirmation, the editor updates profile storage and refreshes migration UI synchronously. Notice/navigation consumers react asynchronously; the editor does not wait for their migration discovery.
- Scaling input: Number of ignored harness/project/category keys retained in profile storage. Each user action adds/removes one or selected keys; normal cardinality is small and no new duplicate keys are possible because Set is used.
- Effective concurrency: A single synchronous storage update fans out to mounted consumers, each with cancellation-aware async refresh. The editor's own UI refresh remains immediate and local.
- Cache behavior: No cache is introduced. Reads deserialize the stored object and construct a Set, preserving prior editor behavior; consumers independently read the latest value on the storage event.
- Mechanism confidence: High: helper extraction is behavior-equivalent for storage, and all production writers were inspected.
- Magnitude uncertainty: Profiles can retain keys for multiple projects/harnesses, but realistic storage size is small and the PR does not change retention policy or representation.
- Expensive boundaries:
  - serialization at <code>src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationIgnoredGroups.ts:39</code>: Serialize the ignored migration key Set into profile storage.; cardinality: One profile-storage write per ignore or restore action; payload size is bounded by harness/category/scope combinations accumulated by the user.
    - Introduced by diff: false; previous behavior: The editor previously serialized the same groupKeys array directly to the same profile key.; critical-path effect: The storage write is on the action path, but the extracted helper preserves the prior write shape and target.
- Verdict: No performance regression. Serialization/allocation is unchanged, and the new reactive work is bounded to explicit ignore/restore actions.

- Effective concurrency: Five category computations remain parallel via Promise.all; the PR neither raises category concurrency nor introduces per-candidate async work.

- Mechanism confidence: High: the implementation was compared directly before/after and no expensive operation moved into the candidate loops.
