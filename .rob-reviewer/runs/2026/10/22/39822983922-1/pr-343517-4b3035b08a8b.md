### Scenario 1: Opening and dismissing the Agents welcome/Get Started UI while a new-session onboarding trigger is active

- Critical path: SessionsSetUpService synchronously sets or resets sessionsWelcomeVisible; OnboardingService already reevaluates registered scenarios on every context-key change. The changed expressions add one constant-time predicate per affected scenario. While visible, eligibility stops before enqueue/presentation; after dismissal, normal eligibility and the existing serialized presentation path may proceed.
- Scaling input: Four registered new-session tour variants among the bounded onboarding registry; each global context change already caused a registry scan before this diff.
- Effective concurrency: OnboardingService deduplicates pending/in-flight scenario IDs, claims the shared seen key across variants, sorts a single queue, and pumps presentations serially. The added gate does not create parallel work.
- Cache behavior: Seen-state and resolved experiment state are reused across evaluations. Cold experiment states remain ineligible until assignments resolve; warm states use in-memory values. The new predicate adds no cache, key growth, misses, or retries.
- Mechanism confidence: High: the changed lines only extend ContextKeyExpr conjunctions, and the traced service already subscribes to every context-key change and serializes eligible presentations.
- Magnitude uncertainty: Registry size and context-change frequency vary, but the diff adds only four primitive expression checks to an already-existing evaluation pass and suppresses rather than adds presentation work while welcome is visible.
- Expensive boundaries:

- Verdict: No reportable regression. The only new runtime cost is bounded constant-time predicate evaluation; expensive account/setup and presentation boundaries are not introduced or multiplied.

### Scenario 2: Normal new-session onboarding eligibility after the welcome UI is absent or dismissed, across original, view, V2, and V3 variants

- Effective concurrency: One presentation at a time; duplicate IDs join an existing run and shared seen-key claiming suppresses sibling variants in the same pass.
- Cache behavior: Warm seen and experiment state skip or cheaply admit scenarios; cold unresolved experiments remain gated. No positive/negative cache behavior changes.
- Mechanism confidence: High: call flow and queue/coalescing behavior are explicit in OnboardingService, and no filesystem, IPC, subprocess, database, or newly introduced network operation is reached by the changed expressions.
- Magnitude uncertainty: Exact registry cardinality is not material because the scan pre-existed and the diff adds a fixed number of boolean terms.

- Verdict: No reportable regression. Work after dismissal is the same bounded, coalesced onboarding work that existed before, with timing intentionally deferred.
