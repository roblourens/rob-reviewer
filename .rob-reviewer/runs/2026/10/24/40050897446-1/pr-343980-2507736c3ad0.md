## Findings (1)

### 1. [low] Cache launch-only tool configuration between changes

**Finding ID:** `PERF-C0394F350CAE`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:7159</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** CPU work and temporary objects from tool filtering/sorting, prompt construction, YAML parsing, custom-agent projection, and deep comparison  
**Scaling:** The synchronous cost is paid once for every send/resume even when nothing changed, and grows with the client-tool count, custom-agent/tool-reference count, and prompt-override YAML size.  
**Outcome:** increased turn-start latency and CPU/GC pressure  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this change, the common per-turn refresh path compared client tool definitions structurally; prompt overrides and the launch-only SDK configuration were resolved only while creating or resuming a session.  
**Changed behavior:** The added tail check invokes clientToolsRequireRestart for every otherwise-current session. That calls configuration.resolve(tools), which reconstructs the complete tool-dependent launch payload; when a prompt override is configured, applyPromptOverridesFromString reparses the retained YAML on every invocation before the result is deeply compared.  
**Confidence:** 0.95 — The synchronous call path and per-send frequency are explicit, and the resolver's YAML parse/allocation work is directly traced. Exact milliseconds and prevalence of large prompt overrides are uncertain, so severity is low.

**Causal diff evidence:** Added RIGHT line 7159 appends \`entry.clientToolsRequireRestart(currentSnapshot.tools)\` to every otherwise-clean refresh check; this per-turn call did not exist before the PR.

Every message waits synchronously for this reconstruction before it can be sent. The overhead is most visible in sessions with large experimental prompt overrides, many enabled tools, or many custom agents, and repeats across long conversations despite unchanged inputs.

**Evidence:** \_sendMessageOnce and \_resumeTurnOnce await \_refreshSessionConfiguration on the turn critical path. The new line 7159 unconditionally calls clientToolsRequireRestart on the common no-restart path; copilotAgentSession.ts:3674 resolves the full configuration, and copilotSessionLauncher.ts:1451/1461 reparses promptOverride.content and rebuilds filtered names, systemMessage, excludedTools, mapped custom agents, and sorted built-in-agent tool lists. The new test at copilotAgent.test.ts:27358 explicitly demonstrates that this comparison runs on each of three consecutive sends, including equal configurations.

**Suggested direction:** Retain the last resolved launch-only payload and recompute it only when tool definitions or the relevant configuration settings change. At minimum, parse the launch-frozen prompt override once and reuse its parsed representation while still re-evaluating settings that are intentionally live.


## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:11147` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:11134`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`  
**Introducing commit:** `f27c58f5fea16b220ec69b68ef6587e0f7cbd74c`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.98

**Mechanism:** The old restart comparison used generic deep equality on discovered resources, so URI objects whose mutable fsPath/toString caches differed after launch were treated as customization changes and caused an unnecessary SDK-session teardown/resume.

**Symptom:** Unchanged discovered agents or additional-root instructions could restart the SDK at subsequent turn boundaries, adding avoidable session-resume latency; the new integration test exercises repeated turns/tool toggles and expects one launch with no refreshes.

**Fixed behavior:** The PR compares discovered resources with semantic URI equality while comparing the remaining metadata structurally, preventing cache-only URI mutations from triggering session restarts.

**Evidence:** The deleted base lines compared discoveredAgents/additionalRootInstructions with generic equals. Added discoveredResourceEquals strips uri and uses isEqual for it. Tests populate URI fsPath/toString caches and verify no restart, and the multi-turn integration test records a single create, zero disconnects, and zero configuration refreshes.
