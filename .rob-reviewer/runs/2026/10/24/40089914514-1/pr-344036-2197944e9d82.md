## Findings (2)

### 1. [medium] Index rerun results before matching failure targets

**Finding ID:** `PERF-822C1761ECFF`  
**Location:** <code>test/unit/electron/index.js:770</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** CPU work and short-lived arrays created while repeatedly filtering all passed and failed test records  
**Scaling:** For T unique retry targets and P/F pass/failure records from the rerun, this executes O(T × (P + F)) scans; T is not bounded when the &gt;50-target whole-file fallback is active.  
**Outcome:** increased retry latency and CPU/GC pressure on broad-failure CI runs  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The Electron retry path tracked failed files in sets and reconciled a rerun with set construction/membership work linear in the number of failed files; it did not rescan every test result for every failure target.  
**Changed behavior:** Each pending target now independently filters the complete failure and pass arrays to rebuild per-file title collections after every rerun.  
**Confidence:** 0.98 — The nested scans, unbounded fallback target count, synchronous completion path, and CI retry enablement are explicit in the changed code. Exact wall-clock impact depends on how many failures a broad incident produces, which affects severity but not the mechanism.

**Causal diff evidence:** RIGHT line 770 adds construction of \`failedTitles\` by filtering the entire failure array inside the per-target callback; RIGHT line 772 similarly filters all passes. Before this diff, retry reconciliation operated on failed-file sets rather than a target/result cross-product.

When a shared or infrastructure failure produces more than 50 unique failed tests/suites, \`planRerun\` deliberately reloads their whole files, so a recovered retry can report thousands of passes while \`findPassedTargets\` rescans that full result once per original target. This synchronous work runs before the Electron test process can finish and can turn a broad retry into quadratic CPU and allocation cost.

**Evidence:** \`planRerun\` falls back to whole files once \`targets.size &gt; MAX\_RERUN\_TARGETS\`, but \`findPassedTargets\` then runs \`result.failures.filter(...).map(...)\` and \`result.passed.filter(...).map(...)\` inside the loop over every deduplicated target. The PR workflows enable two reruns for the full Electron and integration suites, making this path reachable on broad transient failures.

**Suggested direction:** Pre-index passes and failures once per rerun by file (and title/prefix as needed), then resolve every target from those indexes so reconciliation remains O(P + F + T), including the whole-file fallback.

## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `test/unit/electron/index.js:756` (`RIGHT`)  
**Blamed base line:** `test/unit/electron/index.js:650`  
**Introducing path:** `test/unit/electron/index.js`  
**Introducing commit:** `0b9c9384fcec8f929335c8a95380e55f756c9465`  
**Mechanism family:** `repeated-work`  
**Performance category:** `latency`  
**Confidence:** 0.96

**Mechanism:** A single flaky test caused every test in each affected file to execute again in a fresh Electron window on every retry, repeating already-successful test work in proportion to file size.

**Symptom:** Retry latency and CI resource use grew with all tests contained in failed files rather than with the actual failed tests; PR CI performs up to two retries.

**Fixed behavior:** The rerun plan now builds a title grep for up to 50 failed tests or failed-hook suites, so the fresh Electron window loads the required files but executes only the unresolved targets, retaining whole-file fallback for unsupported or broad cases.

**Evidence:** Base line 650, introduced by commit 0b9c9384fcec8f929335c8a95380e55f756c9465, constructed the next run from every failed file. The changed planner at line 756 creates a grep from deduplicated failed test/suite titles and passes it to the next window, directly removing execution of successful sibling tests for ordinary flaky failures.
