**Relevant issue families:** repeated-work, synchronous-ui-work, serialization-allocation, boundary-fanout

### Scenario 1: A server-initiated Agent Host turn completes with a selected or usage-reported model and the observing chat is open.

- Critical path: The existing Agent Host protocol completion action updates subscribed state; the single-shot turn observer queues one microtask, formats response details, finds the matching request, calls setResult, then marks the streamed session turn complete. The new formatting and result update are on the completion/UI critical path, but all work is synchronous and bounded by the completed turn and current transcript.
- Scaling input: One invocation per completed server-initiated turn. Formatting scans that turn's responseParts once, model lookup is a Map lookup, and matching the response scans the chat's request array once. Concurrent chats retain independent observers; each chat has at most one active turn observer in this path.
- Effective concurrency: State changes are handled by the existing subscriptions; each observer terminates once and invokes onTurnEnded once. Different active sessions can complete concurrently, with no new fan-out or unbounded scheduling introduced by the diff.
- Cache behavior: Language-model metadata is read from the existing in-memory \_modelCache. Cold cache misses return undefined without I/O; warm hits return metadata directly. No new cache key, retry, coalescing, or negative-cache behavior is introduced.
- Mechanism confidence: High confidence in the call path and costs: onTurnEnded is explicitly single-shot, lookupLanguageModel is a Map.get, and getRequests returns the existing array. Confidence is also high that no expensive boundary is added.
- Magnitude uncertainty: Very long transcripts or turns with many response parts increase the two linear scans, but each occurs once per server turn and is small relative to the existing per-progress rendering and completion flow; there is no evidence of a realistic user-visible regression.
- Expensive boundaries:
  - network/IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:\_watchForServerInitiatedTurns/\_observeTurn</code>: Receive the Agent Host chat turn lifecycle and usage actions through the existing session/chat subscription.; cardinality: Existing protocol actions per turn; the diff adds zero protocol calls.
    - Introduced by diff: false; previous behavior: The same subscribed completion action ended the streamed server turn without attaching response details.; critical-path effect: The completion action must already arrive before the turn can settle; the diff performs local formatting after arrival and does not add or move this boundary.
- Verdict: No finding. The new work is bounded, single-shot completion metadata formatting and a required response-model update; it does not introduce repeated boundary calls, concurrency bursts, retained state, or substantial synchronous UI work.

### Scenario 2: A server-initiated peer-chat turn completes without selected-model or usage-model evidence.

- Critical path: The same single-shot completion callback scans the completed turn's response parts and attempts in-memory model resolution. With no model evidence, details remains undefined, so the new condition does not call getSession, scan requests, or emit a result-change event unless pre-existing error or routing metadata already requires it; session completion proceeds as before.
- Scaling input: One responseParts scan per completed peer turn; no transcript request scan or UI result event is added when model evidence is absent.
- Effective concurrency: One active observer per peer chat turn, replaced/disposed through the existing MutableDisposable and terminal guard; no added parallel work.
- Cache behavior: Any attempted model lookup is against the same in-memory model cache and a missing model produces no I/O or retry. There is no fallback to another chat's model cache entry.
- Mechanism confidence: High confidence from the details guard and the test covering a model-less peer turn.
- Magnitude uncertainty: Response-part counts vary, but the scan is single-shot and no additional render/update occurs in this no-evidence case.
- Expensive boundaries:
  - network/IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:\_watchForServerInitiatedTurns</code>: Receive existing peer-chat turn start/completion actions from the Agent Host subscription.; cardinality: Existing lifecycle actions per peer turn; zero additional boundary operations from this diff.
    - Introduced by diff: false; previous behavior: The same peer turn completed from the subscribed state transition without attempting response-footer formatting.; critical-path effect: Action receipt remains the prerequisite for completion; the diff only performs local inspection afterward.
- Verdict: No finding. The no-evidence path adds only a bounded local inspection and preserves the prior absence of a response result update.

**Summary:** Reviewed the complete two-file diff and traced server-initiated turn start, streaming, single-shot completion, model-cache lookup, response mutation, and UI notification paths. No actionable performance regression or qualifying regression fix was found.
