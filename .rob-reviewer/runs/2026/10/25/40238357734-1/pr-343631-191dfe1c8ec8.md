- Mechanism confidence: High: the changed CSS selector and removed onMouseOver/onMouseOut observable updates directly establish the before/after UI-thread behavior.

- Expensive boundaries: none found
- Verdict: No reportable regression. Pane entry/exit now repaints all visible hierarchy guides as required, while row-to-row pointer traversal removes the previous repeated observable/set/class-update path and does not add a scaling boundary.

### Scenario 2: Scrolling, collapsing, or expanding sessions while the pointer remains over the pane

- Critical path: Existing tree virtualization renders/recycles visible rows; normal CSS matching then gives each newly rendered hierarchy guide the pane-hover opacity. No explicit iteration or follow-up notification was added by the diff.
- Scaling input: Rows entering or leaving the rendered viewport during scroll, plus visible children added by expansion; total session history does not determine DOM cardinality.
- Effective concurrency: Synchronous virtualized row rendering on the UI thread; existing animation-frame coalescing for list updates is unchanged.
- Cache behavior: No new cache or retained hover state exists. Recycled/new rows derive visibility from the current ancestor hover state, avoiding cache invalidation and per-row hover bookkeeping.
- Mechanism confidence: High: the changed selector operates on descendant rendered elements, and the list implementation is a WorkbenchObjectTree with recycled viewport rows.
- Magnitude uncertainty: The exact number of rows recycled per scroll varies with row height and viewport, but only rendered rows have DOM/pseudo-elements and participate in style/paint.
- Expensive boundaries: none found
- Verdict: No reportable regression. The added work is constant per rendered row and replaces rather than adds hover-state synchronization; there is no unbounded retention or repeated full-collection work.

### Scenario 3: Selection and keyboard focus preserve one or more hierarchy guides after the pointer leaves the pane

- Critical path: Existing selection/focus events update small sets of owning session IDs, and existing renderer autoruns toggle classes on rendered rows. The diff only removes hovered-session participation from that derived state.
- Scaling input: Deduplicated selected/focused session IDs and rendered row count.
- Effective concurrency: Synchronous event and observable propagation on the UI thread; no asynchronous fan-out or external boundary.
- Cache behavior: The selected/focused ID sets are transient observable state with unchanged lifecycle; the removed hovered value reduces retained and invalidated state. No positive/negative cache behavior applies.
- Mechanism confidence: High: the changed derived observable no longer reads or merges the hovered session ID, while selection/focus handling remains unchanged.
- Magnitude uncertainty: Multi-selection size can vary, but guide ownership is deduplicated in a Set and renderer work remains limited to currently rendered rows.
- Expensive boundaries: none found
- Verdict: No reportable regression. The changed code reduces observable recomputation and allocation by removing the hover ID and preserves the existing bounded selection/focus path.
