# Performance review: agentHost: eagerly load rename\_chat for active title generation

[PR #340020](https://github.com/microsoft/vscode/pull/340020) at `41170a57a8617d58228a26f227acfaa74bd13438`

## Findings (1)

### 1. [low] Defer \`rename\_chat\` again after the title is settled

**Finding ID:** `PERF-62E488A15E9E`  
**Location:** <code>src/vs/platform/agentHost/node/shared/sessionServerTools.ts:1857</code> (<code>RIGHT</code>)  
**Performance category:** <code>network</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** The roughly 1 KB \`rename\_chat\` description and JSON schema, plus the model's input-token processing for that schema  
**Scaling:** For Claude and for Copilot sessions with tool search active, the extra schema cost repeats on every model request for the lifetime of each active-agent session, including restored sessions whose title was already generated; cost grows linearly with subsequent turns and concurrently active sessions.  
**Outcome:** Repeated model-request bytes and input-token work increase per-turn latency and model/network throughput consumption after automatic naming no longer needs the tool.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** \`rename\_chat\` retained \`deferLoading: true\`, so supported runtimes kept its full schema out of normal model requests and loaded it through tool discovery only when needed.  
**Changed behavior:** Every session whose immutable title-generation strategy is \`activeAgent\` now receives \`deferLoading: false\`, regardless of whether its automatic title is still pending.  
**Confidence:** 0.95 — The changed flag, provider mappings, session-lifetime strategy, and post-rename reminder suppression are directly traced in code. The exact latency varies with provider prompt caching and chat length, which limits severity, but not the repeated eager-schema mechanism.

**Causal diff evidence:** The added return at line 1857 overrides the base definition's \`deferLoading: true\` with \`false\` for all \`activeAgent\` sessions, introducing unconditional eager loading beyond the initial title-generation turn.

After the first \`rename\_chat\` call, \`markTitleRenamed\` suppresses the naming reminder, but the session strategy remains \`activeAgent\`; every later turn—and every restored already-named session—still eagerly sends this tool. Claude maps the flag to \`alwaysLoad: true\`, and Copilot maps it to \`defer: 'never'\` when tool search is active, so long chats repeatedly pay for a tool needed only during initial naming.

**Evidence:** \`prepareInstructionForAgent\` stops requesting automatic naming once \`\_renamedTitles\` is set or persisted title source is agent/user (\`agentHostSessionTitleController.ts:552-568\`), while the strategy is retained for the session. This new branch checks only that strategy. The resulting flag is consumed as \`alwaysLoad: \!def.deferLoading\` by Claude (\`claudeServerToolMcpServer.ts:76\`) and as \`defer: ... ? 'auto' : 'never'\` by Copilot (\`copilotAgentSession.ts:2983\`); both provider tool inventories are built at launch. The definition includes a long description and four-property schema (\`sessionServerTools.ts:134-143,228-234\`).

**Suggested direction:** Base eagerness on whether automatic naming is actually pending (including persisted title source), and refresh/rematerialize the provider tool metadata after a successful rename; restored or already-renamed active-agent sessions should keep \`rename\_chat\` deferred.
