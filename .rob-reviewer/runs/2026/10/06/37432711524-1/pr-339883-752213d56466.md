## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:394` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:393`  
**Introducing path:** `src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts`  
**Introducing commit:** `4a6c184a37b4acaa5b1c085220c1ffd94d6fbe56`  
**Mechanism family:** `repeated-work`  
**Performance category:** `subprocess`  
**Confidence:** 0.97

**Mechanism:** The normal detached-launcher exit was treated as backend failure, closing live relay leases and causing each recovery to repeat WSL detection and bootstrap subprocess work.

**Symptom:** Successful WSL agent-host launches immediately lost their reusable session and forced avoidable WSL subprocess/bootstrap work and reconnection latency.

**Fixed behavior:** A code-0 launcher exit after readiness no longer tears down the per-distro session or relay leases, so later connects reuse the detached host URL and avoid repeated WSL platform detection/bootstrap subprocesses.

**Evidence:** In the base revision, every child `exit` called `onChildFailure`; after the URL had produced a session, that path called `_closeSession`, disposed every relay, and forced the next `connect`/`reconnect` through `_connectUnguarded`, including `_resolvePlatform` (`wsl uname`), a new `wsl.exe` bootstrap process, and a new WebSocket. The changed guard at line 394 recognizes the launcher's documented normal code-0 exit after printing the detached host URL. The added lifecycle tests exercise exits before, during, and after relay acquisition and prove subsequent connect/reconnect reuse one spawn rather than bootstrap again.

### Scenario 2: Successful detached launcher exit followed by additional connect or reconnect

- Critical path: After the URL is known, a code-0 launcher exit now returns without closing the session. A later connect/reconnect only opens a relay WebSocket against the retained URL; platform detection and bootstrap are off this warm critical path.
- Scaling input: Effective work is one retained session per active distro and one WebSocket per new relay lease, regardless of how many successful launcher-exit events occur for that single child.
- Effective concurrency: The retained session is shared; concurrent relay acquisitions can open separate WebSockets, while duplicate reconnects for one expected connection ID coalesce in \`\_pendingReconnects\`.
- Cache behavior: The \`\_sessions\` map is the positive cache keyed by distro and remains valid through the launcher's normal exit. It is invalidated on relay acquisition failure, explicit disconnect, final lease release, service disposal, or nonzero/signal/error launcher failure.
- Mechanism confidence: High: the changed guard preserves \`\_sessions\`, and added tests prove connect/reconnect use one child spawn across exits before, during, and after relay acquisition.
- Magnitude uncertainty: The saved latency depends on WSL state and whether CLI installation is already warm; the removed subprocess count is deterministic.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:\_createRelay</code>: Open a localhost WebSocket to the detached host for each additional lease.; cardinality: One handshake per effective new relay lease; reconnect calls for the same expected ID are coalesced.
    - Introduced by diff: false; previous behavior: A relay handshake was still needed, but normal launcher exit first destroyed the session, so recovery also repeated platform detection and launcher bootstrap.; critical-path effect: The handshake blocks that lease, but WSL detection/bootstrap no longer does.
  - subprocess at <code>src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:394</code>: Avoided repeat WSL platform-detection and bootstrap processes.; cardinality: Zero on warm reuse after the change versus a fresh detection and launcher after the old normal-exit teardown.
    - Introduced by diff: false; previous behavior: Every normal launcher exit entered \`onChildFailure\`, closed all leases/session state, and made the next connection cold-bootstrap again.; critical-path effect: The diff removes subprocess work from subsequent warm connection critical paths.
- Verdict: Performance improvement, not a regression. The concrete repeated-bootstrap fix was recorded with introducing commit provenance.

### Scenario 3: Host or relay failure after the detached launcher has exited

- Critical path: A physical WebSocket close notifies the reconnecting transport. Reconnect first checks running distros, then attempts a WebSocket against the retained session URL; connection-refused retries are bounded by the existing 30-second open deadline. On failure \`\_createRelay\` closes the stale session, allowing a later attempt to cold-bootstrap.
- Scaling input: One running-distro probe and one bounded WebSocket retry sequence per reconnect attempt; duplicate reconnects for the same connection ID coalesce. Cost does not scale with output history, and buffered launcher output is capped at 50 lines.
- Effective concurrency: Per-connection reconnect promises coalesce by expected ID, but independent relay IDs can reconnect concurrently. The diff does not alter the existing retry loop or aggregate limiter behavior.
- Cache behavior: The retained positive session is invalidated when relay acquisition fails. There is no negative cache; a later attempt can create a fresh session. Launcher output retention remains bounded.
- Mechanism confidence: High for the reconnect path and 30-second bound; lower for real-world frequency of detached-host-only crashes.
- Magnitude uncertainty: A detached host crash while its WSL distro remains running is less common than normal launcher exit, and whether localhost forwarding recovers within the deadline depends on the failure mode.
- Expensive boundaries:
  - subprocess at <code>src/vs/platform/agentHost/electron-browser/wslRemoteAgentHostServiceImpl.ts:81; src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:\_resolvePlatform</code>: Probe \`wsl --list --running --quiet\` before reconnect and, after stale-session invalidation on a later attempt, perform platform detection/bootstrap.; cardinality: One running-state probe per reconnect attempt; cold bootstrap occurs once after stale session removal, coalesced per distro.
    - Introduced by diff: false; previous behavior: The reconnect probe and bootstrap path already existed; before this fix, the normal launcher exit had already removed the session and forced bootstrap immediately.; critical-path effect: The probe and any eventual bootstrap block recovery.
  - network at <code>src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:\_openWebSocket</code>: Retry localhost WebSocket establishment against the retained URL with linear backoff capped at 500 ms and a 30-second total deadline.; cardinality: One bounded retry loop per effective reconnect, coalesced for duplicate expected connection IDs.
    - Introduced by diff: false; previous behavior: The same retry policy existed; the old normal-exit bug generally removed the session before a later reconnect could reuse it.; critical-path effect: The retry loop can delay stale-endpoint recovery, but it is the pre-existing bounded policy that also tolerates WSL forwarding startup.
- Verdict: No reportable regression. The retry is bounded, coalesced, and pre-existing, and the diff replaces an immediate, unconditional teardown that already made the successful-launch workflow unusable rather than moving a previously healthy recovery onto a slower path.

### Scenario 4: Final relay release, explicit disconnect, or service shutdown

- Critical path: Release crosses IPC, closes the WebSocket synchronously in the shared process, and when no acquisitions or leases remain disposes the session. Because the launcher already exited successfully, \`\_killChild\` returns immediately; the detached host self-cleans via its 300-second idle timeout off the release critical path.
- Scaling input: Cleanup is linear in leases belonging to the one session during explicit session close; normal final release handles one lease. Retained session state is bounded by active distros and leases.
- Effective concurrency: Pending relay acquisition prevents premature session close. Session disposal owns child listeners, and explicit service disposal iterates current connections and sessions once.
- Cache behavior: Final lease release invalidates the distro session. No session remains cached without a lease or pending acquisition; the remote detached process has its own bounded idle lifetime.
- Mechanism confidence: High: \`\_closeRelay\`, \`\_canCloseSession\`, \`\_closeSession\`, and \`\_killChild\` explicitly define ownership and cleanup.
- Magnitude uncertainty: The detached host's actual post-release shutdown time can be up to its configured 300-second idle timeout, but that bounded remote lifetime existed in the launch command and is not extended by retained local state after final release.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/electron-browser/wslRemoteAgentHostServiceImpl.ts:74</code>: Renderer releases the relay lease in the shared process.; cardinality: At most once per relay ID due renderer-side released/in-flight deduplication.
    - Introduced by diff: false; previous behavior: The same release IPC and deduplication existed.; critical-path effect: IPC dispatch precedes local cleanup; detached-host idle shutdown is off path.
  - network at <code>src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:\_closeRelay</code>: Close the relay WebSocket.; cardinality: Once per released lease.
    - Introduced by diff: false; previous behavior: The same WebSocket close occurred before the change.; critical-path effect: Local close is part of release; no new handshake or remote call is added.
  - subprocess at <code>src/vs/platform/agentHost/node/wslRemoteAgentHostService.ts:\_killChild</code>: Potentially signal the launcher child during session close; after a successful code-0 exit \`\_killChild\` observes the recorded exit code and does not signal or schedule escalation.; cardinality: One check per closed session, with zero signal calls for the successful detached-launcher case.
    - Introduced by diff: false; previous behavior: The same child-state check existed, but the session was often closed prematurely at normal launcher exit.; critical-path effect: No subprocess wait blocks release; detached host idle cleanup is asynchronous and remote.
- Verdict: No regression. Listener/session cleanup remains owned and bounded, and the diff does not retain local session state after the final lease.
