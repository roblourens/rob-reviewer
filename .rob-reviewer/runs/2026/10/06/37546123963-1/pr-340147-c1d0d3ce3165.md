## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:1289` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:1288`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`  
**Introducing commit:** `34a41e00d4609f76a472da3a7feb0a0090430d1c`  
**Mechanism family:** `repeated-work`  
**Performance category:** `rendering`  
**Confidence:** 0.97

**Mechanism:** Each sticky-enabled width resize invalidated measured source geometry but deferred recomputation until after an immediate sticky-tree refresh, producing an estimated sticky state followed by a measured state and repeated sticky DOM/editor construction and disposal.

**Symptom:** Width resizing a populated chat, especially across multiple panes, repeatedly rebuilt transient sticky rows and their heavyweight rendered content, increasing layout/render work and frame gaps.

**Fixed behavior:** The changed renderer.layout performs refreshStickyScrollSourceRanges synchronously after invalidating width-dependent ranges, so the immediate tree refresh consumes measured geometry and retains the existing sticky template instead of rendering an estimated row and rebuilding it after the animation-frame measurement.

**Evidence:** On a width change, ChatListWidget.layout calls tree.layout, then renderer.layout, then tree.refreshStickyScroll. In the base revision renderer.layout cleared stickyScrollSourceRangesByRequestId and only scheduled refreshStickyScrollSourceRanges for the next animation frame. The immediate tree refresh therefore received an estimated range from getStickyScrollSourceRange. StickyScrollWidget.setState renders a new state when measured height/source fields differ; the scheduled callback then measured request/sticky DOM bounds and refreshed the tree again, causing a second sticky-state render. The added test establishes that a real width change now measures geometry while preserving the same sticky row, bubble, and code-editor instances.
