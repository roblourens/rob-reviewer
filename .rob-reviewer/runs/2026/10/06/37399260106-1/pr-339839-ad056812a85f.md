## Performance regression fixes detected (1)

### 1. missing-coalescing

**Fix location:** `extensions/copilot/src/platform/authentication/common/quotaTokenRefresh.ts:68` (`RIGHT`)  
**Blamed base line:** `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts:1714`  
**Introducing path:** `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts`  
**Introducing commit:** `12b75316326c32737472cd3d496133b4501e54ec`  
**Mechanism family:** `missing-coalescing`  
**Performance category:** `network`  
**Confidence:** 0.98

**Mechanism:** Each sequential HTTP 402 (and the analogous WebSocket quota error) could reset the cached Copilot token and synchronously await another remote token mint when legacy quota metadata remained false, placing repeated authentication network calls on every failed inference's error path.

**Symptom:** Repeated quota-exhausted chat requests incurred repeated token-reset and token-mint latency/network traffic instead of one refresh per quota episode.

**Fixed behavior:** QuotaTokenRefreshRequest sets the scope latch before starting a token refresh and shares the in-flight promise, so repeated failures for the same account/endpoint/model perform at most one token mint until a newer successful inference rearms the scope; a five-minute gate bounds retries after refresh failures or rapid recovery cycles.

**Evidence:** In the base HTTP 402 path, line 1714 awaited getCopilotToken() after resetCopilotToken whenever the newly minted token still reported isChatQuotaExceeded=false. The same handler is reached once per failed chat inference request, so sequential quota failures each performed another Copilot-token mint network request. The PR routes HTTP and WebSocket quota failures through QuotaTokenRefreshRequest; its per-account/scope `latched` state and shared `pending` promise are exercised by the added regression tests, including repeated quota errors and concurrent refreshes.
