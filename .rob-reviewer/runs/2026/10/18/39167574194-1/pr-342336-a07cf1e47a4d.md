**Relevant issue families:** eager-work, serialization-allocation, boundary-fanout

### Scenario 1: Create or resume a Copilot Agent Host session

- Critical path: The launcher resolves existing BYOK, shell, plugin, prompt, and managed-settings inputs, constructs the fixed available-tools filter locally, then performs the existing SDK create/resume call. The changed allow-list construction is synchronous bounded array work on this path and adds no await or remote operation.
- Scaling input: One fixed allow-list of roughly forty built-in names plus two source wildcards per session launch/resume; it does not scale with workspace files, conversation length, or tool invocations.
- Effective concurrency: The pre-existing BYOK, shell-tool, and custom-agent work remains joined with Promise.all. The new filter is built once before the single SDK session operation and creates no additional concurrency.
- Cache behavior: The session config is recomputed on cold create and resume; there is no new cache or retry state. The same fixed default is used unless a per-model override replaces it.
- Mechanism confidence: High: the changed launcher line performs only local array construction and passes the result into the pre-existing one-session SDK call.
- Magnitude uncertainty: Exact SDK matching cost is not measured, but it is bounded by a small constant tool list and does not add a boundary call.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:\_createSession / session launch config</code>: Create or resume one session in the bundled Copilot runtime with the tools and filters in SessionConfig.; cardinality: One SDK session operation per create or resume; unchanged by the diff.
    - Introduced by diff: false; previous behavior: The same session operation ran with availableTools unset unless an override existed; all runtime tools were therefore eligible except excludedTools.; critical-path effect: This remains the terminal expensive boundary for launch. The diff only adds a bounded filter field to its existing payload.
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:session configuration assembly</code>: Resolve plugin custom agents and optional prompt overrides before session creation.; cardinality: Existing per-plugin/per-config reads, with ephemeral sessions skipping custom-agent enumeration; unchanged by the diff.
    - Introduced by diff: false; previous behavior: Identical plugin and prompt-resolution reads occurred before session creation.; critical-path effect: These existing reads can delay launch but remain concurrent where already designed and are not increased by the changed tool filtering.
- Verdict: No reportable regression. The default allow-list adds only bounded launch-time serialization/matching and can prevent future unreviewed built-ins from adding eager prompt work.

### Scenario 2: Submit model turns with tool search enabled or disabled

- Critical path: Each turn reaches the existing model network request. With tool search active, server definitions marked deferred are omitted from the eager request and may be discovered through the existing tool-search flow when needed; without tool search, all server tools remain eager as before.
- Scaling input: Prompt cost scales with model requests and visible tool definitions. The currently wired production server-tool groups explicitly set deferLoading true or false, and per-session exceptions keep set\_workspace and active-agent rename eager, so the changed undefined default does not newly defer the current product set.
- Effective concurrency: Model continuations and tool calls retain the runtime's existing sequencing. The diff adds no parallel searches, queue, or burst.
- Cache behavior: Tool definitions are fixed at launch and participate in the existing prompt cache. Current materialized tools are refreshed from definitions, preserving their explicit deferral metadata; there is no new retained cache or miss loop.
- Mechanism confidence: High for the current set: repository search and group construction show explicit deferral on all wired production definitions and scoped eager overrides for first-turn tools.
- Magnitude uncertainty: Future contributed server tools that omit deferLoading could trade a discovery continuation for fewer repeated prompt tokens, but no such current hot path is established by the repository definitions.
- Expensive boundaries:
  - network at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:\_createServerSdkTools and model turn execution</code>: Send model requests containing eager tool definitions; when applicable, execute the existing deferred-tool discovery protocol.; cardinality: At least one model request per turn; additional discovery continuations occur only for deferred tools. The diff does not increase discovery cardinality for the currently wired server-tool set because those definitions already specify deferral explicitly.
    - Introduced by diff: false; previous behavior: Current explicitly deferred tools used the same discovery path and explicitly eager tools stayed eager; unspecified definitions would previously have been eager.; critical-path effect: Model requests remain on the turn critical path. The changed fallback can reduce request bytes for future unspecified tools rather than adding an existing product request.
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:tool-search override handlers</code>: Forward tool-search metadata/results between the runtime and host/client tool implementation.; cardinality: One forwarding sequence per model-requested tool search, with effective candidates deduplicated by tool name; unchanged for current definitions.
    - Introduced by diff: false; previous behavior: The same bridge handled tools already marked deferLoading true.; critical-path effect: Only runs when the model searches for a deferred tool and remains an existing continuation on that turn.
- Verdict: No reportable regression. The change establishes a future-safe default without moving a current important tool onto an extra discovery boundary.

### Scenario 3: Run the new built-in allow-list provider integration test in CI

- Critical path: The test starts one Copilot SDK client, creates four sessions serially (two model profiles with filtered and unfiltered variants), switches each through three modes, reads tool metadata, then stops the client and loopback server.
- Scaling input: Fixed at two models, two filter variants, and three modes: four sessions and 36 mode/initialize/metadata RPCs, plus bounded create/disconnect operations.
- Effective concurrency: The model and filter loops are serial; one SDK client and one local HTTP server are shared for the single test. There is no unbounded parallel process or request burst.
- Cache behavior: A fresh temporary directory and client are used for the test, so this is cold-start work once per test invocation; no state is retained after teardown.
- Mechanism confidence: High: the test loops and process lifecycle establish the exact bounded concurrency and session count.
- Magnitude uncertainty: Exact CI wall time depends on bundled runtime startup, but all multiplicities are fixed and the test shares one process.
- Expensive boundaries:
  - subprocess at <code>src/vs/platform/agentHost/test/node/providerIntegration/copilotBuiltinToolAllowlist.integrationTest.ts:setup/teardown</code>: Start and stop one bundled Copilot runtime client.; cardinality: One process lifecycle per test case; introduced by the new test.
    - Introduced by diff: true; previous behavior: This dedicated allow-list test and its runtime process did not exist.; critical-path effect: Adds bounded CI test latency only and is required before session metadata can be inspected.
  - IPC at <code>src/vs/platform/agentHost/test/node/providerIntegration/copilotBuiltinToolAllowlist.integrationTest.ts:registeredBuiltins</code>: Create sessions, set three modes, initialize tools, fetch current metadata, and disconnect.; cardinality: Four sessions; 12 mode changes, 12 initializations, and 12 metadata reads, all serial.

  - network at <code>src/vs/platform/agentHost/test/node/providerIntegration/copilotBuiltinToolAllowlist.integrationTest.ts:loopback synthetic API server</code>: Serve SDK ancillary requests from a local synthetic endpoint.; cardinality: Bounded by the four session setups and runtime initialization behavior; no external network access.
    - Introduced by diff: true; previous behavior: This test-specific loopback server did not exist.; critical-path effect: Loopback responses support SDK startup/session creation and do not fan out with repository size.
- Verdict: No actionable performance regression. The added CI work is test-only, fixed in cardinality, serial, and directly exercises the runtime behavior under review.
