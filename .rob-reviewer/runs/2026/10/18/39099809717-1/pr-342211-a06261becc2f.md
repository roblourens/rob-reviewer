# Performance review: Experimental Fusion model picker with inline tier presentation

[PR #342211](https://github.com/microsoft/vscode/pull/342211) at `a06261becc2f24a7fec49de35370eb4b44eb1d37`

## Findings (1)

### 1. [medium] Do not block tier selection on profile-file persistence

**Finding ID:** `PERF-372461838833`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts:1152</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** Scoped storage writes plus language-model profile filesystem reads, JSON parsing, and save operations  
**Scaling:** Each distinct tier click queues another per-model configuration edit; latency grows with filesystem delay, language-model configuration file size, and additional clicks made while the popup remains open.  
**Outcome:** Blocked interaction critical path and increased tier-selection latency  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this diff, selecting a model row applied the selection and hid the picker synchronously; configuration edits were available only in the details flow, where keeping the details open was intentional. No direct picker-close path waited for profile persistence.  
**Changed behavior:** Selecting a mutable inline Fusion tier now keeps the model picker open and delays applying the model until configuration persistence has fully completed.  
**Confidence:** 0.98 — The changed action is explicitly async and awaits setModelConfigValues, and the changed delegate explicitly waits for thenables before hide(). The traced implementation synchronously writes the chat-scoped storage bucket, then awaits ILanguageModelsService.setModelConfiguration, which reads/parses and saves the language-models profile file and reads/parses it again. The only uncertainty is the absolute duration on a given filesystem, not the mechanism or critical-path reachability.

**Causal diff evidence:** The added inline-tier action at RIGHT line 1152 awaits setModelConfigValues before applying the model selection; the same diff changes the selection delegate at lines 530-537 to defer hide() until that returned promise resolves.

With inline tiers enabled, clicking Standard/High/Max can leave the popup visibly open and the requested model unapplied for the duration of profile-file I/O. On a slow or busy profile filesystem, this makes a basic picker selection feel stuck; repeated clicks while it remains open can also queue additional serialized saves.

**Evidence:** setModelConfigValues queues per model and awaits configurationAccess.setModelConfiguration. In normal chat, ChatModelConfigurationStore.setModelConfiguration first persists the scoped bucket, then awaits ILanguageModelsService.setModelConfiguration. That service updates the language-models configuration through LanguageModelsConfigurationService, whose update path performs fileService.exists, creates/parses a text-model reference, saves the profile file, and reloads/parses it. The new delegate does not hide the picker until this chain settles.

**Suggested direction:** Hide the picker immediately after accepting the inline tier and keep only selection ordering/cancellation behind the save promise, or update the scoped in-memory value/apply the selection synchronously and persist in the background with explicit error reporting. Do not make popup dismissal await the profile-file write.

- Effective concurrency: SequencerByKey serializes edits per model. Rapid clicks do not run filesystem writes concurrently, but distinct tier changes queue and extend total latency; there is no latest-value coalescing.
- Cache behavior: The chat-scoped configuration is cached in memory, but a real changed tier is persisted to both the scoped storage bucket and profile-global language-model configuration. A repeated identical value can become a no-op after an earlier edit completes, but distinct queued values are not coalesced.
- Mechanism confidence: Very high: both awaits, the per-model sequencer, scoped storage write, and profile file read/save/re-read implementation are directly traced.
- Magnitude uncertainty: Absolute delay depends on profile file size, platform storage, filesystem load, and whether multiple configuration groups exist. The hidden setting limits prevalence, which lowers severity but not confidence in the latency mechanism.
- Expensive boundaries:
