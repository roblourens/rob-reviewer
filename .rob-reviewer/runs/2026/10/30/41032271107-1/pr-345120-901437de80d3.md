### Scenario 3: A user queues, steers, reorders, or removes pending requests in an Agent Host chat, causing renderer-side pending-message synchronization.

- Critical path: Each explicit pending-queue mutation synchronously rebuilds snapshots for the current queue and deep-compares them with protocol state; changed custom-agent requests additionally decode/normalize their wrapped URI. Only new or changed snapshots dispatch protocol actions.
- Scaling input: Work scales with effective pending-queue length Q per explicit mutation. The newly added URI decode is O(Q) only for custom-mode entries; queues are user-created message queues and the existing synchronization already performs materially larger O(Q) snapshot/attachment/equality work.
- Effective concurrency: The model event callback is synchronous and processes the queue serially. Protocol sends remain one-way notifications; this change does not use Promise.all or create parallel fan-out.
- Cache behavior: No cache is used for URI conversion. Protocol-state comparison acts as deduplication, so unchanged entries do not generate repeat IPC; remote projections are guarded to avoid feedback synchronization.
- Mechanism confidence: High: listener registration, full-loop placement, URI decoder implementation, deep equality, and dispatch boundary were traced directly.
- Magnitude uncertainty: Very large manually accumulated queues would increase synchronous decode work, but realistic queue cardinality and tiny URI metadata make the incremental cost insufficient for a high-confidence user-visible regression.
- Expensive boundaries:
  - serialization at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:443 and 2531</code>: Decode agent-host URI metadata (URL query parsing, base64/JSON decode) and stringify the original URI for custom-mode pending requests.; cardinality: At most once per pending request with custom mode instructions on each pending-queue change event; default-agent and host-origin requests skip decoding.
    - Introduced by diff: true; previous behavior: Pending synchronization already traversed the full queue but did not decode the selected-agent URI.; critical-path effect: Runs synchronously inside the queue-change callback before diff dispatch, but alongside pre-existing per-item attachment conversion, model selection, maps, and deep comparisons.
  - IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:2676 via src/vs/platform/agentHost/browser/agentHostProtocolClient.ts:2007</code>: Serialize and send ChatPendingMessageSet/Removed/Reordered notifications to the agent host.; cardinality: One set action per actually new or changed message, plus existing removal/reorder actions; deep equality includes the agent URI and suppresses unchanged snapshots despite fresh wrapper objects.

- Verdict: No reportable regression: the only new scaling CPU work is a small URI normalization per custom queued request, with no added IPC cardinality or hot render/frame trigger.
