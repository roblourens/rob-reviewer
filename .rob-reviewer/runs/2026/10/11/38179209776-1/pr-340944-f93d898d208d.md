### Scenario 2: A canvas generated from /create-canvas opens, reads private durable state, and writes state from actions across hosts or workspaces

- Critical path: The skill now directs generated extensions to resolve COPILOT\_HOME, create their data directory on first use, validate a selected record when opening/reading, and perform temp-file-plus-rename writes. Those filesystem operations are on the generated canvas open/action critical path only when that canvas actually requires private durable state.
- Scaling input: Durable-state reads and writes, keyed by the selected domain identity. Effective cardinality is one selected record per open/action rather than all repositories or all records; concurrent sessions may target the same record.
- Effective concurrency: Multiple hosts may call generated extension actions concurrently. Unique temporary files plus atomic rename avoid partial reads; the skill does not introduce a loop, Promise.all fan-out, queue, or shared limiter.
- Cache behavior: Cold first use creates the extension directory; warm use reuses it. The guidance intentionally validates each read rather than caching potentially stale cross-process state. No in-memory cache, negative cache, or retained collection is introduced by the repository code itself.
- Mechanism confidence: High that the prompt now prescribes bounded validation and atomic filesystem work; low that any fixed workload or file size follows because generated implementations and requested canvas behavior determine both.
- Magnitude uncertainty: State size, action frequency, and whether durable private state is needed are request-dependent. The added rename and validation are bounded per selected record and are justified by cross-process durability; no realistic scaling regression is established by this diff alone.
- Expensive boundaries:
  - filesystem at <code>extensions/copilot/assets/prompts/skills/create-canvas/SKILL.md:37-42</code>: Read and validate a domain-keyed durable record.; cardinality: At most the record selected by the generated canvas operation; exact calls depend on generated extension logic.
    - Introduced by diff: true; previous behavior: The old skill specified a host-provided storage root but did not prescribe format/version/shape validation. The underlying durable-state read was still required by any stateful implementation.; critical-path effect: A generated open/action needing durable state waits for its selected read and validation.
  - filesystem at <code>extensions/copilot/assets/prompts/skills/create-canvas/SKILL.md:40</code>: Write a uniquely named temporary file and rename it over the target.; cardinality: Two filesystem mutations per durable record write, independent of the total records stored.
    - Introduced by diff: true; previous behavior: The old skill required durable storage but did not require atomic temp-file-plus-rename writes, so implementations could use one direct write.; critical-path effect: A generated state-changing action waits for the atomic write if its implementation persists synchronously with the action result.
- Verdict: No reportable regression. The added I/O is bounded per durable write/read and preserves atomicity across hosts; the diff does not prescribe collection-wide scans, unbounded buffering, or per-item boundary fan-out.
