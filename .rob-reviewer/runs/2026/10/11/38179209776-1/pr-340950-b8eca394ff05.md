- Critical path: The pre-existing SDK model-list RPC must finish before a fresh catalog can be published. The changed code then synchronously maps the single Auto model's retained tiers to labels; this bounded transformation is on the publication path but adds no wait or boundary.
- Scaling input: Catalog size controls the existing publication map, but the changed work applies only to the Auto entry and at most the three fixed Auto tiers (two after Ensemble filters Efficiency).
- Effective concurrency: Periodic and lifecycle refreshes coalesce onto one in-flight refresh; scheduled invalidations coalesce on the next task, and retries are sequenced by the existing generation/backoff logic.
- Cache behavior: The last known good CAPI catalog is retained on failures, BYOK enumeration is read from an existing registry cache, and repeated refresh requests share the in-flight promise. The diff changes neither cold catalog discovery nor warm-cache behavior.
- Mechanism confidence: High: the call path, one-RPC refresh behavior, coalescing, and fixed tier cardinality are explicit in the inspected code.
- Magnitude uncertainty: Runtime catalog size and RPC duration vary, but they do not change the added work's fixed upper bound or boundary count.
- Expensive boundaries:

- Verdict: No reportable regression. The diff adds only bounded string selection/localization and a two-element label array for the single Auto model; it neither increases RPC frequency nor scales with catalog size beyond pre-existing publication work.

- Critical path: Opening details synchronously obtains or reuses a ModelCard, builds routing-alternative options, refreshes the card DOM, and shows it. The changed branch computes one localized description for each available HydraFusion routing alternative before rendering.

- Effective concurrency: This is synchronous UI work on the interaction path; selection and refresh callbacks run serially on the UI thread. There is no added queue, fan-out, or asynchronous creation.
- Cache behavior: ModelCard instances are reused from \_cards by model/speed-variant key and updated in place. The diff does not change cache keys, lifetime, invalidation, or cold versus warm behavior.
- Mechanism confidence: High: model-card caching, synchronous render path, and the two-model bound are explicit.
- Magnitude uncertainty: Actual DOM render duration depends on the rest of the card, but the changed work remains two bounded string branches and replaces an equal or greater number of prior localize calls.
- Expensive boundaries:

- Verdict: No reportable regression. The changed descriptions do not increase routing-alternative cardinality, DOM ownership, or boundary calls, and for Ensemble they omit the prior tooltip localization.
