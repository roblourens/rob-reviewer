# Performance review: agentHost: retain client tools across nested session unsubscribe

[PR #340894](https://github.com/microsoft/vscode/pull/340894) at `9298dca48608764b01f8c655fee19b33a215085e`

## Findings (1)

### 1. [low] Avoid global reconciliation on every unsubscribe

**Finding ID:** `PERF-6BBD626C50B5`  
**Location:** <code>src/vs/platform/agentHost/node/protocolServerHandler.ts:3084</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Synchronous server-side iteration plus URI parsing/base64 decoding for every live subscription  
**Scaling:** For S resident sessions and T remaining subscriptions, each unsubscribe now performs O(S\*T) subscription checks; disposing T references emits T separate notifications, producing O(S\*T^2) aggregate work (O(T^3) when held sessions scale with subscriptions).  
**Outcome:** Increased CPU and event-loop latency while closing or replacing many agent-session subscriptions  
**PR causality:** <code>introduced</code>  
**Previous behavior:** An explicit unsubscribe released only the affected chat or iterated the affected parent session's chats, so disposing many references did not rescan unrelated sessions and subscriptions.  
**Changed behavior:** Every active state unsubscribe now invokes the reconnect-wide reconciliation. That method iterates all session URIs and calls \_hasActiveSubscriptionToSession for each, which re-iterates all live connections/subscriptions and reparses chat URIs.  
**Confidence:** 0.93 — The synchronous call path, nested iteration, per-subscription parsing, and one-notification-per-reference disposal are directly established in repository code. Exact user-visible duration depends on how many sessions/resources a client keeps live, so severity is low, but the scaling regression and critical-path reachability are not speculative.

**Causal diff evidence:** The added call \`this.\_reconcileActiveClientSubscriptions(client)\` at line 3084 replaces the deleted channel-local release logic; the changed reconciliation at lines 1203-1209 invokes the added nested subscription scan for every session.

Closing a window, session tree, or other owner with many held session/chat resources can monopolize the agent-host message loop before later protocol actions are processed. The trigger is a disposal burst across many open/retained agent sessions rather than a single ordinary unsubscribe.

**Evidence:** \`AgentSubscriptionManager.dispose\` and refcount release send one unsubscribe notification per resource, and \`ProtocolServerHandler\` handles each notification synchronously via \`\_removeSubscription\`. \`\_reconcileActiveClientSubscriptions\` scans \`getSessionUris()\`, while \`\_hasActiveSubscriptionToSession\` scans every connection subscription and calls \`parseChatUri\`, which performs URI parsing and base64 decoding. Subscribed sessions are exempt from the default residency eviction, so S can grow with the set being disposed; there is no batching or coalescing between notifications.

**Suggested direction:** Keep reconnect-wide reconciliation for reconnect/auth flows, but on explicit unsubscribe reconcile only the unsubscribed resource's owning session (after checking remaining parent/sibling subscriptions), or coalesce a disposal burst and precompute active parent-session URIs once so subscriptions are parsed once per pass.
