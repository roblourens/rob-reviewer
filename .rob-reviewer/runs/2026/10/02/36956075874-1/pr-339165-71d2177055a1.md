## Performance regression fixes detected (1)

### 1. serialization-allocation

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:1016` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/common/copilotCliConfig.ts:11`  
**Introducing path:** `src/vs/platform/agentHost/common/copilotCliConfig.ts`  
**Introducing commit:** `31671b1f50693b2b9f551f72b519c3afe225990a`  
**Mechanism family:** `serialization-allocation`  
**Performance category:** `network`  
**Confidence:** 0.94

**Mechanism:** HydraFusion sessions inherited the generic Agent Host tool inventory, so dozens of VS Code-only tool definitions were included in the model's request context instead of the lean CLI-compatible profile.

**Symptom:** Each HydraFusion model request carried substantially more serialized tool-schema tokens, increasing request cost and agent interaction consumption.

**Fixed behavior:** On every HydraFusion create/resume without an explicit tool filter, the launcher passes HYDRAFUSION\_DEFAULT\_EXCLUDED\_TOOLS to the SDK, preventing 42 VS Code-only tool schemas from being serialized into repeated model requests while preserving explicit user overrides.

**Evidence:** Commit 31671b1f50693b2b9f551f72b519c3afe225990a introduced the selectable HydraFusion model. In the base launcher, absent a user override, excludedTools stayed undefined and the generic runtime registered the full client/server/extension tool set into the SDK session. The changed path now selects a 42-name HydraFusion denylist and forwards it through ResumeSessionConfig.excludedTools. The PR's measured comparison reports HydraFusion request input falling from 44.0K to 27.6K tokens and AIC/task from 74.9 to 56.4, consistent with the code comment identifying roughly 13K tool-definition tokens per request.
