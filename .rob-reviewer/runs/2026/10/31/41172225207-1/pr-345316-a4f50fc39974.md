The modal-safe options preserve the modal. - Effective concurrency: Eligible canvases can still begin independent opens concurrently as before; each CanvasInput is coalesced by the opening map, and browser model creation is coalesced by modelPromise.
- Cache behavior: Cold presentations may create one browser view and load one URL. Warm presentations reuse presentation.model; simultaneous cold resolves reuse modelPromise. Source changes invalidate and dispose the model.
- Mechanism confidence: High: editorGroupView explicitly skips pane opening for inactive editors except when the group is empty, and CanvasService has direct model/modelPromise reuse.

- Mechanism confidence: High: the test asserts exactly two editor calls in the overlap, while source code proves serialization and browser-model reuse.

### Scenario 5: Working-set restore or ordinary canvas open completes and reconciliation runs after open completion.

- Critical path: doOpenInput updates presentation state and triggers reconciliation; the new finally block deletes the opening marker and triggers another reconciliation. Each pass scans contexts/canvases and in-memory presentation maps, with no boundary calls when the presentation is already acknowledged.
- Scaling input: One additional O(number of contexts + canvases + presentations/requests) in-memory scan per completed open. Opens are infrequent lifecycle events rather than frame/input events.
- Effective concurrency: The signal-driven scans are synchronous/reactive and serialized; the extra completion pass cannot start another open for an acknowledged normal/restore request.
- Cache behavior: No cache miss or boundary is introduced; existing presentation/request state causes the completion scan to short-circuit each canvas.
- Mechanism confidence: High that the extra scan exists; low evidence that its bounded in-memory cost is a concrete regression.
- Magnitude uncertainty: Very large live canvas collections could increase CPU cost, but expected collection sizes and event frequency are limited, and there is no evidence of user-visible latency or repeated hot-path execution.
- Expensive boundaries: none found
- Verdict: Not reportable under the performance evidence standard. The extra scan is bounded to open completion and supports the race retry; no realistic hot/scaling impact is established.
