### Scenario 2: External or future simulation invoking FetchWebPage URL ranking

- Critical path: After the internal page fetch, FetchWebPageTool waits for UrlChunkEmbeddingsIndex.findInUrls, which waits for one query-embedding computation and chunking/embedding results for each valid text URL before rendering the tool result.
- Scaling input: Number of valid text URLs per tool invocation and repeated simulation runs. After the diff, a cold invocation performs one query-embedding operation plus up to one chunk request per uncached URL; batches and endpoint limiters determine actual request count/concurrency.
- Effective concurrency: Per invocation, the query embedding and all URL chunk work start through Promise.all; URL chunk requests are additionally governed by ChunkingEndpointClientImpl's request limiter. Across simulation runs, TaskRunner may run up to configured parallelism, with separate service instances.
- Cache behavior: Before the diff, persistent SQLite caches could serve query embeddings and full-content chunk responses across test runs, with remote fallback on misses. After the diff, UrlChunkEmbeddingsIndex retains chunks only in memory for one service lifetime; query embeddings are not persisted. Cold behavior remains remote, while cross-run warm behavior would become remote again.
- Mechanism confidence: High for the cache-miss mechanism if such a scenario is added, but low that it is reachable in the reviewed product scenarios today.
- Magnitude uncertainty: Arbitrary external scenarios may invoke this path, but repository search found no maintained simulation scenario or fixture that invokes FetchWebPage or these embedding/chunk methods. Future workload size is therefore unknown.
- Expensive boundaries:
  - network at <code>extensions/copilot/src/platform/urlChunkSearch/node/urlChunkEmbeddingsIndex.ts UrlChunkEmbeddingsIndex.computeEmbeddings</code>: Compute the query embedding; cardinality: One embedding call per ranking invocation, internally batched by RemoteEmbeddingsComputer; zero for maintained repository scenarios.
    - Introduced by diff: false; previous behavior: A persistent SQLite hit could avoid the network call; misses already used the same remote client.; critical-path effect: If an external scenario invokes the tool, ranking waits for this call.
  - network at <code>extensions/copilot/src/platform/urlChunkSearch/node/urlChunkEmbeddingsIndex.ts UrlChunkEmbeddingsIndex.getEmbeddingsForFiles</code>: Chunk and embed fetched page content; cardinality: Up to one request per valid URL not present in the per-instance memory cache; zero for maintained repository scenarios.
    - Introduced by diff: false; previous behavior: A persistent SQLite hit by full-content hash could avoid the request across runs; misses already used the same endpoint.; critical-path effect: If reached, Promise.all waits for every URL's result before ranking continues.
  - network at <code>extensions/copilot/src/extension/tools/vscode-node/fetchWebPageTool.tsx FetchWebPageTool.invoke</code>: Fetch page content through the VS Code internal tool; cardinality: One internal-tool invocation carrying the URL list, unchanged by this diff.
    - Introduced by diff: false; previous behavior: Identical.; critical-path effect: Completes before changed ranking work begins.
- Verdict: No finding. Removing persistence would increase warm-run network work for a future/external FetchWebPage scenario, but the reviewed repository provides no current realistic trigger; reporting it would be hypothetical rather than a diff-introduced regression on an established path.
