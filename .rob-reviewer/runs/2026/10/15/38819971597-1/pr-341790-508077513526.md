### 1. [medium] Gate the installed-plugin RPC to list output

**Finding ID:** `PERF-F6DB028D3C79`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotCustomizationCommandDisplay.ts:54</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** an SDK/subprocess \`client.rpc.plugins.list()\` IPC and its returned plugin inventory  
**Scaling:** Adds one serialized inventory RPC for every \`/plugin\` command invocation, including browse, install, update, enable, disable, and error/usage responses where the inventory is never consumed.  
**Outcome:** increased command-result latency and unnecessary IPC/subprocess work  
**PR causality:** <code>introduced</code>  
**Previous behavior:** \`getOutput\` formatted the already-returned plugin result synchronously and performed no additional inventory read.  
**Changed behavior:** The plugin branch now awaits \`getInstalledPlugins()\` before calling \`formatCopilotPluginOutput\`, even though that formatter immediately returns for every subcommand except empty/list/ls and for unsupported result shapes.  
**Confidence:** 0.99 — The callback implementation, serial command call path, and formatter guard are all directly traced. The exact RPC duration is environment-dependent, but the extra critical-path IPC and its uselessness for non-list commands are deterministic.

**Causal diff evidence:** RIGHT line 54 newly evaluates and awaits \`getInstalledPlugins()\` unconditionally in the \`plugin\` switch branch; the deleted implementation passed only \`input\` and \`result\` and had no boundary call.

Every plugin action now waits for a second SDK operation before its result is rendered. For example, marketplace browse completes its browse RPC and then serially performs an unrelated global plugin-list RPC; enable/disable already call \`plugins.list()\` in \`findPlugin\` and now call it again after mutation.

**Evidence:** \`CopilotAgentSession\` passes \`options.getInstalledPlugins\` into this handler, and that callback at \`copilotAgent.ts:7217-7220\` executes \`client.rpc.plugins.list()\`. The command path awaits \`runtimeSlashCommand.getOutput\` at \`copilotAgentSession.ts:4764\` before emitting output. \`formatCopilotPluginOutput\` checks the subcommand only after this await and returns undefined unless it is \`''\`, \`list\`, or \`ls\` (\`copilotCustomizationCommandDisplay.ts:529-542\`).

**Suggested direction:** Check the normalized subcommand and supported plain-text list shape before invoking \`getInstalledPlugins\`; fetch the inventory only for \`''\`, \`list\`, or \`ls\` output that will actually be formatted.

### 2. [medium] Coalesce plugin inventory reads across completion requests

**Finding ID:** `PERF-33FB88D02652`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:4472</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** global and session SDK \`plugins.list()\` IPC calls and serialized plugin-inventory payloads  
**Scaling:** For an active session, each plugin argument completion request now performs two list RPCs instead of one; slash completions are requested while the user types, so cost grows with the number of keystrokes/retriggers and overlapping canceled requests are not coalesced.  
**Outcome:** increased interactive completion latency, IPC traffic, and avoidable subprocess work  
**PR causality:** <code>materially-amplified</code>  
**Previous behavior:** When a live session existed, \`\_listInstalledPlugins\` returned \`session.listInstalledPlugins()\`, issuing one session-scoped \`plugins.list()\` RPC per completion request. The global RPC was used only when no session existed.  
**Changed behavior:** The method now awaits the global \`client.rpc.plugins.list()\` first and then, for a live session, awaits \`session.listInstalledPlugins()\` as a second sequential RPC before merging the inventories.  
**Confidence:** 0.98 — The active-session before/after boundary count, serial awaits, editor retrigger path, and lack of coalescing are directly visible. Magnitude depends on SDK responsiveness and typing cadence, which affects severity rather than mechanism confidence.

**Causal diff evidence:** RIGHT line 4472 newly issues the global list before session lookup; the deleted branch returned the live session list immediately, so the active-session boundary count changes from one list RPC to two sequential list RPCs per request.

Typing plugin mutation arguments such as \`/plugin update elastic...\` repeatedly blocks suggestions on two serialized SDK calls. The editor keeps invoking agent-host completions throughout a slash-led token, and the completion provider ignores cancellation, so rapid typing can leave multiple doubled inventory requests in flight.

**Evidence:** The editor gate returns true for any input beginning with \`/\` (\`chatInputCompletionUtils.ts:116-119\`) and calls the agent host for each completion request (\`agentHostInputCompletionsBase.ts:80-94\`). The provider invokes \`getInstalledPlugins\` for plugin enable/disable/update/remove/uninstall prefixes (\`copilotSlashCommandCompletionProvider.ts:166-186\`), and its token is unused. \`session.listInstalledPlugins()\` is itself \`this.\_wrapper.session.rpc.plugins.list()\` (\`copilotAgentSession.ts:1100-1102\`). No inventory cache exists here, while the same provider explicitly uses a per-session promise/TTL cache for marketplace completions.

**Suggested direction:** Coalesce a per-session inventory promise over the completion window (as the marketplace completion cache already does), invalidate it on plugin mutations/reload, and issue the global and session list calls in parallel when both snapshots are required.
