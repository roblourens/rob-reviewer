## Findings (1)

### 1. [medium] Avoid activating Copilot for every cold speech session

**Finding ID:** `PERF-624D5CE925D1`  
**Location:** <code>extensions/copilot/package.json:85</code> (<code>RIGHT</code>)  
**Performance category:** <code>startup</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** extension-host module loading, service construction, and activation IPC for the full Copilot extension  
**Scaling:** The cost is paid once per window/profile while Copilot is still cold; it is added to every first editor, terminal, or chat dictation invocation that races startup, regardless of whether BYOK Voice Mode is configured. Warm invocations avoid it after activation.  
**Outcome:** increased latency and a blocked speech-session critical path  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Copilot did not subscribe to the generic onSpeech event, so SpeechService.getProvider() did not wait for Copilot activation when starting ordinary speech-to-text; Copilot's onStartupFinished activation remained outside this user-initiated speech path.  
**Changed behavior:** Adding onSpeech makes the existing SpeechService.getProvider() await activation of the entire Copilot extension before it can select a speech provider and create any speech-to-text session.  
**Confidence:** 0.95 — The changed manifest event, awaited activation call, and ordinary dictation callers are directly traced. The only uncertainty is how often users invoke speech before onStartupFinished has already warmed Copilot, which affects severity rather than the mechanism.

**Causal diff evidence:** The added \`"onSpeech"\` activation event at line 85 newly includes Copilot in the pre-existing awaited generic speech activation fan-out.

Starting editor dictation, terminal voice input, or regular chat dictation immediately after launch can now stall while Copilot activates, even when the user has not configured or requested GPT-Live BYOK.

**Evidence:** extensions/copilot/package.json now registers the full extension for onSpeech. In src/vs/workbench/contrib/speech/browser/speechService.ts:256, getProvider() synchronously awaits extensionService.activateByEvent('onSpeech') before selecting the provider; callers include editorDictation.ts:358, terminalVoice.ts:176, and voiceChatService.ts:147. The extension already has onStartupFinished, so this line specifically moves its cold activation onto the interactive speech path rather than merely ensuring eventual activation.

**Suggested direction:** Do not subscribe the full Copilot extension to the generic onSpeech event. Use a provider-specific live-session activation path (or activate the configured Copilot provider only from createVoiceLiveSession) so ordinary STT can proceed without waiting for Copilot, while preserving early BYOK provider registration.
