### 1. repeated-work

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:9412` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:9412`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`  
**Introducing commit:** `066953e45f645f85d2d33bab8470121d40dfc217`  
**Mechanism family:** `repeated-work`  
**Performance category:** `io`  
**Confidence:** 0.98

**Mechanism:** Identical active-client republications retried every failed customization, repeatedly re-reading/re-parsing plugin inputs and emitting protocol updates that fed further active-client publications.

**Symptom:** Cloud quick-chat startup could enter a persistent active-client/customization protocol loop; one reproduction produced 702 active-client and 355 customization-change records for a single turn and continued after completion.

**Fixed behavior:** Structurally identical active-client snapshots now reuse the existing sync result instead of re-parsing failed plugins and republishing customization changes; retries remain bounded to explicit operation boundaries via force: true.

**Evidence:** Base line 9412 bypassed the identical-input no-op whenever any prior customization had Error status. Each republished SessionActiveClient assignment reaches CopilotActiveClientHandle.customizations (line 9733), which calls SessionPluginController.sync; sync then invokes pluginManager.syncCustomizations and emits customization state updates. The PR changes the no-op to apply to structurally identical inputs regardless of prior failure, while retryFailedClientSyncIfNeeded explicitly opts into force. The PR's reproduced scenario reports hundreds of active-client/customization records continuing after a turn, matching this call path.
