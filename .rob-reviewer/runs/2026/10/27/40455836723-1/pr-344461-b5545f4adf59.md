# Performance review: editor: editor switching and breadcrumbs for untitled files, Markdown scratchpad

## Findings (1)

### 1. [medium] Skip outline work when symbol breadcrumbs are disabled

**Finding ID:** `PERF-DC234494A9A9`  
**Location:** <code>src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts:437</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Document-symbol provider IPC calls and provider CPU work  
**Scaling:** One request to every matching symbol provider on open, then another after each debounced edit that changes the model version, per visible active untitled editor.  
**Outcome:** Extra extension-host IPC and CPU pressure during opening and typing  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The file-provider guard rejected untitled resources, so they never constructed BreadcrumbsModel or scheduled document-symbol work.  
**Changed behavior:** The guard now admits every untitled resource into the unconditional BreadcrumbsModel path, which creates and refreshes an outline even when breadcrumbs.symbolPath is off.  
**Confidence:** 0.97 — The changed reachability, disabled-setting behavior, per-edit invalidation, debounce, and extension-host RPC are explicit. Only provider cost and setting prevalence are uncertain.

**Causal diff evidence:** RIGHT line 437 adds the Schemas.untitled exception that newly reaches the unconditional outline creation path.

With breadcrumbs.symbolPath set to off, opening or editing a symbol-capable untitled document repeatedly computes symbols that cannot be displayed. Large buffers or expensive extension providers can add typing latency and extension-host load.

**Evidence:** The added condition admits untitled URIs. update() then constructs BreadcrumbsModel, whose \_bindToEditor immediately calls createOutline. DocumentSymbolsOutline runs an initial request and debounces content-change requests by at least 350ms; OutlineModel.create invokes every ordered provider, and extension providers are forwarded through $provideDocumentSymbols. Yet BreadcrumbsModel.getElements returns before consuming the outline when symbolPath is off.

**Suggested direction:** Keep the editor-type control visible, but only bind/create an untitled outline while breadcrumbs.symbolPath is enabled; react to setting changes by creating or disposing that outline.
