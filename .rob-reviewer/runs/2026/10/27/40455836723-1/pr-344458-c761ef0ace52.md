**Relevant issue families:** eager-work, boundary-fanout, cache-lifecycle, cleanup-lifecycle

### Scenario 1: Activate the Copilot extension and open a normal or previously generated workspace

- Critical path: Extension contribution/service registration runs during activation. Before the PR, the new-workspace contribution constructed an initializer that read persisted workspace-generation state and could inspect the workspace directory; the PR removes that contribution and its service descriptors, so no new work is placed on activation's critical path.
- Scaling input: One activation per extension host; the retired initializer examined the first workspace folder and up to 30 persisted workspace-generation records.
- Effective concurrency: The initializer launched one asynchronous update from construction and at most one directory read; the changed path schedules none.
- Cache behavior: The retired initializer read extension global state. The project-template embedding service was registered lazily and its cold remote/local cache load occurred only when the retired workflow requested it; both registration and workflow are removed. Existing combined-embedding caches are unchanged.
- Mechanism confidence: High: contribution and service registration deletions directly eliminate the initializer and project-template service from activation.
- Magnitude uncertainty: The backing cost of extension global-state access varies by host, but the diff removes rather than adds it.
- Expensive boundaries:
  - filesystem at <code>extensions/copilot/src/extension/getting-started/vscode-node/newWorkspaceInitializer.ts:27-67 (deleted)</code>: Read the first workspace directory when persisted new-workspace continuation state matched the opened folder.; cardinality: At most one directory read per activation for a matching persisted generated workspace; zero for ordinary workspaces.
    - Introduced by diff: false; previous behavior: The initializer contribution was constructed at activation and conditionally read the directory; after the diff the contribution no longer exists.; critical-path effect: Could delay or add work during extension activation for the matching continuation case; this boundary is removed.
  - other at <code>extensions/copilot/src/extension/getting-started/vscode-node/newWorkspaceInitializer.ts:34-66 (deleted)</code>: Read and update persisted extension global state for workspace-generation continuation.; cardinality: One read per activation and up to one update for a matching record.
    - Introduced by diff: false; previous behavior: The old contribution consulted a bounded list of up to 30 records; the changed activation path performs none of this work.; critical-path effect: Small activation-path storage work in the retired workflow; removed by the diff.
- Verdict: No regression. Activation performs strictly less dedicated workspace-generation setup and introduces no replacement boundary.

### Scenario 2: Ask Copilot to scaffold a project or use the retired \#new/newWorkspace workflow

- Critical path: Previously the dedicated intent/tool could render extra prompts, load a template embedding index, recursively enumerate GitHub template contents, and generate project/file content. The PR removes the manifest surfaces, intent/tool registration, prompt code, repository APIs, and template index. Requests now use pre-existing standard agent tools; this diff adds no implementation or boundary to that path.
- Scaling input: Previously costs scaled with template directory count, files previewed, generated files, and conversation history. After effective removal, dedicated-workflow cardinality is zero; any standard-agent tool cardinality depends on the model's existing tool choices and is not introduced by these hunks.
- Effective concurrency: The retired GitHub directory traversal was sequential by directory; generated file content was lazy per opened file. No new limiter, queue, or concurrency burst is introduced because those paths are deleted.
- Cache behavior: Cold dedicated template requests could load the versioned project-template embedding cache; warm requests reused the in-memory loaded index. Both positive cache state and the workflow consuming it are removed. Existing standard-agent caches and tools are unchanged.
- Mechanism confidence: High for elimination of the dedicated boundaries; low evidence for any increased cost on the standard path, so no finding is warranted.
- Magnitude uncertainty: A user asking for scaffolding may still cause existing standard agent tools to run model, terminal, or filesystem operations, but their exact sequence is model-driven and no changed hunk adds or amplifies those existing tools.
- Expensive boundaries:
  - network at <code>extensions/copilot/src/platform/projectTemplatesIndex/common/projectTemplatesIndex.ts:34-58 (deleted)</code>: Load the project-template embedding cache and rank templates for the dedicated workspace intent.; cardinality: At most one cache load per index instance, then in-memory ranking per dedicated request.
    - Introduced by diff: false; previous behavior: Cold requests could fetch/load the cache and warm requests reused it; the PR deletes the index and its service registration.; critical-path effect: Was on the dedicated template-selection path; now absent.
  - network at <code>extensions/copilot/src/platform/github/node/githubRepositoryService.ts:57-102 (deleted)</code>: Recursively call GitHub repository contents APIs for directories and fetch content for previewed template files.; cardinality: One contents request per traversed directory and one content request per opened/copied file in the retired template workflow.
    - Introduced by diff: false; previous behavior: The dedicated template workflow owned these APIs; repository search confirms no remaining callers or replacement project-template index.; critical-path effect: Directory enumeration blocked template preview construction, while file-content fetches blocked individual preview reads; all are removed.
  - network at <code>extensions/copilot/src/extension/intents/node/generateNewWorkspaceContent.ts:23-42 (deleted)</code>: Make utility-model requests for one project specification and lazy file contents.; cardinality: One specification request per generated preview plus one request for each file whose content was opened/generated.
    - Introduced by diff: false; previous behavior: Dedicated previews issued these additional model calls; the changed code does not relocate them.; critical-path effect: The specification blocked file generation and each file request blocked its preview; the PR removes this generator.
- Verdict: No regression. The PR removes substantial dedicated network/model work and shortens registered tool metadata; fallback to existing standard tools does not itself prove diff-added performance cost.

### Scenario 3: Materialize a generated workspace or file from a preview

- Critical path: The retired Create Workspace command sequentially read preview content, created directories, wrote each file, updated a tracking file, transferred chat, and opened a folder. The command and providers are removed; the diff adds no equivalent write loop.
- Scaling input: Previously filesystem work scaled linearly with the number of generated files and collision checks scaled with existing same-named sibling folders. The dedicated path now has zero operations.
- Effective concurrency: The retired file loop was deliberately sequential; no changed path replaces it with parallel work or creates a burst.
- Cache behavior: Preview content promises were cached on tree nodes and prior file contents were retained per response. All preview managers and their maps are removed; no new cache is introduced.
- Mechanism confidence: High: command registration, providers, preview managers, and write implementation are all deleted.
- Magnitude uncertainty: Standard agent file tools remain available and can write projects, but their existing implementation and cardinality are unaffected by this PR.
- Expensive boundaries:
  - filesystem at <code>extensions/copilot/src/extension/conversation/vscode-node/newWorkspaceFollowup.ts:102-223 (deleted)</code>: Read preview content, create parent directories, write each generated file, and update aiGeneratedWorkspaces.json.; cardinality: Approximately one preview read, directory creation, and write per generated file, plus bounded name-stat checks and one tracking-file update.
    - Introduced by diff: false; previous behavior: The dedicated Create Workspace command performed an O(file count) sequential materialization; no surviving handler in the diff performs it.; critical-path effect: All file operations completed before the old workspace-open prompt; the entire command is removed.
  - IPC at <code>extensions/copilot/src/extension/conversation/vscode-node/newWorkspaceFollowup.ts:138-147 (deleted)</code>: Transfer the active chat and execute the open-folder command after materialization.; cardinality: At most one transfer and one open-folder command per accepted generated workspace.
    - Introduced by diff: false; previous behavior: The old command transferred/opened the generated folder; the retired command has no replacement in these changes.; critical-path effect: Occurred after file creation and before navigation to the generated workspace; removed.
- Verdict: No regression. O(file count) dedicated filesystem and retained-preview work is removed rather than amplified.

### Scenario 4: Close or quit VS Code while a supported chat or local agent-host session is active

- Critical path: Shutdown computes the effective reason, checks active sessions, may query native window count for CLOSE, and may show a confirmation. The PR removes a context-key bypass that was set only by the simultaneously deleted workspace-opening tool. For ordinary and still-supported sessions the key was false before, so the IPC/dialog cardinality is unchanged.
- Scaling input: One lifecycle callback per shutdown attempt; active-session checks scale with current session count exactly as before.
- Effective concurrency: The chat and local-agent-host lifecycle vetoes can both participate in a shutdown as before; this PR neither adds callbacks nor increases parallel boundary calls for remaining scenarios.
- Cache behavior: No cache participates. The removed context key was transient state, and repository search finds no remaining setter or reader.
- Mechanism confidence: High: repository search shows the key is gone except as a test literal for another retired name, and the deleted tool contained the sole setter.
- Magnitude uncertainty: External code could theoretically set the old raw context-key string, but there is no repository caller and that is not a realistic supported trigger for a performance finding.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/electron-browser/chat.contribution.ts:203-205 and src/vs/sessions/contrib/providers/agentHost/electron-browser/localAgentHostLifecycle.contribution.ts:52-54</code>: Query native window count for a CLOSE shutdown to derive the effective shutdown reason.; cardinality: At most one query from each existing lifecycle contribution per CLOSE attempt; unchanged for supported sessions.
    - Introduced by diff: false; previous behavior: Ordinary sessions already executed this query because the removed bypass defaulted false; only the retired workspace-opening flow set it true.; critical-path effect: Blocks shutdown reason evaluation before a possible confirmation dialog.
  - other at <code>src/vs/workbench/contrib/chat/electron-browser/chat.contribution.ts:209 and src/vs/sessions/contrib/providers/agentHost/electron-browser/localAgentHostLifecycle.contribution.ts:59</code>: Show the session-shutdown confirmation dialog when an active session would stop.; cardinality: At most one confirmation per applicable lifecycle veto path and shutdown attempt, unchanged for all remaining flows.
    - Introduced by diff: false; previous behavior: The dialog was already shown for ordinary active sessions; the only internal bypass setter was deleted with the retired new-workspace tool.; critical-path effect: Intentionally blocks shutdown for user confirmation.
- Verdict: No regression. The remaining shutdown path retains the same one-shot IPC and dialog behavior; only an obsolete workflow-specific bypass is removed.

**Summary:** Completed the performance pass over all 68 changed files, with detailed tracing of activation, dedicated scaffolding, preview materialization, caches, GitHub/model/filesystem boundaries, and shutdown. The PR is a feature retirement composed almost entirely of deletions; it removes eager setup, cache loads, network fan-out, retained preview state, and sequential file work. No high-confidence diff-introduced performance regression or separately evidenced shipped regression fix was found.
