- Cache behavior: On a cold assignment service, getTreatment can await TAS client initialization and a shared initial assignment fetch; on a warm service it reads the cached treatment. ### Scenario 3: Spotlight renders workspace/model steps, including a preselected workspace and navigation back to earlier steps

- Critical path: For each step that passes its context condition and resolves a visible target, \_showStep now reads selection state before constructing callout content, then performs the existing overlay DOM rendering and requestAnimationFrame-based target settling. For the session workspace target, hasSelection reads only \!\!this.\_selectedFolderUri.
- Scaling input: One selection probe per displayed step attempt. The new variation has two steps; normal forward completion therefore performs two probes, with additional probes only when the user explicitly navigates back or a target is replaced and retried. Across other spotlight tours, the added global probe scales linearly with displayed steps, but each probe is a WeakMap lookup and currently the sole registered callback is a boolean property read.
- Effective concurrency: Steps and retries are serialized by the presentation loop; no selection probes run concurrently and none are attached to layout, scroll, animation-frame, or input event loops.
- Cache behavior: No cache is needed for the selection read because it is current owner state and is evaluated once when a step is shown. The same result is reused for selected copy and the existing ifUnselected open decision. Target resolution and overlay layout behavior are unchanged.
- Mechanism confidence: High: hasOnboardingTargetSelection is a WeakMap lookup plus optional synchronous callback, and the only production hasSelection registration found reads a URI field. The call is outside recurring layout/event handlers.
- Magnitude uncertainty: User back-navigation can repeat step display, but realistic cardinality remains the small tour step count and there is no data-size-dependent callback in current registrations.
- Expensive boundaries: none found
- Verdict: No finding: although non-ifUnselected spotlight steps now incur one extra selection-state lookup, the mechanism is bounded O(1), not a layout read or external boundary, and is too small to establish an actionable synchronous UI regression.
