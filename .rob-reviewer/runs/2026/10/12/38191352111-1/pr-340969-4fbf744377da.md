## Performance regression fixes detected (1)

### 1. synchronous-ui-work

**Fix location:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:8300` (`RIGHT`)  
**Blamed base line:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:8298`  
**Introducing path:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`  
**Introducing commit:** `39f91b155cb34b670a38a4fe5f1bbdaa8aa972c9`  
**Mechanism family:** `synchronous-ui-work`  
**Performance category:** `layout`  
**Confidence:** 0.94

**Mechanism:** Each partial catalog/status notification could replace the default chat with a peer and each detailed-state update replace it back, causing repeated active-chat fallback and synchronous layout/panel reconciliation on message and tool-confirmation status transitions.

**Symptom:** Visible Agents-window layout blinking and redundant synchronous layout work during repeated session status updates.

**Fixed behavior:** The changed handler merges the cached backend default-chat URI into partial catalog notifications before reconciliation, so metadata/state updates retain the same main-chat object and no longer trigger active-chat fallback or downstream layout reconciliation. Explicitly supplied defaults still override the cached URI.

**Evidence:** The base handler passed partial `changes` directly to `chatMetadataFromSummary`; when `defaultChat` was omitted, an opaque advertised default failed `isDefaultChatUri`, was recreated as a peer, and removed the stable main chat from `session.chats`. `VisibleSessions` then synchronously fell back because its active chat was absent (visibleSessions.ts:985-995). Alternating detailed-state and summary updates reversed this identity on each update. The added regression test drives three status cycles and asserts a single active-chat publication, while layout consumers synchronously observe active-chat changes: ChatLayoutContext increments layout generations (chatLayout.ts:84-94), panel visibility/view synchronization reruns (baseSessionLayoutController.ts:360-421), and the desktop strategy reapplies session composition in multi-session mode (desktopExistingSessionStrategy.ts:141-174).
