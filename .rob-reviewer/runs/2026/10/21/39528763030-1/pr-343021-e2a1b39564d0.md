## Findings (1)

### 1. [medium] Keep irrelevant completion triggers on the line-local fast path

**Finding ID:** `PERF-B8F224EF453E`  
**Location:** <code>src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptBodyAutocompletion.ts:55</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>synchronous-ui-work</code>  
**Resource:** Main-thread CPU plus full-document string, line-array, and YAML parse allocations  
**Scaling:** On each cache-cold model version, cost grows linearly with the complete prompt document; typing any registered trigger character (\`.\`, \`:\`, \`/\`, \`\\\`, or \`{\`) can repeat that work even when the cursor is not in a reference.  
**Outcome:** Increased input-to-suggestion latency and transient allocation/GC pressure while editing larger prompt, instruction, skill, or agent documents.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The provider first inspected frontmatter delimiters and the current line in \`findVariableReference\`; irrelevant trigger characters returned without copying, splitting, or parsing the complete model.  
**Changed behavior:** Every completion invocation now synchronously calls \`getParsedPromptFile\` and resolves the target before checking whether the current line contains a relevant \`\#...\` or \`{{...\` reference.  
**Confidence:** 0.97 — The changed call, version-keyed cache miss after edits, full-content parser implementation, all-prompt registration, and trigger-character \`onDidType\` call path are directly traced. Exact latency varies with document size and whether another feature happened to populate the same-version cache first, which affects severity but not the mechanism.

**Causal diff evidence:** Added RIGHT line 55 unconditionally invokes \`this.promptsService.getParsedPromptFile(model)\` ahead of the pre-existing line-local \`findVariableReference\` check; no equivalent full-model parse existed on this completion path before the PR.

With trigger-character suggestions enabled, ordinary prose such as periods and paths invokes this provider immediately after an edit. The edit advances the model version, so \`PromptsService.getParsedPromptFile\` misses its version cache and calls \`model.getValue()\`, splits the whole document, and, for agents, parses the YAML header before suggestions can proceed. Large customization documents can therefore make common keystrokes and suggestion display noticeably slower.

**Evidence:** \`PromptBodyAutocompletion\` is registered for all prompt language selectors and declares common trigger characters including \`.\` and \`/\`. The changed line calls \`getParsedPromptFile\` before \`findVariableReference\`. \`PromptsService.getParsedPromptFile\` caches by model version but on a miss executes \`new PromptFileParser().parse(textModel.uri, textModel.getValue())\`; parser construction splits the full content, and \`getTarget\` reads \`header.target\`, forcing YAML parsing for agent files. VS Code's suggest model invokes providers directly from \`onDidType\` for their trigger characters. Thus a fresh edit realistically puts whole-document synchronous work on the input/suggestion critical path even when no completion can be returned.

**Suggested direction:** Preserve the current-line fast path: first reject invocations that are neither inside a \`\#\` reference nor an open \`{{\` placeholder, and only then resolve the parsed target. This keeps Copilot suppression and placeholder completion behavior while avoiding whole-document parsing for unrelated trigger characters.
