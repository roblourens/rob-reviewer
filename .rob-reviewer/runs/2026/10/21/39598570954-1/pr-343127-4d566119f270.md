### 1. boundary-fanout

**Fix location:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostUntitledProvisionalSessionService.ts:372` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostUntitledProvisionalSessionService.ts:378`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostUntitledProvisionalSessionService.ts`  
**Introducing commit:** `5d8fefffb67c0a48954f6c5f8e8df43b8b4014c5`  
**Mechanism family:** `boundary-fanout`  
**Performance category:** `ipc`  
**Confidence:** 0.96

**Mechanism:** Each workspace-folder change fanned out over all tracked sessions; every rebound session whose desired roots changed could schedule one agent-host createSession and one disposal of its previous backend.

**Symptom:** Workspace changes could cause avoidable per-started-session host I/O, provider initialization, and teardown latency.

**Fixed behavior:** The added ownership guard skips rebound, non-owning entries during workspace-root reconciliation, preventing their backend recreation and disposal while preserving the existing behavior for owned untitled drafts.

**Evidence:** In the base revision, the workspace-folder listener skipped only disposed entries, so rebound started sessions reached \_reconcileWorkspaceRootSet. A changed root set then reached \_reconcileGeneration, which calls IAgentHostService.createSession and disposes the prior generation across the agent-host protocol. Node-side creation initializes a provider and touches database/filesystem state; disposal performs database, provider, and storage cleanup. Added tests verify that workspace-folder changes now produce zero create and disposal calls for rebound sessions.
