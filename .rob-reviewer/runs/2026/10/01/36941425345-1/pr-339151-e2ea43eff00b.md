- Effective concurrency: The marketplace query is a single request in this scenario. Lazy icon requests are browser-scheduled; the diff does not increase their count or concurrency.
- Cache behavior: Empty-query catalog pages are cached by selected source; browser image caching remains unchanged. The diff neither changes cache keys nor invalidation.
- Mechanism confidence: High confidence that network, image, render cardinality, and cache behavior are unchanged; low confidence in any measurable regression from the CSS-only stacking change.

### Scenario 2: Search customizations, scroll virtualized results, and activate a result or its independent install action

- Critical path: A debounced marketplace query supplies search results; WorkbenchList virtualizes row templates, and visible rows render their existing lazy icons. - Scaling input: Search result pages contain 24 resources and grow by pagination, but live DOM/template count remains viewport-bounded by WorkbenchList; effective network page concurrency is one.
- Effective concurrency: Catalog loads are sequential and prior requests are cancelled on query changes; continuation uses a RunOnceScheduler. Icon loading is browser-managed and unchanged.
- Cache behavior: Search pages are not stored in the empty-query browse cache, while browser image caching remains available. The diff does not change cache behavior or negative-cache handling.
- Mechanism confidence: High confidence from the renderer, WorkbenchList setup, scheduler, and icon helper that no hot/scaling work was introduced.
- Magnitude uncertainty: The precise number of virtual rows depends on viewport overscan, but the diff removes three per-template listeners and does not increase row creation, network calls, or per-scroll work.
- Expensive boundaries:

- Effective concurrency: Synchronous single fixture execution; no parallel boundary work is introduced.
- Cache behavior: No cache behavior is involved.
- Mechanism confidence: High confidence that the added getBoundingClientRect/getComputedStyle calls can force style/layout only in the component test harness.
- Magnitude uncertainty: Layout flush cost depends on the test browser state, but cardinality is constant and confined to tests.
- Expensive boundaries: none found
- Verdict: No user-visible performance regression: constant test-only synchronous layout reads do not affect shipped runtime behavior.
