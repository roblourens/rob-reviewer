# Performance review: chat: let language model providers contribute an icon for the model picker

[PR #341578](https://github.com/microsoft/vscode/pull/341578) at `edd3f4d2d4d178eabed344f3f1c2e414f7077503`

## Findings (1)

### 1. [low] Reuse one vendor snapshot for provider icons

**Finding ID:** `PERF-264757D3436F`  
**Location:** <code>src/vs/workbench/contrib/chat/common/languageModels.ts:798</code> (<code>RIGHT</code>)  
**Performance category:** <code>cpu</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** vendor-array allocations, context-expression parsing/evaluation, and linear scans  
**Scaling:** O(R\*M\*V), for fallback models M, visible vendors V, and destination rebuild count R; a picker show rebuilds destinations at least twice.  
**Outcome:** increased UI-path latency and CPU/GC pressure  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Fallback grouping scanned visible vendors for the display name but did not perform a second vendor snapshot and scan to obtain an icon.  
**Changed behavior:** Provider icon resolution now rebuilds and scans the visible-vendor collection once for every fallback-group model.  
**Confidence:** 0.94 — The added helper, per-model call sites, and repeated destination-build path are explicit. The PR's test covers an agent-host provider group absent from the configured group map, proving fallback reachability; only real-world catalogue size is uncertain.

**Causal diff evidence:** The new helper's added return at RIGHT line 798 creates and scans \`languageModelsService.getVendors()\` on every icon lookup, and the diff calls this helper from \`getProviderGroupForModel\`, which runs inside the \`userModels\` loop.

With a large relayed-provider catalogue, opening or rebuilding the model picker performs avoidable CPU work and short-lived allocations, increasing popup latency and GC pressure.

**Evidence:** \`getLanguageModelProviderIcon\` calls \`getVendors().find\`. The concrete service implementation of \`getVendors()\` allocates \`Array.from(\_vendors.values())\`, filters every vendor, deserializes each \`when\` expression, and evaluates context keys. \`buildModelPickerDestinations\` invokes the helper through \`getProviderGroupForModel\` for each fallback user model, while \`\_showCurrent\` builds destinations before showing and again from \`createActionList\` (plus an optional sizing build).

**Suggested direction:** Snapshot visible vendors once per destination build and pass a vendor descriptor/icon map into grouping, or resolve display name and icon together from one descriptor lookup.
