### 1. cleanup-lifecycle

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:2392` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts:2391`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`  
**Introducing commit:** `9ab103a9f4bf101d1115f17f79119e763c8c6f07`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `latency`  
**Confidence:** 0.98

**Mechanism:** Ordinary GitHub.com Connector token rotation was treated as client-level authentication, scheduling a shared Copilot runtime restart. Restart safety deferred teardown until every active turn/subagent completed, while subsequent session acquisition waited on the pending restart waiter, coupling new chat creation/restoration to unrelated long-running chats and then incurring subprocess teardown/startup.

**Symptom:** After GitHub.com token rotation, opening or restoring another Agent Host chat could remain blocked for the lifetime of an unrelated busy chat, followed by shared runtime restart latency.

**Fixed behavior:** The changed branch leaves clientAuthenticationReason undefined for GitHub.com, supplies credentials in each SDK session, and updates live static-token sessions without restarting the shared CopilotClient. New create/restore work therefore no longer waits for an unrelated busy chat or pays subprocess teardown/startup solely for Connector token rotation; Enterprise and credential-mode changes retain the deferred restart path.

**Evidence:** In the base revision, GitHub.com token changes with Connectors enabled set clientAuthenticationReason to 'Copilot Connector authentication updated', making restartRequired true and calling \_requestClientRestart. That method parks the restart while any chat has in-flight work; \_ensureClientForSession then loops and awaits \_pendingClientRestartWaiter, so creating or restoring another session is blocked until the unrelated busy chat ends and the shared runtime is stopped. The added create/restore test at copilotAgent.test.ts:10310-10406 exercises this exact busy-chat path and asserts zero client stops plus immediate session launch after rotation.

Unlike before, ordinary Connector rotation does not schedule or await shared-client teardown.
- Scaling input: Number of currently live resident static-token sessions after deduplication by the live-session map. Unchanged tokens are suppressed by the workbench auth-token cache, and refreshable/provider-backed sessions contribute zero setCredentials calls.
- Effective concurrency: Credential versions are globally sequenced. Within one version, static-session setCredentials RPCs run sequentially; this existing loop now also applies when Connectors are enabled. Credential-mode changes and Enterprise updates retain deferred global restart semantics.
- Cache behavior: The per-connection auth-token cache coalesces identical in-flight credentials and suppresses completed unchanged tokens. Static sessions update their captured token after a successful RPC; provider-backed sessions read the shared provider. Failed updates request the existing safe restart fallback.
- Mechanism confidence: High for cardinality and serialization: the loop, SDK RPC implementation, credential-mode guard, and auth cache are explicit.
