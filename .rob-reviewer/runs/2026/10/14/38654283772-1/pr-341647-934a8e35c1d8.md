## Performance regression fixes detected (3)

### 1. repeated-work

**Fix location:** `src/vs/workbench/contrib/chat/common/model/chatViewModel.ts:387` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/common/model/chatViewModel.ts:379`  
**Introducing path:** `src/vs/workbench/contrib/chat/common/model/chatViewModel.ts`  
**Introducing commit:** `fb4a02b3e41d0d7c43d4908cca03b6eba9722e3f`  
**Mechanism family:** `repeated-work`  
**Performance category:** `cpu`  
**Confidence:** 0.99

**Mechanism:** Hot scrolling and rendering callers repeatedly invoked getItems(), and each invocation allocated and scanned the entire transcript.

**Symptom:** A 1,157-request chat spent about 3.6 seconds per scrollbar drag in getItems/isHiddenFromTranscript scans, contributing to renderer freezes.

**Fixed behavior:** Returns one cached readonly visible-items array until a model or response change invalidates it, removing transcript-wide scans from repeated scroll/render queries.

**Evidence:** Before the PR, every getItems() call rebuilt the visible transcript by filtering the full \_items array and computing pending/divider state. The changed implementation caches that result at RIGHT line 387 and invalidates it on model/view-model changes. The PR's traced large-chat scrollbar scenario reports getItems/isHiddenFromTranscript scanning falling from 3.6s per drag to under 1ms, and the added test verifies repeated reads perform one pending-request scan independent of call count.

### 2. synchronous-ui-work

**Fix location:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:1982` (`RIGHT`)  
**Blamed base line:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:1967`  
**Introducing path:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`  
**Introducing commit:** `34a41e00d4609f76a472da3a7feb0a0090430d1c`  
**Mechanism family:** `synchronous-ui-work`  
**Performance category:** `layout`  
**Confidence:** 0.98

**Mechanism:** Each rendered request row immediately read bounding rectangles after render writes, forcing repeated synchronous layout during scrolling and rerendering.

**Symptom:** Dragging the scrollbar in a 1,157-request chat produced repeated long tasks and several seconds of sticky-scroll/layout CPU.

**Fixed behavior:** Defers request-row geometry reads to one coalesced per-frame pass and refreshes sticky scroll only after ranges are measured.

**Evidence:** The base code measured sticky-scroll source geometry synchronously from each request-row render. RIGHT line 1982 now schedules one shared source-range pass, and the new scheduler measures all rendered rows after writes once per animation frame. Tests verify zero geometry reads during row render and one measurement per row in the frame. The PR trace reports sticky-scroll drag CPU dropping from 5.2s to 0.57s and long tasks from 170 to 40.

### 3. eager-work

**Fix location:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:4198` (`RIGHT`)  
**Blamed base line:** `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:7695`  
**Introducing path:** `src/vs/sessions/contrib/agentHost/browser/baseAgentHostSessionsProvider.ts`  
**Introducing commit:** `a1c44a69c436e13172693438eb8f53bf72a84b60`  
**Mechanism family:** `eager-work`  
**Performance category:** `ipc`  
**Confidence:** 0.97

**Mechanism:** Rendering passive session-list metadata eagerly subscribed to each session's full default-chat snapshot, transferring and processing large transcripts that were not open.

**Symptom:** On reload, list rows pulled a 71MB default-chat snapshot and spent about 704ms on data that the visible workflow did not need.

**Fixed behavior:** Passive list-row reads retain only the lightweight session-state subscription; default-chat draft hydration is started lazily for visible or explicitly queried sessions and restored on reconnect.

**Evidence:** In the base revision, opening a session-state subscription unconditionally called \_whenBackendDefaultChat and hydrated the draft agent/model, which subscribes to the default chat snapshot. The PR changes passive session-list reference paths to call \_ensureSessionStateSubscription(sessionId, false) and tracks hydration separately; tests show list rows subscribe only to session state while the visible/explicit session alone subscribes to its default chat. The supplied user trace identifies a 71MB default-chat snapshot pulled by list rows for 704ms.
