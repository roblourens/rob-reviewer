**Relevant issue families:** boundary-fanout, repeated-work, cleanup-lifecycle, concurrency-burst

### Scenario 1: Workbench startup and agent-host root-config hydration

- Critical path: The contribution registers two additional setting forwarders and asynchronously reconciles them after the local agent-host schema is available. These pushes are not awaited by workbench startup or UI rendering. The agent already reads schema defaults, so forwarding the default empty model and enabled Explore value does not change the SDK startup configuration or restart an existing client.
- Scaling input: Constant: two new keys per local agent-host start or schema hydration, deduplicated by structural equality across windows.
- Effective concurrency: Both key computations may run concurrently as microtasks; each dispatch is independent, and the root-state equality guard suppresses unchanged values. There is no collection-dependent concurrency.
- Cache behavior: The root state is the authoritative cache. Warm/equal values cause no dispatch; on a cold host with absent values, each key is forwarded once. The schemaSeen set prevents repeated hydration pushes.
- Mechanism confidence: High: the forwarder, structural equality guard, and dispatch boundary are directly traced.
- Magnitude uncertainty: Exact IPC duration is not measured, but the fixed cardinality and off-critical-path placement make material impact unlikely.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostRootConfigForwarder.ts:\_push</code>: Dispatch RootConfigChanged from the renderer/workbench to the local agent-host protocol; cardinality: At most two additional dispatches on a cold host for the two new keys; zero when the root state already contains structurally equal values.
    - Introduced by diff: true; previous behavior: The same reconciliation existed for the prior key set; these two key dispatches did not exist.; critical-path effect: Off the workbench startup critical path because reconcile does not await the asynchronous pushes; constant agent-host processing follows each dispatch.
- Verdict: No reportable regression. The diff adds bounded, deduplicated constant work rather than hot-path or scaling fan-out.

### Scenario 2: Changing the search-subagent model while a Copilot SDK client exists

- Critical path: A setting change forwards one root-config action. The agent detects the startup-baked model change, waits for active turns and subagents to finish, tears down the current SDK client, and lazily starts a replacement when SDK work is next requested. The next request can therefore pay the existing cold client-start path, including runtime resolution and subprocess start.
- Scaling input: One restart request per distinct model value change. Multiple pending restart reasons are collected in a Set and applied together once all chats are idle; cost does not scale with open chats except for scanning live sessions to determine idleness and disposing resident entries once.
- Effective concurrency: Restarts are serialized by \_clientStarting/\_clientStopping and deferred while work is active. Concurrent startup-config changes coalesce into one pending restart application rather than spawning multiple clients.
- Cache behavior: No model cache is involved. Equal root values are suppressed by structural equality and equal startup snapshots return without restart. The model catalog is invalidated intentionally after an applied restart and refreshed once.
- Mechanism confidence: High: the new field is compared in CopilotAgentStartupConfig, and tests establish one stop per distinct model change. The operation is intentionally documented and coalesced.
- Magnitude uncertainty: Runtime startup duration varies by platform and cache warmth, but the restart mechanism and lazy-start latency are certain.
- Expensive boundaries:
  - IPC at <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostCopilotCliSettingsContribution.ts:SearchSubagentModel descriptor</code>: Forward the changed model setting as RootConfigChanged; cardinality: One dispatch per distinct setting change after equality suppression.
    - Introduced by diff: true; previous behavior: There was no search-model key to forward.; critical-path effect: The dispatch itself is asynchronous; it schedules/defer-applies the restart.
  - subprocess at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_restartClientIfStartupConfigChanged/\_applyPendingClientRestart/\_ensureClientOnce</code>: Stop the existing stdio Copilot runtime and lazily start a replacement carrying SEARCH\_SUBAGENT\_MODEL; cardinality: At most one stop for a coalesced group of startup-config changes, followed by one lazy start when the client is next needed.
    - Introduced by diff: true; previous behavior: Changing this newly introduced model setting could not restart the client; other pre-existing startup-baked settings already used the same restart path.; critical-path effect: Stop is deferred off active turns; the next SDK-dependent request may pay cold startup latency.
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_ensureClientOnce</code>: Resolve bundled runtime and ripgrep paths during the subsequent existing cold SDK startup; cardinality: Once per replacement startup, with independent lookups run concurrently.
    - Introduced by diff: false; previous behavior: The same work occurred on every pre-existing SDK client cold start and restart.; critical-path effect: On the next SDK-dependent request's cold-start path.
- Verdict: No finding. A process restart is an intentional, bounded requirement for applying a subprocess environment variable; it is deferred past active work and coalesced rather than repeated on a hot path.

### Scenario 3: Creating or resuming a Copilot session with Explore enabled or disabled

- Critical path: Session configuration construction now reads one boolean and includes a zero- or one-element excludedBuiltinAgents array before the existing SDK createSession/resumeSession call. The added read/allocation is constant and does not add an SDK call, filesystem operation, or network request.
- Scaling input: One constant-size configuration value per session create or resume, independent of repository size, tool count, or history size.
- Effective concurrency: Session creation/resumption retains its existing concurrency behavior. The diff adds no limiter, queue, fan-out, or parallel task.
- Cache behavior: The current root configuration is read directly for every build; no cache is needed for a boolean and a constant-size array. Cold and warm session paths have the same added constant work.
- Mechanism confidence: High: the session config and SDK call sites are directly traced.
- Magnitude uncertainty: The runtime's internal serialization cost is not measured, but the host adds only a constant-size array and no extra boundary call.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:\_createSession/\_resumeSession</code>: Existing SDK stdio createSession or resumeSession call carrying the session configuration; cardinality: One existing SDK call per session create or resume; excludedBuiltinAgents is serialized as part of that same call.
    - Introduced by diff: false; previous behavior: The same create/resume call occurred without the constant-size excludedBuiltinAgents field.; critical-path effect: The existing call remains on the session launch/resume critical path, but the diff does not increase boundary-call count or payload with user-scaled data.
  - network at <code>Copilot SDK runtime reached through CopilotSessionLauncher</code>: Potential runtime/CAPI activity associated with the existing session and later agent invocations; cardinality: No additional network operation is established by the changed host code; disabling Explore can only exclude a built-in agent, while enabling preserves the runtime default.
    - Introduced by diff: false; previous behavior: Explore was available according to the runtime default and existing session operations already crossed the SDK boundary.; critical-path effect: No newly introduced network boundary is placed on session launch by the diff.
- Verdict: No reportable regression. The change modifies metadata on an existing boundary with constant payload and unchanged call cardinality.

### Scenario 4: Invoking the search subagent with a configured model

- Critical path: When the separately controlled search tool is enabled and selected by the agent, the runtime reads SEARCH\_SUBAGENT\_MODEL to choose the CAPI model. This PR changes model selection, not the number or scheduling of search invocations from the host.
- Scaling input: Search invocation count remains controlled by agent/tool use; the configured string is process-wide and does not grow with repository contents or session history.
- Effective concurrency: No host-side concurrency behavior for search calls is added or changed by the diff.
- Cache behavior: The environment value is fixed for the SDK client lifetime. Applying a different value uses the coalesced restart path; no per-search recomputation or retained-key cache is introduced.
- Mechanism confidence: High for environment propagation; low for any model-dependent latency claim, so no regression is inferred.
- Magnitude uncertainty: Different models may have different latency, but no specific model is forced by default and the PR provides no code mechanism that increases request count or payload size.
- Expensive boundaries:
  - network at <code>Copilot runtime selected through SEARCH\_SUBAGENT\_MODEL from src/vs/platform/agentHost/node/copilot/copilotCliEnvironment.ts</code>: Existing runtime request(s) made when the search subagent is actually invoked; cardinality: No evidence of additional requests; only the model identifier on an existing optional subagent path changes.
    - Introduced by diff: false; previous behavior: The runtime selected its default search-subagent model for the same invocation.; critical-path effect: Relevant only after the agent elects to invoke the optional search tool; model-specific latency is not established by this diff.
- Verdict: No finding. Configurable model selection does not itself prove increased network work, latency, or fan-out.

The diff adds two bounded root-config forwards, a coalesced intentional subprocess restart only when the model value changes, and constant-size session metadata. No high-confidence actionable performance regression was introduced.
