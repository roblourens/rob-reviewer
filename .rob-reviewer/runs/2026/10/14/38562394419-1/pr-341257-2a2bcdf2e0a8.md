# Performance review: agentHost: support managed OpenTelemetry file export

[PR #341257](https://github.com/microsoft/vscode/pull/341257) at `2a2bcdf2e0a83be2ddc8032098a52ac13d7ca4cc`

## Findings (1)

### 1. [low] Create managed export directories only once

**Finding ID:** `PERF-45B0DAE96702`  
**Location:** <code>src/vs/platform/otel/node/otlp/outboundForwarder.ts:233</code> (<code>RIGHT</code>)  
**Performance category:** <code>io</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** filesystem mkdir operations and queued telemetry buffers  
**Scaling:** Cost grows linearly with non-empty telemetry batches: after the first successful parent creation, each batch still adds one recursive mkdir call. The queue has effective concurrency 1, so each added call directly lengthens the serialized drain path.  
**Outcome:** excessive filesystem I/O and lower telemetry-export throughput  
**PR causality:** <code>introduced</code>  
**Previous behavior:** File forwarding previously issued only the append operation per batch; it did not perform parent-directory creation. The PR adds one mkdir boundary per managed-file batch rather than only for the cold first write.  
**Changed behavior:** Managed file forwarding now performs recursive parent-directory creation for every queued append, including warm writes after the directory was already created.  
**Confidence:** 0.99 — The call path is direct: each non-empty \`forwardSpans\` queues \`\_append\`; \`\_append\` unconditionally awaits \`fs.mkdir\` when the new managed option is true; the same class queue serializes that operation before \`appendFile\`. Tests explicitly send successive batches with the option enabled. Only exact event volume and filesystem latency vary.

**Causal diff evidence:** RIGHT line 233 adds \`await fs.mkdir(dirname(this.\_options.filePath), { recursive: true })\` inside \`\_append\`, and AgentHostOTelService now sets \`createParentDirectories: this.\_config.managedFilePath\`; therefore every managed-file call to \`forwardSpans\` executes this new filesystem operation.

Managed file export generates a redundant filesystem operation ahead of every telemetry write. On busy sessions or slower/network-backed managed destinations this lowers export throughput, extends flush/shutdown latency, and can let queued serialized batches retain their JSON strings longer.

**Evidence:** \`FileForwarder.forwardSpans\` queues one \`\_append\` per non-empty decoded/synthetic batch. The changed \`\_append\` calls \`fs.mkdir(..., { recursive: true })\` whenever \`createParentDirectories\` is true, without a success flag or promise cache, and only then calls \`appendFile\`. \`AgentHostOTelService\` enables the option for every managed path. Host session, turn-timing, first-response, user-interaction, and received OTLP batches all reach this forwarder, so a long session repeatedly traverses the same parent path.

**Suggested direction:** Memoize successful parent setup in the forwarder (for example, a shared initialization promise or ready flag), and clear it only on failure so later batches can still retry after repair. Then each process lifetime pays mkdir once on success while preserving the documented recovery behavior.
