### 1. cleanup-lifecycle

**Fix location:** `src/vs/platform/agentHost/node/copilot/copilotSandboxPolicyDisplay.ts:51` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/agentHost/node/copilot/copilotSandboxPolicyDisplay.ts:52`  
**Introducing path:** `src/vs/platform/agentHost/node/copilot/copilotSandboxPolicyDisplay.ts`  
**Introducing commit:** `c0f6c8cd52aeceb78b91631bce1b37d161a93d3f`  
**Mechanism family:** `cleanup-lifecycle`  
**Performance category:** `io`  
**Confidence:** 0.98

**Mechanism:** Each command invocation allocated and retained a new directory plus Markdown file until explicit session deletion, causing filesystem bytes and inode count to grow linearly with policy-report history even after the live session was disposed.

**Symptom:** Repeated policy checks accumulated persistent report snapshots and directory entries, increasing session storage and later filesystem traversal/deletion work with the number of invocations.

**Fixed behavior:** The changed line uses the stable per-session `diagnostics/sandbox-policy.md` path, so each successful invocation replaces the prior report and bounds retained report files to one per session.

**Evidence:** The base line created a fresh UUID directory for every successful `/sandbox policy` invocation, and the adjacent write stored a full Markdown report there. Session data lives under persistent `agentSessionData/<session>` and is deleted only when the session itself is deleted; disposing the live session does not remove those snapshots. The changed test explicitly exercises two invocations followed by session disposal and now expects one latest file. Blame identifies c0f6c8cd52aeceb78b91631bce1b37d161a93d3f as introducing the UUID path.
