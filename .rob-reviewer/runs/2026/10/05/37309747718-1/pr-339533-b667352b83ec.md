### Scenario 1: Cold Dev Container sample launch

- Critical path: Reading source.json, resolving repository HEAD, downloading the pinned devcontainer.json, validating and writing it must complete before volume/container setup, clone, hooks, and agent-host startup can proceed.
- Scaling input: Cold launches across the six distinct built-in samples. Same-source connections are serialized by SequencerByKey; distinct samples may overlap. The governed queue permits one active anonymous request per origin, allowing an API request and raw-host request to overlap across launches but serializing requests within each origin.
- Effective concurrency: Each launch awaits REST then raw serially. Across distinct launches, the shared queue has global concurrency 4, host concurrency 2, caller concurrency 2, and account identity effectively limits each anonymous origin to one active request. Same sample connections are serialized before preparation.
- Cache behavior: source.json eliminates all GitHub reads on warm launches. On cold concurrent reads, REST HEAD requests for an identical repository coalesce while leases overlap; different repositories do not. The raw body is bounded to 1 MiB and is not retained beyond the returned text/source cache.
- Mechanism confidence: High confidence in the two unchanged network calls, cache gating, and queue limits from traced code; lower confidence that multi-sample cold fan-out is common or materially affects total startup.
- Magnitude uncertainty: Several distinct sample launches can now queue their same-origin network stages where direct requests previously had no GitHub queue, but the cardinality is bounded to six and typical interaction launches one sample; no evidence shows a meaningful user-visible regression against the much larger unchanged container/clone path.

### Scenario 4: Authenticated and new anonymous raw downloads through GitHubTransport

- Critical path: A download is admitted by the shared queue, follows bounded redirects, streams a bounded response, and decodes it after the body read. Existing authenticated callers use the same prior boundary with only constant-time anonymous branching added.

- Effective concurrency: Governed by the shared queue; raw.githubusercontent.com has a separate anonymous account/origin from api.github.com, preventing REST quota cooldown from blocking raw content.
- Cache behavior: Raw downloads intentionally use no-store and have no body cache; the Dev Container source cache prevents repeat calls. Raw and REST cooldowns are keyed to separate origins/resources.
