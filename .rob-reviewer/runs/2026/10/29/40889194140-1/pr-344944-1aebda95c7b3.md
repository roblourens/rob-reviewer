<summary>Reviewer scenario analysis</summary>

**Relevant issue families:** repeated-work, serialization-allocation

### Scenario 1: Request \`/plugin enable\`, \`disable\`, \`update\`, \`remove\`, or \`uninstall\` completions for a live Copilot chat

- Critical path: The completion request awaits the global plugin inventory RPC, then the live session plugin inventory RPC, then reconciles both inventories, then awaits session customization discovery before candidates can be returned. The diff changes only the in-process reconciliation and candidate naming; both RPCs and customization discovery were already on this path.
- Scaling input: Global installed-plugin count G and live-session plugin count S. The new identity recovery scans G entries for each session entry lacking a directSourceId, so local reconciliation is O(G\*S) in the worst case; candidate construction remains linear in the reconciled inventory. Installed-plugin inventories are realistically small, so the added comparisons are bounded and not evidenced as user-visible beside the unchanged RPC/discovery latency.
- Effective concurrency: The global and session plugin-list RPCs are awaited sequentially. Session customization work follows inventory reconciliation and may internally await cached/in-flight sync and discovery work in parallel. The diff neither adds concurrency nor changes this scheduling.
- Cache behavior: Installed inventories are uncached on both cold and repeated completion requests before and after the diff. The changed merge creates only request-local Map/Set state. Customization controllers retain discovery state, but that lifecycle is unchanged. No new cache, retained key set, or negative-cache behavior is introduced.
- Mechanism confidence: High confidence in the O(G\*S) local scan and in the unchanged sequential boundary call path, based on the changed loop and traced provider callbacks. High confidence that no expensive boundary or repeated boundary fan-out was introduced.
- Magnitude uncertainty: Exact installed-plugin counts and local comparison timings are not measured. However, the changed nested scan operates over installed inventories rather than marketplace catalogs, and no evidence establishes realistically large G or S; the unchanged IPC and discovery operations dominate likely latency.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_listInstalledPlugins</code>: List the shared/global installed plugin inventory through client.rpc.plugins.list(); cardinality: Exactly one RPC per matching completion request, independent of G
    - Introduced by diff: false; previous behavior: The same global plugin-list RPC occurred once on this path before the diff.; critical-path effect: Must complete before reconciliation and completion candidates can be produced
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:listInstalledPlugins</code>: List the live session's installed plugins through session.rpc.plugins.list(); cardinality: Exactly one RPC per matching completion request when a live session exists, independent of S
    - Introduced by diff: false; previous behavior: The same session plugin-list RPC occurred once on this path before the diff.; critical-path effect: Runs after the global list and must complete before reconciliation
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_getSessionCustomizations / SessionPluginController.getCustomizationsSettled</code>: Settle plugin/customization discovery and refresh MCP discovery while resolving session customizations; cardinality: One customization resolution per matching completion request; warm controller state can reuse settled discovery, while MCP discovery refresh behavior is unchanged
    - Introduced by diff: false; previous behavior: The provider already resolved session customizations after listing plugins.; critical-path effect: Occurs after inventory reconciliation and must complete before plugin candidates are returned
- Verdict: No reportable regression. The diff adds a worst-case quadratic in-memory identity lookup, but realistic inventory cardinality does not establish concrete latency, CPU, or GC impact, and all expensive boundary calls retain their previous cardinality and placement.

### Scenario 2: Request plugin completions before a live SDK session exists (cold/provisional chat)

- Critical path: The request awaits one global plugin inventory RPC, returns that inventory without running the changed live-session merge, and then resolves session customizations before formatting completion candidates. The changed reconciliation loop is bypassed entirely.
- Scaling input: Global installed-plugin count G controls linear candidate filtering and formatting; the diff only changes marketplace candidate text selection by a constant amount per plugin.
- Effective concurrency: One plugin-list RPC is awaited before customization resolution. Customization settling may internally parallelize its existing sync/discovery operations. The diff does not alter concurrency or backpressure.
- Cache behavior: The global plugin list is uncached on repeated requests before and after the diff. The new Map and merge are not allocated because there is no live session. Existing customization discovery state may be warm; no cache behavior changed.
- Mechanism confidence: High confidence because \`\_listInstalledPlugins\` returns immediately when no live session exists and the provider's only changed work is constant per marketplace candidate.
- Magnitude uncertainty: Underlying IPC and discovery duration varies by environment, but the diff does not add, move, or multiply either boundary.
- Expensive boundaries:
  - IPC at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_listInstalledPlugins</code>: List the shared/global installed plugin inventory through client.rpc.plugins.list(); cardinality: One RPC per matching completion request
    - Introduced by diff: false; previous behavior: Identical one-RPC behavior.; critical-path effect: Must finish before candidates can be generated
  - filesystem at <code>src/vs/platform/agentHost/node/copilot/copilotAgent.ts:\_getSessionCustomizations</code>: Resolve and settle session customization discovery; cardinality: One resolution per matching completion request, with existing warm discovery reuse
    - Introduced by diff: false; previous behavior: Identical customization-resolution placement.; critical-path effect: Must finish before candidates are returned
- Verdict: No reportable regression. Cold completion boundary count, serialization scale, and critical-path ordering are unchanged; qualified marketplace strings add only negligible per-candidate allocation.

**Summary:** Completed the performance pass over all four changed files and all diff pages. Traced live and cold plugin-completion paths, including IPC and filesystem/customization boundaries, cache behavior, effective cardinality, and concurrency. The only new scaling mechanism is an in-memory O(G\*S) lookup over realistically small installed-plugin inventories; it does not meet the evidence threshold for concrete user-visible impact, and no expensive boundary was introduced or amplified. No findings were submitted.
