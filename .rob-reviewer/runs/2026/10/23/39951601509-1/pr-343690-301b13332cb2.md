# Performance review: Do not forward request credentials across origins on redirects

[PR #343690](https://github.com/microsoft/vscode/pull/343690) at `301b13332cb24cef9f4ea0abe76366ffcece0072`

## Findings (1)

### 1. [medium] Preserve one timeout budget across redirects

**Finding ID:** `PERF-DD2647592093`  
**Location:** <code>src/vs/platform/request/node/requestService.ts:258</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** network wait time  
**Scaling:** The effective timeout grows linearly with followed redirects, up to four timeout periods with the default redirect limit.  
**Outcome:** increased critical-path latency  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Electron followed redirects on one ClientRequest, so one timeout timer bounded the complete redirect chain.  
**Changed behavior:** Electron redirects now abort the current request and create a new request that receives a fresh full-duration timeout.  
**Confidence:** 0.95 — Manual redirect mode, recursive request creation, timer setup per request, the redirect limit, and timed desktop callers are explicit in the changed and surrounding code.

**Causal diff evidence:** The added manual redirect mode at line 258 replaces Electron's single automatically redirecting ClientRequest with the new per-hop request recursion.

A slow redirect chain can leave extension gallery requests pending for multiple 60-second periods rather than the configured single period.

**Evidence:** The Electron service always sets isChromiumNetwork. Each nodeRequestAttempt arms setTimeout(options.timeout), and the new redirect handler recursively invokes nodeRequest for every hop. Gallery asset calls set a default 60000 ms timeout.

**Suggested direction:** Carry the initial absolute deadline or remaining timeout through recursive redirects.
