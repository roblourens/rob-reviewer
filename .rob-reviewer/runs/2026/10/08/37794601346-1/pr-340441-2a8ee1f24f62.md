- Cache behavior: Cold use probes runtime files and starts the subprocess. Warm use returns the retained \`\_client\`; failures clear startup state and cleanup owns the subprocess. There is no changed negative-cache behavior in host code.
- Mechanism confidence: High confidence in host critical-path reachability, laziness, coalescing, and boundary cardinality; low confidence in unreviewable upstream implementation details, which is insufficient for a finding.

- Effective concurrency: Concurrent stops are coalesced by \`\_clientStopping\`; Agent Host process shutdown is joined and timeout-bounded. Telemetry producers may be concurrent, but no changed producer or batching configuration appears in the diff.
- Cache behavior: Stopping clears prewarmed metadata, client references, pending restart reasons, and the runtime-owned proxy handle so the next start creates fresh state. No changed retained cache or missing disposal is evidenced.
- Mechanism confidence: High confidence that cleanup ownership, stop coalescing, and process timeout are unchanged; insufficient evidence of a new runtime retention or flush mechanism.
- Magnitude uncertainty: The upgraded binary's exact telemetry flush duration and batching internals are opaque, but no changed source, failure, or benchmark demonstrates a regression.
