# Performance review: chat: stabilize reference details loading and share pill hovers

[PR #340433](https://github.com/microsoft/vscode/pull/340433) at `d3672d0b92ac8a1d1762de9a4d04ca32c3597197`

## Findings (1)

### 1. [low] Release cached commit cards when their hover closes

**Finding ID:** `PERF-4D0B121FB099`  
**Location:** <code>src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts:1080</code> (<code>RIGHT</code>)  
**Performance category:** <code>memory</code>  
**Mechanism family:** <code>cache-lifecycle</code>  
**Resource:** detached rich-hover DOM nodes, tabbable element arrays, onclick handlers, and callback closures  
**Scaling:** O(H) retained rich DOM trees where H is the number of distinct commit entries hovered while they remain in the session; each commit can retain compact and default views.  
**Outcome:** retained memory and increasing GC pressure  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Commit previews were created for the active hover and were not inserted into a session-scoped per-commit hover cache, so closing the preview did not leave its rich DOM reachable from a cache for the remainder of the session.  
**Changed behavior:** Commit rows in the agent-host References/Artifacts collections now use a session-scoped \`ChatPillHoverCache\`, so rendering a commit preview permanently populates a cached view for that commit until the commit disappears or the session changes.  
**Confidence:** 0.94 — The added cache call, session-scoped retain set, and \`\_views\` ownership are directly traced. ActionList treats HTMLElement hover content as caller-owned and removes it without disposing it on ordinary navigation, while \`CachedChatPillHover\` has no cleanup for detached views. The exact retained bytes depend on how many commit previews a user visits, so severity is low rather than speculative omission.

**Causal diff evidence:** The added commit path wraps every commit entry with \`this.\_commitHoverCache.get(...)\` at line 1080. \`ChatPillHoverCache\` retains each key for the whole current session, and each cached entry's \`\_views\` map keeps the rendered compact/default HTMLElement trees after they are detached; unlike the previous commit hover closure, no close/dispose hook clears those views.

In a long agent session with many commit references, navigating through commit previews leaves every visited card retained after it closes. Memory and later GC work grow with preview history, increasing the workbench's footprint for the rest of the session.

**Evidence:** \`AgentHostSessionInputPills\` retains \`\_commitHoverCache\` keys for all current commit artifacts/references and line 1080 inserts the cache presentation into each commit. \`CachedChatPillHover.\_render\` stores the rich element and its tabbable/live children in \`\_views\`; subsequent closure of the submenu only detaches caller-owned HTMLElement content, and neither \`hover\` nor \`pillHover\` supplies a lifecycle callback that deletes the view. Rich commit cards contain multiple DOM nodes, onclick handlers, and callbacks capturing the session services.

**Suggested direction:** Keep the stable descriptor/action cache, but evict each density's view when its hover closes or becomes detached; retain a view only while connected so reopening reconstructs fresh content without preserving closed-card DOM.
