# Performance review: Refactor agentic browser opening lifecycle

[PR #331996](https://github.com/microsoft/vscode/pull/331996) at `854143a8acd7c939f640390baf0ceeb734cd0ef6`

## Findings (1)

### 1. [medium] Do not wait for the full load event before starting Playwright readiness

**Finding ID:** `PERF-C16E79A62B5D`  
**Location:** <code>src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts:345</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>eager-work</code>  
**Resource:** network navigation and the IPC promise waiting on Electron WebContents.loadURL  
**Scaling:** The added wait lasts until every load-blocking subresource completes and can consume the full 30-second timeout for each newly opened agent page; concurrent tool calls each incur their own navigation wait.  
**Outcome:** increased latency and a blocked tool critical path  
**PR causality:** <code>introduced</code>  
**Previous behavior:** The prior OpenBrowserTool path delegated to PlaywrightSession.openPage, whose page.goto awaited only DOMContentLoaded before producing the page summary.  
**Changed behavior:** The new workbench creation path awaits BrowserViewModel.loadURL before returning the input, and only afterward invokes Playwright's DOMContentLoaded readiness and summary path.  
**Confidence:** 0.97 — The changed await, complete call path to Electron's network load, and sequencing before \`waitForPageAndGetSummary\` are explicit. The exact added duration varies by site, but slow load-blocking resources are a realistic trigger and the previous DOMContentLoaded boundary is visible in the deleted code.

**Causal diff evidence:** The added \`await model.loadURL(initialUrl)\` at RIGHT line 345 is now awaited by \`\_openNewPage\`; the deleted \`page.goto(url, { waitUntil: 'domcontentloaded', ... })\` in \`PlaywrightSession.openPage\` was the previous readiness boundary.

Opening an agent browser page can stall for many seconds on sites with slow or hanging subresources even though the DOM is already usable, delaying the chat tool result and subsequent agent actions.

**Evidence:** \`BrowserViewModel.loadURL\` crosses to \`BrowserViewMainService.loadURL\`, which awaits \`BrowserView.loadURL\`; that in turn awaits \`webContents.loadURL(url)\` (browserView.ts:742), whose promise completes at Electron's finished-load boundary. \`OpenBrowserTool.\_openNewPage\` awaits \`createBrowserView\` before calling \`waitForPageAndGetSummary\`, so Playwright cannot begin discovery or return its DOMContentLoaded summary until this stricter full-page load finishes. A page whose DOM is ready but whose images/scripts are slow therefore used to progress after DOMContentLoaded and now blocks until full load or 30 seconds.

**Suggested direction:** Start \`model.loadURL(initialUrl)\` without making full-load completion the return condition, then let \`waitForPageAndGetSummary\` remain the authoritative DOMContentLoaded/timeout gate; preserve explicit rejection logging or propagate immediate navigation failures without awaiting the later load event.
