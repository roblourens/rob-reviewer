# Performance review: Fix browser double-navigating pages opened via \`window.open\`

[PR #339436](https://github.com/microsoft/vscode/pull/339436) at `98a8389f7f915f990108e714429051be18933e45`

## Performance regression fixes detected (1)

### 1. repeated-work

**Fix location:** `src/vs/platform/browserView/electron-main/browserViewMainService.ts:438` (`RIGHT`)  
**Blamed base line:** `src/vs/platform/browserView/electron-main/browserViewMainService.ts:437`  
**Introducing path:** `src/vs/platform/browserView/electron-main/browserViewMainService.ts`  
**Introducing commit:** `ec0c2dd6cd9b9354e54eaa79b902871abaeb3378`  
**Mechanism family:** `repeated-work`  
**Performance category:** `network`  
**Confidence:** 0.98

**Mechanism:** Every allowed window.open popup previously combined Chromium's navigation of the returned WebContents with a second explicit WebContents.loadURL of the same URL, repeating page fetch, document parsing, lifecycle events, and associated subresource work once per popup.

**Symptom:** Pages opened through window.open were navigated twice, causing duplicate network/page-load work and added popup-open latency; for about:blank popups subsequently populated with document.write, the extra load also replaced the initial document.

**Fixed behavior:** Popup WebContents supplied by Electron no longer receive an additional explicit loadURL; Chromium completes the original window.open navigation once. Child views without supplied WebContents still receive their initial URL through the existing loadURL path.

**Evidence:** In the base revision, BrowserView.setWindowOpenHandler passes Electron's existing popup WebContents and details.url into \_createChildView (browserView.ts:187-226). The callback at browserViewMainService.ts:431-439 always copied that URL to initialUrl, and \_createBrowserView then unconditionally invoked view.loadURL(initialUrl) at lines 477-481. Electron also completes the original window.open navigation after createWindow returns the same WebContents, so the base path issued a second navigation for each allowed popup. The changed line gates initialUrl when electronOptions.webContents exists, while preserving explicit loading for child views created without existing WebContents (browserView.ts:769).
