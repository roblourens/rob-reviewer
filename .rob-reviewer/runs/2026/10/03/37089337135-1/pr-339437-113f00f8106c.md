## Findings (1)

### 1. [low] Omit the default coauthor option on new sessions

**Finding ID:** `PERF-79E65037609E`  
**Location:** <code>src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:1146</code> (<code>RIGHT</code>)  
**Performance category:** <code>ipc</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** one serialized JSON-RPC \`session.options.update\` call to the Copilot runtime subprocess per newly created session  
**Scaling:** The cost grows linearly with new session creation count (one additional awaited IPC per create); distinct sessions may initialize concurrently, increasing aggregate runtime RPC load.  
**Outcome:** increased latency on the session-launch critical path  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Before this diff, new sessions omitted \`coauthorEnabled\`, used the SDK's enabled-by-default behavior, and did not issue this option-specific update.  
**Changed behavior:** Every new Copilot session now explicitly sends the SDK-default \`coauthorEnabled: true\`; the SDK applies this option with an additional \`session.options.update\` JSON-RPC after session creation, adding an awaited subprocess round trip even when the user did not opt out.  
**Confidence:** 0.94 — The changed config field is on the awaited \`createSession\` launch path, the mirrored registered default is concretely \`true\`, and the SDK behavior for this session option is explicitly identified as an extra \`session.options.update\`. The exact milliseconds vary by host load and transport, but the additional critical-path RPC and its one-per-create cardinality are established.

**Causal diff evidence:** The added RIGHT line 1146 unconditionally includes \`coauthorEnabled\` in every built session config. The same diff registers and mirrors the setting with default \`true\` (\`chat.shared.contribution.ts\` lines 1742-1747), and configuration sync resolves registered defaults, so ordinary sessions send \`true\` rather than leaving the field absent.

Starting a new Copilot Agent Host chat pays an unnecessary subprocess IPC round trip before the session can finish initialization, increasing first-use latency for every default-configured session.

**Evidence:** \`CopilotAgentSession.initializeSession\` awaits \`CopilotSessionLauncher.launch\` before the session is registered; \`\_createSession\` awaits \`plan.client.createSession({...config})\`. The added field is therefore on the user-visible session startup critical path. Agent-host configuration sync falls back to registered defaults, so default installations pass \`true\`. For this SDK option, explicit presence causes a separate \`session.options.update\` RPC to the Copilot runtime. A newly created session already has the SDK default of enabled, so that RPC performs no state change.

**Suggested direction:** For \`plan.kind === 'create'\`, omit \`coauthorEnabled\` when the effective value is \`true\` and send it only for the opt-out (\`false\`). Continue sending an explicit value on resume when needed to override a value persisted by an earlier launch.
