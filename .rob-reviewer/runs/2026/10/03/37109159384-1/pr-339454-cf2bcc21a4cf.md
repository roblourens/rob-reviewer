# Performance review: agentHost: restore authentication on transport reconnect

[PR #339454](https://github.com/microsoft/vscode/pull/339454) at `cf2bcc21a4cfb6244047bdbef92678a68b243a49`

## Findings (1)

### 1. [high] Avoid reminting credentials on every replay reconnect

**Finding ID:** `PERF-8196FEA63AD6`  
**Location:** <code>src/vs/platform/agentHost/browser/agentHostProtocolClient.ts:955</code> (<code>RIGHT</code>)  
**Performance category:** <code>latency</code>  
**Mechanism family:** <code>repeated-work</code>  
**Resource:** Mission Control network calls, authenticate RPCs, and provider authentication work  
**Scaling:** One forced cloud credential refresh and one authenticate RPC per cached authentication entry on every replacement transport; cost grows with reconnect frequency and credential count.  
**Outcome:** Higher resume latency and potentially about 30 seconds of blocked reconnect progress on closely spaced transport failures.  
**PR causality:** <code>introduced</code>  
**Previous behavior:** Ordinary replay reconnects reused host authentication and drained queued traffic; restoration ran only for fresh initialization or an interrupted restore pass.  
**Changed behavior:** Every replacement transport with configured or cached authentication now awaits authentication restoration before outbox drain and Connected state, regardless of whether reconnect reported any authentication loss.  
**Confidence:** 0.99 — Production wiring always configures the resolver for cloud sandboxes; the forced Mission Control refresh, 30-second limiter, and reconnect-gate ordering are explicit. Only the exact remote duration varies.

**Causal diff evidence:** RIGHT line 955 newly makes restoration true from the mere presence of a resolver or cached credential, so even Replay with missing=\[\] enters the blocking authentication path.

An ordinary mobile resume or network flap now blocks queued cloud-sandbox chat traffic on a Mission Control request and host authentication even for Replay with missing=\[\]. A second flap within 30 seconds hits the refresh limiter, delaying recovery until a later retry.

**Evidence:** CloudSandboxConnectionFactory always supplies resolveInitialAuthentication. Its prepareAuthentication calls refreshAuthenticationCredentials when the current sealed token was previously used, which forces ICloudSandboxApiService.reconnect. CloudSandboxCredentialRefresher rejects another forced refresh within MIN\_CREDENTIAL\_REFRESH\_DELAY\_MS=30,000. This predicate ignores result.missing and AuthRequired, and reconnect awaits it before draining queued messages.

**Suggested direction:** Restore only on a concrete loss signal, such as missing protected subscriptions or AuthRequired, while retaining fresh-initialize and interrupted-pass restoration; let Replay with no authentication debt drain immediately.
